### 13. Platform architecture

- Process model: the desktop Electron main process supervises a Python backend started in serve mode (apps/desktop/electron/backend-*.ts: claim, command, discovery, exit recovery, health, ownership, recycle, spawn env) [SRC names; DOC apps/desktop/AGENTS.md]. The TUI is Node (Ink) talking to Python over stdio JSON-RPC (tui_gateway/AGENTS.md "Process model") [DOC]. The dashboard is FastAPI with a PTY WebSocket (/api/pty) that spawns the real `hermes --tui` (web/AGENTS.md) [DOC]. The gateway is a long-running Python process hosting adapters, and one process serves many profiles [DOC gateway/AGENTS.md; root AGENTS.md]. Multiplex rule: exactly one `hermes serve` and one `hermes gateway run` per host per OS user (gateway/host_rendezvous.py docstring) [SRC].
- Control socket: gateway/control_socket.py (local-only socket; versioned JSON verbs identify and status; a connectable socket with a valid identify reply counts as liveness; never a TCP port) [SRC docstring].
- Desktop IPC: about 200 Electron ipcMain channels named hermes:* (apps/desktop/electron). Counts by prefix: git 21, hud 13, fs 10, connections 9, window 7, pet-overlay 7, connection-config 7, terminal 6, quick-entry 6, profile 5, cloud 5, bootstrap 5, logs 4, context-menu 4, plus about 40 singletons [SRC grep]. The renderer has no direct Node access; native power is exposed through typed capabilities [DOC apps/desktop/AGENTS.md].
- Wire protocols: TUI and desktop RPC are newline-delimited JSON-RPC over stdio, and WebSocket for the other transport (tui_gateway/transport.py, ws.py). Server-to-client requests carry srq-N ids and block until answered (tui_gateway/AGENTS.md) [SRC; DOC]. ACP: JSON-RPC over stdio (acp_adapter). MCP: stdio and HTTP. A2A: plugins/platforms/a2a (protocol v1.0, both directions, per manifest). Relay: WebSocket (gateway/relay/ws_transport.py). Browser: CDP over WebSocket. Bot Desktop: RFB (VNC). ## 5. Data and protocol hints

- Storage: SQLite sessions database under the profile home (WAL, read pool, lock owners and holders, repair and portability modules, FTS5 with the CJK tokenizer built from native/fts5_cjk). Separate SQLite stores for kanban boards and per-profile projects (hermes_cli/projects_db.py). JSON state for cron jobs and executions, curator (.curator_state, .usage.json), skill archive (~/.hermes/skills/.archive/), and pets. Checkpoints go to one shared shadow git store (tools/checkpoint_manager.py). Process checkpoints are JSON (tools/process_registry.py). Memory is MEMORY.md and USER.md. Settings live in config.yaml, secrets in .env only, logs under logs/ [SRC; DOC AGENTS.md "User state"].
- Trajectory format: from/value message pairs in batch output (batch_runner.py docstring); developer-guide/trajectory-format.md [SRC; DOC].
- Wire formats: newline-delimited JSON-RPC over stdio for the TUI and desktop (tui_gateway/AGENTS.md); WebSocket for the dashboard PTY (raw bytes, resize escape sequence) and other sockets; OpenAI-style HTTP JSON and SSE for the API server (chat/stream, runs/events); JSON-RPC for ACP; MCP over stdio or HTTP; CDP over WebSocket for browsers; RFB for Bot Desktop; OTLP over HTTP for telemetry [SRC; DOC].
- Correlation: server-to-client requests use srq-N ids and block until the response arrives; open requests are replayed on session.resume and session.events.since so a reconnecting client can re-render them (tui_gateway/AGENTS.md) [DOC].
- Authentication: dashboard uses an ephemeral session token; the WebSocket path takes it as a query parameter, since browsers cannot set Authorization on WebSocket upgrades (web/AGENTS.md) [DOC]. dashboard_auth stack with token auth, WebSocket tickets, cookies and refresh singleflight [SRC]. Provider OAuth flows include PKCE (OpenRouter), device flow (Copilot) and browser flows (Codex) [SRC names]. GitHub App JWT for the Skills Hub [SRC]. DM pairing for messaging platforms, plus per-platform allowlists [SRC].
- Sync and multi-process coordination: hosted rooms keep an append-only event log in gateway/hosted_rooms.py, with delivery and relay leasing in other modules [DOC docstring]. Host-wide singleton rendezvous per role per OS user (gateway/host_rendezvous.py). Control socket for liveness (gateway/control_socket.py). Relay connector over WebSocket, marked EXPERIMENTAL in its docstring (gateway/relay/__init__.py) [SRC].
- Consent and telemetry: shared metrics are opt-in and default off; packages are sent only inside recorded consent windows [SRC].
- Retention and bounds: memory char limits (2200 and 1375 by default); compression thresholds and protected head and tail; checkpoint pruning; curator archives rather than deletes, with pre-run backups; rolling 200 KB output buffer for background processes; FTS-backed search instead of full transcript loads [SRC].
- Localisation data: locales/*.yaml and *.tui.yaml; apps/desktop/src/i18n/*.ts (per-area files such as *_boot, *_onboarding, *_shared_metrics) [SRC].
- Install and runtime paths: $HERMES_HOME (default under ~/.hermes; native Windows under %LOCALAPPDATA%\hermes per README), accessed only through get_hermes_home() (root AGENTS.md rule HX001) [DOC README; DOC AGENTS.md].
