## Appendix D. What code verification changed

Code verification read the Verevon implementation for every recommendation. Outcome: 98 recommendations kept in the list, 1 moved down one tier, 0 dropped as already built; 81 were reworded because the code showed a more precise gap, a better place to build it, or reusable parts.

### Tier changes after code verification

- [F-t3-016](#F-t3-016) Multi-replica-safe run control: shared cancel, queued-input, plan-mode and turn state, durable send receipts and an editable message queue: Priority to Recommended. Real but a scale-readiness hardening for a single-replica deployment with drain and Redis resume already shipped, and it is not a precondition for durable runs because approvals already persist in session-core; the queue UX part needs a design decision first.
