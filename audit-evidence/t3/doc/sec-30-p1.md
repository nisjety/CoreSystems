### F-t3-001 · One server-assembled run context for Do, Plan and scheduled runs: instruction stack, thread history, persona, memory and run notes
| Tier | Verevon today | Effort | Plane | Wave | Confidence |
|---|---|---|---|---|---|
| Priority | Partial | M | Model Plane (model-gateway composer, execution-core loop, session-core assembly) | W1 | High |

**What to build.** Give every Do, Plan and scheduled run the same context that an Ask turn already gets: the composed instruction stack (platform, org, Space, persona), the prior turns of the thread under the compaction budget, a memory prefetch and attachments. Add a composed authored-instructions field and bounded prior-turn messages to RunAgentRequest, fill them in model-gateway before the agentic branch returns, and insert them in run_rounds. Stamp completeness flags (instructions, history, memory) on the run record. Automations get a per-schedule notes block later, once [F-t3-018](#F-t3-018) lands.

**Why it matters.** The governed agent loop is the one place where the model takes actions, and today it starts from a preamble plus the goal. Org policy, Space instructions, persona and memory are silently dropped exactly where they matter most. This is a governance gap, not only a quality gap, and it is the cheapest high-impact fix in the audit.

**What the references do.** Cursor renders typed context components to role messages and loads rules from project files, team and user settings with confirmed activation modes: always, glob, agent-fetched and manual [SRC]. DeepSeek chains workspace instruction files under a byte budget [SRC]. Codex passes a typed turn context [SRC]. Claude desktop labels seven instruction scopes (Global, Folder, Space, Project, Channel, Profile, Organization); the only documented precedence is that organization instructions override personal preferences, and the organization budget observed is 3000 characters [SRC, from i18n strings, not runtime code]. Layered instructions are table-stakes at 8 of 12 references; memory in agent tasks is 3 of 12 [SRC/DOC]. The ordering org > Space > persona > user is Verevon's own design, not a reference behaviour [INF]. Caveats: ChatGPT, Claude.ai, Manus and Perplexity instruction layering is DOC-only; Cursor automation memory rests on service names only.

**Verevon today.** Ask turns compose instructions in the ADR-0003 composer (apps/Model Plane/rust/services/model-gateway/src/sse.rs:6360-6420) and prefetch memory with a 400 ms bound (sse.rs:1655), but the agentic branch returns at sse.rs:1405-1500 before either runs, and build_run_agent_request passes only the content plus an approved-plan block (sse.rs:9118-9190). RunAgentRequest (apps/Model Plane/proto/model_plane/v1/execution.proto:76-200) has no history, instruction, persona or memory field, and run_rounds seeds a fresh preamble-plus-goal history (apps/Model Plane/rust/services/execution-core/src/runtime_loop/agent.rs:1185-1226). The BFF already injects org, Space and persona text onto the same request on both ingress paths (apps/Frontend Plane/verevonv3/apps/gateway/src/domains/ag_ui.rs:85-130, apps/gateway/src/domains/chat/streams.rs:55-100), so the data reaches model-gateway and is dropped there. Reuse authored_instructions_message and its tests, load_context_assembly_messages, fetch_chat_memory_context, the compaction.rs budget planner and the existing space_id and plan_mode fields. Plan rows B3 and B4 (CHAT_GAP_CLOSURE_PLAN_2026-10-01.md:109-110) cover instructions and hook_context only.

**How to build it in Verevon.** The resolver is not in Model Plane: the BFF resolves (client values stripped, Space layer gated on live Control membership) and model-gateway composes, so execution-core must receive finished text and never re-resolve or read Space data. Hydrate history in model-gateway, which already holds the verified user bearers, rather than giving execution-core a second session-core read path. Subagents keep isolated history but inherit instructions. Memory prefetch must honour Zero Data Retention (ZDR) and the per-thread pause or off switch from [F-t3-020](#F-t3-020). Sequence with [F-t3-022](#F-t3-022) so volatile blocks sit in the append-only tail and the cached prefix stays stable; otherwise larger prompts raise the cost of every run.

**Quick win.** The proto field and gateway composition are S-sized and reuse code that already runs for Ask turns; the gain is immediate for every Do run.

### F-t3-002 · Durable agent loop: checkpoint every round and pause, resume in place after approval, answer or crash, close dangling tool calls, effect ledger
| Tier | Verevon today | Effort | Plane | Wave | Confidence |
|---|---|---|---|---|---|
| Priority | Partial | L | Model Plane (execution-core loop and continuation, session-core run state) | W1 | High |

**What to build.** Persist the Do loop's message fold in session-core at every round and before each effectful call, and re-enter the loop at that checkpoint when an approval, a clarifying answer or a crash recovery arrives. Stage it: first a continue that starts a fresh run seeded by [F-t3-001](#F-t3-001) context plus completed step summaries (plan B7 and open decision OD6), then true in-place resume from a scrubbed fold checkpoint. Typed closers for interrupted tool calls, an effect ledger, parking on provider exhaustion and an ask_user tool are separable follow-on items.

**Why it matters.** Today an approval is a dead end for a multi-step task: the loop pauses durably but discards its reasoning state, and only three tool kinds are re-executed cold from a descriptor. That blocks plan-continue, scheduled runs with approvals, goals and the computer-use loop.

**What the references do.** DeepSeek checkpoints before each model dispatch, before each tool body and at the next request boundary, fails closed, and resumes with ownership [SRC]. It explicitly disclaims exactly-once: it records dispatch intent, writes an unknown-outcome closer instead of retrying, recommends forwarding the call id as an idempotency key, and does not checkpoint inside an active model attempt; its durable out-of-turn approval workflow is deferred [SRC]. Hermes holds a refreshed turn lease (TTL 300 s) with a stall watchdog, classifies 29 failover reasons, and parks a turn with a visible countdown over five cycles [SRC]; its blocking server-to-client requests use an in-memory event and are replayed only to reconnecting clients while the process lives [SRC]. Durable resume is 5 of 12 references, provider retry and failover 6 of 12 [SRC]. Manus keeps an in-memory action ledger (4096 entries, 10-minute horizon) for browser side-effect actions only, returning a replay-conflict on digest mismatch [SRC]. No reference shows a crash-durable pause and resume after approval; that is a Verevon synthesis [INF]. Cursor auto-continue is server-flag-gated [SRC].

**Verevon today.** pause_for_approval writes an approval with an encrypted descriptor and returns (apps/Model Plane/rust/services/execution-core/src/runtime_loop/agent.rs:4476-4560); history is a local Vec per run_rounds call (agent.rs:1185-1200). The only continuation is approval_delivery_worker.rs:1-60, which resumes execute_provider_action, book_shipment and tickets.create and fails every other tool closed. resume_durable_approval_continuation always returns unavailable (apps/Model Plane/rust/services/execution-core/src/grpc.rs:706-713) and model-gateway never turns a grant into ResumeRun (apps/Model Plane/rust/services/model-gateway/src/approvals.rs:255-275). Run state is in-memory (execution-core/src/state.rs:1-40). Reuse the session-core checkpoints table and SaveCheckpoint RPC with its 4 MiB cap, the approval outbox and receipt protocol, continuation_crypto.rs, the terminalization recovery loop, stream_buffer replay and approval rehydration, which already exist.

**How to build it in Verevon.** Decide the host explicitly: orchestrator-core has Temporal workflows with approval signals and per-turn activities (apps/Model Plane/go/services/orchestrator-core/cmd/workflows/interactive_run.go:52-55), but they drive ExecuteStep, and the chat Do path bypasses Temporal. ZDR: durable step records are content-redacted under ZDR (agent.rs:4376-4398), so a ZDR run must not checkpoint content durably; refuse resume or keep it memory-only. Resume must re-authorise through Control with a fresh delegated bearer (OD8); a service-principal shortcut would break delegated identity. browser_agent resumption stays excluded until a browser run itself survives a pause, and MCP tools have unknown idempotency, so no exactly-once promise applies to them. Lists [F-t3-016](#F-t3-016) as a dependency, although verification demoted it because approvals already persist in session-core and it is not a precondition for durable runs. Keep the core slice at L; bundling closers, ledger, parking and ask_user makes it XL, so split.

### F-t3-003 · Declared tool side-effect classes, a never-auto set and per-tool allow/ask/never policy, so MCP tools become callable through the signed gate
| Tier | Verevon today | Effort | Plane | Wave | Confidence |
|---|---|---|---|---|---|
| Priority | Partial | L | Model Plane (capability-core registry and policy, execution-core and model-gateway enforcement) | W1 | High |

**What to build.** Replace name-substring risk guessing with a declared side-effect class on every capability-core row (built-in, provider action, discovered Model Context Protocol (MCP) tool), derived at MCP discovery from tool annotations and pinned by digest. Make trusted_capability_id resolve dynamic mcp__server__tool names through the registry, have the autonomy-rung ladder read the class, seed a non-delegable never-auto set, and store per-tool allow/ask/never policy at user and org scope in capability-core. Deliver Do mode first; read-only MCP in Ask is a later step.

**Why it matters.** The model cannot call any MCP tool today, although registration, OAuth and staged disclosure are built. MCP client runtime is table-stakes at 6 of 12 references. The substring classifier is the weakest link in an otherwise strong signed-gate design: risk should be declared data.

**What the references do.** Hermes runs each MCP server as a supervised task owning one session, with recovery handlers and a circuit breaker; its trust gate is a binary readOnlyHint check applied only to servers configured as untrusted, asked once per call with no stored policy, and the default is full trust [SRC]. Claude desktop has a per-tool toolPolicy for its two built-in connectors (GitHub, Microsoft 365) with code-defined ask defaults, readOnlyHint skipping, a stricter-wins merge, an 8-tool never-allow set per connector and sliding-window write and send throttles [SRC, from prettified bundles]. Manus declares five side-effect levels for its 22 browser tools, but in code they drive only replay deduplication and MCP annotations, not approvals [SRC]. ChatGPT documents graduated app permissions (always ask, read, low-risk, all) [DOC]; Perplexity documents always-ask plus once, thread or deny, with recurring runs inheriting thread grants [DOC]. Using a declared class to drive approval policy is therefore a Verevon synthesis [INF]. The per-tool policy count in the original data was inconsistent and is not restated.

**Verevon today.** execution-core matches name substrings and treats every mcp__ name as risky (apps/Model Plane/rust/services/execution-core/src/permission/mod.rs:200-293); capability-core rows carry only a three-level risk_level (apps/Model Plane/go/services/capability-core/internal/models/capability.go:1-60) consumed by the policy engine (internal/policy/engine.go:105-155). MCP tools are offered to Do runs, but trusted_capability_id is a static map returning None for them (execution-core/src/capability_policy.rs:736-840), so execute_step_inner refuses every call (runtime_loop/mod.rs:495-565). Ask refuses them by design (apps/Model Plane/rust/services/model-gateway/src/tool_loop.rs:625-642). McpToolAnnotations::side_effect exists with no production consumer (model-gateway/src/mcp_jsonrpc.rs:55-125); the never-auto set is only tickets.create (permission/mod.rs:72-100). Reuse risk_level, rung_required_for and check_autonomy_rung (permission/mod.rs:100-200), requires_durable_owner_approval, and operation_is_write as the fail-safe model.

**How to build it in Verevon.** Model Plane owns capabilities, so classes and MCP tool rows are registry-owned and bound server-side; a binding may never be synthesised from a model-supplied name (capability_policy.rs:836-838). The code warns that two risk tables diverge (permission/mod.rs:81-92), so the class replaces is_risky_call as the rung input rather than sitting beside it. Hooks are an in-memory registry (model-gateway/src/state.rs:317) and not a policy store. ZDR must propagate: agentic runs carry zdr (execution.proto:100-107), so MCP servers outside the attestation boundary are refused there. Unknown classes default to the strictest; mis-declared classes are silent over-permission, so declarations need review. Ask-mode MCP needs an inline continuation contract (tool_loop.rs:625-638) and would push the item to XL.
