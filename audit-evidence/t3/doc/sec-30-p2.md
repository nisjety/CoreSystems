Durable reference-based uploads, PDF page images and OCR (optical character recognition) are a later phase sized against owner ruling OD18 (4 MB, 60,000 characters).

**Why it matters.** Uploading a spreadsheet and asking for analysis is expected of any assistant (4 of 11 references for attachments, three vendors). Dropping an image without telling the user contradicts Verevon's own "never fake success" rule.

**What the references do.** Fail-closed handling is confirmed in two sources: DeepSeek's read_image refuses when the model capability is unknown before any file work, and Antigravity's model config carries supported_mime_types per model with the copy "Selected model does not support this media type" [SRC]. claude.ai documents 500 MB per chat file and 20 files, PDFs up to 100 pages visually, 30 MB project files, and 30 MB per file inside the file-creation sandbox; the limits differ by surface [DOC]. Its sandbox egress tiers (off, package managers, package managers plus domains, all) are confirmed for Team and Enterprise with plan-specific defaults [DOC]. DeepSeek's attachment store is content-addressed by sha256 with dedup, on a single machine [SRC]. T3 Code queues image uploads with three per environment, a five-minute timeout and HEIC decoding with a quality ladder; generic files use another path and no content hashing was found [SRC]. Sandbox data analysis is documentation only for claude.ai, ChatGPT, Manus and Perplexity [DOC]. Presigned direct upload to object storage, read-only mounts at a known path and per-call minute limits are Verevon design, not reference behaviour [INF].

**Verevon today.** Documents are extracted client-side, capped at 1 MB, 60,000 characters per file and 120,000 per turn, and inlined into message text (apps/Frontend Plane/verevonv3/src/features/chat/lib/prepare-chat-attachments.ts:6-43; chat-normalizers.ts:1150-1240). Only image parts are dropped on the ChatGPT subscription route (apps/Frontend Plane/verevonv3/src/shared/api/chat-client.ts:1144); text still reaches the model. An image diverts the whole turn, including a Do turn, into AnalyzeImage (apps/Model Plane/rust/services/model-gateway/src/sse.rs:1405-1432; vision.rs:1-60 uses the first image only). The composer has no MIME or capability check (DashboardComposer.tsx:1699-1725,3419-3430), although inference-core already emits vision and image feature flags (apps/Model Plane/rust/services/inference-core/src/provider/mod.rs:655-685). The durable upload route is text-only, asynchronous, refused under ZDR with 412 and has no production caller (chat-client.ts:2081-2118). code_interpreter files_in is model-authored base64 only (execution-core/src/code_interpreter.rs:180-260). Reuse ModelInfo.capabilities, the imports-core extract route and inference-core AnalyzeDocument OCR.

**How to build it in Verevon.** Phase 1 ships alone at S to M. For H6, bytes reach the sandbox through Data Plane or an ephemeral model-gateway store, never direct DB access, and a Do run receives only what model-gateway resolves into RunAgentRequest. Make durability an org-policy opt-in and hash content per org; do not wire the existing async text route as-is, because it recreates the failure client-side inlining fixed. Vision turns stay refused for waived ZDR turns (sse.rs:960-977). Feeds [F-t3-014](#F-t3-014). Risks: retention under ZDR, cross-tenant dedup leaking existence, deletion cascading to derived documents.
