## 1. Executive summary

1. **Teams is a thin-but-deep native shell around a web client.** ms-teams.exe (C++) hosts the UI in WebView2 and owns every OS-facing concern; the web client (Maglev) is served **from disk inside the MSIX** with a network fallback and a version floor. [SRC]
2. **One contract connects web and native: PIE.** A typed, namespaced, versioned RPC (53 native-module namespaces, about 545 methods/events; SlimCore adds 434 more) over WebView2 host objects and postMessage, with batching and a sync path. This is the single most reusable idea for Verevon. [SRC]
3. **Risky native capabilities run out of process.** SlimCore (calling), HID and others can run in a separate AppContainer instance of the same exe, connected by a named pipe, with job objects, crash restart, rehydration and a restart-storm guard. The same RPC is tunneled over VDI virtual channels. [SRC]
4. **A second, locked-down "Trusted UI" web app** (CSP default-src 'none', Trusted Types, 12 bridge modules instead of 53) renders sign-in end pages, the multi-account hub, the screen-share picker and the data viewer. [SRC]
5. **Everything is flag-gated and ring-targeted** through ECS with layered providers (default, ECS, package, GCC, local, LDS) and a built-in editor page. About 13.8k web flags and about 1.4k shell settings. Strength and also sprawl. [SRC]
6. **Realtime is a push channel plus a safety-net poll.** Trouter (socket.io over WebSocket, per-cloud URLs, registrar) carries messages, presence and call signals; polling intervals relax when push is healthy; the client data layer runs in a worker with a normalized GraphQL cache; four mutations are queued offline for up to 48 hours. [SRC]
7. **Multi-account is first-class (MTMA).** One isolated web instance and storage partition per account/cloud, a native global store with consistency checks, a cross-account hub, and per-cloud badge arbitration. Nine cloud types (including sovereign and air-gapped) share one shell. [SRC]
8. **Operational maturity is high:** native error curtain with cause-specific text and repair, renderer-hang recovery, crash and unexpected-exit tracking, production chaos drills (GameDay), a local self-healing agent (LDS) with a bounded action budget, scenario timing shared by host and UI. [SRC]
9. **Governance hooks live in the client too:** CSP + Trusted Types + SRI, per-account partitions, permission broker, screen-capture exclusion, privacy-category telemetry with a viewer, and a **client-side detector for external recorders and AI notetaker apps** (167 classified processes, ECS-updatable). [SRC]
10. **Agents are arriving as roster members** (agentic-user flags, bot streaming with Stop, MCP-based meeting artifacts, agent blueprints), but most agent UX is dark in this build's defaults. [SRC]
11. **Verevon today has none of the shell layer** (web SPA only, 6 s poll, no push, no notifications, no offline cache or queued sends, no global presence or DND, no cross-room unread). The cheapest wins do not need a desktop app at all (section 16). [per Verevon baselines t1/v-space-*.baseline.md]

## 3. Package, processes and distribution

- **Three apps plus a module container in one MSIX**: MSTeams (full trust), MSTeams.Update, msteamsautostarter, and MSTeamsRemoteModuleContainer (same ms-teams.exe, `Windows.PartialTrustApplication`, `uap10:TrustLevel appContainer`). [SRC R/AppxManifest.xml:126-1155]
- **WebView2 is an optional external dependency** (min 128.0.2739.67). If missing/outdated the shell shows a native error screen with a Get-WebView2 link; there is also an "Open Teams on the web" escape hatch. [SRC AppxManifest:99; R/locale/generated-touchdown/en-us/desktop.json]
- **Process manifest** (REA-located, bytes read): PerMonitorV2 DPI, segment heap, asInvoker, `disableWindowFiltering`. [REA ev_63833651...]
- **Distribution**: signed MSIX (AppxSignature.p7x, block map, three code-sign summaries), x64/arm64/x86 builds, per-machine provisioning with `teamsbootstrapper.exe` (local or UNC MSIX) [SRC; DOC-F Learn VDI page], migration from classic Teams via `desktopAppMigration`, and Skype-consumer migration flags. [SRC AppxManifest:1119-1121, ms-teams.exe strings]
- **Tamper boundary**: Windows owns the file ACLs under WindowsApps; DOC-F says changing them makes the app "corrupted" and breaks updates, and the shell has a "damaged installation" screen. [DOC-F Learn teams-client-update; SRC desktop.json error_curtain_body_corrupt_package]
- **Capabilities declared**: voipCall, phoneCall, graphicsCapture (+programmatic, without border), microphone, webcam, location, Wi-Fi control, radios, USB, HID, Bluetooth, smbios; inbound/outbound TCP/UDP firewall rules. [SRC AppxManifest:102-123, 1167-1183]
- **Auto-start**: MSIX startup task plus Run key; usage-driven (launch count in past hours), suppressed on low-memory and HDD devices, honours user opt-out and a group policy, and shows a toast with a Disable button. [SRC ms-teams.exe strings 30702-30711, 37770-37776]

## 4. PIE: the host bridge (the key design)

**What it is.** A generated RPC layer that every native module presents to the web client. Each module appears under `globalThis.nativeModules.<Name>` and calls `HostBridge.invokeHost("<module>.<method>", args, postProcessor)` or `registerForEvent("<module>.<event>", handler)`. [SRC client-bindings/bundle.js]

**Wire and transport.** [SRC bundle.js]
- Message types: InvokableSuccess, InvokableFailure, IdRequest, SyncFunction, Function, HostEvent. Fields: messageName, messageId (max 1,073,741,823), isInvokable, isIdRequest.
- Batching: `{contentType: "app/piebatch", messages: [...]}` so many calls cross the WebView2 boundary in one postMessage.
- Sync path: `window.chrome.webview.hostObjects.sync.piehostbridge` (getStartingSyncId, invoke sync), used only for calls that must return immediately.
- Versioning: namespace versions are queried with IdRequest "version"; a "version-change" message (id -3) lets the host change a namespace live; each generated module exports `GetPIEScriptVersion()` (1) and `JsonPostProcessing`.
- Robustness hooks: abandoned-call and timed-out-call handlers, event forwarders, proxy forwarding (used for VDI), extended message properties, post-processors for Date, 64-bit pointers (two uint32) and Uint8Array. `window.pieSharedBridgeFactory` shares one bridge across scripts.
- The same JSON-RPC is reused by SlimCore (`SlimCorePIE`, `Hid2PIE`, `BttPIE`, `NativeHost` in scwv2_bundle.js) and tunneled by `scpie_vdi_*` bundles (`V8Bridge_ToHost`, content type `app/webrr`).

**Catalog (53 namespaces).** Largest: windowcontrols 65, osutils 51, hid 38, core 34, vdi 25, toasts 24, mtmahub 21, telemetry 21, hfp 20, userdataxcloud 18, auth 16, files 13, bluetoothproximity 13, gatt 12, customvideobackground 12, officeintegration 11, thirdpartydevices 10. The full list is in the catalog file. Native side mirrors them as `msft::teams::native_modules::<Name>Module`. [SRC bundle.js; ms-teams.exe RTTI names]

**Typed where native must act, opaque where it need not.** Enums are exported for auth state, availability, window tags, toast modes, permission kinds, VDI modes, hub types and quit reasons (141 string enums). State the shell only stores and forwards (hub data, user data, login flows, cloud ids) is passed as opaque blobs. [SRC bundle_enums.txt; mtmahub.getOpaqueGlobalHubData]

**Two trust tiers.** The full bridge (bundle.js, 53 modules) goes to the main web client. A reduced "trusted" bridge (bundletrusted.js, scwv2_bundle_trusted.js; 12 modules, 37 endpoints) goes to the Trusted UI: authtrusted.getAccountsFromMachine, filestrusted (local MRU), hostcapabilitiestrusted, loggingtrusted.writeEntries, moduleloadertrusted, mtmahubtrusted, screensharingtrusted, screenshottrusted, secureipctrusted.generateToken, telemetrytrusted, testtrusted, userdataxcloudtrusted. The `secureipc` token and the `echoSecureToken` test module suggest per-session token binding; the algorithm is not visible. [SRC trusted_rpc.txt; ms-teams.exe strings]

**Capability negotiation and plug-in loading.** `hostcapabilities.getCapabilities/onCapabilitiesUpdated` tells the web client what this host supports; `moduleloader.hasModule/loadModule/unloadModule` loads or unloads native modules on demand (including out-of-process ones). [SRC]

**Why this matters.** The same web build runs across Windows, Mac, VDI and Teams Rooms with the host advertising what it can do. Every OS feature is a small module with a typed surface. [INF from the above]

## 5. Delivering the web client: WebAppLoader, CSP, SRI, isolation

- **Local index with network fallback.** WebAppLoader intercepts WebView2 resource requests for the statics endpoints, maps `networkPaths` to gzip files in `desktop-assets` via asset-manifest.json, and answers from disk. It falls back to the network when the bundled build is older than a critical version, when the cloud lacks `localIndexSupported` (true for work; false for life, DoD, etc.), or on a service-worker update. Responses carry `X-Ms-Maglev-Served-Asset`. [SRC ms-teams.exe strings 33740-33900; R/desktop-assets/maglev-configs/*.json]
- **Per-cloud serve-configs** inject headers after placeholder substitution: nonce `[[random]]`, `[[staticsPath]]`, `[[rootUri]]`, `[[containerName]]`, `[[workload]]`, `[[experienceName]]`, `[[environment]]`, `[[spoVanityDomains]]`. [SRC serve-configs/work.json]
- **CSP**: enforced policy with `require-trusted-types-for 'script'` and 43 named Trusted Types policies, nonce'd scripts, `object-src 'none'`, 44 connect-src entries, 59 frame-src entries (many app protocols, including competitor UC clients), plus a parallel **report-only** policy and violation reporting to a Microsoft endpoint per workload. [SRC serve-configs/work.json]
- **Integrity**: the decompressed index.html lists every chunk with SHA-256 SRI and an integrities-manifest chunk; build-time config chunks per cloud are pinned too. [SRC R/desktop-assets/unhashed-assets/index.html.gz, decompressed copy at scratchpad/tmp/teams/maglev_index.html]
- **Cross-origin isolation**: `Document-Isolation-Policy: isolate-and-credentialless`, COOP `same-origin-allow-popups`, `crossOriginIsolationVersion 4`, enabling SharedArrayBuffer. Supported browsers listed (Edge/Chrome 97, Firefox 101, Safari 16) and link-preview bots whitelisted (Slackbot, WhatsApp, etc.). [SRC]
- **Storage and workers**: the desktop build swaps the service worker for a no-op; assets come from the package; IndexedDB holds session recovery, MSAL storage and diagnostic buffers. Workers: precompiled web worker (six inner CDL worker bundles), WebRTC worker (WASM VQE and CV, encoded streams), telemetry worker (BroadcastChannel batching 10), editor index-readjuster workers (diff-match-patch). [SRC R/desktop-assets/workers]
- **Updates are two-tier.** The shell updates through MSIX; the updater can refresh `MicrosoftTeamsWebAssets` separately (ECS keys webAssetsLatestVersion/webAssetsBuildLink), using an allow-listed downloader. [SRC ms-teamsupdate.exe strings 6097-6106, 6975, 8284]

## 6. Native shell subsystems

### 6.1 Windows and layout
Window tags (Core, MeetNow, Loading, Main, Mini, ChatPopout, Meeting, Presenter), persisted placement per type (Meeting, Chat, CallMonitor, Channel) plus screen-topology memory, named mutations, docking, hide-by-rectangle, always-on-top, custom frame and title-bar overlay, Mica-style backdrops, shared zoom. ### 6.2 OS surfaces
- **Tray**: presence-aware icon (with OOF variants), Open, Settings, My status, Sign out, Quit, auto-start toggle, plus support actions (collect support files, collect process dumps, open dev tools). [SRC desktop.json]
- **Jump list**: availability setters, New Message, Open Calendar, Schedule Meeting, upcoming events with join, accounts (add, sign out all/active); implemented as command-line verbs (`--set-presence-to-*`, `--reset-presence`) handled by the running instance. [SRC desktop.json, ms-teams.exe strings]

- **Intent routing**: toasts, deep links and lifecycle events become (HostEntityType x HostEntityAction) commands (calls, chats, channels, activity, reminders, communities, meet ... x view, join, list, mutate, info, update), acknowledged with `core.intentHandled`. [SRC bundle_enums.txt]

### 6.3 Close, restart, quit
Close actions (destroy, hide, minimize, force quit, quit, do nothing, prompt), speed bumps for "leaving the call" and "unsent pop-out message", 17 quit reasons, restart reasons, `--previous-web-client-state` handoff, silent/background launch. [SRC]

### 6.4 Updater
Separate app with background-task registration (works while Teams is closed), ECS-driven version targets, min/max update period with a rescheduling multiplier, idle restart and a toast, disabled in VDI. DOC-F: updates twice a month with staggered rollout; checks at launch and every few hours; differential download through Windows Delivery Optimization; in-app alert at 1-3 months old, blocking page beyond 3 months. [SRC; DOC-F Learn teams-client-update, ms.date 2026-07-20]

### 6.5 Resilience
- **Error curtain** (native, works when WebView2 is the problem): generic, certificate, proxy-auth, policy, damaged package, low resources, unsupported OS, outdated WebView2; buttons Restart, Repair Teams, Open on the web. [SRC desktop.json]
- **Renderer hang recovery**: Wait / Trace / Reload / Restart toast; ProcessFailedKind taxonomy; stack collection. [SRC]
- **Crash and unexpected-exit** tracking, Watson dumps, memory-pressure tracker. [SRC]

### 6.6 Configuration, flags, diagnostics

Prewarm of WebView2 and SlimCore, prelaunch controller, throttling knobs by window tag and app id, low-spec rules, scenario marks and heartbeat metrics, INP and responsiveness ETW events, loader marks (`exp_loader_*`). [SRC]

## 9. Notifications and attention

- **Native toasts** with COM activator, registered categories, image cache, size guard, and a failure taxonomy: disabled by group policy / manifest / app / user, dismissed by user / hidden / timed out / Focus Assist. [SRC]

## 15. Weaknesses and limitations of the Teams approach

- **Flag sprawl and opacity.** About 13.8k web flags and about 1.4k shell settings; many features dark; behaviour depends on ring/tenant. Needs an editor, rings, and a self-healing agent to stay operable. [SRC]
- **Large native footprint.** The media stack alone is tens of MB of native DLLs (RTMPLTFM 22.8 MB, SlimCoreWebview2 19.7 MB, RtmCodecs 10.7 MB, onnxruntime 8.4 MB), with dual DTLS implementations and legacy Skype-era components (UC type library with 299 COM interfaces). [SRC]
- **WebView2 dependency.** Outdated or blocked runtime breaks the app (hence the curtain and web fallback). [SRC; DOC-F]
- **Offline is narrow.** Only four message-state mutations queue; 48 h expiry; no offline search or offline media. [SRC]
- **Heuristic recorder detection** is process-name based and easy to evade or false-positive. [SRC; INF]
- **No E2EE for chat; E2EE removes server features** (recording, recap). [DOC-S]
- **Platform specificity.** Many modules are Windows-specific (HID/GATT/jump list/AppContainer); a Verevon shell would not inherit portable value from copying them. [INF]
- **Hard to audit.** Trouter, LDS, BRB, "T22", PIE name expansions are undocumented; server behaviour is unseen. [SRC; open questions]
- **Defaults vs reality.** Agent features are largely off here; capability claims must not be read from flag names alone. [SRC]

## 16. Verevon: gaps and what to copy or avoid

Baseline reference: `v-space-ui.baseline.md` and `v-space-backend.baseline.md` (this folder). Verevon constraints that shape adoption: no cross-plane DB access; Control is the only authority; every post needs a content-bound, 2-minute Control decision; ZDR must propagate; Channel Plane is docs-only; Space access never widens an owner-plane ACL.

### Gaps (per Verevon baselines)
Stated by the baselines: web SPA only (no native shell), room updates by 6 s polling, no push or notifications, no cross-room unread, no offline cache or queued sends, no global presence or DND, no calls. Not mentioned in the baselines (so treat as unconfirmed gaps): a typed intent scheme shared by notifications and deep links (routes and tab hashes do exist), multi-window, a support-bundle/diagnostics flow, and a client-side error screen beyond the "never go dark" API contract.

### Copy (ranked by value over cost)
1. **Typed, namespaced, versioned host/UI contract (PIE pattern)** for anything Verevon adds beyond the browser (notifications, windows, deep links, auth handoff). Include a capability-negotiation call and trust tiers. (records: PIE protocol, catalog, capabilities)
2. **Push channel with message-loss events and a relaxed fallback poll**, lock/visibility-aware, plus re-sync on resume. Re-authorize at subscribe time and on revocation because decisions are short-lived. (records: Trouter, hybrid push+poll)
3. **Intent schema** (entity x action) shared by notifications, deep links, tray and agent hand-offs. (record: host command routing)
4. **Attention model**: typed signals, DND/Focus awareness, failure taxonomy for notifications, cross-room unread/attention projection (the hub), Trusted-UI rendering of approvals. (records: toasts, hub, Trusted UI)
5. **Layered feature flags with provenance** and a local override editor; ship dark, ring-target. Pair with Verevon's deny-by-default org policies. (record: layered configuration)
6. **Out-of-process, sandboxed capability hosts** with restart budgets for agent browser/computer sessions; keep the UI contract identical in-proc/remote. (record: remote modules, VDI tunnel)
7. **Client resilience kit**: cause-specific error screen with repair and web fallback, hang recovery, unexpected-exit tracking, scenario timing, "collect support bundle". (records: error curtain, crash, diagnostics, scenarios)
8. **Offline queue** limited to a few mutations with ordering and TTL, but redesigned around Control decisions (queue an intent, request a fresh decision on replay). (record: offline queue)
9. **Disclosure for recording agents**: since Verevon's own Meeting Scribe agent records, show a visible indicator and consider detecting other recorders; do not rely on name heuristics for enforcement. (record: external recording detection)
10. **Loopback paired control API** with allow/block lists, admin kill switch and token refresh for local agents or hardware. (record: third-party devices API)
11. **Bounded self-healing agent** with consent toasts as a first non-chat agent. (record: LDS)

### Avoid
- Flag sprawl without ownership/expiry metadata; per-feature ring complexity without an editor.
- Duplicating legacy surfaces (COM type library, dual DTLS) unless a customer requires them.
- Heuristic-only governance (process-name detection) as a control.
- Windows-only shell features (HID/GATT/jump list) before web-level parity exists.
- Letting agent-rendered content share the origin of trusted prompts.

### Prioritized adoption for Verevon (no desktop app required first)
- **P0 (web-only):** push transport with gap detection, intent/deep-link schema (https links), attention signals and a notification center, web-push via service worker for background alerts, CSP with Trusted Types and SRI, scenario timing and an error screen, offline draft persistence in IndexedDB.
- **P1:** global presence/DND, cross-room unread projection owned by an Application-plane service, support bundle, flag layers with local override.
- **P2 (needs a thin desktop host, e.g. WebView2/Tauri):** typed host contract, native toasts with Focus Assist, tray/badge/auto-start, protocol handler, auto-update with web-assets channel, out-of-process agent sandbox host, loopback pairing API.
