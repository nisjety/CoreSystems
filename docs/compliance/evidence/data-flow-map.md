## 0. How to read this

**Region status** says what the code does about where content is processed:

- **ENFORCED**: a request-path check refuses to send the content elsewhere. The row names the check.
- **DECLARED**: an operator-supplied or vendor-supplied label that is logged, stamped or shown, and gates nothing.
- **UNKNOWN**: the code does not say. It needs the vendor contract, the vendor's own account settings, or the live environment.

**ZDR** says what happens when a request is flagged zero data retention (by the signed token claim or by the request). **Privacy tier** is the tier the provider derives for itself (`global`, `eu_resident`, `zdr_contractual`, `sovereign`) or `n/a` when the flow does not pass through the inference-core chain.

**Retention** lists what the code shows on our side and, separately, what it cannot show about the vendor. Per-record retention and erasure are J12's subject and are not repeated here.

Four limits apply to every row:

1. The local stack is not production. Production hosting, production compose overrides and production secrets were not read. Rows that depend on them say UNVERIFIED.
2. A vendor's retention, region and sub-processors are facts in the vendor's contract, not in our code. Where a row says UNKNOWN the contract has not been read.
3. Line numbers are as of 2026-10-01 and several cited files are being edited by other work. The checker's anchors catch a line that moved; run it before relying on any row.
4. Several code comments are stale. Section 5 lists the ones this map found, so nobody quotes them as evidence.

## 1. What the code shows, in short

1. The chat-path gates are real and fail closed, but they are opt-in per request. The privacy-tier floor is whatever the client sends: the model's own tier for an explicit model pick, nothing for Verevon intent modes. The residency floor (`min_residency`) exists in the chain and no caller in this repository sets it (G1, G2).
2. On the local stack no provider has a ZDR attestation, Azure OpenAI is classed EU on its region label alone with its deployment type unset, Foundry Claude declares no residency, and the ChatGPT subscription route declares none by design. A ZDR-flagged chat request therefore fails, and the only providers that can satisfy an EU floor are Azure OpenAI and the Cohere chat deployment (G3, G5; LIVE).
3. A large part of the data flow never meets those gates. Data Plane embeddings and rerank call a Foundry Cohere endpoint directly under their own ZDR guard and, on the query side only, a jurisdiction guard, the search fan-out reaches external search engines through SearXNG whatever the ZDR flags say, and connectors, billing, email and SMS are separate vendor calls (G13, G14, sections R6 to R11).
4. Some labels are configuration, not measurement. Every run record is stamped with the configured region, not the serving provider's (G9), and a Space's signed privacy flags are checked for presence but not applied to provider choice (G18).
5. Three comments say a provider with no residency commitment refuses to register. The code only logs a warning (G7, section 5).
6. What stays unknown is mostly outside the code: vendor retention and regions, the production deployment, and whether the Codex connection volume still holds pre-hardening logs.
