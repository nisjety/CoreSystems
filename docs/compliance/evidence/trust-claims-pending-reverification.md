# Trust claims pending re-verification: public sentences that depend on work still being built

> **Engineering evidence, not legal advice.** Written on 2026-10-03 with the trust-edits pass (the J13 follow-up). It lists every sentence on the Trust Center and on the pages and product copy that repeat its claims that mentions zero retention (ZDR), reranking or contextual retrieval, with what must be checked again when the build item behind it lands. Each sentence is worded as the code and the developer stack are today (read on 2026-10-03, not production); none describes a feature that is not built. It is not reviewed by counsel and must not be quoted as a compliance claim.

## 0. How to use this

1. When a build item in section 1 lands, open the rows in section 3 that name it. For each, re-read the code and the live posture named in the "Re-check" column, then change the sentence, its level badge, or both. A claim may only be broadened to what the new code and a fresh read of the stack show.
2. Update the matching entry in `apps/Frontend Plane/verevonv3/apps/verevon-web/src/components/trust/trust-claims.ts` (the `mustSay` sentence and the `evidence` anchors). Its drift test, `trust-data.test.ts`, fails when an evidence anchor of a pending claim is gone from the code, which is the signal that the code moved.
3. Remove the `pending` field of each claim you have re-verified. A claim that keeps the field must stay in section 2, because the test fails for a pending claim that is missing from this file.
4. Run the checks of section 5, then update the verdicts in `claims-vs-code.md` and the statements in `honest-limits.md` that section 4 names. Item d, the delivery of the "Used by AI?" audit trail, is not one of a, b and c: it has its own section, 6, with the reads that must pass before its sentences change.
