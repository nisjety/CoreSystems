FINDING (a defect no unit test saw, found by this proof)
  The park events RunParked and RunResumed were refused by session-core: the executor logged "run_agent: failed to publish RunParked (best-effort)" for run A's park and "failed to publish RunResumed (best-effort)" for run D's resume, both with grpc code InvalidArgument (the two cases whose executor log was read; the old gate in source refused every such event before any persist or broadcast). Cause: session-core's RecordOrchestrationEvent allowed those two tags only for the principal service:execution-core, but the executor records every run event under the RUN OWNER'S delegated bearer (the same path SubagentStopped uses), so its own park events never matched. Effect: best-effort and display-only. The run_parked frame the client sees comes from the RunAgent response and was unaffected; no RUN_PARKED or RUN_RESUMED row was observed (the events table was not queried in this first proof, and the old gate sat before any persist) and nothing else depends on one. Not shown by this first proof: the events being recorded. The fix (commit 3b3c2a69) replaces the principal gate with the park-store switch; the events being recorded is proven in the RE-PROOF section below.
