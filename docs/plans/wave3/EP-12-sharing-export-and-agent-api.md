## 2. Verified current state

**Run origin (DEC-17, WS20 S2, built).**
- The closed run-origin vocabulary is `RunOrigin{Chat, Schedule, Trigger, Api}` with wire tokens `chat|schedule|trigger|api`, stored as `runs.metadata.origin`; absent reads as `Chat`, an unknown token reads as `None` (refused) (`MPC/run_origin.rs:11-63`). Go twin `MP/go/services/capability-core/internal/models/run_origin.go`.
- Stamped at birth only for people: `run_origin_at_birth(user_id)` returns `{"origin":"chat"}` unless `auth::is_system_run_owner(user_id)` (`SC/grpc.rs:6169-6178`), bound as the `metadata` column of the run INSERT (`SC/grpc.rs:6229-6249`). A scheduled run is stamped by its binding (`SC/grpc.rs:2585-2650`, `"origin": RunOrigin::Schedule.as_str()` at `:2593`, rebinding refused at `:2618-2625`). No code path stamps `trigger` or `api` today.
- Parent id: `runs.parent_run_id` is set from `StartRunRequest.parent_run_id` (`SC/grpc.rs:6229-6236`), and the child takes its parent's retention receipt (`SC/grpc.rs:6205-6217`). Execution-core passes the parent on subagent starts (`MPR/services/execution-core/src/runtime_loop/agent.rs:5515,5583,5831`). The child's origin is NOT inherited: a subagent of a person's run is stamped `chat` from its own caller, and a child started by a service is unstamped (reads as chat) [INF from the code above].
- `StartRunRequest` uses tags 1-7 on this branch and on `main`, `space-w2`, `mp-w2w3`, `w23/integ` (`PROTO/sessions.proto:558-577`). The design adds no field: origin comes from the verified caller, never from the request (D1).
- A second, display-only origin exists on trace envelopes: `Envelope.origin = 23` with enum `RUN_ORIGIN_{USER, AGENT, SCHEDULE, WEBHOOK, API}` documented "never an authorization input" (`PROTO/events.proto:66-67,92-107`); model-gateway maps ten browser-run surfaces onto it (`MG/browser_run.rs:489-553`); session-core decodes it from strings (`SC/eventlog_grpc.rs:101-106`).
- The run read model: `RunDetail` tags 1-19 (`MP/proto/model_plane/v1/runs.proto:392+`, max 19 on all five branches), `ListRunsRequest` 1-7. model-gateway projects `RunDetail` through an allow-list that already includes `parent_run_id` and the whole `metadata` object (`MG/http_routes.rs:7969-7994`), so `metadata.origin` reaches the client but no top-level `origin` exists.

**Public API surface today.**
- Run routes live in `authed_routes()` (`MG/http_routes.rs:250-388`): `GET /v1/runs`, `/v1/runs/system`, `/v1/runs/:run_id`, `/v1/runs/:run_id/events/replay`, `/v1/runs/:run_id/trace`, `/v1/runs/:run_id/events` (SSE), plus `orchestration_routes()` cancel/resume/continue (`:484-488`). The plan's citation `http_routes.rs:132-236` is stale; the table moved.
- `get_run` forwards the caller's session bearer to `RunService.GetRun` (`MG/http_routes.rs:1655-1673`).
- An `api_key` principal already exists in model-gateway (INNH-10 MP-3, ledger `MP/docs/decisions/ledger.md:109`): `PrincipalKind::ApiKey`, `sub = "apikey:<key_id>"`, claims `key_id` and `acting_user_id` (`MG/auth.rs:58-117,143-151`); it is admitted ONLY on `POST /v1/browser/key-grants` and `DELETE /v1/browser/key-grants/:grant_id` with scope `browser:agent` (`MG/auth.rs:153-178,1790-1803`), and it may not send any user-bound delegation header (`API_KEY_FORBIDDEN_DELEGATIONS`, `MG/auth.rs:1167-1178`; enforced `:1540-1558`).
- session-core accepts only `user` (or empty) and `service` principal types; anything else is `unauthenticated` (`SC/auth.rs:851-905`). inference-core and execution-core read `principal_type` in their own `auth.rs` [verify at slice start for the exact arms].
- OpenAPI: `MP/api/openapi.yaml`, 3.1.0, `info.version 0.1.0`, 2,044 lines, LF, documents the gateway's own port (`:1-30`), already lists `/v1/browser/key-grants` (`:668,777`). `MP/api/generate-sdk.sh` generates a typescript-fetch SDK (`@model-plane/sdk`) and a python SDK into `MP/api/sdk/` from that one spec (`:1-30`). No test checks the spec against the router.

**Control (auth-core).**
- Better Auth's api-key plugin is configured behind `API_KEY_ENABLED === 'true'` with two configs, `user-keys` (references user) and `org-keys` (references organization), header `x-api-key`, metadata enabled, rate limits (`AC/auth/auth.ts:1121-1170`). The `apikey` table has `config_id`, `reference_id`, `permissions`, `metadata`, `expires_at`, `enabled` (`AC/db/schema.ts:351-375`). No route consumes a key today: `git grep "apikey:"` finds nothing in auth-core on this branch, `main`, `mp-w2w3` or `w23/integ`.
- Token issuance for the Model audience: `GET /api/model-plane/token` (session cookie) and `POST /api/model-plane/internal-token` (registered service credential) (`AC/auth/model-plane-token.controller.ts:117,135,215`). The RFC 8693 exchange `POST /api/:audience/token-exchange` takes a registered service principal plus a verified subject token, requires the registry field `tokenExchange` (absent by default) and mints `acting_user_id` with a fail-closed durable audit (`AC/auth/plane-token.controller.ts:404-470`). `issuePlaneToken` knows `principalType: 'user' | 'service'` only (`AC/auth/convex-token.service.ts:48,200-235,651-700`). Registry: `apps/Control Plane/config/plane-service-principals.json`, parsed in `AC/auth/plane-service-principal.ts` (`tokenExchange` at `:83,370-380`).
- INNH-10's design (`.plan-work/quarry-w1w2/INNH-10-design.md` sections 3, 12, 13) specifies the `api_key` token shape (sub, `principal_type`, `key_id`, `acting_user_id`, no `user_id`, TTL at most 120 s, `jti`, zdr raise-only) and asks auth-core for CP-1 (`POST /api/:audience/api-key-exchange`, gateway-only, user-keys only) and CP-4 (`issuePlaneToken` learns `api_key`). Neither is built and neither is in `.plan-work/execution/queue.json`. The Quarry and model-gateway halves are built dark.

**Export, replay, share today.**
- Export exists only per answer, client-side: `FES/features/chat/lib/chat-export/` (docx, xlsx, pptx, print, zip builders over one answer's markdown; `types.ts:15-37` `ExportMeta{title, createdAt, sources, locale}`). No whole-conversation export, no server export.
- The transcript read is `GET /v1/threads/:thread_id/messages` -> `ListConversation`, active branch only, optional paging (`MG/http_routes.rs:12295-12420`). Thread fork exists (`MG/http_routes.rs:302-305`; BFF `domains/chat/history.rs:518-560`; action `thread.fork` in `FES/shared/actions/chat-history.ts:15`), the closest precedent for "copy a thread under a new owner-controlled id".
- Retention per run: `runs.retention_class IN ('zdr','persistent','zdr_waived')` (`SC/../migrations/0044_run_retention_receipt.sql:22-23`). A ZDR caller writes no thread content; a thread whose runs are all `persistent` is the only thread with a complete durable transcript [INF from 0044 and the ZDR path].
- Sharing precedent: documents are shared through Control's `resource_grants`, the single grant authority; the owning plane proves ownership before Control writes the grant (`BFF/domains/shares.rs:1-16`). The resource taxonomy lists `document` as the only ownable type and `conversation` as team-shared (`UC/internal/authztaxonomy/resource_taxonomy.json`); parity is linted against the Data Plane mirror `apps/Data Plane v2/services/retrieval-engine-rs/src/authz/taxonomy.rs` by `scripts/lint-resource-taxonomy.sh`.
- Erasure: session-core erases by organisation only (`SC/gdpr.rs:237`, `DELETE FROM threads WHERE org_id = $1` at `:419`); there is no per-user thread erasure path, so key-owned threads are covered by the org purge.

**ZDR contracts.** `MP/api/contracts/zdr-refusals.json` has 34 feature keys (none for export, share, import or the Agent API); the list is generated from `MPC/zdr_refusal.rs` (`key: "sandbox_workspace"` at `:349` is the last) by `MP_UPDATE_GOLDEN=1` tests. `zdr-posture-matrix.json` has 79 rows; enforcement rows use the `e_` prefix (`e_zdr_default_route`, line 493).

### S1 - Origin on every run [BUILD]
**Goal.** Every run carries the right origin: a child run inherits its parent's token, and the run read model names the origin at the top level, so the WS15 trigger chip and the Agent API read one field.
**Files.**
- `SC/run_origin_stamp.rs` - NEW. `pub(crate) fn origin_at_birth(user_id: &str, parent_origin: Option<RunOrigin>, inherit: bool) -> serde_json::Value`: with `inherit` and a parent origin, stamp the parent's token; otherwise exactly today's rule (moved here from `grpc.rs`). `pub(crate) async fn load_parent_origin(tx, org_id, parent_run_id) -> Result<Option<RunOrigin>, Status>`: reads `metadata` of the parent row in the same transaction, org-scoped; an unknown token yields `None` (never copied). `inherit_enabled(raw: Option<&str>) -> bool` reads `SESSION_RUN_ORIGIN_INHERIT`.
- `SC/grpc.rs` - `start_run_inner` (`:6181+`): when the switch is on and `parent_run_id` is set, call `load_parent_origin` after the retention inheritance (`:6205-6217`) and bind `origin_at_birth(...)` instead of `run_origin_at_birth(&req.user_id)` (`:6249`); delete the old function (`:6169-6178`) and point its test (`:12830`) at the new module. `mod run_origin_stamp;` goes in `SC/main.rs` beside the other `mod` lines.
- `MG/http_routes.rs` - `run_detail_value` (`:7969-7994`): when `MODEL_GATEWAY_RUN_ORIGIN_FIELD` is on, add `"origin"` = `RunOrigin::from_metadata(metadata)` token, or `null` for an unknown stamp. Off: the projection is byte-identical.
**Contract/proto/migration.** None (JSONB merge, the read model already carries `metadata`).
**Flags.** `SESSION_RUN_ORIGIN_INHERIT` (session-core), `MODEL_GATEWAY_RUN_ORIGIN_FIELD` (gateway), both default off, compose `${NAME:-false}`. Off: unchanged stamp and projection.
**ZDR.** No new store: the stamp rides an existing column; a ZDR run's origin is `chat` or inherited, never content.
**Tests.** `SC/run_origin_stamp.rs` unit: `child_inherits_parent_origin_when_switch_on`, `switch_off_stamp_is_todays_stamp`, `unknown_parent_token_is_not_copied`, `system_owner_without_parent_stays_unstamped`, `inherit_parser_takes_only_literal_true`. DB test in the existing harness: `api_parent_child_run_is_stamped_api` (parent row seeded with `{"origin":"api"}`). Gateway: `run_detail_value_names_origin_when_switch_on`, `run_detail_value_unchanged_when_switch_off`, `unknown_origin_stamp_projects_null`. Commands: `cargo test -q -p session-core --lib run_origin_stamp`, `cargo test -q -p model-gateway --lib run_detail_value`.
