## 6. OPEN QUESTIONS FOR THE USER

Twelve questions that block or shape building, each with a recommended default so an answer of "ok" accepts it.

1. **Baseline the in-flight work.** About 324 uncommitted entries sit under files nearly every slice edits (`main.rs`, `state.rs`, `config.rs`, `routes.rs`, `search_routes.rs`, `extract_routes.rs`, `openapi.yaml`, `zdr-contract-sync.test.sh`, Model Plane `http_routes.rs`, `grpc.rs`, `tool_loop.rs`, session-core `0044`/`0045`). **Default:** commit or branch them as a baseline before W1 starts; designs assume it.
2. **Merge governance.** One arbiter for merge order, one engineer as single editor of the execution-core browser files and `agent_routes.rs`, a two-working-day freeze on `agent_routes.rs` for D2 S2, migration/proto/event allocations from section 2 recorded in one ledger entry. **Default:** yes; the user or a named delegate arbitrates.
3. **Control Plane sign-off for `quarry-edge` as a read-only `browser-broker` principal (`browser:read`).** Unblocks all production browser work. **Default:** approve this row now; approve the model-gateway, inference-core, org-keys, web-policy and credential rows one by one as each design reaches merge (R-13).
4. **ZDR semantics (ADR-4).** **Default:** adopt D4's matrix as published; keep every existing refusal; refuse monitors, schedules, profile CRUD (except list and delete) and AI formats for ZDR orgs behind a flag with a one-week observe period and customer notice; scrape is inline-only; metadata tombstone only after counsel.
