## 1. Goal, success criteria and scope

### 1.1 Goal

Make Verevon Space the hybrid room for people and agents. People get Teams-class groups and teams (membership with roles, a directory, direct messages, guests and teams later) and Slack-class multi-person rooms (human posts and thread replies without a model turn, live push, mentions, reactions, edit and delete, attachments, search, permalinks, per-room attention across rooms). Agents get Grok-Bot-style colleague behaviour (personal agents with an owner-controlled access list and audience-safe memory, work that the whole room can watch and stop, approvals that really resume, a computer with caps and a browser the room can see and take over). All of it runs inside Verevon's authority model: Control Plane signs short-lived, audience-bound decisions, Space access never widens an owner-plane ACL, ZDR fails closed with typed refusals in every plane that persists or pushes content, and the Model proposes while Quarry executes browser actions. The audit's 96 recommendations are split in this plan into 40 items built in detail as 20 workstreams (WS01-WS20, 23 Priority items plus 17 Recommended items; waves W1-W3) and 56 items parked as 12 later-wave epics (E01-E12, section 1.4).

Starting point (audit 1.2 and 1.3, code-verified): Verevon is an authority-first agent cockpit on a conversation model that is still an AI prompt box. Every room post is a model turn, there is no room-level push (6 s poll), only the sender sees an agent work, governance cannot be administered (no effect-policy UI; SCIM stub returns fake success; any org member can read all org audit events), and DMs, reactions, edit and delete, attachments and message search do not exist.

Applies to every criterion:
- Each flag in the delivering design's section 6 is flipped off once on the rebuilt stack and the feature returns to the legacy path without a data change (kill-switch drill).
