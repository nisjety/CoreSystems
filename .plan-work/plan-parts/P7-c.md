
## 5. Cross-session interfaces

Two sibling planning sessions share pieces of this plan. Sibling (a) is Verevon Space (agent PC and browser inside Spaces, Space grants that must never widen an owner-plane ACL, ZDR-safe telemetry and projections). Sibling (b) is Model Plane plus chat and agents (BrowserBroker grants, agent browser path, delegated bearer, approvals, the `browser.*` tool schema, the execution-core planner, model-gateway `browser_run`, cost-core). Source audits: `01-verevon-space-audit.md` (F-t1-020 room-scoped agent browser, F-t1-021 agent computer confinement, ADR 6) and `03-model-plane-chat-and-agents-audit.md` (F-t3-008 agent browser on real broker grants, F-t3-006 approvals v2, F-t3-002 durable loop, F-t3-018 scheduled runs). "Owner" is the proposed owner of the code; the contract owner is named in the contract column. Every row ends in a question only the user can settle, marked FOR USER TO RECONCILE.

**Rule that governs every row.** Space access can only narrow an owner-plane decision (`apps/master-ownership-matrix.md` rule 10, line 166: projections only narrow access): grants are minted from the owner's bearer, Quarry compares `grant.owner_id` with the run owner, policy meets only tighten, projections hold ids and counters. A Space feature that needs a member to act on or read a browser owned by another member is a new design (a shared-session ACL), out of scope here.

### 6.2 Deployment evidence standard

The repo counts a deployment claim only after rebuilt local images, a running stack and a verified end-to-end flow with a stated observable assertion. No slice, wave exit or production flag flip is called done on a green unit test alone.

Every PR description records: (1) the rebuilt image ids and `SOURCE_REVISION` (the production overlay needs `SOURCE_REVISION` and `BUILD_DATE`; `GET /version` shows the revision); (2) `docker ps` showing the service healthy in the intended mode (for example quarry-edge `ENVIRONMENT=production`); (3) a transcript of the end-to-end flow with its observable assertion; (4) where the slice fixes a defect, a pre-fix capture on the old image; (5) a log scan for the hop (no URL, host, title, query, grant domain, secret canary); (6) rollback notes, including any one-way door (the gateway cache fix must roll back with `GATEWAY_CACHE_REDIS_URL` unset, never set); (7) the stale doc corrected and a line in `apps/STALE_DOC_DELETION_REGISTER.md` [C] (OQ-15).

Evidence types used in the success criteria: **CI** hermetic test in CI; **L2** live prod-overlay stack run recorded in the PR; **LOG** log or artifact scan with a canary; **PROBE** scripted adversarial request. L2 is a pre-merge evidence run on a developer or self-hosted host, not a GitHub-hosted job (it needs outbound HTTPS to `example.com`: the broker requires dotted non-IP hostnames and Quarry's SSRF guard blocks private targets, so a local fixture site cannot stand in).
