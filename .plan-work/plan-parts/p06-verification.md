### 6.2 Evidence rule for any deployment claim

#### 6.2.1 The rule

A deployment claim counts only after all three hold: (1) images rebuilt locally from the slice's commit, (2) the stack running on them with up-proof captured, (3) an end-to-end flow verified on that stack including negative cases. This is the repo rule restated by every design, and it is the same bar as "L2" in the Quarry plan (rebuilt images, running stack, verified flow). Vocabulary used in PRs, ledgers and status docs:

| Word | Allowed when |
|---|---|
| built | code merged, T1-T3 green |
| tested | T2 green on a real database |
| verified (dev, L2) | all three conditions on a developer stack, evidence file attached |
| deployed / shipped | L2 evidence plus a rollout record for that environment (flag values, order, date). Nothing deploys from this repo (CI `deploy-*` jobs only echo), so "deployed" also names the environment |

Not evidence: green unit tests, `docker compose config -q`, an image that was built but not started, a container that is up but whose migration was not confirmed, session-core `/healthz`, a skipped Playwright spec, a flow run with the flag off, a flow run only as the owner.

#### 6.2.2 Required content of every evidence file

1. Header: workstream and slice ids, git SHA of each touched plane, date, who ran it, stack (compose project name, environment).
2. Rebuild transcript: the exact commands from the design, image ids and build times (`docker images`), `docker compose ps`.
3. Up-proof per service (6.1.2), migration proof (`\d <table>`, `schema_migrations` rows), flag values in effect (names and values only).
4. Seed commands (no tokens, no passwords). Test users come from seed or fixture scripts (`SEED_DEV_ACCOUNT=1`, `apps/Frontend Plane/verevonv3/apps/gateway/scripts/zdr-seed-test-org.mjs`, `apps/Control Plane/scripts/seed-verified-test-user.sh`).
5. Happy-path flow with one capture per step (SQL, HAR, screenshot, log excerpt).
6. Negative-authority legs: viewer, non-member, removed member, forged authority field, expired or other-audience token, wrong digest.
7. ZDR leg: typed refusal body from the catalogue, row counts before and after, no Control call in user-core logs where the design says so.
8. Content-free proof: canary grep (6.3.4) over every captured channel.
9. Kill-switch drill: each flag flipped off once, legacy path observed, flipped on again.
10. Test summaries: the gate pack output with the baseline failing set.
11. Redaction statement: tokens, cookies and `Authorization` headers removed from HARs; decision tokens shown as decoded claims only, never signature material.

Storage: `docs/compliance/evidence/live-proof-space-<ws>-<slice>-<yyyy-mm-dd>.txt` (same folder and naming as the Model Plane build's `live-proof-ws03-s5-effect-ledger-2026-10-17.txt`, verified on branch `model-plane`), linked from the PR and from a dated note beside the `apps/Frontend Plane/verevonv3/docs/SPACE_*` records. WS09 left the location open ("confirm with the sequencing owner"): this is the proposal. A Model Plane ledger row is added only for slices that touch its ledger (WS18 per its design).

### 6.4 Rollout and rollback pattern

#### 6.4.1 Pattern

1. Expand first. Migrations are additive and idempotent (`IF NOT EXISTS`; `DROP CONSTRAINT IF EXISTS` before `ADD`), each with a `revert/NNNN_*.down.sql` (the 0044/0045 convention). Indexes on large tables use `-- no-transaction` and `CREATE INDEX CONCURRENTLY` (WS13). No migration drops data in the same release that stops using it.
2. Dark deploy. Code ships with every flag off; legacy path unchanged; kill switch tested before the first enable.
3. Order inside a release: Session Core, model-gateway, user-core (Control), Application (Convex deploy, then `docker restart convex-gateway`), gateway, SPA last. A gateway that stamps a field an older model-gateway ignores is harmless, but the reverse is not, so the producer plane goes first.
4. Environment ladder: dev (two real members, seeded policy) then staging (two members and one personal Space) then one pilot org with the Control entitlement then per-org. Gateway flags default ON outside production, which includes staging (6.4.2): staging overlays set explicit `false` until its rollout step.
5. Tri-state flags go `observe` or `shadow` before `enforce`: `SESSION_CORE_SPACE_ZDR` (observe), `EXECUTION_CORE_SPACE_APPROVAL_GATE` (shadow, two weeks), `EXECUTION_CORE_QUARANTINE_MODE`, `SPACE_AGENT_ADMISSION` (observe, two weeks reading the `would_skip` ledger), `AUDIT_READ_ROLE_ENFORCEMENT` and `SSO_ENFORCEMENT` (report), `EXECUTION_CORE_SPACE_SHELL_LEASE` (observe).
6. One flag at a time, with the evidence file updated after each flip, and a watch period (WS02: one retention-sweeper cycle between emit and stream).
7. Entitlement beats flag. A flag is a rollout control and never an authorization input; authority comes from Control decisions and the deny-by-default entitlement bits. Turning an entitlement off takes effect within one decision life (2 minutes).

#### 6.4.2 Flag mechanisms (what exists, what to use)

| Mechanism | Where | Default behaviour | Use for |
|---|---|---|---|
| Model Plane Rust boolean | `mp_contracts::switch_value_is_on` (`apps/Model Plane/rust/crates/mp-contracts/src/agentic_subscription.rs:66`; accepts `1`, `true`, `on`, `yes`, `enabled`, case-insensitive); compose `${VAR:-0}` in the base file, `"1"` in `docker-compose.override.yml` | off unless set; dev override on | session-core, model-gateway, execution-core booleans |
| Model Plane Rust tri-state | one exact-match enum parser per switch in `mp-contracts` | named default (`observe`, `off`) | `observe`/`enforce`, `off`/`shadow`/`enforce` switches |
| Gateway | `AppState.space_features` fields from `env_bool(key, dev_flags_allowed(APP_ENV))` (`apps/Frontend Plane/verevonv3/apps/gateway/src/config.rs:429-441`); never `std::env::var` inside a handler; served to the SPA through `space_context.features` | ON unless `APP_ENV` is `production` or `prod` | UI and BFF route flags; flipping needs a gateway restart, no SPA rebuild |

| Control | user-core env read once in `NewServer`; per-org policy rows and entitlement bits (deny by default); service credential scopes (`USER_CORE_SERVICE_CREDENTIALS`) | off, no row means deny | authority gates; "dark by credential" for WS04 |
| Data Plane | service env, compose `${VAR:-false}` | off | wiki-store, documents-api, retrieval |

Decisions taken where designs disagree:
- WS06 says Model Plane switches use an exact-match parser with no `true` or `1` truthiness, while WS01, WS08, WS11, WS12, WS13, WS15, WS18 name `switch_value_is_on`, which does accept those values. Pick: booleans use `switch_value_is_on` (verified above); only tri-state flags use exact-match enums.
- Gateway flags default to ON for any `APP_ENV` other than `production`/`prod`, including an unset `APP_ENV` and staging. A production image with `APP_ENV` unset would turn every Space feature on. Guard: production compose files set `APP_ENV: production` (WS02 cites `docker-compose.production.yml:12`; UNVERIFIED for the other overlays), and the proposed config test asserts every Space gateway flag is off under `APP_ENV=production` and under `APP_ENV` unset in the production overlay.
- Naming: designs mix lowercase feature keys (`space_*`) and uppercase env names. Canonical name is the UPPER_SNAKE env var; the lowercase form is the `features.*` key the SPA reads.

#### 6.4.4 Kill-switch checklist

Run once per flag on the rebuilt stack before the flag is enabled anywhere shared, and again at every environment step. Record each line in the evidence file.

- [ ] Name the flag, its owner service and the exact reset command (compose `up -d` with the env, or `docker restart convex-gateway`, or Control policy PUT, or credential scope removal). Gateway flags: restart the gateway only, no SPA rebuild.
- [ ] Flip off. Confirm the service read it (log line or `features` object in `space_context`).
- [ ] Observe the legacy path: routes answer the documented 404 or typed code, the UI hides the surface or falls back (6 s poll, legacy list, old dialog, local-only preferences), no error banner.
- [ ] Confirm no data step is needed: stored rows still readable, outbox drains, no orphaned lease, in-flight runs finish or end cleanly, streams close and clients fall back.
- [ ] Confirm authority is unchanged: the flag off never widens access and never grants (spot-check a viewer and a removed member).
- [ ] Flip on again; the feature returns without a restart of unrelated services; generation or cursor semantics behave as designed (WS02 emit off to on bumps `generation`).
- [ ] Emergency ladder, fastest first: (1) Control entitlement false, effective within 2 minutes; (2) remove the service credential scope and recreate user-core; (3) gateway flag off and restart; (4) plane flag off and restart; (5) revert migration file only with an export of the affected rows and the owner's approval. Never delete rows to roll back.
- [ ] Known one-way or special cases are acknowledged: `SPACE_MEMBERSHIP_WRITER_API` flip is emergency only; `MEMORY_SPACE_CONTAINMENT=0` and `SPACE_ROOM_METADATA_LEGACY_PASSTHROUGH=true` reopen known leaks; `EXECUTION_SANDBOX_LIMITS=off` removes caps; `EXECUTION_CORE_SPACE_APPROVAL_GATE=off` only loosens back to current behaviour; WS07-S2 (nginx and build args) needs an image rebuild, so its rollback is a redeploy.
- [ ] Incident rule: a suspected content leak or authority widening is handled by killing the surface first (steps 1-4), preserving logs and rows as evidence, and recording the incident in the section 8 evidence folder; the fix is a new slice with a new guard test.
