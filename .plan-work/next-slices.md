## 8. Narrowing the tab-attach lock (WS3.D leftover; prerequisite of WS3.F)

**Goal.** Stop one session's slow tab attach from blocking every other session's `acquire`, `release` and `goto`, and make a failed or timed-out attach clean up the page and the browser context it created.

**What the plan says.** plan:755 (WS3.D file list: "`open_tab_page` attach sequence in `with_deadline(Op::TabAttach, ..)` with an `AttachGuard` closing the page and disposing a context this call created, and the `browser` mutex no longer held across the function"), plan:759 (live tests `attach_timeout_cleans_up_partial_context`, `navigation_during_content_read_is_retried_once`), plan:761 (risk: "changed attach lock scope can reorder concurrent attaches (WS3.C live test stays green)"). The WS3.D commit `d724763d`: "Not done: the tab-attach lock narrowing and AttachGuard (WS3.F), the two live tests that need a racing navigation or a stalled attach".

**Status check.** Not done, confirmed in code. In `apps/Ingestion Plane/Quarry-v2/crates/quarry-browser/src/chromiumoxide.rs`, `open_tab_page` (402-~616) takes `let browser_guard = self.browser.lock().await;` at line 410 and holds it to the end of the function, across: context creation and download-behavior (`with_deadline(Op::TabAttach, ...)` at ~474), `new_page` (~497), `apply_page_hygiene`, the collectors, `install_network_guard`, `page.goto(initial_url)` (`Op::Navigate`, up to 30 s, ~559), cookie and storage hydration and a reload (~567-590), `install_popup_bridge`. Every other path that needs the browser waits on the same mutex: `ensure_browser` (211), `acquire` startup-mode probe (2106), `release` context disposal (2147), 2460, 2520, 2792. So a 30 s navigation in one session delays every other session's acquire and release. Partial state on failure: the `?` after `with_deadline(Op::TabAttach, new_page)` returns with an already created browser context stored in `session_pages.browser_context_id` (stored at ~536 before `new_page`) and an already created `tab_id` index bump; after `apply_page_hygiene` failure the page is closed but later `?` points (`install_network_guard`, `goto`, hydrate, `install_popup_bridge`) leave a created page open and un-registered in `tabs`.
