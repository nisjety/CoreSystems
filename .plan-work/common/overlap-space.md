## B. Interfaces: what each build needs from the other

1. **Conversation record.** Space session needs from Model: non-owner branch in `AppendMessage` (owner `Mutate` check at `grpc.rs:4504`; subject-vs-caller compare in `verify_append_space_decision`, `grpc.rs:2102`); `SessionMessage` carrying `message_id`, `seq`, `author_subject_id`, `entry_kind`, `revises_message_id` (S618); `limit/before` cursor, `last_activity_at`, `turn_count`, `participants` on `ListThreads`/`ListConversation`; `SearchMessages(space_id, space_read_decision_*)` returning candidates only. Model needs from Space: Control `thread:append` decision per member, `history_from` on member-add (S604), durable `membership_changed` (S1649), gateway no-invoke route with `idempotency_key`.
2. **Approvals.** Model gives: `Approval.context.cause_code`, `scope`, `addressee`, `continuation_delivery` for the card. Space/Control give: signed standing-grant record `{subject, space_ref, agent_ref, action_hash, scope, expiry, revoked}` (generalise `owner_grant_decision.go`) and a closed `turn_origin` claim on every decision (no code uses `turn_origin` today).
3. **Policy.** Control to Model: `allowed_models` by service-principal pull (org_quota pattern, M696), signed org registry. Space to Model: role-gated PATCH writing binding `allowed_tools`/`approval_mode`/ceiling. Model to Space: typed denial codes mapped from Control reason codes (S432).
4. **Memory.** Space to Model: audience hash/revision (already stamped per message), Control declassify decision. Model to Space: an explicit `withheld` state for over-filtered context (S533), erasure hook for scoped rows on Space deletion (M1146).
5. **Attention.** Model to Application: one run-state enum + typed events from the session-core outbox with `space_id`/`thread_id` added to the envelope (S400), metadata only. Application to Frontend: seq-numbered frames, per-user aggregate; gateway re-checks a new Control stream-read audience on every delivery (S400).
6. **Browser / computer.** Control to Model: shared-Space browser + sandbox-capability decisions (new). Model to Quarry: `space_id` on `ExecuteStepRequest`. Quarry to Model: `ChallengeSignal`. Space to Model: stop/kill route under a Control effect decision (S799).
7. **Automations.** Control: shared-audience schedule create/fire/run/step + watch decisions. Ingestion: `webhook_received` refs with `webhookEventId` (M988). Application: room Work tab, recipient acceptance record.

## C. Contradictions between the two documents

- **C1 Resume.** S497 "do not rebuild the dispatcher; widen kinds" vs M366 "re-enter the loop at a checkpoint"; M1728 records it as unresolved OD6. Code: `approval_delivery_worker.rs` header and `resume_durable_approval_continuation` (`execution-core/src/grpc.rs:706`, returns unavailable).
- **C2 Input request.** S773 end-turn + new run, owner-only answer vs M514 pause-in-place. ZDR: S775 stores nothing; M514 says ZDR needs an in-stream non-durable ask.
- **C3 Message versions.** S620 append-only revision entries (agents see "edited/deleted" markers) vs M530 version tree where `ListConversation` returns only the active path.
- **C4 Space as project.** M546/M1685 puts Space threads into /chat; `0034_thread_origin.sql:44-47` enforces `(origin='space') = (space_id IS NOT NULL)` and the chat list filters `origin='chat'` (`use-chat-controller.ts:2274-2286` removed the Space entry deliberately). S1254 uses "project" for a Space bound to a work object; M533 means a chat container.
- **C5 Memory key.** M1140 scope kind/id + isolation vs S525 audience hash/revision labels, plus capability-core's third scope enum.
- **C6 Action schema source.** M724 keys the table by the Frontend catalog hash vs S654 "do not let Model consume the Frontend registry" and the code comment in `model_action_view.go`.
- **C7 Credential custody.** S994 Ingestion broker vs M940 Model proxy with Control secret store vs M466 Quarry vault.
- **C8 Retention store.** S1085 TTL in `space_effect_policies` vs M1168 org-core `DataRetentionDays`; hold-vs-erasure precedence open on both (S1638, M1170).
- **C9 Origin vocabulary.** S391 `turn_origin` {direct, ambient, automation} on Control decisions vs M1192 origin on run metadata {chat, schedule, trigger, api}; thread `origin` already has six values (migrations 0034, 0041). Needs one closed enum.
- **C10 Steering.** `queued_input.rs` + M1252 (owner-bound, model classifies, no editable queue) vs S416, S836, S942 (member steer, editable queue chips, classifier).
- **C11 Instruction order.** S1450 "platform, org, Space, user, agent" vs M344 "org > Space > persona > user" vs ADR-0003 "platform, org, Space, per-agent persona".
- **C12 Naming.** "Quarantine" (A2). "Project". "Origin".
