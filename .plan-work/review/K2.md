## Five most dangerous remaining risks

1. Member posts reaching the owner's model through any `ListConversation` caller that did not opt in (K2-01): the plan's "always on" containment is a per-caller flag, and `reattach_context` is model-callable. Invert the default before any `space_human_posts_core` flip.
2. WS01 cannot be proven (and WS04-S5 can be skipped by sequencing) without a registered recipient audience (K2-03): today no code registers one, so a second member is refused by Control and the plan's flow would be "verified" only against owner posts.
3. The action-surface parity gate silently stops covering Space actions after `P-SPA1` (K2-06): human-only and model-ineligible assertions for about 25 slices ride on a test that reads one file.
4. Seam PRs presented as "pure moves" contain new behaviour (K2-08, `org_zdr_lookup` and flags): the first merge gates (test counts unchanged, moved lines only) will either fail or be waived, weakening every later slice's review standard; ZDR typed-412 vs 503 semantics in WS01/WS07/WS16 depend on that one function.
5. ZDR classification drift for the new Space routes (K2-04): hand lists in `zdr_posture.rs` and a scan limited to `http_routes.rs` leave `space_routes/*` outside the enforced inventory; Session Core's untyped refusal is the only backstop.
