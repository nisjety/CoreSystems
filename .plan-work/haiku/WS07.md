Its request comment says only the user's threads are returned (sessions.proto:961), and space_id is applied inside that owner-bound query (969). The only shared read today is per thread (ListConversation with the decision, from line 901), so the room aggregate means N transcript reads or a new RPC, not a reuse. The card's "mostly frontend reuse" framing understates this.

Confirm before design, since ZDR must propagate to every content-persisting boundary.
