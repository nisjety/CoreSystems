2. The append payload digest (grpc.rs:2063) also binds the owner user id, so a non-owner append needs the digest and the subject check changed together.
3. AppendMessageResponse carries only sequence (sessions.proto :324-327). An idempotent replay cannot return the original message id or a deduplicated flag without a proto change in a file already MODIFIED-UNCOMMITTED.
4. Client idempotency keys are honoured by the gateway, but an absent key is replaced by a generated key (spaces.rs :605-624), so retries without a key never dedupe. The only events dedupe is a per-org unique index on the raw key (migration 0002 :35-38).
