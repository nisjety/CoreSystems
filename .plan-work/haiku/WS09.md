## Surprises

1. `list_runs` already accepts the Space thread:read decision and the Work tab uses it (`run_service_grpc.rs:684-738`, `spaces.rs:2427`). Room run listing is not owner-only; the audit's "only the sender sees agent work" holds for the stream and the snapshot RPCs.
2. The stream attach crosses an unauthorised Go pass-through (`orchestrator-core/internal/orchestration/handlers.go:162-182`) that the audit does not cite. Run-ownership authorisation happens only at session-core `orchestration_grpc.rs:3249`; the model-gateway hop verifies the bearer only.
3. step_update SSE frames carry no id (`sse.rs:7608-7613`, `sse_events.rs:732-736`). The resume cursor exists on raw frames only, so the verdict's reuse claim is half wrong.
4. No late-joiner snapshot. An empty cursor replays nothing (`orchestration_grpc.rs:3257-3264`). ListPlans (1877, 1882), ListApprovals (2330), GetRunProofBundle (2377) and ListTodos (2205) are all owner-bound, by run or by thread, so a snapshot needs Space branches too. The verdict's "gives late joiners their snapshot" is wrong.
5. Lagged subscribers drop events with a warn only (`orchestration_grpc.rs:3286-3288`). No gap signal reaches the client, so the audit's "snapshot on gap" has no trigger today.
6. `stream_run_events` has no ZDR check. ZDR turns run on a persistence-free path with no session or run (`sse.rs:1042-1044`), so no run stream exists for them. The verdict's "Session Core already refuses run output for ZDR callers" is not found in the code path. UNVERIFIED as stated.
7. Modified Session Core code imports UNCOMMITTED-NEW `retention_receipt.rs` (`orchestration_grpc.rs:36`, `grpc.rs:3100`), and migrations 0044 and 0045 are untracked. A checkout of HEAD does not contain this path.
8. Member steer is refused by design. `enqueue_for` binds each entry to org and user (`queued_input.rs:184-186`), so another member gets 404 "no active stream" with `resend_as_new_turn: true` (`http_routes.rs:7479-7491`): the same 404 an ended run returns, so a member cannot tell a refused steer from a finished run. The composer also blocks sends while awaiting approval (`SpaceRoomComposer.tsx:372-378`), which the audit does not mention.
9. The activity grammar has 8 render classes and no tool-call or plan class (`activity-grammar.ts:45-61`). Tool and plan cards are net new, not a mapping.
10. `zdr_posture.rs` (UNCOMMITTED-NEW) pins the queue route's ZDR refusal at line 829. That guard test is untracked.
