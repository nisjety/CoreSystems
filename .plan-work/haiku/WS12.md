## Surprises

1. Session Core's `authorize_thread_owner` is defined three times (grpc.rs:294, orchestration_grpc.rs:246, run_service_grpc.rs:71). `OwnerIntent` has only `Read` and `Mutate` (auth.rs:469-475). A member append or revision needs the same change in each path or one shared helper.
2. The audit says non-owner append is the blocker for F-t1-016. Control already issues a member-capable `thread:append` for shared Spaces (personal_thread_decision.go:364-378). The blocker is Session Core alone (grpc.rs:4504-4505).
3. Both TypeScript transcript normalizers drop `message_id` (spaces-client.ts:627-656 and SpaceRoomTimeline.tsx:52-69), though the model gateway already emits it (http_routes.rs:8518). `SessionMessage` has no `sequence` (sessions.proto:922-949), and the Session Core SELECT omits `m.sequence` (grpc.rs:5455). A "seq" in the DTO needs a proto field, a buf breaking check, and a SELECT change.
4. SpaceRoomTimeline.tsx:60 drops every turn whose role is not user or assistant. spaces-client.ts:635 accepts system and tool. A history-window system entry (F-t1-016) or a revision marker (F-t1-017) would not render until line 60 changes.
5. The ZDR refusal path is uncommitted. `zdr_refusal.rs` and `zdr_features.rs` are UNCOMMITTED-NEW; `mp-contracts/src/lib.rs` and `model-gateway/src/lib.rs` are MODIFIED. At HEAD afb83928, neither lib.rs declares the module, and session-core `grpc.rs` has no `zdr_refusal` reference (checked with `git show`). WS12 ZDR behaviour builds on uncommitted work.
6. Session-core migrations: the highest tracked file is 0043, but on-disk 0044 and 0045 are untracked. The next free number, 0046, therefore sits on uncommitted files. Control's next free is 030 (tracked highest 029).
7. Changing the Space kind list touches four places that must change together: the named CHECK constraint (017:19-20), Control validators (authority.go 14-20, 105-112, 350-360), the Convex union (schema.ts:549-554), and the gateway create refusal (spaces.rs:2873-2881) with its test (7394-7399).
8. Naming collision. "Pin" in the Space UI is thread-level (SpaceRoomTimeline.tsx:396-409). "Message pinning" and `pinned_message_ids` in Session Core and the model gateway (grpc.rs:5452-5454; sse.rs:5384-5392; zdr_features.rs:108) mean model-context protection. `revision_preservation.rs` in the model gateway is an unrelated Markdown copier. Decide names before adding message-level actions.
9. No Space action contract exists in `src/shared/actions`, although CLAUDE.md requires one before a meaningful UI operation. Space actions also reuse `domains::spaces` handlers through `domains/actions/dispatchers.rs:80` and `handlers.rs:472`.
10. `deletion_authorization.go` has no test file among tracked files. Hide-versus-delete semantics for DMs would be untested by a dedicated file.
11. The chat `messages` Convex table (schema.ts:144) is keyed on `conversations`. Space messages live only in Session Core. There is no reaction table anywhere in convex-core, so `spaceReactions` would be a new name.
