## 3.A: Wave 1 foundations: human posts, realtime substrate, governance admin, room administration

- Delivers four W1 workstreams that make the room a place people can use together: people post and reply without waking a model (WS01), every member sees changes within about a second on one resumable stream (WS02), org admins govern Space effects with typed, honest denials (WS03), and rooms get a real roster, rename, archive, directory and audience (WS04).
- Order: WS03-S1/S2, WS04-S1/S2/S3, WS01-S7a and WS02-S1/S2 start at once (no shared prerequisite beyond `M0-BASE` and the seams); then the G2 train (WS01-S2, WS04-S4, WS01-S3, WS02-S3), then gateway (WS01-S5, WS02-S4, WS03-S4/S5, WS04-S5/S6), then SPA; WS04-S8..S12 follow in M2.2. `WS09-S1` (run guard) must be ON before `space_human_posts_core` is ON anywhere.
- Evidence rule for every slice: rebuilt local images, a running stack, the named end-to-end flow verified by someone who did not write the slice (`06` scenarios M1-S1 to M1-S4, M1-S5, M1-S6).

**API, proto, data model and migrations**
- Migration 0071 only (see 3.A.0). No Convex table, no user-core migration (next free stays 053 overall).
- `POST /api/v1/spaces/{space_ref}/threads` body `{content (1..8000 chars, no NUL), client_send_id (^[A-Za-z0-9_-]{16,64}$)}` -> 201 `{data:{space_ref,thread_id,message_id,sequence,deduplicated}}` (200 when deduplicated). `POST /api/v1/spaces/{space_ref}/threads/{thread_id}/messages` same body -> 201 `{data:{thread_id,message_id,sequence,deduplicated}}`. Errors (typed envelope): 400 `invalid_post` (`details.max_chars`), 400 `invalid_client_send_id`, 403 `active_membership_required`, 403 `space_post_not_authorized` (Control gives no reason; WS03 fills `details.reason`), 404 `space_not_found`, 404 `thread_not_found`, 404 `space_human_posts_disabled`, 409 `idempotency_key_conflict`, 409 `space_authority_stale` (BFF re-mints once), 409 `thread_state_conflict`, 412 `zdr_durable_mutation_forbidden` (typed, before any Control call), 503 `zdr_decision_unavailable` (typed, org-core failure), 503 `space_lifecycle_unavailable`, `space_decision_unavailable`, `delegated_auth_unavailable`, `session_unavailable`, 502 `post_not_stored` (create ok, append failed; retry with same keys).
- `GET /api/v1/spaces/{space_ref}/context` adds `data.features{human_posts,thread_pane,send_idempotency,connectivity_banner}` and `data.limits{post_max_chars:8000}`; list threads adds `reply_count`, `last_author_subject_id`; transcript turns add `post_kind`.
- model-gateway: `POST /v1/threads` `{space_context, session_key, first_message:{content,post_kind:"post",client_message_id}}` (Space threads only), `POST /v1/threads/:thread_id/messages` `{content,post_kind:"post",client_message_id,space_append_context}`; typed structs `deny_unknown_fields`; `role` fixed to `user`; org from claims. gRPC map: PermissionDenied -> 403 `space_post_not_authorized`, NotFound -> 404, AlreadyExists -> 409 `idempotency_key_conflict`, Aborted -> 409 `space_authority_stale`, InvalidArgument -> 400, FailedPrecondition with ZDR trailer -> typed 412 (`Refusal::from_status`) else 409, other 503.
- Session Core `AppendMessage` (no new RPC): member gate allowed only when all hold: flag on, human caller, org equal, `role=='user'`, `post_kind=='post'`, complete decision envelope with the v2 schema, thread Space equals request Space, owner not a system owner, no `space_membership_revocations` row (migration 0032) for (space, caller), 1..32768 bytes. Member decision subject is the caller; reject `Status::aborted("space_authority_stale")` when `req.recipient_audience_revision < threads.recipient_audience_revision`; no thread-column UPDATE; stamp the message from the verified request; ignore client `metadata`.
