## Flag and default

`QUARRY_EDGE__CHANGE_TEXT_FP`, default off. Off: the edge ignores `fresh_text_fingerprint` and compares raw bytes exactly as before. The orchestrator always forwards the text fingerprint from the version marker on (it is a hash, harmless to send). Workflow marker `change-text-fp-v1`.

## Assumed decisions

1. The baseline keeps one fingerprint column; the scheme is marked in the value (`text:blake3:...`) instead of a schema change, so no migration is needed and every stored baseline says which scheme wrote it.
2. Re-baseline in both directions (deploy and rollback), so flipping the flag either way never floods.
3. The re-baseline reports `status: unchanged` (not a new status string) plus `rebaselined: true`, so consumers that switch on new/unchanged/changed keep working.
4. With the flag on, `RecordResponse.fingerprint` (and the event's `fingerprint`) is the marked text fingerprint; the raw one is in `raw_fingerprint`. The Idempotency-Key of the record call still uses the raw fingerprint.
5. The public check route takes the text fingerprint as an optional field (the caller computes it); no fetch is added there.
