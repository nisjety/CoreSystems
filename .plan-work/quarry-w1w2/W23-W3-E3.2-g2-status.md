## What it does

- Six managed abilities as switches: `browser.act.input`, `browser.act.interact`, `browser.act.upload`, `browser.act.download`, `browser.profile.persistent`, `search.paid_provider` (the non-reserved abilities of `web-policy-catalogue.v1.json`). `browser.act.script` is always off and has no switch. Reserved keys have none. `robots_max` and `proxy_max` are not editable here.
- Allowed and blocked host lists. `canonicalBrowserHost` mirrors org-core `validWebPolicyHost`: lower-case ASCII, no wildcard, port, path, IP literal or trailing dot, label rules, last label not all digits. Lists are trimmed, lower-cased, de-duplicated and sorted, with 64 entries and 2048 bytes across both lists.
- Per-origin consent: the viewer's own user-core decisions (E3.2-e3), read-only.
- Save: `port.propose(orgId, { ifMatch: revision, document })`. The copy says "sent for approval" and nothing is shown as applied until the stored document changes. A revision conflict reloads and keeps the draft.
- Hidden unless `port.load` reports `available: true`. A failed load also hides it.
- Members see the effective view, read-only.

## Flag and default

No build-time flag, the same rule as the model access section. The gate is the port: the default `unavailableBrowserPolicyPort` reports `available: false`, so the section renders nothing and sends nothing. The feature is therefore off by default until the g1 adapter replaces that default.

## Assumed decisions

1. **Port seam, not a direct call.** The section takes `port?: BrowserPolicyPort`. The g1 integration swaps the default for an `executeAction` adapter over `browser.get_org_policy` and `browser.set_org_policy`, in this same file. The contract stays the source of truth.
2. **Wire shape from WS7.H.** The load result carries `revision`, `canManage`, `document` (null for members), `effective`, `entitlements` (keyed `web.robots_override`, `web.proxy_pool`, `web.paid_search`), and `originConsents`. The field names follow the org-core GET envelope in `W23-W2-CP-WS7H-status.md`. g1's output schema must be checked against them, or the adapter maps them.
3. **Save shape.** The document is the claim body, snake_case: `caps`, `robots_max`, `proxy_max`, `domains`. A save sends the whole document. Unmanaged caps, `robots_max` and `proxy_max` are carried over from the stored document. Empty containers are omitted, as org-core normalises them.
4. **Baseline removal.** A managed key at its catalogue baseline (all six are `allowed`) is removed from `caps` on save. The effective outcome is unchanged.
5. **Paid search gating.** The switch cannot turn on unless `web.paid_search` is true. Otherwise it is disabled with the plan note. Server-side, the fold and the 402 already refuse it.
6. **ZDR.** `browser.profile.persistent` and `search.paid_provider` carry a static note that they are off for zero-data-retention organisations. Enforcement stays in Quarry and the broker. The section does not read the org's ZDR state.
7. **Per-origin rows are per person.** The port must fill `originConsents` from `GET /api/v1/settings/browser-consent`. No gateway route serves it yet, so the rows stay read-only here.
8. **Every save is a proposal.** Setting the policy requires approval, so there is no apply-now path. The view has no pending field, so a sent change is not shown as pending (see depth rows).
9. **Copy.** Norwegian first, English second, through `tr`, as in the other settings sections. Not reviewed by a native speaker or counsel.
10. **Not mounted.** `WorkspaceSettingsPage.tsx` (outside this unit) should render `<BrowserPolicySection />` beside `OrgSpacePolicySection` once the port is live.
