## Assumed decisions

1. Flag name `QUARRY_BROWSER_AX_PER_FRAME`. The queue row names no flag. Default off.
2. Per-frame bound `Op::AxFrame` = 2 000 ms. The snapshot budget is `Op::AxSnapshot` (10 s), counted from the start of the projection, so the top-level read's time counts against it. A frame gets the smaller of 2 s and what is left.
3. Only frames the top-level read does not carry are read one at a time. Same-process child frames stay inside the top-level read under its bound. A separate read of those would duplicate nodes and would not stop a hung same-process renderer.
4. The "50-target cap aligned with the planner's 40" is read as the driver cap of 50 (the runtime's own cap), with the planner's 40-target window inside it. The planner (Model Plane `execution-core`) was not changed. If the owner meant a driver cap of 40, it is one constant.
5. Targets are capped in tree order, after the top-level nodes. Child-frame targets therefore come after the top frame's.
6. A failed frame read is `ax_frame_unavailable` with no error text. A bound that expires is `ax_frame_timeout` with the bound in `deadline_ms`.
7. Budget exhausted: one `ax_budget_exhausted` warning, and no further frame reads. The frame limit is `FRAME_PROJECTION_LIMIT` (64, the same as the frames list): one `ax_frame_limit` warning when the tree has more frames.
8. `accessibility.truncated` now also means a frame could not be read. No new wire field is added in this unit.
9. A per-frame read that loses its context to a navigation is not retried. The root read keeps its retry. A frame that navigated mid-snapshot is left out with a warning.
10. Masking is unchanged. The merged tree goes through the same probe and mask. An editable control the probe cannot resolve classifies as `Secret` (fail closed, `field_probe.rs` `verdict`).
11. Nothing is stored or logged by the new reads, so no ZDR branch is needed.
