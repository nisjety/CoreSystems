## Assumed decisions (owner: take the plan's default)

1. With the flag on, the sitemap body cap is 10 MiB as sent (the INNH-6a `MAX_COMPRESSED_BYTES`). It applies to plain XML too, because the cap is set before the body type is known. Before, a plain sitemap over 1 MiB was silently skipped.
2. A sitemap the transport drops for size or a driver error stays "skipped, not partial" (the existing `Ok(None)` path). Not changed.
3. Gzip is inflated by `parse_body` (50 MiB decoded cap, the sitemap protocol). A corrupt or truncated gzip body is an invalid sitemap, so `sitemap_partial` is set, as for bad XML.
4. Robots sitemaps: with the flag on and the best-effort robots text present, `sitemap_urls_from_robots` (validated, normalised, deduplicated) replaces `RobotsTxt.sitemaps`. The enforce gate keeps its parsed list. That list is still filtered by `nested_in_scope` (https, public, same origin).
5. The Go mirror is conservative and fails closed. It covers the plain ASCII subset only. It refuses non-ASCII, userinfo, IPv6, IPv4-looking hosts, `..` in the host, a `%` in the host, a backslash, a space, a `|`, or a `'` in a query, and returns `ok=false`. Those URLs keep today's raw id.
6. Canonical request id = `FrontierRequestID(runID, canonicalURL)`, the existing sha256 family, not the Rust `cu1-` blake3 id. For a URL that is already canonical the id does not change, so flipping the flag does not churn existing ids. The queue treats ids as opaque.
7. `FrontierMarkSeen` follows the `enqueue_batch` shape: at most 500 ids per call, blank ids skipped, body `{org_id, request_ids}`, reply `{data:{accepted}}`. The edge route it needs is proposed here, not built.
8. Redirect seen ids: the requested id, then the final id when it differs (mirrors `Reconciliation::seen_request_ids`). An empty final URL gives the requested id alone.
