## Built

`scrape.rs`:
- `PiiRedaction { Off, On }`, default `Off`, serde `off` and `on`, `JsonSchema` under the `jsonschema` feature.
- `ScrapeOptions.redact_pii: Option<PiiRedaction>`. `OPTION_KEYS` gains `("redact_pii", "redactPii")` (12 entries). `from_value` accepts only the strings `off` and `on` (`unsupported_redact_pii` otherwise). Aliases follow the existing rule (`conflicting_aliases`).
- `resolve(zdr, limits)`: with `on`, refused outside ZDR (`requires_zdr`, path `redact_pii`), refused with a screenshot or PDF (`not_supported_with_redact_pii`, path `formats`), refused with actions (`not_supported_with_redact_pii`, path `actions`).
- `ResolvedScrapeOptions.redact_pii`. `is_default()` and `result_cache_admissible()` say no when on, so the page cache and the URL result cache neither read nor write a redacted request. `canonical_options_key()` adds `redact_pii` only when on, so every existing key is unchanged.
- `EffectiveScrapeOptions.redact_pii` (serde default), always reported, `off` by default.
- Tests in `mod tests`: both spellings and the conflict rule; only `off` and `on`; default off and explicit off give the same key; refused outside ZDR; ZDR bypasses both caches and keys apart; capture and action refused, text formats served; the effective report for on and off; the field-name pin now covers 12 keys.

`routes.rs`:
- `ScrapeRequest.redact_pii` and `redact_pii_camel` (raw values, read only by the stream route).
- `redact_pii_text(output, inline, max_inline_bytes)`: redacts the inline markdown, html and raw_html, the AI source, the page title, description, author and keywords, and the extraction title, excerpt and summary. Clears `text_fp`. A field the markers grow past `max_inline_bytes` is cut again on a character boundary and named in `truncated`.
- `scrape_with`: `redact_pii` is decided from `resolved`. A redacting runner gets no local index and no model title enricher. The run's output is redacted before any cache write, the AI step, the scrape record and the response.
- `scrape_stream`: refuses a `redact_pii` other than `off` with `unsupported_in_stream`, the same refusal as actions, captures and AI formats.
- Tests in `mod tests`: ZDR redacts the inline markdown and reports `on` (no record); outside ZDR is refused with the field named (400, `requires_zdr`); the default is off and the text is the page's.

## Flag and default

- No separate flag. The request option is the switch and defaults off (absent or `off`). That matches the queue ("Default off").
- No environment variable is read here. `QUARRY_EDGE__PII_REDACTION` belongs to E3.6-4a (the pipeline stage and the org default). It is not needed for the option to work under ZDR, and wiring it needs `scrape_contract.rs`, which is outside this unit.
- Non-ZDR is refused rather than gated, because that refusal is what keeps an unredacted copy out of storage (assumed decision 2).

## Assumed decisions (owner said stop asking)

1. "ZDR runs still redact" is read as: the option is honoured under ZDR, and ZDR does not force redaction on. Default off applies to every run. Alternative, not built: ZDR forces redaction whatever the option says.
2. Non-ZDR is refused (`requires_zdr`) until E3.6-4a/4b redact before the stored artifacts, the index and ingest. Alternative, rejected: honour non-ZDR now. The pipeline writes the raw body and the markdown as artifacts for every non-ZDR run (`pipeline.rs` about lines 1357 to 1377), so an honoured non-ZDR request would store unredacted text, against E3.6-4b's "no representation bypasses pii.rs".
3. Captures and actions are refused with redaction. An image or a PDF cannot be scanned. An action can take one, and its error text is not scanned.
4. Redacted inline text is cut again to `max_inline_bytes`, because a marker is longer than the value it replaces. The field is named in `truncated`, so the inline contract still holds.
5. The marker form is the one `pii.rs` writes, `[redacted:pii.<kind>]`. D2-221 (one marker form across Quarry) is not ratified. This unit does not change it.
6. Accepted values are the strings `off` and `on` only, no booleans, matching the scope's `(off | on)`.
7. The stream route refuses rather than redacts. Its run events carry the page text (the `page_extracted` payload mirrors `PageExtraction`, with title and excerpt), and this unit does not redact events.
8. A redacting run builds no local index copy and no model title enricher. This is defence in depth: ZDR already skips both (`LocalIndexWriteback` takes the ZDR mode, and `model_hop_allowed` is false under ZDR).
9. The text fingerprint is cleared, because it hashes the text as the page had it. The raw-byte `fingerprint` is kept, since change detection and artifact addressing use it.

## What is covered and what is not

Covered for a ZDR run: the inline response text, the AI source, the page metadata text, the extraction text, and the usage metadata (computed after the redaction). No scrape record is written under ZDR.

Not covered in this unit:
- Stored artifacts, the local index and ingest for non-ZDR runs: refused, so not reached.
- Run events under ZDR: the `page_extracted` payload (title, excerpt) is unredacted. Under ZDR it goes only to live subscribers and the in-memory replay ring, never the durable publisher (`zdr_run_keeps_page_extracted_off_the_durable_channel` in `pipeline.rs` pins this). Redacting the payload belongs to E3.6-4a.
- URLs (requested and final, canonical, og:image), the branding JSON, warning messages and action messages.
