# WS3.K design note: actionability pipeline and trusted input (default off)

Read first: plan slice detail (line 892), table (785-800), flag row (3657). Tree facts checked before design: `execute_native_target_action` (chromiumoxide.rs ~2083) runs `element.click()` / a value setter inside `Runtime.callFunctionOn`; `click_point` (~3936) is the only place that dispatches `Input.dispatchMouseEvent`; only `download_from_verified_target` reuses the native click helper (the plan's own CLAIM-FALSE); `BrowserDriverCapabilities` derives Default and every literal site already uses `..Default::default()`, so the new field is additive.

## Data model
- `actionability.rs` (cfg chromiumoxide, like deadlines.rs). `Probe` (serde, all fields defaulted) is what `ACTIONABILITY_PROBE_JS` returns from ONE `Runtime.callFunctionOn` on the resolved element: `attached, visible, enabled, editable, tag, box, viewport, hit{ok, covered_by_tag}`. The hit test is shadow-root aware (`elementFromPoint` descended through open shadow roots, containment checked on the composed tree, `label.control === target` accepted).
- Pure core, unit-tested without a browser: `click_point_from_quads` (clips every quad to the viewport with Sutherland-Hodgman, needs area >= 1 px^2, returns the vertex mean; Err(NoBox) when every quad is empty, Err(Unreachable) when boxes exist but none is inside the viewport), `stable` (last two box samples within 0.5 px), `decide(probe, intent)` (one reason per failure), `into_error` (409 TargetRepairRequired, details = reason + tag name only).
- Async: `prepare_click` (probe, scroll into view, stability sampling, `DOM.getContentQuads`, hit test at the point), `prepare_type`, `prepare_select` (probe only plus scroll), `dispatch_click(page,x,y)` (extracted from `click_point`, unchanged messages), `insert_text` (`DOM.focus`, in-page select-all, `Input.insertText`).
- Deadlines: `Op::Actionability` 2 s total, probe polled every 100 ms; `Op::StablePoll` 500 ms in 25 ms steps. Both are effect-less ops (nothing has been clicked yet), so a timeout there is retryable. The outer `Op::NativeAction` (10 s) still wraps the whole action.
- Errors: `quarry_core::error::target_repair_reason` closed list (`target_not_attached`, `target_not_visible`, `target_disabled`, `target_covered` with `covered_by_tag`, `target_unstable`, `target_has_no_box`, `target_unreachable_after_scroll`). The legacy in-page strings stay valid for the synthetic path; `native_target_not_connected` is an alias of `target_not_attached`. `QuarryError::target_repair_reason()` reads `details.reason`.

## Failure cases and mapping
Not attached fails at once (a stale ref will not come back). Everything else is polled until the 2 s budget ends and then reports the LAST reason seen: not visible (display none, visibility hidden, no layout box), no box (zero area), disabled (also readonly / not editable for type: the closed list has no separate reason), unstable (box moved more than 0.5 px across the window), covered (hit element is not the target, a descendant, or its label), unreachable (point outside the viewport after scrolling). A modal `alert` raised by the click stalls `mouseReleased`: the click races a watch on the driver's dialog collector, and a dialog that appeared after the click began counts as delivered (the dialog stays pending for `respond_dialog`).

## ZDR consequence
Nothing is persisted. Error details carry the reason, a sanitised tag name (`[a-z0-9-]`, 32 chars) and nothing else: no selector, URL, text or CDP error text. The log line `quarry.browser.actionability_rejected` carries a closed reason and a closed intent label, so the log-field lint and the ZDR event filter stay quiet.

## Flag and default
`QUARRY_BROWSER_TRUSTED_INPUT=off|on`, default `off`, read in `ChromiumoxideDriver::new()` (builder `with_trusted_input(bool)` for tests). The capability `trusted_input` is true only when the flag is on. Off: byte-identical behaviour to today. On: ref-targeted click/type/select on a top-level target use the pipeline; child-frame targets (frame id differs from the root frame), downloads, uploads, the legacy selector-script path and `wait_for` stay on the synthetic path. `atomic_target_actions` (which gates every ref action) is untouched; observation.rs is not touched.

## Will not do
No Model Plane change (planner sentence, closed `browser.act` schema), no SPA/gateway change, no flipping the flag, no deployment evidence on a rebuilt edge (not possible here), no WS3.L (cross-process iframe hit test, modifiers, drag, paste, per-key typing, file chooser). Select keeps in-page `change` events (not trusted, same as Playwright's selectOption): trusted input applies to the pointer and keyboard-text paths only. Typing does not fire a synthetic `change`; the browser fires it on blur like for a person.
