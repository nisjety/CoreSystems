## Assumed decisions (owner said stop asking)

1. Bearer: Quarry's own service token, aud `ingestion`, scope `imports:read` (imports-core's `require_internal_auth` accepts a service principal with `imports:read` or `imports:write`). Never a shared key.
2. The token request is injected (`ManifestImportsBearer::new(tokens, request)`), not built in this file: a `from_manifest("<row>")` literal for a row that does not exist yet fails `token_request_contract.rs`, and the manifest is outside this unit. Tests use a fake `ImportsBearer` for the same reason (a `from_manifest` call in tests would count as a call site).
3. Input cap defaults to imports-core's 1 MB default, operator-raisable to 25 MiB to match `CHAT_EXTRACT_MAX_BYTES`.
4. Separate slot pool (4) from the CPU-bound PDF/DOCX permits (2): a remote call should not starve local parses.
5. A 401/403 that survives the refresh is `DRIVER_FAILED`, not 403 to the scrape caller: it is a deployment fault, not the caller's.
6. ZDR allowed: the route is ephemeral by contract; the client enforces it on every answer (`persisted` must be `false`).
