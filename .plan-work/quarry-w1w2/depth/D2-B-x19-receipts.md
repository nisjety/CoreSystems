# D2-B-x19-receipts: findings not fixed (2026-10-28)

Unit: X-19, list B (prepare, receipts stay off for real users). Built: the event follows the flag (D2-210), the key-by-key password gap (D2-065), the retention design note. Every item below is something I found and did not fix, or fixed only in part.

1. **No `RULE_VERSION` bump, so `qr-redact/4` rows can hold a raw key press.** The drift fingerprint covers text rules only; this change is in the action layer. Bumping needs the golden `rule_version`, its `.sha256` pin, `PINNED_FINGERPRINTS` and every vendored copy (see `docs/SECRET_REDACTION.md`, "Changing a rule"), and then a read-time re-mask of older `press` rows. No real-user receipts exist (receipts are off), so I left it. Decide after the retention design: either bump (read-time re-mask) or rely on retention. The read path already masks a `press` character on rows with no stamp or an older stamp than the current one.
2. **The event and the receipt still differ on one input: a raw `type` action whose selector says nothing (D2-064).** The event masks the text as a secret; the stored receipt classifies by selector only and keeps it under `sensitive`. This is the stricter side on the event, and it is not a flag matter, so I left it. If the owner wants one rule, the receipt should fail closed too (a one-line change in `redacted_for_record`, but it would mask `type #q "shoes"` in stored receipts, which hurts procedure replay for raw-selector callers).
3. **Focus tracking is best effort and only as good as the run's view.** `key_focus` is set from the snapshot target of a click or typing action. A page that moves focus by script, an autofocus the run never clicked, or a click that opens a modal with a password field is not seen, and the key is then judged by the last known focus. The worst case is a password typed after a click on a non-sensitive text control where the page moved focus to a password field: the characters would be kept under `sensitive`. The only closed fix is to read the focused element from the page after every step (a native `document.activeElement` probe in the field probe, on `quarry-browser`), which is a browser-crate change with a cost per step; I did not build it. Failing closed covers every case where the run has no click or type on a text control since the last focus-moving action.
4. **A click on a native text target with `field_kind: None` leaves the focus unknown.** The probe sets `None` for controls that take no text; for a text input the probe sets `Unknown` or a kind. If the field probe is off (`QUARRY_BROWSER_FIELD_PROBE=off`) the targets probably carry `None` too (not checked), and then every key press is masked as a secret. That is the safe direction; it also means `sensitive` keeps less when the probe is off.
5. **Dropped-observation counter (step 3 of the decision's "If accepted") not built.** `redact_observation_durable` returns `None` when the masked observation cannot be rebuilt and the receipt then stores no observation. Nothing counts it. Not in this unit's spec, so not built; it is a small metric in `step_receipts.rs` plus the label list in the metrics module.
6. **Stale `qr-redact/3` text remains in `docs/RUNBOOKS.md`** (the WS12.S3 section: the sentence at its end of the policy flag paragraph and the psql check). RUNBOOKS is append-only for this round, so the correction is in the new section appended at the end, not in place. A later pass that may edit RUNBOOKS in place should fix both lines and the sentence "the product owner's answer to X-19 is still owed".
7. **`docs/CONTRACTS.md` has no mention of the receipt text policy or the key press rule.** The decision's step 4 asked to sync CONTRACTS.md; there was no `qr-redact/3` text in it to fix, and the receipt masking rules are documented in `docs/SECRET_REDACTION.md` and RUNBOOKS only. I did not add a new CONTRACTS.md section; if the contract doc is meant to carry the receipt wire rules, add one paragraph under the receipts heading.
8. **The migration comment `0013_step_receipt_redaction_version.sql` still says `qr-redact/3` as its example.** It is a comment in an applied migration; changing it changes the file hash for `_sqlx_migrations`. Leave it.
9. **The stack evidence (condition (d)) did not run.** Everything here is unit-tested only. The procedure in the appended RUNBOOKS section has the psql checks for a key-by-key login and for `all` mode.
10. **Retention and erasure are a design only** (`.plan-work/quarry-w1w2/D2-x19-retention-design.md`). The quarry-control consumer acts on `organization` events only; user erasure needs a Control Plane answer on which orgs the event carries (design note, 5.3). Receipts must not go on for real users before it is built.
11. **The Model Plane side of X-19 was not looked at.** The Model Plane keeps its own copy of what an agent typed (planner prompts and event scrub, WS12.S4 `mp-scrub`). This unit changed Quarry only.
