# Depth findings left open by D-D-B2-profiles-receipts (2026-10-27)

- DB2P-01 (decision D16 Q2, medium): a run's own profile save (chromiumoxide.rs about 1840 and kernel.rs about 591: `SaveMeta { owner: None }`) stamps no owner, and the owner is stamped on INSERT only. A profile that a run creates (start_run with an unknown `profile_id`, now guarded by `ProfileOp::Attach`) therefore reads as legacy-ownerless; under `enforce` a private one is hidden from everyone, including the user who made it. Needs the actor id on the lease (D2-044 is the same gap) or the save made by the edge. Not decided here; profile enforce stays observe.
- DB2P-02 (X-19, low): an ActionStarted event now masks the text of a raw `type` action whose control is unknown (D2-064), while the stored receipt keeps its default text policy (sensitive-only). The two differ on purpose; if X-19 settles on `all` or `sensitive`, the event rule can follow. A driver that reports the control kind for a raw selector would let the event keep ordinary text again.
- DB2P-03 (low): `normalized_text` in an element fingerprint is lower-cased, so the case-sensitive vendor shapes `AKIA`/`ASIA` and `AIza` are not masked there (shape.jwt now is, in any case). Fix at the source: have the fingerprint masking use the masked text lower-cased instead of masking the lower-cased copy.
- DB2P-04 (low): `X-Csrf-Token: value` as free text under `Live` is not masked (the JSON header key and pair are). Durable masks it through the labelled-secret rule. Same as `X-Api-Key` text.
- DB2P-05 (info): RUNBOOKS.md line about the rule set still says `qr-redact/3` (shared append-only file).
- DB2P-06 (info, erratum): the commit messages e46bb66cb and 4f3eeb43c give wrong per-target counts for two side checks: `profile_roundtrip` passed 11 (not 8) and `agent_events_replay` passed 6 (not 11). The named targets are right.
- DB2P-07 (info): the WS8.F agent attachment (`attach.rs`) names no profile, so D2-045's attach path is the start of a run that names a `profile_id`; `attach.rs` was not touched. Resume of a run keeps its checkpoint's profile (no re-check: its own owner started it).
