# W2-U09 depth bullets (WS13.2, contract types for scrape capture and actions)

Written during the build, not fixed. Format: severity, kind, what | where | why deferred.

- [severity high] [kind test] The U09 test set is written and compile-checked only (cargo check --tests, default and --features jsonschema). No test was run; the first run belongs to the final test phase | crates/quarry-core/src/{capture.rs,scrape_actions.rs,scrape.rs} | batch rule: tests come at the end of the wave.
- [severity high] [kind risk] The capture and action wire contract is only as safe as its flag: `ScrapeLimits.captures_enabled` and `actions_enabled` default to false, so a request with them is `feature_disabled` (400 at `formats` or `actions`). WS13.4b must set them from `QUARRY_EDGE__SCRAPE_CAPTURE` and `QUARRY_EDGE__SCRAPE_ACTIONS` and must not flip the defaults | crates/quarry-core/src/scrape.rs ScrapeLimits | WS13.4b and WS13.5 own the env wiring.
- [severity medium] [kind decision] Default PDF paper is Letter (Chromium default). The plan's example request uses `"format":"A4"`. Confirm the default with the product owner before WS13.4b documents it | crates/quarry-core/src/capture.rs PdfPaper | product choice, not in the approved 13.
- [severity medium] [kind decision] The action type for a selector or time wait is `wait` (`{"type":"wait","selector":...,"timeoutMs":...}`). The plan's test names use `wait_for`, which is the driver method name. The WS13.5 docs must state the wire name | crates/quarry-core/src/scrape_actions.rs | WS13.5 and WS13.8 docs.
- [severity medium] [kind hardening] The credential heuristic adds the token `password` to the plan's list (`pass`, `pwd`, `otp`, `secret`, `token`, `cvc`, `cvv`), so `#password-reset-button` is refused as a write target. Conservative false positive; the plan does not name it | crates/quarry-core/src/scrape_actions.rs CREDENTIAL_TOKENS | ADR-2 soft guard; tune with the negative table in WS13.5 evidence.
- [severity medium] [kind hardening] The credential check applies to `write` and `select` only. A `click` on a credential control is not refused. Plan is silent on click | crates/quarry-core/src/scrape_actions.rs check_action | decision for WS13.5 (ADR-2 is OTP first).
- [severity medium] [kind risk] `ingest: true` is refused with actions by reading the root key in `ScrapeOptions::from_value`. The edge does not yet define an `ingest` request key in quarry-core; WS13.4b must confirm the key name the edge uses | crates/quarry-core/src/scrape.rs from_value | WS13.4b.
- [severity medium] [kind risk] Timeout budget: the wait budget is 60 s (`max_total_wait_ms`) but `ScrapeLimits.max_timeout_ms` is 55 s (WS5 cap). An action run with a full wait budget cannot finish inside the 55 s timeout. WS13.5 raises the timeout to 115 s only with actions on, as the plan says | crates/quarry-core/src/scrape.rs ScrapeLimits::default; crates/quarry-core/src/scrape_actions.rs ActionLimits | WS13.5 (and H2 timeout layer note).
- [severity medium] [kind risk] `ScrapeFormat` lost `Eq` and `Hash` (f64 in the capture options). No consumer in the workspace needed them (grepped), but a future map keyed by format will not compile | crates/quarry-core/src/scrape.rs | accepted; documented in the code.
- [severity medium] [kind other-plane] The Model Plane vendors `docs/schemas/scrape-options.schema.json` as the scrape tool argument schema. The golden changed (formats now have an object form, and `actions`, `actionsOnError` are new keys). The vendored copy in the Model Plane is stale until the sibling (b) owner refreshes it | docs/schemas/scrape-options.schema.json; apps/Model Plane | sibling (b), not ours.
- [severity low] [kind test] The hand-written `JsonSchema` for `ScrapeFormat` (anyOf of string and object) is not checked against the parser. A round-trip test (every schema string parses, every object form parses) belongs in WS13.8 | crates/quarry-core/src/scrape.rs | WS13.8.
- [severity low] [kind doc] Effective options echo a screenshot or pdf format by name only; its options are not echoed. WS13.4b must decide whether the echo carries the options (the options hold no caller content) | crates/quarry-core/src/scrape.rs EffectiveScrapeOptions | WS13.4b.
- [severity low] [kind hardening] The canonical options key includes the action list, text included, before hashing. The key is hashed and never stored, and cache admission refuses actions, so no text is persisted through the key. Keep it that way: WS13.4b must not log the key | crates/quarry-core/src/scrape.rs canonical_options_key | WS13.4b review.
- [severity low] [kind risk] Behaviour change for an edge that already enables the WS5 options flag: `formats: ["screenshot"]` was a 400 `reserved_format`; it is now a 400 `feature_disabled` (same status, different code). `actions` was an ignored-with-warning key; it is now a 400 `feature_disabled` while its flag is off. Clients that matched the old code need a note in CONTRACTS | crates/quarry-core/src/scrape.rs | WS13.8 docs.
- [severity low] [kind bug?] `SINGLE_CAPTURE_MAX_DEVICE_PX` (16,000) and the tile constants are provisional. WS13.3 spike sets the measured limit | crates/quarry-core/src/capture.rs | WS13.3 spike.
- [severity low] [kind doc] The `ScrapeLimits` doc comments and the FieldError code list mention the new codes by module, not in one table. A single closed table belongs in CONTRACTS section 10 | crates/quarry-core/src/scrape.rs FieldError | WS13.8.
- [severity low] [kind hardening] `ActionLimits::lowered` and `CaptureLimits::lowered` are written but nothing calls them yet. WS13.4b must read the env caps through them so a caller cannot raise a cap | crates/quarry-core/src/{capture.rs,scrape_actions.rs} | WS13.4b.
