# W2-U41 depth notes (WS17.E3: backfill, erasure hop, plaintext removal)

Everything below was noticed during the build and is deferred, not fixed. Format: severity, kind, what | where | why deferred.

- [high] [kind evidence] Deployment evidence not run: backfill a canary profile on a live stack, `psql` check that no canary is in `quarry_profiles` (envelope set, snapshot NULL), Redis shows no `quarry:profile:*` legacy key for it, erase the org through the control event, check rows, tombstones and `quarry:profile:v2:*` keys are gone, a second erasure reports zeros | apps/Ingestion Plane/Quarry-v2 (plan WS17.E3 evidence) | test phase of wave 2; needs a live stack.
- [high] [kind risk] Migration 0017 applies at the next edge boot (`sqlx::migrate!`). Its UPDATE and NOT VALID CHECK are inert on a consistent store, but the plan's release gating (ships only after REQUIRED=1 and the backfill gate) is not enforced by code. A deployment that reaches the edge before the gate runs it anyway | crates/quarry-runtime/migrations/0017_profile_plaintext_null.sql | decide before the release: hold the file out of the image until the gate, or accept the inert migration with the RUNBOOK note.
- [high] [kind risk] A pre-0016 binary that writes a row after `on` has run fails the new CHECK (its upsert keeps the envelope column and sets snapshot). Old binaries also cannot read envelope rows, so this is a rollback hazard the runbook states, not a fix | migrations/0017 | none in code; the runbook says it is not a rollback target.
- [high] [kind decision] Erasure does not achieve cryptographic erasure: the env key provider has no per-org key, so a copy of the master key still opens an erased org's envelopes. Real shredding waits for WS17.E2 (org KEK, org-core migration 024) | crates/quarry-runtime/src/profile_keys.rs (EnvKeyProvider) | WS17.E2 (WAIT-OTHER, X-8 gate).
- [high] [kind test] Tests written and compile-checked (`cargo check -p quarry-runtime --tests --features postgres-queue` rc 0) and not run. The edge bin-root test target does not compile yet: main.rs lacks `mod schedule_preflight;` (WS15.S2 unit's edit). The lib and integration test targets compile. | crates/quarry-runtime/src/org_erasure.rs and profile_backfill.rs tests; crates/quarry-edge/src/main.rs | rerun the edge test check once that unit lands; then cargo test in the test phase.
- [medium] [kind bug] DEK cache eviction is per process. `EnvKeyProvider::evict_org` drops the entries of the replica that answers the erasure only; other replicas keep unwrapped DEKs for up to the 300 s TTL | crates/quarry-runtime/src/org_erasure.rs ProfileErasure::purge_org | needs a fan-out or a shared invalidation; acceptable while the env provider is interim.
- [medium] [kind bug] Cache populate race (as in the U36 depth notes): a `CachedBlobStore::get` that read the row before the purge can write the envelope to Redis after the purge scan, leaving it for up to the 1 h TTL. The envelope still needs the master key | crates/quarry-runtime/src/cached_profile_store.rs CachedBlobStore::get; org_erasure.rs purge_cache | versioned key or a re-check after the write; test phase.
- [medium] [kind risk] The purge deletes the org's tombstones (plan). A save for the erased org that arrives after the purge is no longer refused by a tombstone and can recreate the row. It relies on auth refusing saves for a deleted org | crates/quarry-runtime/src/postgres_profile_store.rs purge_org_rows | confirm in the test phase that org deletion blocks writes; or keep tombstones for the TTL.
- [medium] [kind risk] Other erasure families are not covered: receipts, checkpoints, the crawl frontier, baselines, history and artifacts in quarry-runtime and quarry-edge have no erasure hop (named in plan section 3.6). The inventory test the plan asks for (every table with `org_id` must be in an erasure list) is not written | plan 3.6 row; crates/quarry-runtime, crates/quarry-edge | a later slice; new families join `OrgErasable` by one line.

If the pre-provisioned JetStream consumer has a finite MaxDeliver, a long edge outage can exhaust redeliveries and drop the erasure | apps/Control Plane/audit-core/internal/provisioner (consumer config) | check the provisioner value; add an alert on redelivery exhaustion.

No secrets-ledger entry was made | apps/Ingestion Plane/docker-compose.yml (quarry-control env block); secrets ledger | deploy step.
- [medium] [kind hardening] The internal route is gated only by the shared token. The edge's `QUARRY_EDGE_AUTH_DEV_BYPASS` (honoured by `verify_internal_token`) also bypasses this erasure route. Confirm the bypass is never on in production | crates/quarry-edge/src/change_routes.rs verify_internal_token; internal_routes.rs | none; same as the change record route.
- [medium] [kind hardening] No dry run in `profiles_backfill`. `--max-rows` bounds the run but nothing counts without writing | crates/quarry-edge/src/bin/profiles_backfill.rs | add `--dry-run` (count the plaintext rows) before the live run.
- [medium] [kind hardening] Backfill and purge SCAN the keyspace (`quarry:profile:*` for the backfill, a per-org pattern per erasure). A per-erasure SCAN is O(keyspace).
