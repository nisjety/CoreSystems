# W2-U53 depth notes (WS13.5, scrape-time actions, built dark, NOT run)

Written during the build, not fixed. Each bullet: severity, kind, what | where | why deferred.

- [severity high] [kind risk] The gateway does not yet give Model-proposed or SPA scrapes with actions the 125 s client timeout; its default is 25 s, so any actions run longer than 25 s is cut at the gateway even with the edge at 115 s. The plan's `knowledge/quarry.rs` per-request timeout and the `initiated_by:"agent"` stamping on the action-dispatcher path are not built. | apps/Frontend Plane/verevonv3/apps/gateway/src/domains/knowledge/quarry.rs (scrape 28-60); config.rs 289-293 | gateway is not in U53's owned paths; batch 11 or the gateway unit owns it.
- [severity high] [kind evidence] Nothing has been run: the action_runtime unit tests, the edge actions_tests, and the live Chromium test `scrape_actions_live` (post-click DOM extraction, off-host denial after an action) are written or owed, not executed. | crates/quarry-runtime/src/action_runtime.rs (scrape_run_tests); crates/quarry-edge/src/scrape_actions.rs (actions_tests) | build-first rule; tests run in the wave's final phase.
- [severity high] [kind hardening] The wire response does not carry `data.actions[]` yet. `ScrapeResponse` keeps only the `ActionsSummary` echo; the ordered outcomes, output `artifact_id` and inline `data_base64` are not mapped. A caller of an actions request gets the page but cannot see per-action status. | crates/quarry-core/src/scrape.rs (ScrapeResponse, effective options); crates/quarry-edge/src/routes.rs (`finish`, `from_output`) | the plan puts `ScrapeResponse.actions: Vec<ActionOutcomeView>` in pipeline.rs (`persist_captures`, not in the tree); unbuilt.
- [severity high] [kind hardening] Action output bytes (screenshot and PDF from an action) are held in `PageCaptures.action_outputs` and dropped at the end of the fetch. They are not stored (no `ArtifactStore::put`, no ZDR inline cap) and not returned. | crates/quarry-runtime/src/pipeline.rs (persist_captures, NEW in 4b, absent); crates/quarry-runtime/src/browser_driver.rs (do_fetch action block) | pipeline.rs is hot (H6) and the persistence has a ZDR and label contract (`action.<i>.<kind>`) that needs its own pass.
- [severity high] [kind bug] The plan's safe mode is a `safe_mode_runner(&AppState, base)` that builds a PageRunner with the five optional fields set to None. U53 sets three of them (`local_index`, `page_renderer`, `title_enricher`) in routes.rs and `source_registrar` was already None; the plan's per-field no-op check [UNVERIFIED per field] is not done, and no test asserts it. Ingest is refused by the contract (`not_supported_with_actions`). | crates/quarry-edge/src/routes.rs (scrape_with runner literal, `actions_safe`); crates/quarry-runtime/src/pipeline.rs (use sites ~795, ~846, ~1000-1058) | verify each None is a no-op at the use sites, then add `actions_force_safe_mode_so_no_ingest_index_or_title_hop`.
- [severity medium] [kind bug] `scroll` by direction wheels at the lease viewport centre (or 640 by 400 when the lease names none). The plan asks for `Page.getLayoutMetrics` in the driver; the BrowserDriver trait has no viewport query. An actual page whose viewport is not the lease viewport gets a wheel at the wrong point. | crates/quarry-runtime/src/action_runtime.rs (`attached`, DEFAULT_VIEWPORT_CENTRE); crates/quarry-browser/src/lib.rs (BrowserDriver trait) and chromiumoxide.rs (H4 queue) | adding a trait method touches the H4 serial queue file; deferred.
- [severity medium] [kind decision] With actions on, the handler bound is always 115 s (`run_deadline_ms`), ignoring a caller `timeout_ms` that is smaller. The plan's intent is unclear on this; a caller who asked for 10 s gets 115 s. | crates/quarry-edge/src/scrape_actions.rs (run_deadline_ms); crates/quarry-edge/src/routes.rs (run_deadline_ms use) | owner decision: take the smaller of the caller bound and 115 s, or keep the plan's fixed 115 s.
- [severity medium] [kind risk] The CancellationToken passed to `run_scrape` is never fired (do_fetch uses a fresh token). An action in flight when the handler drops the future keeps running in Chromium until its own CDP call returns; the session is released by the HeldSession drop. The plan's child token fired by the request deadline is not built. | crates/quarry-runtime/src/browser_driver.rs (do_fetch action block); crates/quarry-runtime/src/action_runtime.rs (run_scrape) | the drop path releases the session; a token fired from the deadline is a small follow-up once the wire shape is settled.
- [severity medium] [kind hardening] The heavy permit is taken with `try_acquire_owned` and held for the whole fetch, including the post-actions content read. A single org can hold the one permit for up to 115 s; the plan notes per-org fairness is WS6's. | crates/quarry-runtime/src/browser_driver.rs (`_heavy_permit`) | WS6 per-org fairness, plan risk section.
- [severity medium] [kind test] The edge integration tests the plan names are not written: `tests/scrape_capture.rs` cases `actions_disabled_is_a_field_error`, `service_principal_without_scrape_interact_is_403_with_actions`, `actions_with_ingest_true_is_400`, `actions_bypass_the_page_cache_even_with_prev_fingerprint`, `scrape_stream_and_batch_reject_actions`, `action_failed_returns_ordered_details_and_no_write_text`, `router_deadline_is_125s_for_scrape_with_actions_and_60s_otherwise`, `denied_aliases_return_action_denied`. Only the unit tests of the mode, the principal check and the deadlines are written (scrape_actions.rs `actions_tests`). | crates/quarry-edge/tests/scrape_capture.rs (not extended) | integration harness work; the wave's test phase.
- [severity medium] [kind test] The batch route (`POST /v1/scrape/batch` or equivalent) is not checked for `actions`. The stream route is refused (`unsupported_in_stream`). | crates/quarry-edge/src/routes.rs; crates/quarry-edge/src/scrape_actions.rs | confirm the batch path refuses actions before the wave closes.
- [severity medium] [kind test] `zdr_active_refuses_store_put_in_the_legacy_screenshot_arm` and the defensive `zdr::guard(.., WriteKind::Artifact)` before `store.put` are not built. The attached runtime has no artifact store, so the path is unreachable for scrapes today; the legacy `ActionRuntime::run` arms are untouched. | crates/quarry-runtime/src/action_runtime.rs (execute_action Screenshot/Pdf arms) | the guard belongs with the pipeline persistence (see the high bullet above).
- [severity medium] [kind hardening] `initiated_by` is a request key that the contract parse does not know, so it is listed in `unknown_keys` and produces the unknown-field warning, and the echo in `effective_options` reports it. The plan asks for a tighten-only hint; the warning text should not name it as an unknown contract field. | crates/quarry-edge/src/scrape_contract.rs (unknown keys); crates/quarry-edge/src/routes.rs (ScrapeRequest.initiated_by) | the contract keys table in quarry-core/src/scrape.rs (`("actions", "actions")` style) needs a row; a contract change, so WS13.8 docs follow.
- [severity medium] [kind risk] The router deadline middleware `path_deadline` returns the empty 408 that `TimeoutLayer` gave, but its byte shape is not pinned by a test, and the middleware is not run under axum in any test. | crates/quarry-edge/src/scrape_actions.rs (path_deadline); crates/quarry-edge/src/routes.rs (router layer) | integration test owed (`router_deadline_is_125s_...`).
- [severity medium] [kind risk] A proxy or front load balancer may cut a 125 s request before the edge answers. The plan marks this [UNVERIFIED]: check the proxy read timeouts in the compose stack, or cap the total wait near 20 s (plan X-20). | apps/Ingestion Plane/docker-compose.yml; apps/Frontend Plane gateway proxy | not verified here.
- [severity medium] [kind decision] `user` and `on` both admit user tokens; `user` additionally refuses service principals. The plan wants `user` used in dev only and not beyond dev until `agent_labelled_user_token_cannot_send_actions` is green on the evidence stack. That test is written as a unit check of `check_principal`, not an HTTP test. | crates/quarry-edge/src/scrape_actions.rs (check_principal, parse_actions_mode) | evidence step; ADR-6 ruling for `on`.
- [severity low] [kind doc] `ENV_SCRAPE_ACTIONS` is read once (OnceLock) like the capture switch, so an integration test cannot change it within one process. Tests that need `user` or `on` must set the variable before the first read or run in a child process. | crates/quarry-edge/src/scrape_actions.rs (actions_mode) | known pattern from WS13.4b; note for the test phase.
- [severity low] [kind bug] A `write` action whose selector is missing is a field error at validation (`selector_required` / `invalid_action`), and the runtime's `selector_of` also returns `selector_required`. Both are correct, but the reason string is shared with a different class of failure in the abort outcome; check the reason vocabulary against `docs/ERROR_REASONS.md` before the docs slice (WS13.8). | crates/quarry-runtime/src/action_runtime.rs (selector_of); docs/ERROR_REASONS.md | the reason table is a docs owner's list; append-only.
- [severity low] [kind doc] `docs/ERROR_REASONS.md` has no entries for `actions_deadline`, `actions_cancelled`, `wait_budget_exhausted`, `wait_too_long`, `scroll_needs_one_target`, `wait_needs_a_target`, `attached_runtime`, `no_browser_session`, `heavy_browser_busy` (the 429 reason), `action_failed`, `scrape_interact_scope_required`, `unsupported_in_stream`. | docs/ERROR_REASONS.md | WS13.8 docs slice.
