# Depth items from W2-U25 (WS10.S3, Quarry trace core: per-run seq, replay ring, resume, gateway events proxy)

Written during the build phase, not fixed (new build strategy, 2026-10-23). Format: severity, kind, what | where | why deferred.

- [severity high] [kind risk] A resumed run (`resume_run_id` after an edge restart) opens its trace at seq 1 again, because the ring lives in memory and does not survive the restart. A client that kept `Last-Event-ID` from before the restart receives events under reused seq numbers and cannot tell them apart. | crates/quarry-edge/src/agent_routes/lifecycle.rs start_run (`open_run(&run_id, 1)`) | the plan's WS10.S4 adds `trace_seq` to the run checkpoint (JSONB state, no migration); that slice is not built. Until then a resume should be treated as a new trace by the client.
- [severity high] [kind other-plane] Agent events still reach NATS JetStream with their raw payload for non-ZDR runs (`publish_event` publishes the minted event as before). The WS10.S4 `is_agent_class` exclusion (D10) that closes this exposure is not built. S3 does not widen it: the ZDR path never reached NATS and still does not. | crates/quarry-runtime/src/nats_event_bus.rs publish_event | WS10.S4 (projection and exclusion), sibling (b) consumers.
- [severity high] [kind other-plane] The SPA has no consumer of `streamBrowserEvents` and no action contract in `src/shared/actions`. The plan says the contract comes before any UI uses the operation; S3 adds the typed reader only, so no contract is needed yet. | apps/Frontend Plane/verevonv3/src/shared/api/browser-client.ts streamBrowserEvents; src/shared/actions | the first UI consumer (WS10.S8 or the browser timeline work) adds the contract in the same change.

- [severity medium] [kind hardening] The ring's byte bound is an estimate (`payload.to_string().len() + key + 192`), not the real heap size of the events. Measure the real memory of a run with a large payload before raising `QUARRY_EDGE__TRACE_RING_MAX_BYTES` or `..._EVENTS`. | crates/quarry-runtime/src/events.rs retain(), RETAINED_OVERHEAD_BYTES | the plan asks for a bounded ring, not a measured one.
- [severity medium] [kind hardening] The gateway forwards the events-stream query string verbatim (`query_suffix`). - [severity medium] [kind hardening] A stream request that races the run's close can hang: `subscribe()` (used when there is no resume point) creates a sender entry with `or_insert` for a run that has just been removed, so the receiver never sees `Closed`. The window is between the registry lookup and the subscribe call. | crates/quarry-edge/src/agent_routes/live.rs agent_events_stream (no-replay branch) | add a `subscribe_if_open` on EventSink that returns None for a run without a trace, and treat None as `done run_closed`.

Harmless at shutdown; a drain that does not exit would leak the ring. | crates/quarry-edge/src/agent_routes/close.rs drain_runs | add `close_run` per drained run when the drain path is changed next.
