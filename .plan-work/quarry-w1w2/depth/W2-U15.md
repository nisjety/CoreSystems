# Depth items from W2-U15 (WS17.P1, monotonic saves, tombstones, exists, migration 0015)

Written during the build phase, not fixed (new build strategy, 2026-10-23). Format: severity, kind, what | where | why deferred.

- [severity high] [kind bug] `create_profile` and the rename path of `update_profile` do not stamp `owner_user_id`: `save_metadata` has no ordering metadata, so a profile created with `POST /v1/profiles/create` gets a NULL owner (a legacy row, which WS17.P2 hides under user_private). The plan text says create_profile takes SaveMeta; the trait does not carry it for save_metadata | crates/quarry-edge/src/profile_routes.rs create_profile; crates/quarry-browser/src/session.rs ProfileStore::save_metadata | widening save_metadata changes every metadata call site; P2 owns the owner rule.
- [severity high] [kind decision] Capture paths stamp no owner: `BrowserLease` (crates/quarry-core/src/lease.rs) carries no actor id, so chromiumoxide `persist_current_page` and kernel `release` pass `owner: None`. A profile whose first row comes from a capture is ownerless | crates/quarry-browser/src/chromiumoxide.rs persist_current_page; crates/quarry-browser/src/kernel.rs release; crates/quarry-core/src/lease.rs | a new lease field touches every BrowserLease literal across three crates (cross-unit); P2 needs it before enforcement.
- [severity medium] [kind risk] `S3ProfileStore` is unordered: `save` ignores `SaveMeta` and reports `Stored { rev: 0 }`, so a zombie session can resurrect a deleted profile on the S3 backend | crates/quarry-runtime/src/s3_profile_store.rs save | S3 is archival; the live path is Postgres. Fixing needs conditional writes or a read-modify-write.
- [severity medium] [kind decision] `POST /v1/profiles` (save_profile) answers 200 with the profile id even when the save was ignored (stale or tombstoned); the caller cannot tell. The plan says log only | crates/quarry-edge/src/profile_routes.rs save_profile | changing the response is an API decision (not in the approved 13).
- [severity medium] [kind evidence] Deployment evidence owed for WS17.P1 (plan detail, rebuild the edge image, `docker logs quarry-edge | grep -i migrat` shows 0015): (1) zombie delete while a run is open leaves 0 rows and one tombstone; (2) two overlapping runs keep the later `saved_at` and count only stored saves in `rev`; (3) the edge logs `profile save ignored reason=stale` | docs/RUNBOOKS.md (W2-U15 section) | needs a stack; forbidden during the build phase.
- [severity medium] [kind test] Postgres tests (postgres_profile_store.rs, 8 new), the Redis cache test (cached_profile_store.rs) and the in-memory tests (session.rs) are written and compile-checked only. The CI job `quarry-postgres-store` is advisory (continue-on-error) | .github/workflows/quarry-v2-ci.yml; crates/quarry-runtime/src/postgres_profile_store.rs | test phase at the end of the wave.
- [severity medium] [kind risk] Clock skew: `saved_at` is the pod clock (capture start), while the tombstone `deleted_at` and the clamp use the Postgres `NOW()`. A pod ahead by up to 5 s is tolerated; further ahead, its captures can outrank deletes it should lose to, or be refused after a real newer save | crates/quarry-runtime/src/postgres_profile_store.rs save and delete | plan-accepted risk; watch the `IgnoredStale` rate after rollout.
- [severity medium] [kind hardening] The cache changed from write-through to invalidate-on-write: each save costs a DEL, and the first load after a save reads Postgres. Measure the restore latency before WS17.E1 replaces the cache | crates/quarry-runtime/src/cached_profile_store.rs save | the plan keeps this until E1; no evidence yet.
- [severity medium] [kind risk] Migration 0015 on a live table: `ADD COLUMN ... DEFAULT 0` on `rev` is metadata-only on Postgres 11+, but `ALTER COLUMN snapshot DROP NOT NULL` takes a brief ACCESS EXCLUSIVE lock. Old pods ignore the new columns during a rolling deploy (a NULL `saved_at` accepts the next ordered save) | crates/quarry-runtime/migrations/0015_profile_ordering.sql | deploy note; check the lock on the first rollout.
