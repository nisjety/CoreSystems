# Depth items from W2-U24 (WS17.P2, owner and ACL enforcement)

Written during the build phase, not fixed (new build strategy, 2026-10-23). Format: severity, kind, what | where | why deferred.

- [severity high] [kind other-plane] Attach path not guarded: a run whose request names another user's profile id still attaches that profile. The plan's P2 table puts the guard in `agent_routes` (profile id block, ~1415-1432). The queue defers that call site to WS8.F, so the guard exists (`ProfileOp::Attach`) but is not called | crates/quarry-edge/src/agent_routes/ (profile id block) | queue row U24 defers it to WS8.F; the agent_routes submodules are one-writer files (H1).
- [severity high] [kind decision] Capture-created profiles stamp no owner. `BrowserLease` carries no actor id, so `persist_current_page` and the kernel `release` pass `owner: None`, and the row is legacy. Under `enforce` such a user_private profile is hidden from everyone | crates/quarry-browser/src/chromiumoxide.rs persist_current_page; crates/quarry-browser/src/kernel.rs release; crates/quarry-core/src/lease.rs | needs an actor field on the lease (a cross-unit type, and H4 serial queue on chromiumoxide.rs); enforce stays off until it lands.
- [severity high] [kind decision] Legacy-owner policy (D16 Q2) is undecided and is not among the approved 13. The code makes two choices that need the owner's ratification: unowned user_private rows fail closed, and unowned org_shared rows keep their owner-only operations open to the org | crates/quarry-edge/src/profile_guard.rs decide(); docs/RUNBOOKS.md WS17.P2 section | product owner. Enforce cannot be promoted until this is decided.
- [severity medium] [kind decision] Org-shared members may save (`Import`) into a shared profile. The plan text lists list, attach and probe for members and rename, rescope and delete for the owner, and does not name save. It is allowed here because an attached run persists its profile | crates/quarry-edge/src/profile_guard.rs decide(); crates/quarry-edge/src/profile_routes.rs save_profile | confirm with the product owner.
- [severity medium] [kind risk] S3 profile backend: `save` (snapshot) does not stamp the owner, only `save_metadata` (create) does, because the S3 store writes the metadata object as JSON. A captured profile on this backend is ownerless | crates/quarry-runtime/src/s3_profile_store.rs save | U15 already notes the S3 store is unordered and archival; confirm the production backend before enforce.
