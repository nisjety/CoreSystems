- [severity medium] [kind bug] The stitch decision is made twice from two layout reads. The runtime asks screenshot_needs_stitch (one getLayoutMetrics, with the viewport's device scale factor, or the lease's when no viewport is asked), and capture_screenshot_on reads the layout again after the viewport override is applied. A viewport override that changes the width can change the content height between the two reads, so the permit can be taken for a page the capture then crops (or the reverse). The permit is released after the capture, so the cost is one wasted lane slot, not a wrong image. | crates/quarry-runtime/src/browser_driver.rs (stitch_permit_for), crates/quarry-browser/src/chromiumoxide.rs (screenshot_needs_stitch) | the fix is to pass the decided plan into the capture; deferred to avoid touching the capture path again in this unit.
