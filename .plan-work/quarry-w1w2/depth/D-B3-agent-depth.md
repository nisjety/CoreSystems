2. D1-009 `search_suggest` has no owner (matrix row still **gap**): D1-072, an owner decision, not this unit's.
3. Delegate lane egress (found while doing D2-019): `attach.rs` builds the delegate's lane with `LaneState::default()`, so its context has no `egress_policy` and an empty `egress_denied`, and `open_tab` is given `from_allowed_domains(attach allowed_domains)` without the run's web-policy deny list. A delegate step therefore runs under the attachment's own allow list only. That is the attachment's narrower grant, but the run's policy deny list is not applied on that lane. The fix is the intersection rule of D2-013 (D-B3-egress-caps owns `tab_control.rs` and `human_browse.rs`); once it lands, the lane's ctx should be seeded with `egress_policy` from it.
4. D2-031 residual: the one action that was already inside the browser when the attachment ended has run. The step now records a failed receipt `attach_released_during_step` and answers 404, which says "outcome not delivered", not "did not happen". If the owner wants "no receipt at all" or a distinct receipt outcome, that is a receipt-contract change (WS12).
