# Depth list, unit W3-B1-03 (E3.6-2, E3.6-3)

Written, not fixed. Each bullet: severity, kind, what | where | why deferred.

- [high] [risk] lopdf's parser recurses on nested arrays and dictionaries; a deeply nested object can overflow the stack, and the inflate budget pre-scan does not count depth | quarry-transform/src/pdf.rs load_doc; lopdf 0.42 parser | a stack overflow aborts the process, so it cannot be a unit test in-process; needs a child-process fixture (WS5 slice 3, doc_parse_child.rs).
- [medium] [evidence] the classifier and the docx total cap are not checked against any real scan or Office file | pdf.rs classify_page, MIN_TEXT_CHARS; docx.rs MAX_DOCX_DECLARED_BYTES | needs the E3.6-10 fixture corpus (B3).
- [medium] [kind] page_has_image does not see images inside form XObjects or inline images (BI/EI); such a page reads as text or empty, so a scan can be missed | pdf.rs page_has_image | needs a content-stream walk; the routing slice decides whether it is worth it.
- [medium] [decision] the text threshold (20 non-white-space characters) and the scanned bias for short text over an image are judgment calls, not measured | pdf.rs classify_page | ratify on the corpus (E3.6-10).
- [low] [bug] page_text_chars counts control bytes from unmapped subset-font glyphs as text; a page whose glyphs cannot be mapped reads as Text and so is not sent to OCR | pdf.rs page_text_chars | rule needs a real subset-font scan to decide.
- [low] [kind] classify_pages parses the document with load_doc; the extraction path parses it again, so routing would parse twice | pdf.rs classify_pages; answer.rs, content_route.rs | the routing slice should share one parse.
- [low] [hardening] no page-count cap: a 25 MB PDF with a very large page tree is classified page by page with no limit | pdf.rs classify_pages | a page budget belongs to WS6 limits.
- [low] [hardening] no compression-ratio check for DOCX parts (declared size against compressed size); only absolute caps | docx.rs extract_text | outside the plan's stated budgets (part, total, count).
- [low] [test] the bomb tests inflate 150 to 300 MiB of zeros; in a debug build this takes seconds each, and the set is repeated in pdf.rs and docx.rs | pdf.rs and docx.rs tests | a shared fixture generator would help once the suite is run at the end of the wave.
