- [severity high] [kind bug] map_routes.rs fetches /sitemap.xml and nested indexes with fetch_text (a String), so a gzip body is lossy UTF-8 and is never inflated; the wiring must fetch bytes and call sitemap::parse_body | apps/Ingestion Plane/Quarry-v2/crates/quarry-edge/src/map_routes.rs ~189-210 | the plan puts this hunk after W2 U33 and U63, so it is not touched in this wave.
- [severity high] [kind test] The eleven new unit tests in sitemap.rs were compile-checked only (cargo check --tests -p quarry-transform, rustfmt --check clean), never run | apps/Ingestion Plane/Quarry-v2/crates/quarry-transform/src/sitemap.rs tests module | build-first rule for this wave; run cargo test -p quarry-transform at the end of the wave.
- [severity medium] [kind bug] parse() matches tags case-sensitively for <url>, <loc>, <sitemap> (only the index detection lowercases), and does not decode XML entities, so a <loc> with &amp; in a query string comes out with the literal entity | apps/Ingestion Plane/Quarry-v2/crates/quarry-transform/src/sitemap.rs extract_inner, parse_urlset | outside the gzip and Sitemap-line scope; needs an XML parser or an entity decision.
- [severity medium] [kind risk] robots.rs still collects Sitemap values unvalidated (no scheme or URL check); sitemap_urls_from_robots exists but has no caller | apps/Ingestion Plane/Quarry-v2/crates/quarry-transform/src/robots.rs ~80 | W2 U63 owns robots.rs; U63 should switch to sitemap_urls_from_robots.

- [severity low] [kind hardening] The compressed input size is not capped in decode_body_limited; the bound is the caller's fetch limit | apps/Ingestion Plane/Quarry-v2/crates/quarry-transform/src/sitemap.rs decode_body_limited | the caller must cap body bytes (rule 2 in docs/SITEMAP_PARSING.md).
