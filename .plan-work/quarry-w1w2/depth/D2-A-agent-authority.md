# D2-A-agent-authority: findings not fixed (2026-10-28)

What was done is in `D2-A-agent-authority-progress.md` and the commits. Open items:

1. Takeover enforcement is observe-only by default. Rules 2, 3 and 4 of the progress file's table (an agent may not step, open, select or close a tab, or send a socket action while a person holds the browser) have a Quarry check, but it refuses only when `QUARRY_EDGE__TAKEOVER_ENFORCEMENT` is on; the default logs `would_reject`. A Model Plane agent drives Quarry directly with a service token and never meets the gateway's 409, so for that path the takeover rule is not enforced until the switch is flipped. The switch was kept off until the planner maps the 409 (WS11). Flipping it is a stack-session step (list B territory) and is not done here. For the decision's check "a capped run can be taken over and the agent's budget is unchanged on hand-back" see the stack session list.
2. Takeover use is metered by the exempted steps and the seconds those steps ran. The wall-clock a person holds the browser without stepping is not metered; the run's budget ledger keeps it (`paused_ms`) but does not expose it, and a takeover that ends by a close or a sweeper release never reaches `resume`. If the X-12 shadow review wants held time, expose `paused_ms` at hand-back as a second histogram. The per-run figure is not a metric label (unbounded); it is the run's `human` receipts.
3. Accepted residual (decision 3.4 and 3.9, recorded, not a defect to fix): an agent on a person's session token (`UserSession` basis) is a person for `set_browser_session_control` (the hint is ignored there), so it can switch to takeover and then step without budget. The same token could open an uncapped interactive run anyway. It closes only when agents always use service principals.
4. Accepted residual: the live-view socket trusts the client frame's `actor`; that is a person's channel (decision 3.9, outside the decision).
5. Gateway `prepare_client_ws_message` / `prepare_client_control_ws_message` (agent during takeover, and the control change on the socket) are `#[cfg(test)]` only. The production proxy (`browser_ws_proxy_loop`) forwards client frames upstream, so those gateway tests pin code that does not run in production. Quarry's socket path is the only live check. Not changed: other plane's tests, no behaviour wrong, but the unit tests give a false sense of a gateway guard on the socket.
6. The delegate lane (an attached agent) reload refusal is covered by the shared `admit_action` and its unit tests, not by a wire test against a live attachment (`attach_cobrowse.rs` would carry it).
7. `CallerClass::ServicePrincipal` and `effective_actor` stay in the gateway as dead code (kept, with the reason reworded) so a future Model Plane to gateway browser path has a place to land. If the owner prefers the dead code removed, it is the enum variant, `effective_actor`'s service arm and the four `None` arguments in `dispatchers.rs`, plus four tests in `browser.rs`.
