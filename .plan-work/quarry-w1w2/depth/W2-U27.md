- [severity medium] [kind risk] `hard_reload` and `reload` are advertised as static capability strings in both gateway projections, so the SPA shows the hard reload button whenever the gateway is new, even if the Quarry edge is old. The plan wants them listed only after the Quarry edge is deployed | apps/Frontend Plane/verevonv3/apps/gateway/src/domains/browser.rs (capabilities in the two session projections) | a config-gated list needs a gateway config field (config.rs and AppState literals are a hot file, H3); deferred to the deploy sequence.
- [severity medium] [kind bug] `run_action` takes the actor from the request body (`body.actor`, default human). The agent refusal for reload therefore depends on the caller saying `actor: "agent"`; a caller can send `actor: "human"` and reach reload. The agent-surface check should use the server-side agent marker, as the takeover check does | apps/Frontend Plane/verevonv3/apps/gateway/src/domains/browser.rs (run_action, reload_refused_for_actor) | the actor trust model predates this slice; changing it touches every browser route.
- [severity medium] [kind hardening] Reload skips the egress guard calls that goto makes (`guard_navigation_target`, `require_configured_egress`). A reload re-requests the current URL under the current policy, but a policy change between load and reload is not re-checked on this path | crates/quarry-browser/src/chromiumoxide.rs (reload) | plan scope says "like back"; decide whether reload should re-run the egress check.
- [severity medium] [kind decision] challenge.rs `gate_of` treats `reload` like `back` (no exhausted-host gate). A reload loop against a host that answers with a challenge is therefore not refused by the challenge gate. The plan allows one reload of the same URL per host | crates/quarry-runtime/src/challenge.rs (gate_of and the blocked-host list) | needs a decision on whether reload counts as a navigation for the challenge budget.
