Unit D-D-B2-go (W2-green, Go: quarry-orchestrator and quarry-control). Everything in the unit's item list is fixed and committed; these are the things found on the way that are not fixed.

| id | where | finding | why not fixed here |
|---|---|---|---|
| D-B2go-001 | quarry-control `GET /v1/internal/schedules/desired` (`desiredSchedulesHandler`), orchestrator `fetchDesired` | The desired read returns one page of at most 500 schedules (`defaultMaxPage`) as a bare array with no cursor, and the orchestrator reads once. With more than 500 schedules in all orgs the rest are never created, updated or paused by the reconciler (the reaper is org-scoped and stays safe: it only reaps for orgs present in the set). | Needs a cursor in the answer (the pg cursor is internal) and a loop in the reconciler; a contract change on both sides. Next unit that touches the reconciler. |
| D-B2go-002 | `docs/RUNBOOKS.md` line about the job timeouts ("Every value is capped at 6 hours and floored at 60 seconds") | After `timeouts.go` changed, the 60 s floor applies to computed defaults only; an explicit `QUARRY_JOB_TIMEOUT_*_S` is clamped to the 6 h ceiling alone (the plan WS15.L2 never specified a floor). The runbook sentence is now wrong for overrides. | RUNBOOKS.md is append-only in this batch. One-word fix: "Every computed default is floored at 60 seconds; an explicit value is capped at 6 hours." |
| D-B2go-003 | `controlCall` in `services/quarry-orchestrator/internal/jobs/control.go` | It tries a bare `json.Unmarshal(data, out)` first and returns nil on success. For an object `out` an enveloped answer ({request_id, data}) also "succeeds" with every field zero, so the envelope branch is never reached. Today its callers pass slices (pending, running), which fail the bare decode and then take the envelope, so nothing is wrong yet; a future object caller would silently read zero values. | Not exercised by any caller; cheap to fix (try the envelope first when `data` is present) when a caller needs an object. |
| D-B2go-004 | quarry-control `GET /v1/schedules` without `org_id` | The legacy unscoped list still answers every org's rows unless `QUARRY_CONTROL_SCHEDULES_REQUIRE_ORG=1`. It has no caller in this tree (orchestrator reads the internal desired route; the edge's list passes `org_id`). The default is unchanged by design (owner order). It can be switched on after the control image is deployed; the existing test now asserts the desired read is unaffected by the switch. Then the legacy branch can be deleted. | Deploy decision, not a code change; compose files do not set the variable. |
| D-B2go-005 | `RegisterScheduledRun` / `PreflightFire` activities | There was no test for either before this unit; `RegisterScheduledRun` now has three (data-converter round trip, path and body, envelope and bare answers). `PreflightFire` has none: it reads a bare answer, which matches the edge's route today (`Json(s2_answer())`), but an enveloped answer would read as `allow: false` and skip every fire. | Needs a small test against a stub; no defect today. |
| D-B2go-006 | `ScheduledJobWF` activity options | `RegisterScheduledRun` runs under `defaultActivityOpts()`; a 409 "schedule is disabled" from control is a non-retryable class only if `errs.FromHTTPStatus` marks it so; not checked. A disabled schedule that still fires (race with the reconciler pause) would retry per the default policy. | Out of the unit's items; check when the live L2 proof for scheduled fires is written. |
