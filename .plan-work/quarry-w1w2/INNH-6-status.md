## The gap
Two independent builds; ship 6a then 6b.
6a SITEMAP: accept sitemap = skip | include | only (Firecrawl vocabulary; absent = skip) and actually seed. The Go activity cannot fetch safely, so add an edge-internal HMAC-bound route (pattern of /v1/internal/run_page: runtime token + x-quarry-run-sig, org in body) `POST /v1/internal/crawl/sitemap {org_id, url, scope, robots, max_urls, zdr:false}` that: fetches robots.txt via the existing RobotsGate and reads `Sitemap:` lines through sitemap_urls_from_robots, falls back to /sitemap.xml, fetches sitemap BYTES through the guarded driver chain (new fetch_bytes; compressed-size cap, SSRF heur, web-policy gate_url), parses with parse_body, follows nested indexes bounded (<=5 children, depth <=2, as map does), requires every sitemap host inside the crawl scope hosts (reject cross-host Sitemap: lines), filters each loc through CompiledScope + robots allow, canonicalises/dedups with canonical_url, caps at max_pages, returns {urls[], discovered, nested_fetched, skipped{out_of_scope,robots,duplicate,cap}}. CrawlJobWF calls a new SitemapSeeds activity behind `workflow.GetVersion(ctx,"crawl-sitemap-seeds-v1")` when params.sitemap is include|only, then enqueues URLs with enqueueChildrenBatch at depth 0 (never one activity per URL: history growth) before the loop; `only` skips seed-link following, `include` unions. Must work in BOTH durable-frontier and in-memory-frontier paths (in-memory keeps the frontier in workflow state, so cap or force durable for large sitemaps). Counts surface in existing run_started/page event payloads (no new EventType per CONTRACTS).
6b SCRAPE_OPTIONS: accept `scrape_options` restricted to the per-page extraction subset of ScrapeOptions: formats limited to markdown|html|rawHtml|links|metadata, only_main_content, include_tags, exclude_tags, remove_base64_images, extractor, timeout_ms; keep `actions`, `actions_on_error`, `screenshot`, `pdf`, `json/summary/...` as 400 unsupported_option on /v1/crawl. Validate at the handoff with ScrapeOptions::from_value/resolve (same FieldError paths prefixed `scrape_options.`), stamp the canonical resolved JSON into job params `scrape_options`, add ScrapeOptions to CrawlJobInput/CrawlInputFromParams and RunPageInput (omitempty so non-crawl bodies stay byte-identical; additive, no GetVersion needed since activity inputs are not replay-compared), extend InternalRunPage with `scrape` (raw JSON re-validated in the edge: defense in depth), and in internal_run_page call run_with_inline_request with CleanOptions from the resolved options. When options are non-default, SKIP the page-cache read and write (routes.rs ~1748: put_with_ttl keyed only by fingerprint would poison later default reads) using cache_admissible(). Note ingest=true pages then feed the CLEANED markdown into Data Plane; document it.
Out of scope: ignore_query_parameters, per-job webhook, crawl results route (INNH-12), actions in crawl.

## Risks
- SSRF/abuse (highest): sitemap and robots `Sitemap:` URLs are attacker-controlled; every fetch goes through the guarded driver chain with heur check and web-policy gate, sitemap host stays inside crawl scope hosts, nested fan-out bounded, compressed + decoded size caps (gzip bomb covered by decode_body), fetch time budget; each loc scope-filtered and robots-checked before enqueue AND again per page in run_page.
- Amplification/cost: a 50k-URL sitemap multiplies fetches; cap at the clamped effective max_pages; only normal quarry.crawl.page metering (sitemap fetches unmetered; decide whether to count one map-like call).
- Temporal: seeds must go through FrontierEnqueueBatch, not per-URL activities nor workflow input (history size); needs GetVersion; the in-memory frontier keeps URLs in workflow state.
- Cache poisoning: non-default scrape options MUST bypass the fingerprint-keyed page cache (key quarry:page:{fingerprint}; org segment present since WS4.K per INNH-7 reading, verify) or later default requests receive differently-cleaned markdown.
- Ingest semantics: Data Plane gets cleaned markdown with ingest=true; document it.
- ZDR: crawl refused under ZDR; the new internal route declares zdr:false only and must be classified in the ZDR matrix.
- Options: include_tags/exclude_tags are CSS selectors parsed by the cleaner (cap count/length, reuse scrape validators); timeout_ms must stay under the activity timeout.
- Drift/skew: SDKs and gateway (other session) must not forward unvalidated scrape_options; hot spots workflows.go, store.go, routes.rs (plan E3.7 risks, R-20 merge order). An old edge ignoring `scrape` would crawl with default cleaning silently: gate by the edge flag AND have the edge echo `applied_options` in the run_page response so the workflow can fail the run like edgeScopeUnsupported does for scope. The new edge must tolerate an old orchestrator.
