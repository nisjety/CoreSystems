#### Security self-review (one pass over the MP-3 diff)
- Who reaches the key routes: only `PrincipalKind::ApiKey` passes `require_api_key`; users and services reach the handler (the user fence is unchanged) and get 403 before any broker call (tested both routes). A key reaches nothing else: `authorize_principal_route` is an allow-list on method + concrete path + scope, proven over every route in the source and mutation-checked. The gRPC surface refuses the type (no arm; tested).
- Identity confusion: a `key_id` on a user/service token is refused (401), so no token is both. `principal_type` absent defaults to user and is refused when `key_id` is present. `api_key_id()` returns only for a fully valid shape. `require_user` refuses `api_key` (tested on issue and renew).
- Bearer binding: the broker bearer is a separate type, inserted only from the api_key arm of `require_auth`, only on the two routes, and only for the same `sub`/`org_id`/`key_id`/`acting_user_id` and posture. The dev bypass never mints it. A key cannot carry any other delegated bearer, so no user-bound downstream authority can be presented under a key.
- Body and widening: `deny_unknown_fields` closes `kind`, `mode`, `read_only`, `org_id`, `parent_grant_id`, `allowed_*` (tested); `grant_kind` is always empty; the org is the token's; hosts/budget/TTL are bounded here AND by the broker against the signed ceilings; the TTL can only shorten. No renew route for keys (the renew route is user-only).
- Broker answer: a grant not stamped with the caller's key (empty from an older broker, or another key), or not a session/allowlist grant, is revoked and refused (502), so a confused broker never hands out a foreign grant. DELETE never says whether an id exists (204 for OK and NotFound).
- ZDR: posture decided through `zdr_posture::decide_for` on the key token (named entry point); the pair must agree; hosts omitted from the response under ZDR; grant id and key id not logged under ZDR; no host is logged or echoed in any error; the broker's message is never echoed.
- Left open (DEPTH): per-key rate bucket; key token lifetime not bounded at the gateway; 429 cannot tell per-key from owner cap; the fence test reads only literal route paths.
