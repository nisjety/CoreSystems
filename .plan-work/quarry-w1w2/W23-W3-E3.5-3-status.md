## Assumed decisions

1. Shape: Firecrawl-like `webhook` as a URL string or `{url, events}`; `headers` refused (a caller does not choose what control sends), `metadata` not built.
2. Events are Quarry's stored event types of the job's run (run_* and page_fetched/page_failed), not Firecrawl's `crawl.page` names; default = the terminal events.
3. Signing: per-job secret derived from a control key and (org, job), not stored, shown once on create; same header and HMAC format as subscription deliveries, so one verifier serves both.
4. ZDR jobs may not carry a per-job webhook (delivery rows keep payloads; ZDR must propagate through content-persisting boundaries).
5. The edge does syntax and literal-address checks only; DNS-resolved SSRF vetting stays in control (and the dispatcher's pinned dial), as for subscriptions.
6. A control-side twin flag (`QUARRY_CONTROL__JOB_WEBHOOK`) beside the named edge flag, matching `QUARRY_CONTROL__WEBHOOK_SUBSCRIPTIONS`.
