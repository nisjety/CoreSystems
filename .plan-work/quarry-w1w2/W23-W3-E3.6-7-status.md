## Built

- `DocumentLaneSettings { ocr, pii_model }`, default both off; `from_values` / `from_env` read `QUARRY_EDGE__OCR` and `QUARRY_EDGE__PII_MODEL` through `org_erasure::flag_on` (1/true/on/yes). `ModelPlaneClient::with_document_lanes`, `with_document_timeout` (default 120 s), `document_lanes()`.
- `OcrPagesRequest::for_scanned_pages(pdf, pages, locale)`: base64 body, `content_type: application/pdf`, pages 1-based, sorted, deduplicated, `"2,5,7"`; refuses an empty PDF, no pages, page 0, more than 20 pages (`MAX_OCR_PAGES_PER_CALL`), more than 16 MiB (`MAX_OCR_DOCUMENT_BYTES`). Debug prints the size, never the document.
- `ocr_pages_for_org(org, zdr, req)` -> `POST /v1/ai/documents/layout` (prebuilt-layout). Fails closed: a status other than `succeeded` (or empty), `pages_processed` below the pages asked, or blank `content` is `Unusable`.
- `pii_model_for_org(org, zdr, texts, language)` -> `POST /v1/ai/language/pii`. Input bounds: 1..=25 texts, each non-blank and at most 5120 chars. Reads only `redacted_text`, never entity offsets. Items are matched by the gateway's 1-based `id` ("1".."n", inference-core language.rs); a wrong count, unknown, duplicated or missing id, or an empty/absent `redacted_text` is `Unusable`. Results come back in input order.
- `DocumentLaneError { Disabled, ZdrRefused, InvalidInput, Hop { lane, hop: ModelHopError }, Unusable }`: no variant carries text, so a caller can never pass the input through on failure.
- Order of refusals: flag, then ZDR, then input bounds, then credential: all before anything is sent or minted. Credential follows `chat_for_org`: only the static dev pair (`with_bearer_token` + optional `with_inference_bearer_token`, sent as `authorization` and `x-inference-authorization`); `Dynamic` and no credential answer `Hop { LaneNotGranted }`. No `ServiceTokenRequest` manifest lookup is added (so `token_request_contract.rs`'s source scan is unaffected).
- Retry rule as the chat lane: a connect error, 502 or 503 once; a timeout never. Body capped at the chat lane's 4 MiB.
- Refactor: the chat lane's status table moved to `hop_status_error(status, headers)` and is shared (behaviour unchanged).
- Tests (wiremock fake gateway, in `mod tests`): flags default off and parse; OCR request sorting and every bound; OCR off / ZDR / no credential send nothing (`expect(0)`); OCR happy path checks route, both headers, `pages`, `content_type`, `locale`; OCR fails closed on short pages, blank text, `failed` status; 403 -> RouteDenied, 503 retried once (`expect(2)`) -> Upstream 503, non-JSON 200 -> Decode; PII off / ZDR / bad input send nothing; PII reorders by id; PII fails closed on count, unknown id, duplicate id, empty and absent `redacted_text`; gateway 412 -> `ZdrRefused`.

## Assumed decisions (owner said stop asking)

1. The PII model tier gets its own flag `QUARRY_EDGE__PII_MODEL` (default off) rather than riding on `QUARRY_EDGE__OCR`: they are separate third-party processings with separate routes and grant rows. Alternative: one flag for both.
2. OCR route = `POST /v1/ai/documents/layout` (plan E3.6 scope names it), not `/v1/ai/images/ocr`.
3. The PII model tier is a second pass on text the deterministic `pii.rs` stage already redacted (plan E3.6 "model tier second"); Quarry uses only `redacted_text` because offsets are unverified (W3-B1-02 depth row).
4. ZDR is refused locally for both lanes regardless of what the gateway would do (plan E3.6 "OCR and the PII model never run under ZDR"). A gateway 412 maps to `ZdrRefused` too.
5. Fail closed = typed error with no text; the caller makes it a failed page (approved E3.6-4 fail-closed decision). `pages_processed` below the asked page count is a failure (a short answer cannot be told apart from a partial one).
6. Bounds: 20 pages and 16 MiB per OCR call, 25 texts of at most 5120 chars per PII call, 120 s timeout. Per-org OCR page caps are WS6 and not built here.
7. Only the static dev credential works, like `chat_for_org`; the Dynamic path waits for the DR-15.1 grant (no manifest rows added, nothing minted).
