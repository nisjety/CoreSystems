## Behaviour

- A `fill_otp_ref` step marks the page it ran on (its landed URL, else the last observation's URL), succeeded or failed (a failed insert may have left part of the code: fail closed, as `otp_source::deliver_otp` marks on insert failure). Its own observation is denied.
- Denied observation: snapshot targets and accessibility, DOM summary, screenshot / visual / evidence-delta artifact ids (also removed from `proof_bundle.artifact_ids`), proof content fingerprint (a short code is guessable from a hash), observation delta, extraction result, console lines and challenge evidence are dropped; URL, title, frames, dialogs, outcome and telemetry stay. `policy_denials` gets `OTP_READ_DENIAL` (once), the stamp counts one `otp.credential_delivered` and a present screenshot is stamped `withheld`. The stored receipt keeps this observation, so it carries `[redacted:otp]`, never the code.
- A pure read (`screenshot`, `pdf`, `get_content`) of a marked page is refused before it runs: 403 `FORBIDDEN`, `details.reason = otp_credential_delivered`, no step key, no receipt (same as the download gate's pre-run refusals).
- "Until navigation": the mark of a page ends when a new document is loaded for it: `reload`, or `navigate` to it (not a fragment-only navigate on the same page). Landing on another page is not denied; returning to the marked page by `back`/`forward` (or a click) is still denied (bfcache can restore the field). Marks are per run; `release(run)` forgets them.

## Flag and default

No new flag. The only trigger, `fill_otp_ref`, is admitted only while `QUARRY_EDGE__FILL_OTP` is on (default **off**), and the runtime executor still answers `Unsupported`; the denial itself has no off switch (it only withholds more, a leak guard).

## Assumed decisions

1. Page identity is the URL without fragment (the edge cannot see loader ids through `Arc<dyn BrowserDriver>`); the browser's E3.1-c per-loader mark stays the precise signal for a later driver trait method (D-E31c-1).
2. Navigation that ends the denial = `reload` or `navigate` to that page; back/forward and clicks do not end it (fail closed for bfcache and SPA routes).
3. A failed `fill_otp_ref` that reached the runner also marks (fail closed). Refusals before the runner (admission, flag off) do not.
4. Pure reads are refused before they run (not run and stripped) so no PDF or screenshot artifact of the page is stored; other actions on the page still run, their observations are stripped.
5. The process-wide registry lives in quarry-runtime next to the redactor so any step path can share it; marks are bounded (16 pages per run) and cleared on navigation; run close does not call `release` yet (outside this unit's files, depth row).
