## Traps and findings (not fixed here)

1. `FilesystemStore` does not override `list`, so `GET /v1/artifacts` is always empty on the fs backend (the trait default). A "list does not grow" check on fs proves nothing: use the in-memory backend or count files.
2. The live example.com (2026-10-18) has no `<h1>`, only one `<p>`. `include_tags:["h1"]` therefore matches nothing and warns, which is correct. Baseline markdown on it has no title either (the title is in `metadata`).
3. Full-page markdown (`only_main_content:false`) of the Rust article on Wikipedia is 30,875,117 bytes from a 1,054,920 byte page: the markdown tables are padded, with lines up to 1,123,170 characters. That is over the 8 MB inline ceiling, so even `max_inline_bytes:8000000` returns `omitted:["markdown"]`. Probably the table-alignment padding of the converter; worth a separate look (WS5.E).
4. The SSRF guard has no environment switch for private hosts: `with_allow_private_hosts` is only used by tests, and `blocks_private_host` runs before the allowlist. To serve the bomb without a code change the test server got an address that the guard classes as public (`11.250.0.10` on a private bridge, `docker network create --subnet 11.250.0.0/24`), so the traffic never left the host.
5. A docker named volume is root-owned and the edge runs as uid 65532: the fs backend gives `500 INTERNAL ... Permission denied` until the volume is chowned (`docker run --rm -v vol:/data/artifacts --entrypoint sh python:3.12-slim -c 'chown -R 65532:65532 /data/artifacts'`).
6. Git Bash rewrites `-e X=/data/...` and `-w /www` into `C:/Program Files/Git/...`: set `MSYS_NO_PATHCONV=1` for docker commands with absolute container paths.
7. Dev bypass org is `org_placeholder`; the live frame endpoint takes `format`, `timeoutMs` and returns `dataBase64`/`mimeType` (camelCase); the live frame of a mobile dsf-2 run is 390 px wide (CSS px), the screenshot step artifact is 780 px (device px).
8. The agent run was closed by the edge right after the navigate timeout in check 6 (`page_close`/`context_close` lines directly after `op:navigate`); not investigated whether that is by design.
