## Flag and default

`QUARRY_EDGE__HIT_TEST`, **default off**, read per call from the environment (1, true, yes, on turn it on; `parse_hit_test_flag`). Off: `403 hit_test_disabled`. On: the route is reachable but answers `501 unsupported` until ask 1 lands, so nothing live changes at merge. The CDP reads are read-only, so the flag gates exposure, not a write.

## Assumed decisions

1. Shape: `GET` with `x` and `y` query parameters in CSS px from the viewport's top-left. Nothing is written, so no body and no POST. CDP takes whole pixels, so a fractional point rounds to the nearest pixel (D-E33h-6).
2. The route answers from the person's lane (`human_lane`), with that lane's last observation as the snapshot. Agent (attachment) lanes are not consulted.
3. Bound: both reads use `Op::AxSnapshot` (10 s, effect-less, so a timeout is retryable). No new `Op` was added to `deadlines.rs`, which is outside the file set.
4. The ref is the nearest observed target on the hit node's accessibility chain, not only an exact node match. A click lands on a text span inside a button, so an exact match would miss most buttons.
5. ZDR allowed: nothing is stored or logged by the route or the primitive. `name` (the AX name, which is page text) goes back to the same caller, as the observation already carries it under ZDR.
6. API-key principals: when the API-key route fence is on (`QUARRY_EDGE__API_KEY_AGENT_RUNS`), the route is refused, because it is not on the allow-list in `api_key.rs` (default deny). Intended, because this is a person's view tool. The allow-list test pins only the listed routes, so it is unchanged.
7. The route does not add a frame marker. A point over a cross-origin iframe returns that frame's `@e` ref, which the runtime refuses for ordinary refs (fail closed; `SnapshotTarget.frame_id` doc). Recorded as D-E33h-4.
8. `Accessibility.enable` is called in the second read, as `native_page_projection` does, so the page is in accessibility mode as the observation leaves it.
9. Errors: a `driver_err` maps the browser error with the existing redaction; no new error text carries page content.

## Asks (outside this unit's files; not made)

1. **Required; the route is dark without it.** `quarry-browser/src/lib.rs`:
   - In `trait BrowserDriver`, after `native_page_projection`, a default method: `async fn hit_test_point(&self, _session: &BrowserSession, _x: i64, _y: i64) -> QuarryResult<Option<BrowserPointHit>> { Err(QuarryError::unsupported_action("hit_test")) }`.
   - A type outside the `chromiumoxide` feature gate (the trait cannot name a gated type): `pub struct BrowserPointHit { pub backend_node_ids: Vec<i64>, pub frame_id: Option<String> }`, with `Debug, Clone, PartialEq, Eq`.
   - `chromiumoxide.rs`, in `impl BrowserDriver for ChromiumoxideDriver`: an override that calls the inherent `self.hit_test_point(session, x, y)` (inherent methods win in method-call syntax) and maps `PointHit` to `BrowserPointHit`.
   - `hit_test.rs`: `point_hit` becomes `Ok(state.agent_driver.hit_test_point(session, x, y).await?.map(|hit| PointHit { backend_node_ids: hit.backend_node_ids, frame_id: hit.frame_id }))`, then the rest of the route is unchanged.
   Same shape as the E3.3-e1 ask for `target_box`; one lib.rs change can carry both.
2. **Recommended.** `quarry-runtime/src/observation.rs`: a public accessor on `ActiveSnapshot`, for example `ref_for_backend_nodes(&self, chain: &[i64]) -> Option<&SnapshotTarget>` (nearest first). The route then stops parsing `fingerprint_id`, and the backend id can leave the public fingerprint (D-E33h-1).
3. **Docs, not built.** `quarry-core/src/zdr_matrix.rs`: classify `/v1/agent/runs/{run_id}/hit-test` in a row (the `agent_run_surface` row is the natural home; the golden and the markdown regenerate). `docs/openapi.yaml` and the SDK: a route entry, `ref` documented as an observed snapshot ref.
