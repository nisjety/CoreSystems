## What exists (NOT ACCEPTED, and the existing cache cannot serve a "max age" read)
REQUEST SIDE: `max_age` / `maxAge` is not a field of ScrapeRequest (`crates/quarry-edge/src/routes.rs:451-499`) nor in ScrapeOptions OPTION_KEYS (`crates/quarry-core/src/scrape.rs:418-429`, 10 entries) nor REQUEST_KEYS (`scrape_contract.rs:36-48`, 11 entries). Sent today it is an unknown key: lenient mode ignores it with `warnings[] unknown_field` + `effective_options.ignored_fields` + `Deprecation: true` (scrape_contract.rs:205-227, 261-288; routes.rs:592-601, 657-662); strict mode (QUARRY_EDGE__SCRAPE_REQUEST_VALIDATION=strict) returns 400 unknown_field.

CACHE POLICY: `quarry_core::cache::CachePolicy` (cache.rs:5-33) = {mode, max_age_s: u32, vary_on, stale_while_revalidate_s}; `ScrapeRequest.cache: Option<CachePolicy>` (routes.rs:457). Only `mode` and `max_age_s` are read: `should_read`/`should_write` (routes.rs:58-70) and `effective_ttl` (72-77), where `max_age_s` is the TTL of the WRITE (`put_with_ttl`, routes.rs:814-822, default DEFAULT_TTL_SECS 3600 at edge cache.rs:22). `vary_on` and `stale_while_revalidate_s` are read nowhere. BUG: `CachePolicy.mode` has no `#[serde(default)]` (cache.rs:7), so `{"cache":{"max_age_s":60}}` fails deserialization -> 400 `invalid_request` (routes.rs:564-573) although openapi.yaml:6727-6740 documents default read_write.

READ PATH: the page cache is read ONLY when the caller supplies `prev_fingerprint` (routes.rs:678-688): PageCache key `quarry:page:{org}:{fingerprint}` (edge cache.rs:40-46, org segment since WS4.K, proven by cache_policy.rs:417 `page_cache_is_not_readable_across_orgs`). A fingerprint is a hash of the raw body, so a caller can only hit the cache after already fetching the page; no URL -> result lookup. A hit returns `ScrapeResponse::from_output(cached)` with no inline text (routes.rs:681-686) and does not meter. `cache_state` hit|miss|bypass is in effective_options (scrape.rs:1037-1046, routes.rs:645-654, 839). Age computable from NormalizedOutput.fetched_at (output.rs:14).

ADMISSION: cache read/write only for default options (`is_default` scrape.rs:980: no named formats, no tags, readability extractor, no captures/actions), static/non-browser plan, default web policy, non-ZDR (`quarry_core::zdr::guard(zdr, WriteKind::Cache)`, routes.rs:673-676). Any Firecrawl-style request naming `formats:["markdown"]` (as the Innhenting playground does) bypasses the cache entirely; `max_age` would be useless unless that changes.

PRE-BUILT BUT UNUSED: `ResolvedScrapeOptions::canonical_options_key()` (scrape.rs:1000-1034) and `cache_admissible()` (993) were written for "a URL-keyed result cache: quarry:scrape:{org}:{blake3(url, key)}" and are used only by their own unit tests (1336-1361, 1479-1503, 1395, 1450); `fingerprint(url, vary, js)` at edge/cache.rs:123 is `#[allow(dead_code)]`. `quarry-transform/src/canonical_url.rs` (W3-B1-04, `canonicalize`, line 86) exists for URL normalisation.

DOCS/PLAN: `docs/GAP.md:61` claims "maxAge cache control ... Equivalent" (false; plan line 3462 lists it as CLAIM-FALSE to correct). Existing Redis-gated cache tests: `crates/quarry-edge/tests/cache_policy.rs` (read_write second call 163, bypass 224, write_only 285, max_age_s=0 default ttl 350, cross-org 417, non-default options bypass 510, browser signals 603, honest prior_block 693, default options 788, ZDR 850). ## Contract change
REQUEST (additive, POST /v1/scrape): `max_age` integer milliseconds, alias `maxAge`, 0..=2592000000. Absent: no change. 0: skip the read, still write. N>0: return a stored result for the same org + canonical URL + effective options if at most N ms old, without fetching.
RESPONSE (additive): on a hit `data.effective_options.cache_state: "hit"`, `cached_at` (RFC 3339), `cache_age_ms`; `data.fetched_at` is the ORIGINAL fetch time; inline markdown/html/raw_html present when asked (rebuilt from artifacts); `scrape_id` absent on a hit unless decided otherwise. On a miss `cache_state: "miss"` (today `bypass` unless prev_fingerprint sent). Under ZDR `cache_state: "bypass"` and warning `max_age_ignored_zdr`.
ERRORS: 400 `details.fields[] {path:"max_age", code:"out_of_range"|"invalid_type"}`; with the kill-switch off, 400 `feature_disabled` at `max_age` (consistent with captures/actions) rather than a silent ignore. `cache: {max_age_s: N}` without `mode` becomes valid (default read_write).
Distinction to document: `cache.max_age_s` = write TTL in seconds; `max_age` = read freshness in ms; Firecrawl clients use only `max_age`.

## Risks
- ZDR: cache never read or written and no URL-derived key (even hashed) stored for a ZDR request (plan ADR topic 4: "URL cache and verdicts refused under ZDR, never hash-only"); the token's ZDR floor (`claims.effective_zdr_mode`) drives it, not the body; guard is `quarry_core::zdr::guard(zdr, WriteKind::Cache)` (routes.rs:676); add matrix row and test.
- Tenant isolation: org id in the key; empty org never a key; canonical-URL collision across orgs must miss (cross-org test).
- Stale/poisoned content: only 2xx non-challenge default-policy results written; challenge/bot-wall pages and soft-404s must not be cached (check the write site is after the challenge gate, scrape path WS3.J); monitors and agent runs must never be served from it.
- Policy bypass: a hit must still pass the web-policy URL gate first (routes.rs:640 gates before the cache read) and honour per-request policy tightening (keep `web_policy_edge::is_default(&decision)` in admission). Exclude profile_required/session/cookie/headers/actions requests.
- Option explosion: keying by options widens memory use; rely on TTL (default 3600 s). `max_age` larger than the TTL silently behaves as the TTL (entries expire at write TTL): document and return `cache_state: miss`.
- Billing: hits not metered (routes.rs:681-686); metering them is a product/billing decision (owner).
- Cost: positive (saves fetch/driver cost) but artifact rehydrate adds an artifact-store read per hit; an expired artifact must degrade to refetch, never 500.
- Compat: widening admission changes `cache_state` from bypass to miss for option-bearing requests only when `max_age` is sent.
- Tests need a real Redis; Docker is not running, so proof is a build-time task with a throwaway redis:7-alpine.
