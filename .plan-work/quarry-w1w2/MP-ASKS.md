## Lane C batch 3, E3.2-e1 (broker origin-extension grant kind, OD13), flag off

- **Quarry (Ingestion), Q4:** when an `origin_extension` grant validates, widen the run's egress policy through `configure_egress_policy` with exactly its `allowed_domains`, and only while ValidateGrant keeps answering OK for that grant id. Hard rules the broker enforces and Quarry must not weaken: the extension is a CHILD of the run grant (`parent_grant_id` must equal the run grant Quarry holds; reject otherwise), hosts are exact (a listed host covers itself and its subdomains, the same as `allowed_domains` of a session grant, no wildcard), at most 8 hosts across one parent, and it dies with the parent. An unknown `kind` must be treated as not valid (the proto already says so). Vendor `consent_scope = 21` (string) on `ValidateGrantResponse` and `AcquireGrantResponse` and `consent_scope = 21` / `consent_denied_domains = 22` on `AcquireGrantRequest` into `crates/quarry-runtime/proto/browser.proto` (numbers verified free upstream, F-t2-032 band 21-39). Deny beats approval at Quarry too: its `denied_domains` for an extension are hosts the person or the org refused, never to be re-added. No wildcard until counsel approves the consent pattern language (`grant.ConsentPatternLanguage`, constant `ConsentPatternLanguageApproved = false`) AND Quarry's `BrowserEgressPolicy` changes in the same reviewed change as the broker's `isCanonicalDomain`.
- **Control Plane user-core (E3.2-e3):** the `browser_consent` category in `user_settings` is where "always" and "conversation" consents persist; the broker stores only the scope label (`turn` / `conversation` / `always`) on a grant that lives at most as long as its parent. Decision records must carry host names, so for a Zero Data Retention org only scope `turn` may be offered (the broker refuses the rest).
- **Control Plane registry / principals:** the extension is issued to a signed-in USER principal only (`AcquireGrant` with `grant_kind = "origin_extension"`; a service principal is refused in `authz.Authorize` and at the handler). The gateway/BFF must therefore mint the call with the user's `aud=browser-broker` token; no `plane-service-principals.json` row is needed or wanted for it.
- **Ops:** `BROWSER_BROKER_ORIGIN_EXTENSION_ENABLED` (compose default `0`; on only for `1`/`true`/`on`). Migration `0006_browser_grants_extension` applies on broker start (idempotent) and adds `consent_scope`; the broker image must be rebuilt with it before the flag can matter.
