## Assumed decisions

- The browser-side insert and the credential-delivered mark are behind a runtime trait (`OtpFillTarget`) instead of new `BrowserController` methods: E3.1-c (lane a) owns `chromiumoxide.rs`/`actionability.rs` and the quarry-browser trait is outside this unit, so the helper compiles without them. The executor adapter wraps the E3.1-c resolved target.
- If the trusted insert fails, the loader is still marked credential-delivered (part of the code may be in the field: fail closed), and the insert error is returned.
- The code is dropped (zeroed) before the mark; the only log line is `info` with outcome, loader id and grant id.
- Code shape 4-10 ASCII letters/digits; anything else is `BadRequest` with `details.reason = otp_code_shape`, value never echoed.
- Stub: unknown mail connection is `NotFound`; codes are not single-use in the stub (single use is the E3.1-ab approval-grant set's job).
- Fixture code `482915` is a public fixture value, not a secret (gitleaks passed).
