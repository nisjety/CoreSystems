## Flag and default

`USER_CORE_BROWSER_CONSENT`, default off (only `true`, case-insensitive, turns it on; read once at route registration). Off: all three routes answer 404 `browser_consent_disabled` before touching the store. Migration 044 is not flag-gated: its policy is a no-op for every path that does not set the GUC.

## Assumed decisions

1. Fence numbers from DEC-19 / OD13: start host plus at most 8 hosts here (the broker/Quarry cap of 32 is theirs); private/loopback never grantable.
2. One decision per (startHost, scope, conversationId, turnId); a new PUT with the same key replaces. Deny-beats-allow is evaluated by the broker/Quarry, not here.
3. A deny decision names only its start host (listed hosts refused) to keep its meaning unambiguous.
4. Hosts are canonicalised (case, trailing dot) rather than refused; anything else non-canonical is refused. Internationalised names must arrive as punycode (no IDNA library added).
5. RLS shape copies org-core 008 (permit when the GUC matches or is unset) over the whole table, with FORCE so the owner connection is bound; stricter deny-when-unset is a later step.
6. Store reached via a method on `AclRepository` (same DB handle) because `cmd/server/main.go` and `service.go` are outside the unit's file list.
7. Audit goes to `user_activity_log` in the same transaction, with host digests only (that table outlives an anonymize erasure).
8. ZDR: not enforced here (turn-only rule lives in Quarry/broker per the queue row).
