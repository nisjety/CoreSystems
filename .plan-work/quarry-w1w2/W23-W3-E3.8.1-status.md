## Flag and default

- `QUARRY_EDGE__FETCH_SUB_CODES`, default off. `1`, `true` and `on` (any case, surrounding blanks ignored) turn it on; any other value, or none, is off.
- Off: no runtime change. `settle_chain_error` returns the error as the tiers left it, so the envelope is the same as HEAD for every error. The only new output is one `quarry.fetch_sub_codes` info line at the first FallbackDriver construction.
- On: a DRIVER_FAILED that leaves the waterfall with no typed reason gets `details.reason = all_drivers_failed` (retryable false, as before) or a sub-code if the tiers agree on one (none does today). Nothing else changes.
- No compose line was added (`apps/Ingestion Plane/docker-compose.yml` is a shared anchor and not in this unit's list).

## Assumed decisions

1. Retryable per reason: `dns` true; `connect` true (matches the code-level true that UPSTREAM_BLOCKED carries for connect failures); `tls` false (a repeat of the same driver cannot change a certificate or a handshake, and a different TLS profile is the next tier's job); `all_drivers_failed` false (every tier has been tried, and a straight repeat will not help; matches DRIVER_FAILED's code-level false).
2. `dns` covers NXDOMAIN as well as resolver faults, because a tier cannot tell them apart. The doc says one or two retries at most.
3. Chain rule: the reason is the sub-code that every attempted tier failed with, if they all agree and every attempt ended in a tier error. An attempt that ended otherwise (a block status or a body the chain moved on from, a JS shell, a tier not in the registry) gives `all_drivers_failed`. The unregistered-tier case is the conservative choice (see depth row 5).
4. Only DRIVER_FAILED is settled. TIMEOUT, UPSTREAM_BLOCKED, SECURITY_BLOCKED and the rest keep their codes and get no reason from this unit. The deadline budget and its own sub-codes are E3.8.2.
5. A typed reason a tier already gave (`action_failed`, `session_reaped`, ...) is never overwritten. dns, tls, connect and all_drivers_failed are the only reasons a chain stamps.
6. The flag is read once per process in `FallbackDriver::new` and `from_plan`, the way `QUARRY_BLOCK_ESCALATION` is. Tests pin it with `with_fetch_sub_codes` and never set the environment.
7. Go is a mirror only. `FromHTTPResponse` still maps every DRIVER_FAILED 502 to `CategoryServer5xx` (retryable), so Temporal keeps retrying `all_drivers_failed` and `tls`. Changing that changes crawl behaviour, so it is left to the owner (ask 6).
8. The Rust vocabulary is the source. The Go strings and flags copy it, and the Go test pins the same list.
