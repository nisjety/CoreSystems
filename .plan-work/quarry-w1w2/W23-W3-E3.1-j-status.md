## Assumed decisions

1. The evidence is a verifier over a run the user drives and approves in the UI, plus two local stand-ins: the recorded mailbox and the https login fixture. The script never signs in, never approves and never sets a flag.
2. "Recorded mailbox" means a replay stub for the Microsoft Graph inbox read and the Gmail list and get. It serves the shapes integration-corev2 parses (`mail_otp.go`, `gmailHeaderMap`, `extractGmailMessageBodies`). IC reads only those two providers, and their base URLs are configurable (`MICROSOFT_GRAPH_BASE_URL`, `GOOGLE_API_BASE_URL`; defaults in `config.go`).
3. The stub re-dates each message per request (age 30 to 540 s), so the window in `executeMailOTPRead` (default 600 s) holds.
4. The code comes from the recording's `fixture_code`. It is never printed. The scan looks for it as a whole digit run and as a 3+3 split by a space or a hyphen, the two forms IC reads.
5. Receipts are the evidence source (`GET /v1/agent/runs/{id}/receipts`). A ZDR run stores none, so the evidence org is non-ZDR.
6. Login success is judged from the fixture's own access log (303 on POST, 200 on GET /dashboard). The post-fill page URL in receipts is stripped for ZDR and by E3.1-e, so it cannot be used.
7. Service logs come from commands the operator supplies (`LOG_CMD_*`). Each whole log goes to a private 0700 folder, is scanned, and is deleted at exit. No receipt, log or token is kept.
8. The fixture markup and the 303 and 401 behaviour are copied by hand from `test_site.rs`. The Rust site is in-process only.
9. The audit check is a presence check in the integration-core log only. Otherwise it is NOT-RUN, because the audit goes to the events publisher (NATS in production).
10. The ambiguous-page leg is optional (`RUN_ID_AMBIGUOUS`).
11. Paths: node gets Windows-form paths (`cygpath -m` under Git Bash). curl gets the header file as `@C:/...`. Default ports 18080 (mailbox) and 18443 (fixture), bind 127.0.0.1.
12. Line endings: `*.sh` is LF by `.gitattributes`. The runbook and this file are CRLF in the working tree, like the other docs in this checkout.
13. (Finish pass) One commit for script and runbook instead of the three planned ones: the unit is one deliverable and the depth file already went with E3.1-i.
