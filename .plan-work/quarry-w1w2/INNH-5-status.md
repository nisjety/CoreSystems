## The gap
Storage, dispatcher, retries and signing are done; what is missing is a tenant-safe subscription layer. Build only:
1. TENANCY. webhooks has no org_id and fanoutWebhooks is global: today any active webhook with events=[] or '*' would receive EVERY org's events (change_detected payload includes source_url and fingerprints; job events include page URLs). Harmless only because no tenant route can create one. Add org_id to webhooks (and deliveries), resolve the event's org (change_detected: payload.org_id; run/page events: db.Jobs().Get(ev.JobID).OrgID) and deliver only to that org's subscriptions; legacy rows with org_id='' deliver to nobody (fail closed).
2. ORG-SCOPED CONTROL ROUTES with a different path from the internal CRUD: POST/GET/GET{id}/DELETE (+ optional PATCH active/events, POST {id}/rotate-secret, POST {id}/test, GET {id}/deliveries) on /v1/webhook-subscriptions?org_id=. Create generates the secret server-side (32 random bytes, 'whsec_...'), returns it exactly once, never on read (short id/last-4 only). Validate URL: https only, no userinfo, no fragment, length cap, reject private/loopback/link-local IP literals and localhost via egress.Guard.ResolveAndVet (dial-time pinning already protects delivery; create-time check is UX and defense in depth). events allow-list v1 = [change_detected] (closed vocabulary; run_completed/failed/cancelled can be added for INNH-13 later without a contract change); per-org cap (e.g. 10 active).
3. Retire or lock the legacy unscoped CRUD (410 like MountBlocklistsGone, main.go ~198) so nothing can create an org-less subscription.
4. GDPR: `store/gdpr_purge.go:28` and `pg/gdpr_purge.go` exclude webhooks/webhook_deliveries ("shared/global"); with org_id they become org data and must be purged by org erasure; delivery rows hold the full event payload so add a retention bound (delete success deliveries after N days).
5. EDGE PASSTHROUGH routes (user token, org from claims, service principals refused by require_service_route_scope default) forwarding to control via control_client::get_json/send_json (send_json is `#[allow(dead_code)]` today but used by job control; confirm it supports DELETE and empty 204), with a flag.
6. Contract + docs: openapi.yaml and CONTRACTS.md section 4 corrected to the real signature scheme and payload; docs/CHANGE_TRACKING.md webhook section updated.
NOT in scope (Innhenting session): gateway route and SPA UI.

## Contract change
New org-scoped resource, edge paths (control mirrors under /v1/webhook-subscriptions?org_id=, HMAC-signed).
- POST /v1/webhook-subscriptions `{url:'https://hooks.example.com/q', events:['change_detected'], description?}` -> 201 `{data:{id:'whk_...', url, events, active:true, created_at, secret:'whsec_...' (ONLY here), secret_hint:'...ab12'}}`; errors: 400 details.field in {url, events} with reasons url_not_https / url_private_address / events_unsupported; 409 same url+events exists; 403 under ZDR (details.reason 'webhook_off_process') and for service principals; 429 per-org cap; 501 flag off.
- GET /v1/webhook-subscriptions?limit&cursor -> `{data:{items:[{id,url,events,active,created_at,secret_hint,last_delivery?}],next_cursor}}` (never the secret). GET /{id}; DELETE /{id} -> 204 (foreign or unknown id both 404, hard delete, pending deliveries cascade); optional PATCH {active?, events?, url?}; POST /{id}/rotate-secret -> new secret once; GET /{id}/deliveries?status&limit -> items {id, event_id, event_type, status, attempt, next_attempt_at, last_error (closed vocabulary http_<code>|transport|timeout|blocked_target)} (no payload body).
- DELIVERY to the customer (documented, matches code): POST <url>, Content-Type application/json, header `X-Quarry-Signature: t=<unix seconds>,v1=<hex HMAC-SHA256 of '<t>.<raw body>'>` keyed with the subscription secret; body is the control Event JSON `{event_id, type:'change_detected', ts, payload:{subject:'quarry.change.detected', emitted_at, org_id, source_url, status:'changed', old/new baseline fingerprints, ...ChangeRecord}}`; 2xx = success, 408/429/5xx retry on 1s/5s/30s/5m/1h then dlq after 5 attempts, other 4xx dlq at once. The `events` string is 'change_detected' (stored type) while payload.subject stays 'quarry.change.detected'; document both. CONTRACTS.md section 4 is rewritten to this.

## Risks
- SECURITY (highest): (a) CROSS-TENANT FANOUT: fanoutWebhooks has no org predicate; shipping the API without org scoping lets one tenant receive another's change and job events. Prove with a two-org test. (b) SSRF: dispatch guarded at dial time, but create-time validation absent; verify the production egress allowlist env is empty so internal control-plane hosts cannot be targeted. (c) SECRET HANDLING: webhooks.secret is plaintext in Postgres and returned on GET; new API shows it once; HMAC needs the raw key so envelope encryption with a control key is the proper fix (owner decision: accept plaintext-at-rest for v1 or require KMS/envelope). Rotation grace window (two secrets) is nice-to-have. (d) ZDR: edge suppresses emission for ZDR schedules and control double-checks the body flag, but a ZDR ORG must also not be able to create a subscription (off-process push of page URLs); refuse on create. Delivery payloads persisted in webhook_deliveries.payload contain source URLs and fingerprints: add a TTL and include in org erasure. (e) DOUBLE DELIVERY: edge also emits ChangeDetected on its NATS event sink (change_webhook.rs ~121-128); if a NATS-to-control bridge appends the same event to control's log the fanout could run twice; UNVERIFIED, test against idempotency key 'change_detected:<org>:<url>:<baseline>'. (f) Noisy/abusive targets: per-org cap, per-delivery timeout (30 s), DLQ visibility, auto-disable after N consecutive dlq. (g) Replay: signature includes timestamp; document a 5-minute tolerance.
- Cost: negligible compute; delivery storage bounded by TTL. Compat: renaming the control path avoids breaking internal /v1/webhooks callers (none found besides dispatcher and tests; grep before retiring).
