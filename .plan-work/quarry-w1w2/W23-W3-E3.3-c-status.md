## Assumed decisions

1. D9 (decisions 2026-10-23): the chip renders inline in the composer, no dock. Chip strip under the textarea, as the closest inline form a textarea allows.
2. Re-resolution is a separate gateway route plus a shared function, not a change to the chat route (outside the file set); the chat path must call `resolve_turn_tab_mentions` before any model call (integration ask).
3. Fail closed all-or-nothing: one unresolved mention refuses the whole set (409), nothing partial is attached.
4. ZDR: refused, and a projection without an explicit `zdr: false` is refused too (same rule as browser_evidence receipts and E3.3-d). The client also drops the payload field on a ZDR turn.
5. `@tab` means the single active tab; an inactive tab may be named by id (unlike E3.3-d's region, a mention needs no frame).
6. The token travels with the id and must agree with it, so the id cannot be swapped under a visible token.
7. Limits: 8 mentions per turn, label 200 chars. Wire trust class `browser-scraped` (`TrustClass::BrowserScraped`).
8. Route path `/api/v1/browser/sessions/{id}/context/tab-mentions`, rate class Interactive, behind `require_session`.
