## Flag and default

`VITE_CHAT_BROWSER_STEER`, **default off** (unset). `isChatBrowserSteerEnabled()` reads "1" or "true". With it off the composer renders nothing. The action has no gateway route yet, so even with the flag on a send reads `failed` and the text is kept.

## Assumed decisions

1. Two ways to send while the run works. **Steer:** the owner takes it at the run's next step. **Queue:** held in this browser until the run ends; `settle()` returns it, and the page sends it as an ordinary message. Taken from the room composer's mid-run pattern (WS09-S2), not its transport.
2. Ephemeral means memory only: no browser storage, no transcript, no run event log on our side. A reload drops it. The owner holds the text in memory until a step takes it (MP ask).
3. ZDR refuses both: the composer is replaced by a line, and the controller refuses first. The owner must refuse too (MP ask).
4. Human only. The side-map row is `none` with `no_owner_executor`, the same reason as `chat.queue_invocation_input`. Side-effect class `context_write`, the same as that row.
5. Risk low, not reversible, no approval, the same as `chat.queue_invocation_input`. A steer starts nothing; a new run is `browser_run.start`, which stays approval-gated.
6. A run that ends first answers `run_ended`. Nothing starts, and the text stays in the strip with "Send as a new message". That is the person's choice; nothing is resent automatically.
7. A failed send keeps its text. Sent again unchanged, it keeps its `clientMessageId` and idempotency key (`browser-steer:<id>`), so a deduping owner stores one message.
8. A ZDR refusal is recognised by `ApiError.feature` (the server names the feature). Every other failure reads as `failed`.
9. Limits: 2000 characters (the contract bound), 5 queued messages (`STEER_HELD_MAX`).
10. `delivered` needs a run event the page routes in (MP ask). Until then a steer reads `queued` until the run ends.
11. Keys: Enter steers, Shift+Enter starts a new line, IME composition is respected.
12. Copy in Norwegian first, English second, the repo's convention. Nothing is written to browser storage.
