## Built (answer.rs)

- `PrefetchedPage { outcome: Result<SourceExtraction, FetchFailure>, complete: bool, fetched_at: DateTime<Utc> }` and `PrefetchedPages = HashMap<String, PrefetchedPage>`, keyed by the exact result URL.
- `AnswerPipeline::prepare_with_pages(req, gate, &pages)` and `answer_with_pages(req, gate, &pages)`. `prepare_gated` and `answer_gated` delegate with an empty map, so `/v1/answer`, `/v1/answer/stream` and the search include_answer keep their behaviour.
- Per result, in this order (private `FetchStep` enum): the URL gate (denied: `PolicyDenied`, never read, never fetched); a prefetched page (its stored outcome is used as it is, no fetch); otherwise a fetch, as before.
- `PreparedAnswer` gains `pages_fetched` and `pages_reused`: fetches made by this step, and results answered from the set. A reused page is not counted as a fetch.
- Corpus write-back of a reused page: only when `complete` is true, under the page's own `fetched_at`, through the same `LocalIndexWriteback` hook (ZDR, tenant and empty-body rules unchanged). A capped copy feeds synthesis and is never indexed.
- Tests (answer.rs `mod tests`, 10 new, names in the file): prefetched pages read with no second fetch; a result without a prefetched page is still fetched; an earlier refusal or failure is not retried (a refusal stays `Failed`, with no snippet); a failed prefetch falls back to the snippet with no fetch; the gate still refuses a prefetched URL; a whole prefetched page reaches the corpus for its own tenant; a capped prefetched page answers but is not indexed; a ZDR prefetched page is used inline and persists nothing; `answer_with_pages` synthesizes from prefetched pages with no fetch; with no pages, `pages_fetched` equals the results, as before.

## Assumed decisions (owner said stop asking; recommended defaults taken)

1. Reuse is by exact result URL. A page the caller hands over is used for that URL and not fetched again. The answer's own search still runs; reusing the handler's result list is a separate change.
2. A refusal the earlier step recorded (web policy or preflight) is reused as `PolicyDenied`, with no snippet fallback. A failure keeps its reason and falls back to the snippet, as a fresh failure does. Nothing is retried: a retry would skip the earlier preflight verdict and fetch again.
3. The URL gate runs before the prefetched lookup, so a denied URL is never used, even when a copy is present.
4. Edge mapping, to be written in the wiring unit (the runtime has no hydration types): `policy_denied` and `blocked` to `PolicyDenied`; `timeout` and `deadline_exceeded` to `Timeout`; `http_status(n)` to `HttpStatus(n)`; `too_large`, `decode`, `extract`, `transport`, `empty`, `too_short` one to one; `invalid_url` to `Transport`, which is what the fetcher reports for a URL it cannot build.
5. A reused page enters the local corpus when `complete` is true, as a fetched page does, so answering warms the local tier as it did. The write-back keeps the page's own fetch time. A capped copy is never indexed, because a partial document in the corpus would be wrong.
6. ZDR: prefetched text is used inline for synthesis only. No new ZDR rule: the existing hook refuses it, since `writeback_enabled` is false under ZDR. Nothing in this step caches or logs the text.
7. Metering: this step meters nothing, as today (the answer path meters only `ANSWER_SYNTH`). It reports `pages_fetched` and `pages_reused`, so each fetch is billed once: hydration bills its own fetches and the answer step only its own.
