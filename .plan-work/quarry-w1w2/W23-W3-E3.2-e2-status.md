## Assumed decisions

1. Consent is per tab id in the ledger, not per run; it leaves with the tab.
2. A policy deny is sticky for the tab id (deny beats approval); a bad grant or an uncovered host is not a deny.
3. An approval binds the exact host the tab was on; a tab that navigated needs a new check before attach.
4. Attach mode takes the person's active (visible) tab only, held by the person; an agent-opened tab is not offered.
5. ZDR runs refuse attach mode, as WS8.F attach does (so the E3.2-e1 ZDR turn scope never applies here).
6. The extension must cover the tab's host (host or a subdomain of a listed host), and the tab's host itself must pass the web policy.
