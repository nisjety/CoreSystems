## Flag and default

- `CRAWL_APPROVAL_MODE`: `off`, `observe` or `enforce`. **Default `observe`** (unset or unrecognised).
  - off: no check.
  - observe: a whole-site crawl above the threshold is logged (page counts only) and no response changes.
  - enforce: a whole-site crawl above the threshold without a covering confirmation is refused with 409 `approval_required`.
- `CRAWL_APPROVAL_PAGES`: the threshold. **Default 50**, tighten-only: a lower value lowers it (0 means every whole-site crawl needs approval). A value above 50 is held to 50. Unparsable is 50.
- Read once per process (OnceLock in `knowledge.rs`). A change needs a restart.

## Assumed decisions

The owner said stop asking. These are the recommended defaults from decision 2 and the queue.

1. Threshold: approval is needed when the estimated pages are above 50. At or below 50 the crawl runs under the run budget (decision 2).
2. Estimated pages: the requested `max_pages` or `maxPages`, held to 5,000 (the normaliser's ceiling). A crawl with no bound is estimated at 5,000, because the gateway cannot see the edge default. Under enforce, an unbounded crawl therefore needs approval.
3. Scope: whole-site crawls only. A curated batch (non-empty `urls`) is not gated, because decision 2 names `knowledge.crawl_site` only.
4. Gate point: `POST /api/v1/knowledge/crawl`, a session route used by the human UI. It uses `Surface::Ui`. The action path will use `Surface::Model` when it is wired, so a model proposal can never confirm.
5. Confirmation: the request may carry `approvedMaxPages` (or `approved_max_pages`), which must be at least the estimate. A smaller value is refused. The gateway never forwards it, because the normaliser builds the upstream body from known keys.
6. Schema: `approvedMaxPages` is not added to `crawlSiteInput`. `actionSchemaHash` hashes that schema into the cross-plane admission contract (`agent-action-admission.json`, vendored and pinned by every plane). Adding the key would move the `knowledge.crawl_site` hash. So the action path cannot carry a confirmation.
7. Refusal: 409 `approval_required`, with `details.estimatedPages` and `details.thresholdPages`. The same status social-core uses for an unapproved post.
8. A body the URL normaliser rejects is not gated. `start_crawl` returns its 400 as before.
9. Registry: `requiresApproval` stays false. `actionRequiresApproval` is the input-aware check. The SPA must show the threshold from `thresholdPages` in the 409 (the server may tighten it), not the 50 in the copy.
10. Default mode is observe, per the lane rule (new behaviour defaults to observe or off). Decision 2 is therefore not in force until `CRAWL_APPROVAL_MODE=enforce` is set. That is the owner's call.
11. Settings are read from the environment once (OnceLock) rather than from `AppState`, because `config.rs` is not in this unit's list. Move them to `AppState` later.
12. Logs carry page counts only: no URL, organization or user.
13. The confirmation is an echo of the page count by the same user. It binds the approval to the number shown. It is not an independent second approver.
