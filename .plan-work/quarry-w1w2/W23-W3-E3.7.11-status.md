4. The scrape-block refusals stay on the flat `ErrorBody` the code returns. The typed envelope is not applied to them here (depth D-E3711-3).
5. The scrape block is described as it is: `include_answer` does not reuse the hydrated pages yet and fetches twice.
6. Sitemap options: no change to the openapi `sitemap` text, which already matches INNH-6a. `/v1/map` gzip (E3.7.4) is not documented.
7. The SDKs are not regenerated. `sdks/generate.sh` needs a running Docker daemon, and unit work runs no Docker. The integration step regenerates.
8. The batch and crawl `403` under ZDR are not added to openapi (outside E3.7; depth row D-E3711-4). CONTRACTS mentions the 403 in the job section only.
