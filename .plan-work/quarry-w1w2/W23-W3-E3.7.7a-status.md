## Flag

`QUARRY_EDGE__SEARCH_SCRAPE`, default off (`job_results_routes::flag_is_on`: 1/true/yes/on). Read per request. Off: the block is not validated, nothing is fetched, the response carries `scrape: {"status":"disabled", ...}` only when the request sent a block; every other search is byte-identical.

## Assumed decisions

- "The scrape pipeline" = the edge's markdown fetch path that `include_answer` and `/v1/answer` already use (`SimpleHttpMarkdownFetcher`), gated by the web policy and the policy security engine. Not the `PageRunner` (no browser render, no actions): hydration is a static fetch, priced as such (0 browser pages).
- Flag off ignores the block and reports `disabled` rather than answering 501, so turning the flag off never fails a search that a caller already sends.
- Hydrated text is never cached, for ZDR and non-ZDR alike (simplest correct rule; the E3.8 URL cache can bound hydration cost later). It never enters `SearchIssued`, the search cache or logs.
- Metered by fetch units that left the edge, not by successes: a 404 or a timeout cost an outbound request. Placeholder rates from `JobRates::default()`.
- Hydration covers the results after diversity and rerank (the order the caller sees), before highlight markup.
- `format=context` and `include_answer` do not yet use the hydrated text (E3.7.7b).
