`QUARRY_EDGE__RUN_TTL`, default off (read at each sweep pass; unreadable is off). Off: a release leaves the checkpoint `active`, byte-identical to before. ## Assumed decisions

1. The flag gates only the durable arc; the idle/absolute TTLs and the reaper keep running under their WS2.D switches (they already shipped and are in compose).
2. A reaped run with a persisted profile is `suspended`, any other non-ZDR run `expired` (plan: "suspend is release plus persisted profile"); both resumable.
3. A grant-ended human-browse release (revoked, cap) is marked like any release; the resume then needs a valid grant and is refused 403 without one.
4. "A resumed run needs a fresh grant" is met by the existing revalidation at resume (stored or new `grant_id`, `validate_for_org`); no extra "grant must differ" rule.
5. `resumable` -> `live` is the start save writing `active` (no second `mark_run_checkpoint(Active)` call).
6. No new `SweepReport` field (its literal is compared in tests.rs, outside this unit).
