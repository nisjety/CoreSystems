## Flag and default

- `QUARRY_BROWSER_ACTION_SETTLE`: `1`, `true`, `on` or `yes` turn it on. Anything else, including unset and `0`, is off. **Off by default.**
- `QUARRY_BROWSER_ACTION_SETTLE_MS`: the bound in ms, read only when on. Default 300, capped at 2000, malformed takes the default, `0` is off.
- Off means no sample, no wait, and `settle_ms` absent from the wire. The output is byte-identical to today.
- **Not the queue's name.** The queue says `QUARRY_BROWSER_SETTLE_MS`, which is the live hydration budget: default 3500, read by `settle_budget()`, documented in `SELF_HOST.md`, and set to 3500 in `stack-2026-10-28/qv2e-flags.baseline.env`. A flag of that name with "default 0" would switch the fetch-path hydration settle off. The queue row needs the new names.

## Behaviour

- Runs only for an action that ran. `action_only_observes` (wait, wait_for, screenshot, pdf, get_content) is skipped. A failed action returns before the settle.
- Quiet means two `content()` samples, 100 ms apart, are byte-identical. The samples are compared in memory and dropped. Each read is cut at the deadline, so the wait does not run past the bound.
- Reported value: the elapsed ms when quiet was seen (about 100 on a static page, since two samples are needed); the bound when the DOM was still changing at the bound; the elapsed ms when a read failed.
- No retry of the action and no new retry of a read. The driver's own `read_with_retry` inside `content()` (one retry after 100 ms on a destroyed context, which already exists) runs inside the cut-off read, so it is capped by the bound.

## Assumed decisions

1. Two env vars, not the queue's single `QUARRY_BROWSER_SETTLE_MS`: `QUARRY_BROWSER_ACTION_SETTLE` (on or off, default off) and `QUARRY_BROWSER_ACTION_SETTLE_MS` (bound, default 300, max 2000). The queue's "default 0 (off)" is met by the flag's default. Its "default 300 ms, max 2 s" is met by the bound.
2. Quiescence is "serialised HTML unchanged between two samples 100 ms apart", not a MutationObserver. The `BrowserDriver` trait has no DOM-change signal, and `content()` is the only read available without a new trait method (`quarry-browser/src/lib.rs` and `chromiumoxide.rs`, both outside this unit). Each sample serialises the whole DOM.
3. The report lives on `BrowserTelemetry`, not on the `ObservationReady` event, which keeps its shape. `BrowserTelemetry` is the observation's measured block, and `usable_observation_latency_ms` already sits there.
4. Read-only actions are not settled (wait, wait_for, screenshot, pdf, get_content). Navigate, reload, back, forward and every input action are settled.
5. A failed action is never settled. A failed sample ends the wait at once and is not retried.
6. ZDR: no new branch. The settle reads the DOM through the same `content()` the observation already reads, and keeps, writes and logs nothing. `settle_ms` is a number, not page content.
7. `usable_observation_latency_ms`, which is measured from the start of `execute`, now includes the settle when the flag is on.
8. Scrape-time actions on the fetch path (`do_fetch`, `run_scrape`) are not settled. Reporting them needs `PageCaptures` (`capture.rs`) and the action runtime (`action_runtime.rs`), neither in scope. The helper can be called there later.
