## Flag and default

- `QUARRY_EDGE__SCRAPE_RETRIES`, **default `0` (off)**. The value is the number of extra attempts after the first. `1` or `2` turn it on. Above `2` it is clamped to `2`. Blank, non-numeric or negative is off.
- Read once per process (a `OnceLock` in `routes.rs`), like the other edge switches. A change needs a restart.
- Off: `scrape_retry_config()` is `None`, the driver is the same `Arc` as before, and nothing else runs on the request path.
- On: non-browser sync `/v1/scrape` plans run under `RetryingDriver`. Each wait is at most 10 s and never passes the run deadline.

## Assumed decisions

1. **One config.** The scrape curve is `SCRAPE_CURVE`: exponential from 500 ms, `max` 3. The classifier is `RetryPolicy::default()`: 3 attempts, transient codes 408, 429, 500, 502, 503, 504. Neither source type changed, so no policy fingerprint or stored JSON moves. `RetryPolicy.base_delay_ms` is not read on this path; `Retry.base_ms` is the base.
2. **Retry class.** The error's `retryable` flag decides, with two exceptions. `UPSTREAM_BLOCKED` is never retried (ADR-5: a block is classified and refused, never escaped). `INTERNAL` is never retried, although `ErrorCode::retryable()` says it is retryable (see depth row 7). The retried set is therefore TIMEOUT, RATE_LIMITED, and DRIVER_FAILED with sub-code `dns` or `connect` once those are produced.
3. **`dns` is retried** (decision for the open question in the lane d depth row). E3.8.1 says "one or two retries at most", and the attempt cap gives at most two. NXDOMAIN and resolver faults are not told apart.
4. **Proxy guard.** A failure whose details carry any `"egress": "proxy"` record is final. This covers proxied transport failures and proxied block statuses. The egress broker already rotates within its bounded plan, so a retry would reach proxies beyond that plan.
5. **Transient responses through a proxy** are retried. The retry keeps the answering identity: the broker's sticky primary is a deterministic hash of (org, host), and `mark_ok` only clears health. The retry window is at most 20 s with two retries, which is shorter than the 60 s block cooldown, so no cooled-down identity is picked (depth row 6).
6. **Direct 429 and 503** are `Ok` responses with headers, so they are retried when listed, and their `Retry-After` is honoured. Only delta-seconds are read; an HTTP-date gives no value and the backoff decides.
7. **Wait rule.** The wait is `max(jittered backoff, Retry-After)`. A wait over 10 s ends the retries and the last outcome is returned unchanged; no error is invented.
8. **Jitter** is equal jitter in `[delay/2, delay]`, from std `RandomState`, so no crate is added.
9. **Browser plans are not wrapped.** A render takes seconds, and a repeat is not a transport retry.
10. **Deadline.** `until` is now plus `run_deadline_ms`, taken when the driver is wrapped. That is microseconds before the run starts, so it matches the run's own bound.
11. **Scope.** Only the synchronous `/v1/scrape` path is wrapped. `scrape_stream` and the crawl's `internal_run_page` are not, and the durable crawl keeps its Temporal retries, as the plan says.
12. **Logging.** The one debug line carries the attempt number and the wait. It has no URL, body or org.
