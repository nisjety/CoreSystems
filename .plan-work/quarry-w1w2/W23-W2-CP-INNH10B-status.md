## Flag and default
No new flag. Everything is inert unless `API_KEY_ENABLED=true` AND `API_KEY_AGENT_EXCHANGE_ENABLED=true` (the CP-1 flag, default false): with it off, `browserAgent` creation is refused `api_key_agent_exchange_disabled` and the sweeper does not start. The before-hook always runs while the api-key plugin is on, but it only acts on browser:agent keys or on reserved metadata fields. Tuning knob (not a flag): `API_KEY_REVOCATION_SWEEP_MS` (default 60000).

## Assumed decisions
- OD-4/OD-5: browser keys are `user-keys` owned by the creator and hold exactly `browser:agent` (no other scope). The creator must be owner or admin of the bound org, so plain members get no browser keys in v1.
- Stored metadata contract (for CP-1 and the broker): `metadata_version:1, org_id, key_hosts[], budget_ceiling{micro_usd,max_steps,max_runtime_s}, zdr, browser_agent_granted_by`. CP-1 should read it with `readApiKeyAgentMetadata` and the permission with `apiKeyHoldsBrowserAgent`.
- OD-10: the budget ceiling is always stored (defaults 1 USD / 50 steps / 600 s). The creator may raise it up to the absolute limits of 10 USD / 500 steps / 900 s. An org-plan cap is not modelled.
- OD-15: absent expiry = 90 days, the minimum is 1 day (the Better Auth `minExpiresIn` default), and an update can never push past 90 days.
- Event: `details.{key_id, org_id, reason}`, `resource_id = key_id`, reasons `deleted | disabled | expired | owner_removed`. Removing browser:agent from a key counts as `disabled`. The event_id is `api_key:<key>:revoked:<reason>[:<epoch ms>]` (updatedAt for disable and owner removal, expiresAt for expiry), so retries de-duplicate.
- Delete and disable publish before the mutation and fail closed. If the mutation then fails, the only effect is that grants die early, which is the safe direction. Expiry and owner removal come from the sweep: there is no reliable hook, because organization-events.plugin short-circuits remove-member/leave in its before-hook. After the PubAck the sweep disables the key, so a re-joined owner must re-enable it.
- Events go only for org-bound browser:agent keys, because audit-core requires org_id.
