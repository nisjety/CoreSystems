## Flag and default

`QUARRY_EDGE__DOWNLOAD_HANDOFF`, default off (unset, empty or anything but 1/true/on/yes). Off: `hand_off` refuses with `download_handoff_disabled` and Data Plane is never called. Nothing calls `DownloadHandoff` yet, so the flag is inert until the download path is wired (see depth rows).

## Data Plane dependency

Built against the existing documents-api contract (`POST /v1/documents`, `model.CreateDocumentInput`): text `content` (UTF-8, 5 MiB), free-string `type` (max 64), `title` (max 1024), `source: quarry`. No Data Plane change is needed for this to work, but the Data Plane owner should confirm the four `download_*` document types (no allow-list or retrieval filter knows them today), and the E3.8.8 artifacts contract (W3, Data Plane) is the later path if the bytes themselves must be stored. No direct DB access anywhere.

## Assumed decisions

1. The hand-off carries the parser's text, not the bytes: documents-api stores text only, and the caller already has `quarry-transform` (PDF text layer) from the parse path.
2. Allow-list is PDF, plain text, Markdown, CSV; Office documents are refused, matching the E3.4-4 admission rule ("Office refused"). HTML downloads are refused (a page should come through the page path).
3. A file with no text layer (scanned PDF, no OCR) is a typed `UnsupportedMedia` refusal, not an empty document.
4. The org is taken from the verified claim only; an artifact whose owner org differs is refused (403), checked before anything about the file so a cross-tenant call learns nothing.
5. Document type travels in a reserved metadata key `quarry_download`, so the trait and the gRPC adapter need no new field; an unknown value falls back to `web_page`.
6. Fingerprint is `sha256:<hex>` of the bytes (the download admission's digest), not blake3 of the text.
7. Refusal codes: disabled 501, ZDR/org 403, type/no-text 415, size/URL/digest 400; all non-retryable.
8. `data_plane_http.rs` left unchanged (see Gap check).
