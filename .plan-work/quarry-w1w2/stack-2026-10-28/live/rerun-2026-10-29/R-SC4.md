## Depth

1. **A navigate TIMEOUT on a run's first step closes the tab, so the next step is a non-retryable 502 (T4b).** In `goto`, the recovery that keeps the page after a TIMEOUT runs only when the tab already exists (`quarry-browser/src/chromiumoxide.rs:3920`, `if !created`). A run with no tab goes through `open_tab_page`, whose first navigation has no recovery by design (`chromiumoxide.rs:1597-1600`, "a tab whose first navigation fails is closed by the attach guard"). The next observation then finds no page and answers `DRIVER_FAILED` `no_current_page`, `retryable:false` (`chromiumoxide.rs:1262-1270`). Effects: (a) a page whose HTML arrived but whose load never ended (held image, long-poll, analytics beacon) is readable when it is the second navigation of a run but not when it is the first; (b) an agent that gets a TIMEOUT on step 0 and then observes gets a 502 that says "not retryable", although a navigate on the same run works (200). Options for the lead: commit the tab in `open_tab_page` on a navigate TIMEOUT the same way `goto` does (stop the load, mark the tab abandoned, keep it), or answer the no-page case after a first-step TIMEOUT with a typed, retryable error. Not fixed here.
2. The T3 result depends on the hang not committing: for `/slow.html` the observation after the TIMEOUT shows the previous page (fixture-a), not about:blank and not the slow URL. That matches the 33bf15174 design ("the page, old or new, is readable at once").
3. chromiumoxide logs `WS Invalid message: data did not match any variant of untagged enum Message` (WARN) a few times per run (7 in the final container). Seen in earlier legs too; unrelated to the timeout, noise only.
4. `/ready` generation resets to 0 at every edge recreate and becomes 1 at the first run; a relaunch check across a flag change has to compare per container, as done here.
