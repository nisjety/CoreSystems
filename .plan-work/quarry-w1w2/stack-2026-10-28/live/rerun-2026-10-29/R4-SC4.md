## Depth

1. **The first-step D3 refusal leaves browser-session `currentUrl ""` while `GET /tabs` lists the tab on `about:blank`** (R4-SC4-d3.log D3a try 1: `browser-session {"currentUrl":""}`, `tabs n=1 about:blank`). The goto opened the tab with `FirstNavigation::ByCaller` (`quarry-browser/src/chromiumoxide.rs:1528`, the tab starts on about:blank), the refusal ends it (`chromiumoxide.rs:2516`, `:2605-2638`), and the edge keeps the run's URL empty for about:blank (as for T4b-1 in R3). The next wait is 200 on that tab, so it is consistent; only the two read surfaces differ (`""` vs `about:blank`) until the next observation. Info.
2. **Egress receipts carry the full URL, not the host only.** The refused hop's receipt is `url http://fixture-b.crawl.test/ext`, `host null` in the next observation and in `GET /egress-receipts` (R4-SC4-d3c-*.json), and the D3b image is `http://fixture-b.crawl.test/pixel.png`. This is the R3-SC4 form (R3-SC4-s1-redirect-next-egress.json), so D3c is "as before", but "host-only" in the row text is not what the API returns. The 403 body is clean (no URL, no host). If receipts are persisted or relayed under ZDR, the path is a question for the owner (like CHECK open issue 3 for the SSE stream). Chromium's own `CONNECT https://www.google.com/` blocks still appear without a tab id (pre-existing, info).
3. **A refused navigation is charged as a navigate.** The D3a failed receipt has `cost_micro_usd 1000`, `cost_source flat_table` (R4-SC4-d3a-first-receipts.json), the same as a completed navigate; the refused-landing receipt in R3-SC4 S1b was 100 (a wait). As 304d6cb22 intends (a failed step keeps its flat cost). Info.
4. **Receipt `outcome.latency_ms` is 0 for completed steps** (R4-SC4-d3a-first-receipts.json: wait and navigate `latency_ms 0`) while the HTTP step took 0.16 to 0.28 s. Not checked in earlier legs; not in scope of D1-D3. Info for the lead.
5. **The checkpoint's `step` column stays the count of completed steps** (rs2: `step 1, next_step 3` before the idle with keys 0-2 used; `step 4, next_step 6` at close with keys 0-5). The resume seeds from `next_step` / `MAX(step)` of the receipts (`quarry-edge/src/agent_routes/lifecycle.rs:102-108`, `:231-234`, `:744`; `run_live.rs:261-264`), and the failed step is checkpointed (`step.rs:252`, `:418` `checkpoint_failed_step`), so the column is unused for keys, as 3a2b66c34 says ("Unchanged: `step`"). A reader of the table who takes `step` for the key high-water mark would be off; the key is in `state->>'next_step'`. Info.
6. The placeholder tab path is reached through `action_only_observes` (`quarry-runtime/src/observation.rs:1689`, the runner calls `ensure_page` at `:443`), which in chromium opens `FirstNavigation::Placeholder` (`chromiumoxide.rs:4393-4406`, `:1307`). Only `wait` and `wait_for` were driven live; `screenshot`, `pdf` and `get_content` on a session with no page take the same branch by code but were not run.
7. D3 first-step refusals take 0.13 to 0.15 s against 0.04 to 0.09 s for later steps: the first goto also opens the tab and installs the session's egress policy. Info.
8. chromiumoxide `WS Invalid message` WARN noise: 18 / 5 / 5 per container, unchanged in kind.
