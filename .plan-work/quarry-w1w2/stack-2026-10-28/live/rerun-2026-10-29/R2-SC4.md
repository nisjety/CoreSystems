## Depth

1. **After a first-step TIMEOUT on a page that never commits, the tab sits on about:blank and every observe step is refused with 403 (T4b-1, T2 first-step slow).** e79209b26 commits the tab on `about:blank` before its first navigation (`quarry-browser/src/chromiumoxide.rs:1604-1611`, `FirstNavigation::ByCaller` from `goto` at `:3996`), so when the navigation never commits the page stays at `about:blank` (`browser-session` currentUrl `about:blank`). The next wait runs and its observation url is `about:blank`; the edge then checks the landed page against the run's host list (`quarry-edge/src/agent_routes/step.rs:210-216`, `nav_policy.allows(&obs.url, ...)`), and an allow-list policy accepts only http(s) hosts (`quarry-browser/src/lib.rs:300-307`, "Do not let ... `about:` ... inherit domain-grant authority"; via `human_browse.rs:49-56`). So `about:blank` is "outside the run's allowed domains". Side effects found on the way:
   - (a) The receipt for that wait is already appended as `completed` (`step.rs:150-165`) and the checkpoint already saved (`step.rs:203-208`) before the 403 is decided, so the receipt list says `wait completed` for a step the caller saw as refused.
   - (b) The 403 carries `code:"BAD_REQUEST"` because `status_err` always uses `ErrorCode::BadRequest` (`agent_routes/types.rs:613-620`); the twin check in the shared step path (`step.rs:370-375`) uses `ErrorCode::SecurityBlocked` for the same condition.
   - (c) Not tested live (would need an idle-expiry resume): the checkpoint keeps `current_url` = the summary's last url (`agent_routes/control.rs:13-14`, `human_browse.rs:203-207`), so a run checkpointed after such a wait holds `about:blank`, and a resume would hit `lifecycle.rs:563-573` (non-empty URL not allowed -> 403 "durable checkpoint URL is outside the persisted allowed domains").
   Options for the lead: let the post-step check (and the resume check) treat `about:blank` as "no page yet" rather than a foreign host (keep it refused as a navigate target), and checkpoint `about:blank` as `""`; or, in the `goto` TIMEOUT recovery for a tab that `goto` just opened, report the observation as "no page yet" with a typed retryable error. Not fixed here (no code edits in this leg).
2. The held page case shows the fix's intent works: the first-step TIMEOUT keeps the tab, the committed page is readable at once (0.17 to 0.23 s), and the following navigate drains the abandoned load with no 30 s queue (0.23 to 0.34 s, 4250620d6).
3. chromiumoxide `WS Invalid message` WARN noise: 21 / 6 / 4 per container (31 in all), unchanged in kind from earlier legs.
4. `/ready` generation resets to 0 at every edge recreate and becomes 1 at the first run; compare per container, as done here.
