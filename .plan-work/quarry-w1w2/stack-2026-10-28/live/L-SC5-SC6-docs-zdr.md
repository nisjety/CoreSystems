## Depth

1. "Inline" for a non-ZDR document scrape: the extracted text is in `data.markdown` only when the request asks `formats:["markdown"]`. A body with only `url` returns `formats.markdown` as an artifact reference (17 bytes for the PDF), which holds the same text (`GET /v1/artifacts/{id}`). This is the contract (`quarry-core/src/scrape.rs`, "Present when the caller asked for the `markdown` format, and by default under ZDR"), so it is not a defect; a tester who expects inline text from a bare body will think extraction failed.
2. X-19 and the runbook text. Three different stored shapes for the same keystrokes, depending on who the step is and how focus is known:
   - A person's step (no `initiated_by`, dev stub or a real user): `[redacted]` for every key, `Enter` too (`redacted_for_human_receipt`, `quarry-core/src/redaction/action.rs`, around line 356). The runbook's expected values do not apply to this branch. If the lead wants the `[redacted:password]` / `Enter` shape, the step must be labelled `agent` (or come from a service principal).
   - An agent step after a raw-selector click on a control the selector does not name (`click #pw`): every key is `[redacted:secret]`, including the search box (run `run_01M624384EYGK7T45EWY62YPH8`, file `-x19-agent-failclosed-receipts.txt`). This is the fail-closed rule (`key_focus_after`, `quarry-runtime/src/observation.rs` around line 1925: a raw selector only counts when its own words name a sensitive control, such as `input[type=password]` or `#password`). It is correct, but a test that clicks `#pw` and expects `[redacted:password]` will see FAIL. The tester should click with a selector that names the type, or with `click_ref` on a snapshot target.
   - An agent step after `click_ref` on a snapshot target, or a selector that names the type: `[redacted:password]` (password) or the plain character (search box, sensitive mode); `[redacted:secret]` for everything typed in mode `all`.
3. After `Enter` the focus is "unknown" again (`moves_focus`), so a second line typed after `Enter` without a new click is `[redacted:secret]`. The run showed this only through the design (each block was preceded by a click). No defect.
4. A step on a person's receipt for `navigate` keeps scheme, host and path but not the query. Not tested further.
5. Debug log level: with `RUST_LOG=debug` the edge logs the dev-bypass warning on every request (`QUARRY_EDGE_AUTH_DEV_BYPASS enabled ...`), which is expected here and not a leak. The log lines in the ZDR windows contained no page host, URL, title or query.
