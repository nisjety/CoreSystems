## Depth

1. **Internal routes are open in live dev (g3).** With `QUARRY_EDGE_AUTH_DEV_BYPASS=1` the shared-token guard is skipped: `change_routes.rs:455` (`if dev_bypass { return Ok(()) }`) is used by `change/record`, the schedules preflight (422 seen) and `DELETE /v1/internal/orgs/:org/profiles` (`internal_routes.rs:57`). From the host, no credential is needed. Only the dev stack is affected: production refuses to start with the bypass (`main.rs:171-200`), the edge port is bound to 127.0.0.1, and the gateway does not route `/v1/internal`. Still, the dev bypass should not cover the org-erasure route, and `QUARRY_EDGE_INTERNAL_TOKEN` is empty on this edge. `run_page` is not affected (its own token check; the token is set here). **Deviation from my own rule:** I sent that `DELETE` as a probe, with the stub org `org_placeholder`. It returned `rows_deleted 0` for every family, and `quarry_profiles` holds 0 rows in total (SELECT count on `quarry_edge`), so nothing was removed. I should have used a method that cannot change data. No other write was made.
2. **`rerank` is silent, not "off" (f4).** A caller cannot tell "no rerank wired" from an old edge. This is the designed wire (`search_routes.rs:187-189`), so it is only a note for the runbook wording ("says off/disabled" should read "absent").
3. **Page-image producer fails to start (g2, f5).** The boot WARN reads `page-image producer connect failed; disabled ... dataplane nats connect nats://dataplane-nats:4222: authorization violation`. The edge cannot log in to the Data Plane NATS with its current credential, so `GET /v1/internal/page-images/...` answers 500 and visual RAG page images are not produced. Likely cause: the NATS user or password in the edge env is out of step with the Data Plane NATS (see the memory note on Data Plane cross-plane compose). Not tested further (no env reads allowed). It is not a rerank or Model Plane call.
4. **Metrics are off on live by default (d0).** Every later leg that reads counters needs `QUARRY_EDGE__METRICS_ENABLED=1` in `live-flags.env` (no token needed in dev). The runbook's token command does not work on live.
5. **Scrape counters.** After 2 scrapes `quarry_scrape_outcomes_total{outcome="ok"}` was 2, and the robots counters stayed 0 (scrape and map do not feed the gate; crawl does).
6. **A first search returned 0 results.** `rust programming language` gave `results: []` after 10 s (the SearXNG log shows engine timeouts and a Startpage captcha, search duration 10.3 s against a 10 s limit). The next queries returned 10 results. It is a flaky upstream, not an edge fault, but a leg that needs a non-empty search should retry.
7. **`include_answer:true` is silent without a pipeline (f4).** The edge returns 200 with no `answer` field and no error. The gateway `search/web` passes `includeAnswer` through, so the SPA gets a normal result set without an answer. Possibly intended; noted for the Model Plane relay follow-up.
8. **Log noise.** The window has 5 ERROR lines (the expected 501 and 500 traces) and two WARN lines per dev-bearer request (JWT header decode, then the bypass). Normal.
