## 1. The plain statement

**W1 is built to the plan's scope and NOT proven to the plan's evidence bar.** 38 of 39 slices are built to scope, plus the in-branch halves of WS3.J (the Model Plane half, 4 of its 6 days, is handed to the Model Plane session). That is 144.25 of 148.25 engineer-days built. No image of the final tree was built, no side-by-side stack was run for evidence in the wave (as far as the unit notes record), and no L2 leg has ever run: the plan's evidence bar (rebuilt images, L2 on the production-overlay stack, SC1 to SC7) is not reached, and all seven success criteria are NOT-RUN. The reason is the user's build strategy of 2026-10-23 (build the wave first, depth later): review-and-fix rounds, stack runs and evidence were deliberately deferred and written down as depth items instead.

"Built" means every code, test and doc deliverable of the slice that belongs in this branch is committed and compiles, and the slice's own new tests passed when it was committed. It does not mean correct or deployed: 16 high depth rows are open defects or risks, several inside built slices (for example D1-004, D1-003, D1-002).

## 2. How the columns are counted

- Built: yes = all deliverables of the slice that belong in this branch are committed; partly = some are not (only WS3.J).
- Reviewed: what review is recorded. "N review commits" counts commits whose subject says review fix or round, so it is a lower bound.
- Evidence level, the highest honestly reached by any part of the slice: none < unit (tests in one process) < integration (real Postgres, Redis, router, real child processes, or in-process fake servers) < rebuilt-image (the slice's code in a rebuilt image run in an isolated side-by-side stack, plan 6.2) < L2 (the production-overlay contract run). Image evidence in this table is from images built BEFORE the end of the wave (2026-10-16 to 10-20); none is from HEAD, so a slice at "image" is not proven at HEAD. The wave test phase raised nothing above unit and only for the crates it covered (section 6).
- Left kinds: DEPTH (documented in the register, not built), OUTSIDE (counsel, GitHub CI, the user's live-tree baseline PRE-1, another plane or session, owner decision). BUILD (code to write in this branch) is empty except as named in section 4.
