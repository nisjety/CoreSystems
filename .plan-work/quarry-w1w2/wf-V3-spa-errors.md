## Findings the task did not name
- The gateway's own inbound 429 was plain text: the SPA could not say "too many requests, wait N seconds" (fixed, gateway + test).
- `requestForm` (uploads) never signalled an expired session; the crawl-preview stream threw a bare Error (both fixed).
- `translateApiError` (28 files) did not answer by status class: a lost connection, 401, 403 and 429 read as the caller's "could not do X" (now the same as describeApiError; the old test that pinned the opposite was changed on purpose).
- ~70 catch sites showed `err.message` (English operator text / "Failed to fetch"); 44 converted, the rest listed in section 7 of the list.
- The onboarding crawl warning showed `payload.message || payload.code` (English). Fixed.
- A code-level sentence can be worse than the caller's: PersonaSection and the Integrations settings tests caught two such copies (persona_unavailable, integration_error); both deliberately have none, recorded in the test with reasons.
- The old scan stopped at the first `mod tests {`, so production code after it (`proxy_artifact_bytes` in upstream.rs, after `mod artifact_relay_tests`) was never scanned: `artifact_unavailable` and `artifact_too_large` had no copy. The new scan skips each test module instead.
