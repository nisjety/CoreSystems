## Assumed decisions (owner said stop asking)

1. The route sits in the document lane. It needs `DOC_ROUTING=on`, as PDF and DOCX do. The queue row says "when the flag is on", but Shadow promises to change nothing and Skip refuses, so the flag alone would change Shadow. Operators set both.
2. Kinds on the route: XLSX, PPTX, ODF and EPUB, the four the queue names. PDF and DOCX keep their Rust extractors. Legacy OLE (doc, xls, ppt), RTF, archives and images keep their 415.
3. Client shape assumed: `extract_office_via_imports(kind: ContentKind, body: Vec<u8>) -> QuarryResult<ParsedDocument>`, the same shape as `parse_document`.
4. An imports error passes through as the page's typed error, so its 415 stays a 415. The page event is `page_blocked` with reason `document_parse_failed` (the reason PDF and DOCX use) and `route: "imports"` added.
5. ZDR: the route runs under ZDR, because the queue says the client is ephemeral and ZDR is allowed. No ZDR flag is passed to the client. Under ZDR the text is returned inline and nothing is stored (tested).
6. An unreadable flag value is off, with a warning. The PII flag turns on for an unreadable value (fail closed for redaction). This route sends document bytes to another service, so a bad value must not switch it on.
7. The flag is read once per process (OnceLock), like `DocRouting` and the PII settings. No field is added to `PageRunner`: that would break every construction site in quarry-edge and in other crates, which are outside this file.
8. The pipeline's 16 MiB body cap runs before routing (`MAX_HTML_BYTES`), as it does for PDF and DOCX.
9. No new error code and no new event type. The existing reason is reused.

## Depth findings

Recorded here, not appended to `W23-depth-lane-a.md`: another unit has uncommitted edits in that file, so this unit neither edits nor commits it.

- D1 high, dependency: E3.6-6a is absent (see above). Integrate it before 6b.
- D2 high, contract: imports-core parses only pdf, docx, txt, md, csv, json, html, htm, xlsx and pptx (`apps/Ingestion Plane/imports-core/app/parsers.py`, lines 8-29). ODF and EPUB raise `UnsupportedFileTypeError`, which the endpoint returns as 415. So the ODF and EPUB half of the route is refused until imports-core gains those parsers. The ODF subtype (odt, ods, odp) is not in the magic, so the client must pick a filename extension for the endpoint. Decide: keep the two kinds (6a adds parsers) or drop them from `is_imports_office_kind`.
- D3 medium, contract: the endpoint is a chat-attachment path. XLSX text is cut at 55,000 characters and flagged `truncated`. PPTX text above 60,000 characters gets a 413 (`chat_extract.py`, `_MAX_CHARS`). Quarry's own document text cap is 8 MiB (`content_route.rs`, `MAX_DOC_TEXT_BYTES`). So a long deck fails on the route where PDF and DOCX succeed. Decide whether the route needs a bulk path.
- D4 medium, security: `require_internal_auth` (`apps/Ingestion Plane/imports-core/app/auth_middleware.py`) accepts a verified bearer token. The legacy shared key is marked E2E-only. 6a must present a verified ingestion-audience token and must not reuse the shared INTERNAL_API_KEY, which the readiness roadmap already names as shared across services.
- D5 medium, PII: for a non-ZDR run the Office original is stored as a `raw` artifact, as PDF and DOCX are. Per the E3.6-4b status and its tests, the sink refuses `raw` for a redaction-gated org (`capture_not_redactable`), so the page fails for such orgs. The route inherits this. Decide whether documents skip the raw write under redaction.
- D6 low, size: the 16 MiB body cap runs before routing, so an Office file of 16 to 25 MiB is refused as body_too_large, though the parsers accept 25 MiB. PDF and DOCX have the same limit today.
- D7 low, ops: boot validation (`quarry-edge/src/main.rs`, around line 259) covers `QUARRY_EDGE__DOC_ROUTING` but not the new flag. An unreadable value is off with a warning.
- D8 info, behaviour: setting only `QUARRY_EDGE__OFFICE_VIA_IMPORTS=on` changes nothing, because the route needs `DOC_ROUTING=on`. The 6a runbook should say so.
- D9 low, wording: the `format_unavailable_for_documents` warning still says "a PDF or DOCX". It now also covers Office documents.
- D10 low, scope: `POST /v1/parse` (`parse_routes.rs`) does not use this route.
- D11 info, lane state: the task said lane-a was synced to `w23/integ`. It was at `5d4143522` (S9), eight commits behind `w23/integ` (`dc6c316e5`, S12). Those S12 commits do not touch pipeline.rs.
