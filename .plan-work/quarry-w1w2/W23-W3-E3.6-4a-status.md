## Built

- Flag `QUARRY_EDGE__PII_REDACTION`: `off` by default, or `on`. It also accepts `true`, `false`, `1` and `0` in any case. An unreadable value turns the stage on (fail closed) and logs one warning.
- Org default `QUARRY_EDGE__PII_REDACTION_DEFAULT_ORGS`: a comma list of org ids, or `*` for every org. It matters only while the flag is on.
- `PiiRedactionMode`, `PiiOrgDefault` and `PiiRedactionSettings` (`parse`, `from_env`, `cached`, `applies(requested, org_id)`). Tests override them per thread, as the challenge config does.
- `PageRunner::run_with_inline_request_redacting(.., redact_pii: bool)`. `run_with_inline_request`, and so `run` and `run_with_inline`, delegates with `false`. Crawl and batch therefore redact through the org default only. `run_inner` gains `redact_requested`.
- The stage in `run_inner` runs after the bot-wall check and before everything else that uses the page text: language detection, the fingerprint and change events, branding, artifacts, the local index, ingest, `page_extracted` and the inline parts. It redacts:
  - the markdown;
  - the decoded page text, which feeds the `html` source artifact and the inline `html` and `raw_html`;
  - the cleaned HTML;
  - the links and the metadata, through their JSON form.
  Branding goes through the same JSON redaction before its event and the output.
- The source artifact under redaction: for a page, the redacted page text. For a document, none: PDF and DOCX bytes cannot be redacted, the redacted text is the markdown artifact, and `formats.raw` is absent.
- Fail closed: `redact_text_fail_closed` scans and replaces for up to 3 passes, and returns text only when a scan finds nothing. The scanner runs under `catch_unwind`. Text over 16 MiB is refused. The causes are `too_large`, `scanner_panicked`, `residual_pii`, `reencode_failed` and `capture_not_redactable`. A redacting run that carries a screenshot, PDF or action output fails with `capture_not_redactable` and names the field.
- The typed per-page failure: `ErrorCode::Forbidden` (403, not retryable), a message that holds nothing of the page, and `details {reason: "pii_redaction_failed", cause, field}`. The `PageFailed` event carries `reason`, `cause` and `field`. A crawl or batch counts the page in `pages_failed` through the existing per-page error path and goes on.
- ZDR runs the same stage. A failure returns before anything is written or returned inline.
- Tests in `mod pii_redaction_tests`:
  - Settings: parsing, an unreadable mode failing closed, the org list and `*`, and the `applies` matrix.
  - The redactor: a text is redacted whole or refused, the over-cap case, structured redaction, the typed failure, and capture detection.
  - Flag off: a run that asks is unchanged.
  - A redacting run has no email in the stored markdown and source artifacts, the serialized output, the inline markdown, html and raw_html, or any event.
  - The org default redacts a run that did not ask. An org not on the list is not redacted.
  - Under ZDR the run redacts inline and writes no artifact.
  - A capture fails the page typed in both modes: no artifact, no `page_extracted` or `branding_extracted`, and a `PageFailed` with the reason.

## Flag and default

`QUARRY_EDGE__PII_REDACTION` is off by default. Off, no part of the stage runs and every run is as before. `QUARRY_EDGE__PII_REDACTION_DEFAULT_ORGS` is empty by default (no org default).

## Assumed decisions (owner said stop asking)

1. The typed failure uses `ErrorCode::Forbidden` with `details.reason = pii_redaction_failed`, following the `body_too_large` precedent. `error.rs` is outside this unit, and `Internal` is retryable while a redaction failure is deterministic. A dedicated error code is a follow-up if wanted.
2. The "org default" is a deployment list (`QUARRY_EDGE__PII_REDACTION_DEFAULT_ORGS`, `*` = all), because Quarry has no per-org setting store. A Control Plane org setting would replace it.
3. An unreadable flag value turns the stage on (fail closed), since redaction only removes text.
4. Under redaction, captures (screenshot, PDF, action outputs) fail the page. They are not silently dropped.
5. The stage runs after the bot-wall classifier, which reads the raw page and keeps nothing of it, so a wall is still refused as a wall.
6. The per-request switch is a new method, not an `InlineRequest` field. `quarry-edge/src/routes.rs` builds `InlineRequest` by a full struct literal, and this unit may not touch that file.
7. A text gets up to 3 scan-and-replace passes before `residual_pii`, so an overlap the first pass dropped does not fail a page needlessly.
8. Links and URLs in the metadata are redacted too, because a `mailto:` address is PII.
