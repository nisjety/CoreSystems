## Contract change
REQUEST (additive, POST /v1/scrape): `formats[]` items may also be objects
- `{"type":"json","schema":{...},"prompt":"optional <=10000 chars"}`
- `{"type":"summary","max_chars":4000,"language":"nb"}` (also bare string "summary")
- `{"type":"question","question":"<=10000 chars"}`
- `{"type":"highlights","query":"...","max_highlights":3,"max_chars_each":300}`

Schema accepted subset = what `quarry_core::json_schema` validates (type, required, properties, items, enum, min/max Items/Length, minimum/maximum, additionalProperties:false); `$ref`, `anyOf`, `oneOf`, `const`, `pattern` rejected with 400 `schema_keyword_not_supported` at formats[i].schema (the validator ignores them silently today, json_schema.rs header 1-14, which would make `schema_valid:true` a lie).

RESPONSE `data` additions (optional, only when asked): `json` (object), `summary` (string), `answer` (string, the `question` result), `highlights` [{text,start,end}] (verbatim spans), and `ai`: `{ json|summary|question|highlights: { status: "ok"|"error"|"skipped", code?: "MODEL_UNAVAILABLE"|"MODEL_RATE_LIMITED"|"SCHEMA_INVALID"|"ZDR_UNAVAILABLE"|"BUDGET_EXHAUSTED"|"DISABLED", model?, schema_valid?, schema_issues?[], repair?: bool, truncated_input?: bool, dropped?: n, usage?: {input_tokens, output_tokens, cost_usd?} } }`. These codes are strings inside a 200 body, not new wire ErrorCodes (plan R-10).

ERRORS: 400 BAD_REQUEST `details.fields[] {path,code,message}` for bad specs (routes.rs:540-550); 400 `feature_disabled` at `formats[i]` while the flag is off (replaces reserved_format for these four names; OWNER/CONTRACT decision: keep `reserved_format` while off if the Innhenting UI already keys on it); 501 UNSUPPORTED `details.reason: model_plane_unavailable` when flag on but MODEL_PLANE_URL unset; per-format ZDR refusal is `ai.<fmt>.code ZDR_UNAVAILABLE` inside a 200. Default scrape without AI formats must stay byte-identical (golden).

Example: POST /v1/scrape `{"url":"https://x/p","formats":["markdown",{"type":"json","schema":{"type":"object","required":["title"],"properties":{"title":{"type":"string"}}}}]}` -> 200 `{data:{markdown,json:{title:".."},ai:{json:{status:"ok",model:"..",schema_valid:true}}, ...}}`.

What it does: `chat_for_org` posts exactly `{messages, model, structured_output_schema (a string, json only), zdr (only when true)}` to `/v1/ai/chat` with `Authorization` plus `x-inference-authorization` (dev bypass only); a connect error, 502 or 503 is retried once, a read timeout never; one status mapping into `ModelHopError`; the Dynamic and unauthenticated paths return `LaneNotGranted` without minting. `AiScrapeEngine::run(&[AiSpec], AiScrapeInput) -> (AiFields, AiReport)` frames the page between `<<<PAGE-{128-bit nonce}>>>` and `<<<END-{nonce}>>>` (fresh per call; the rules say the block ends at the last line), runs the specs concurrently under the per-request limit (and an optional process-wide semaphore), checks `json` against the schema after a local repair and at most one model repair that never carries the page, verifies highlights and the question's supporting quote verbatim on the page (char offsets, multi-byte safe), enforces the call, token and page-char budget, short-circuits siblings on a 429, makes no call under ZDR or for an empty page, and logs kind, outcome, code and counts only.

Deviations from the design:
1. `crates/quarry-edge/src/routes.rs` got a 2-line edit (`ai_source_max_chars: None` in the `InlineRequest` literal), or quarry-edge would not compile after the new field. U3 replaces it with the real value. The pre-existing uncommitted `quarry-edge/src/lib.rs` and `main.rs` and `quarry-runtime/src/step_receipts.rs` were not touched.
2. Under ZDR `run` returns the normal `(AiFields, AiReport)` with every format `skipped` / `ZDR_UNAVAILABLE` and zero calls, instead of a `ZdrRefused` error value. It is the same wire result the edge short-circuit gives, and a caller who forgets the edge check cannot bypass it.
3. A client with no credential at all (not only the Dynamic provider) also answers `LaneNotGranted`; the design only named Dynamic, but an unauthenticated chat call can only be a 401.
4. The engine tests use an axum double, not wiremock: they need calls-in-flight counting and per-call scripting. It is strict the way the design asks (401 without both tokens, 400 for an object `structured_output_schema` or a field the gateway does not read, 404 for `/v1/invoke`, every request recorded).
5. `question` and `highlights` replies are prose-instructed JSON (`{found, answer, quote}` and `{quotes: [...]}`), parsed with the same local repair as `json`; only `json` (and its repair call) sends `structured_output_schema`. A reply that cannot be read is `MODEL_UNAVAILABLE` / `bad_reply`.
6. The repair call uses the text alias (as designed) and also sends the schema as `structured_output_schema`; if the budget has no call left for the repair, the report is `SCHEMA_INVALID` with the first output's issues. A deadline that passes before a spec starts is `MODEL_UNAVAILABLE` / `deadline` (per the design sentence), although no call was made for it.
7. A found highlight longer than `max_chars_each` is cut to that length (still verbatim) instead of dropped; overlaps and duplicates are removed without being counted in `dropped`; quotes under 8 folded chars count as dropped.
8. `ModelHopError::RateLimited.retry_after_s` is an `Option` (the header may be absent or an HTTP date); any 4xx other than 401, 403, 412, 429 is `Rejected`; `LaneNotGranted` and 403 both report `model_lane_denied`.
9. Extra knobs: `AiScrapeConfig.phase_deadline` (45 s, used when the input has no deadline), client `with_chat_timeout` (60 s) and `with_retry_backoff` (250 ms), `AiScrapeEngine::with_process_limit`. `lib.rs` re-exports nothing new (types are at `quarry_runtime::mp_client::*` and `quarry_runtime::ai_scrape::*`), as the design says two mod lines.
10. The nonce appears exactly twice in a whole request (the two markers); the system message does not name it and says the page block ends at the last line of the user message, which the page cannot append to.

What it does: `ai_formats::settings()` reads the nine `QUARRY_EDGE__AI_FORMATS*` / `MODEL_PLANE_INFERENCE_TOKEN` names once (`OnceLock`); the switch is on only for `on`, `1`, `true`. `scrape_with`, after the field validation and before the fetch: `check_principal` (403 `extract_ai_scope_required`, `details.field` = `formats[i]` of the first AI format, for an `initiated_by: "agent"` label or a service principal without `extract:ai`), then `availability` (501 `model_plane_unavailable` without a URL, `model_lane_not_granted` with a URL and no usable dev credential), the latter skipped under ZDR. Deviations from the design:
1. The engine is built per distinct (url, token, inference token) and cached in one slot, not "once": tests (and a future Dynamic path) vary the Model Plane settings inside one process, and the env settings are the `OnceLock`. A request pays no client build after the first.
2. The 501 availability checks are not made for a ZDR request (the design says ZDR is never a request error for AI formats; a ZDR request never reaches a model, so whether one is configured is moot). A ZDR caller on an edge with no Model Plane gets 200 with `ZDR_UNAVAILABLE`, not 501.
3. The 403's `details.field` takes the format index from the raw `formats` value (`first_ai_index`) because the resolved options lost it; it is `formats[0]` if the raw array cannot be read.
4. `scrape_actions::route_deadline(scrape_route, actions, ai)` is a new pure function behind `path_deadline`, so the 125 s rule is unit-tested without a router. The deadline is lengthened for every `POST /v1/scrape` while the switch is on (design D14), not only for requests carrying an AI format.
5. The `enforced_by` rows that U1 deferred are added now (`scrape`: `ai_formats::zdr_skips_every_format_with_no_model_call_and_stores_nothing`, `ai_formats_real_token::a_zdr_org_user_gets_every_format_skipped_even_when_the_body_says_zdr_false`; `scrape_stream`: `ai_formats::the_stream_route_refuses_ai_formats_before_any_fetch`); the golden JSON, its `.sha256` and `ZDR_MATRIX.md` were regenerated again.

## Review blockers closed (lane A fix, branch innh/lane-a)
Two blockers from the review of U1-U3 are fixed (commit: `fix(quarry-edge): AI scrape truncated_input and the privacy block before the model hop (INNH-1)`, find it with `git log --grep "INNH-1)" `).

1. `truncated_input` was never set on `POST /v1/scrape`. Cause: the pipeline cut the AI source to exactly `max_input_chars` and the engine then cut again at the same cap, so it never saw an over-cap page. Fix: the edge asks the pipeline for `max_input_chars + 1` chars (`routes.rs`, `ai_source_max_chars`), so the engine's own cut (`cut_chars`) is the one that decides, and `ai.<fmt>.truncated_input: true` is set on every entry that made a model call when the page was over the cap. A page of exactly the cap, or under it, carries no marker; the model never receives more than the cap.
2. The request's `privacy` block was ignored before the model hop. Fix: `scrape_with` computes `model_hop_allowed(zdr, &privacy)` (the rule the page-title hop uses, `page_extract::model_hop_allowed`). When it is false (`credential_or_secret`, `zdr_ephemeral`, or privacy ZDR) and ZDR is not already the reason, every requested AI format is skipped with zero model calls and the new `AiCode::PrivacyPolicy` (`PRIVACY_POLICY`); the page itself is a normal scrape. ZDR is still answered first (`ZDR_UNAVAILABLE`). The page text is not even requested from the pipeline in that case. New code added to quarry-core `AiCode`, openapi `AiFormatReport.code` enum, CONTRACTS "Scrape AI formats", ERROR_REASONS and the openapi parity node test.
3. `/v1/extract` does accept a `privacy` block (`ExtractRequest.privacy`), and its model arm now follows the same rule: a source answers status `error`, `error` starting `PRIVACY_POLICY:`, with its `structured` harvest, and no model call. It is not a 501. Documented in CONTRACTS (Extract section).

Tests added: edge `ai_formats` (3): over-cap page says `truncated_input:true` on json/summary/question, page of exactly the cap and shorter pages do not, and the double saw exactly the cap of page chars; both privacy classifications skip all four formats with the model double counting zero calls and one fetch; unclassified, `customer_private`, `personal`, `public_non_personal` and an empty privacy object still call the model (3 calls).
