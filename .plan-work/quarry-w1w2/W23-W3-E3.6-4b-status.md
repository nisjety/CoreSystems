## Gap check

Already there (E3.6-4a, `pipeline.rs`, merged into w23/integ): the fail-closed redaction stage. It redacts the markdown, page text, cleaned HTML, links, metadata and branding before the artifacts, the local index write-back and the Data Plane ingest request are built, and it fails a page with captures (screenshot, PDF, action outputs) under redaction. So in the scrape pipeline the artifact, local index and ingest sinks already receive only redacted text.

The gap, built here: the sinks themselves did not check anything. Three paths could still persist unredacted content:

1. The search and answer write-backs (`answer.rs` via `LocalIndexWriteback`) index fetched pages with no redaction stage at all.
2. The visual RAG producer (`page_renderer.rs`, after a successful ingest) renders the page to a PNG and writes it to the CAS. A picture of the page cannot be text-redacted, and nothing stopped it under redaction.
3. Any other artifact writer (extract, scrape record, change diff, visual artifacts) and any future caller that skips the stage.

## Built

- `artifact_store.rs`, the shared sink gate:
  - `check_text_redacted(text)`: `Ok` only when `quarry_transform::pii::scan` finds nothing. The scan runs under `catch_unwind`. Text over 16 MiB is refused unscanned (the stage's cap).
  - `check_artifact_redacted(kind, body)`: text kinds (html, markdown, links, extract, meta, scrape_record, change_diff and the visual JSON kinds) must be UTF-8 and scan clean. Every other kind (screenshot, pdf, raw, trace, PNGs) and an unknown kind is refused as `capture_not_redactable`.
  - `SinkPiiRefusal` causes: `too_large`, `scanner_panicked`, `residual_pii`, `not_text`, `capture_not_redactable`.
  - `sink_pii_error(refusal, sink, field)`: `ErrorCode::Forbidden` with `details {reason: "pii_redaction_failed", cause, sink, field}`. It uses the stage's `PII_REDACTION_FAILED`, so a pipeline write the sink refuses fails the page through the same typed per-page path. The message holds nothing of the content.
  - `sink_redaction_required(org)`: reads the stage's `PiiRedactionSettings` (`QUARRY_EDGE__PII_REDACTION`, `QUARRY_EDGE__PII_REDACTION_DEFAULT_ORGS`) as `applies(false, org)`. A test installs its own settings per thread (`SinkPiiTestOverride`).
  - `InMemoryStore`, `FilesystemStore` and `S3Store` run the gate in `put` before anything is written.
  - `PiiEnforcingStore`: a wrapper that checks every write whatever the settings, for a run that asked per request (a sink cannot see `redact_pii`). Reads, lists and counts pass through.
- `cas_store.rs`: `CasStore::ensure_page_image_allowed(org, redacting_run)` refuses a page PNG (`capture_not_redactable`, sink `cas`) when the org must redact or the run redacts. `put_page_png` calls it first.
- `local_index.rs`: `add_document` requires the title and the body to scan clean for an org that must redact, or refuses with the typed failure (sink `local_index`) before the writer is touched.
- Tests: `artifact_store::pii_sink_tests` (the text and artifact checks, the cap, the settings matrix, the memory and filesystem backends refusing and writing nothing, flag off unchanged, the enforcing wrapper), `cas_store` `page_image_is_refused_when_redaction_applies`, `local_index::pii_sink_tests` (body and title refused, nothing written, redacted text and an uncovered org indexed, flag off unchanged).

## Flag and default

The gate reads E3.6-4a's flag: `QUARRY_EDGE__PII_REDACTION` is off by default, and then no sink checks anything (byte-identical behaviour). With it on, only orgs in `QUARRY_EDGE__PII_REDACTION_DEFAULT_ORGS` (empty by default, `*` for all) are gated. `PiiEnforcingStore` is not used by anything yet.

## Assumed decisions (owner said stop asking)

1. The sinks verify and refuse; they never redact. Redaction stays in one place (the stage), and a sink that rewrote text would hide a stage that was skipped.
2. The sinks reuse the stage's settings and its `pii_redaction_failed` reason (no new flag, no new error code), so a sink refusal is the same typed per-page failure as a stage refusal.
3. A binary artifact (screenshot, PDF, raw, trace, PNG) and an unknown kind are refused for a gated org (fail closed), as the stage already does for captures.
4. A sink cannot see a per-request `redact_pii`. The backends enforce the org default; a redacting run is covered by the stage, and by `PiiEnforcingStore` once the pipeline wraps its store with it (follow-up 1).
5. The local index checks the title and the body, not the URL, the host or the fingerprint. The stage does not redact URLs either (D-E364a-5), and URL digit runs would refuse many pages.
6. The local index write-back is detached, so a refusal there is logged and drops the index entry; it cannot fail the page. In the pipeline the text is already clean, so it does not fire.
