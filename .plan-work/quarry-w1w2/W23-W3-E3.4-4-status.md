## Flag and default

`QUARRY_EDGE__DOWNLOADS`, default **off**. Off: none of the new policy runs; `download_ref` keeps its earlier path (capability gate, sensitive approval, runner checks), which on the Chromium driver is refused anyway (`downloads_to_artifacts: false`). On: the gates above. `QUARRY_EDGE__DOWNLOADS_SESSION_MAX_BYTES` (default 104857600) sets the session cap.

## Assumed decisions

1. Allow-list PDF, plain text, Markdown, CSV; Office, HTML, images refused (same list as E3.4-8's hand-off).
2. Flag off = earlier behaviour unchanged (not "refuse all downloads"), so existing tests with a fake driver advertising `downloads_to_artifacts` keep passing; the real driver already refuses.
3. "Session" = the agent run (`run_id`); cap 100 MiB per run, 25 MiB per file (matches the driver).
4. Single use is the existing sensitive-approval grant spend; not duplicated.
5. Admission is settled after the step on the stored artifact (the runner is not this unit's file), so a refused download fails the step but its bytes stay in artifact storage (depth row).
6. A refused download is charged the flat failed-step cost, not the driver cost.
