## Flag and default

- `QUARRY_EDGE__CHANGE_WEBHOOK_DELTA`, new, default off. Off: no stored text is read for a change, `paragraph_delta` is null, and a min-delta filter passes every change (inert in that mode). With it on, every changed check reads the two stored markdown artifacts, whether or not any subscription exists (depth D-E357-11).
- `QUARRY_CONTROL__WEBHOOK_SUBSCRIPTIONS`: stays off. Subscriptions are not mounted, so no subscriber sees the classification.
- `change_type` in the edge body: always set on a change webhook. It is additive and needs no flag. Control reads it from the body and does not write it into the stored event, so a subscriber's delivered body is unchanged.

## Assumed decisions

1. The change types are the closed set `new`, `changed`, `removed`, as the scope lists them. The edge maps `Changed` to `changed` and `New` to `new` (no webhook for `new` today).
2. Minimum paragraph delta is the count of paragraphs added plus removed in the text diff. Moves do not count, a markup-only change counts 0, and 0 (the default) means no threshold. The cap is 1000 and a larger value is refused. It applies to `changed` only.
3. An unknown delta (no stored text, text diff off, flag off) passes a min-delta filter (fail-open): a change is not dropped for lack of text. The owner may prefer fail-closed.
4. A subscription without a filter takes every change type, as before.
5. The filter is applied in `fanoutChangeWebhooks` on the change webhook path only. The run-event path stays unfiltered until ask 3 lands.
6. The paragraph delta re-reads the two stored markdown artifacts (`compute_outcome`), so `record_core_fp`'s signature stays as it is. It is behind the flag.
7. `change_type` is not added to the stored event payload, so the delivered body and the in-product `notifyOnChange` payload do not change.
8. `removed` is in the vocabulary with no producer (ask 4).
