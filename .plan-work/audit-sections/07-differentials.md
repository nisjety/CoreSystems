## 7. What each reference does uniquely well, and how that helps Verevon

Provenance tags: [SRC] read in source or shipped files, [REA] reverse-engineered from the shipped app, [DOC] documentation only, [INF] inference. Codex and Aside facts come from static analysis of the installed apps, Firecrawl facts from its open-source repo, and Apify facts from public docs only.

### 7.1 Codex desktop app (in-app browser, computer use), version 26.1007.2314.0

Codex is best at making agent browsing safe by construction: a typed, fail-closed authorisation pipeline, credential delivery the model never sees, and engine-level enforcement of navigation and downloads. [SRC] It has no crawl, queue, schedule, stealth or proxy layer, so it is a reference for the browser half only. [SRC] Its Electron shell and the user's-own-Chrome extension do not fit Verevon's remote, leased Chromium; the extension is a design spike at most ([F-t2-077](#F-t2-077)) because the product owner ruled it out on 2026-09-28 (apps/Frontend Plane/verevonv3/apps/verevon-web/plans/system-audits/CHAT_PAGE_GAP_PLAN_2026-09-28.md:250-264). [SRC]

- **Credential handoff with an observation gate (Codex Cloud Browser).** `browserAuth` proceeds only if the origin is https, the frame origin equals the top origin and exactly one required input exists; values go from the host into an isolated world, the model receives only a status, and accessibility, DOM and screenshot reads of that document are denied until the next navigation; an email one-time password (OTP) variant raises a user elicitation the reviewer cannot auto-approve. [SRC] This is wired to the hosted Cloud Browser, not the shipped desktop browser. [SRC] Verevon has no secret-reference action; [F-t2-024](#F-t2-024) copies the shape with integration-corev2 as custodian.
- **One policy choke point with typed denials and per-origin consent.** Every command passes an ordered gate chain; a denial carries a reason, a decision source, a retryable flag and text telling the model not to work around it; consent is stored at turn, conversation or global scope and resolved deny-first; an org origin policy merges per field with deny winning. [SRC] Verevon's grant check is a choke point that returns generic codes; [F-t2-032](#F-t2-032) adds consent and typed denials, [F-t2-036](#F-t2-036) adds Codex's one audit record per decision.
- **Hit-tested trusted input.** Before a ref-targeted click Codex probes `elementFromPoint` per frame hop, scrolls into view only if the target is not hittable, polls every 25 ms for two stable samples under a 500 ms deadline, then dispatches trusted `Input` events; failures are typed as covered-by, did-not-settle or could-not-be-clicked. [SRC] Quarry's ref actions call `element.click()` in page script with no actionability check; [F-t2-015](#F-t2-015) carries this.
- **Structurally safe evaluate, gated raw CDP.** `evaluate` runs in an isolated world against a read-only proxy of `document`, masks credential fields, blocks `import()` and caps results; raw Chrome DevTools Protocol (CDP) access needs a preference that defaults to false, an enterprise requirement and per-origin consent. [SRC] Quarry runs `page.evaluate` in the main world with no gate; [F-t2-002](#F-t2-002) adds both.
- **Turn-scoped agent tabs with handoff marks.** Agent tabs open hidden; `markTab handoff|deliverable` decides which survive the turn; a once-only turn-ended tracker closes the rest and the Interrupt, Stop and SubagentStop hooks all call it. [SRC] Codex has no code-enforced "user took over" state, so that part of [F-t2-013](#F-t2-013) is a Verevon design. [SRC] The lifecycle is carried by [F-t2-013](#F-t2-013) and [F-t2-054](#F-t2-054).
- **Settle heuristics and a frame-aware accessibility snapshot.** After an action Codex awaits navigation commit and first paint, then waits for accessibility and DOM mutation events to go quiet (capped at 750 ms); the snapshot stitches `Accessibility.getFullAXTree` per auto-attached frame session under per-frame timeouts inside a global deadline and lists per-frame failures as warnings. [SRC] Quarry captures immediately and walks one root frame; [F-t2-034](#F-t2-034) carries both.
- **Honest bot-block handling and per-command deadlines.** A classifier reads site-served evidence, names explicit non-signals (bare 403/429, timeouts, sign-in pages, paywalls), allows one recovery and reports a closed reason set with the hostname only; no stealth code exists in the app. [SRC] Every CDP call carries a deadline from a constants table and a destroyed execution context is retried once. [SRC] [F-t2-027](#F-t2-027) and [F-t2-026](#F-t2-026) are both W1 quick wins.
- **Operational hygiene and a multi-backend protocol.** Log calls split fields into safe and sensitive maps app-wide (sink behaviour not found); a setting suppresses memory extraction after web or MCP (Model Context Protocol) tool use; the browser API marks each member as unsupported in named backends and the agent lists capabilities and reads docs on demand. [SRC] These feed [F-t2-004](#F-t2-004), [F-t2-045](#F-t2-045), [F-t2-059](#F-t2-059) and [F-t2-043](#F-t2-043). WebMCP page tools are a long-tail bet only ([F-t2-076](#F-t2-076)).

### 7.2 Aside browser, version 1.0.928.2

Aside is best at agent ergonomics for a background-first local agent: authenticated local control surfaces, credential indirection, steering and recovery, and tab hygiene. [SRC] It is a single-user desktop browser with no fleet, proxy pool or crawl scale, and its defaults are open (browser and network rules allow by default, dialogs auto-accept, a cookie-based site API and a CAPTCHA solver), so its topology is not adoptable and those features should be avoided. [SRC]

- **Signed-challenge control channel.** A client fetches a challenge, signs it with an installation key (hardware-backed on Windows) and receives a short-lived bearer; the command bridge is routed per account, profile and mode and rejects stale connections. [SRC] This is a single-user local trust check; no reference implements a durable org-scoped grant issuer, so [F-t2-001](#F-t2-001) is a Verevon requirement that borrows only the short-lived token idea. [INF]
- **Opaque credential references.** Vault fills go through the Vault extension with agent-session, policy and URL-match checks; the tool API returns summaries and opaque refs, never values. [SRC] Verevon persists typed text verbatim in receipts; [F-t2-024](#F-t2-024) takes the reference model and [F-t2-021](#F-t2-021) the attribution and scrubbing.
- **Capture-time redaction.** For durable text and ARIA snapshot capture Aside drops password and tel values and sensitive autocomplete tokens, applies label regexes (cvv, otp, pin, ssn) and value patterns (JWT, cloud keys, private-key blocks) with a Luhn check, and redacts tool arguments and error bodies in logs. [SRC] Its interactive agent snapshot redacts only non-empty password inputs. [SRC] Quarry copies AX values verbatim and its redactor has no caller; [F-t2-021](#F-t2-021) carries this and extends it to screenshots and receipts, which no reference does.
- **Steering protocol and durable suspensions.** Commands carry an idempotency id, an `afterSeq` resume cursor and an expected turn id; runs can be steered, queued or interrupted; human decisions persist on the run record, survive restarts and support "deny with instruction" and "remember this scope". [SRC] [F-t2-038](#F-t2-038) carries steering and [F-t2-033](#F-t2-033) the approval card with redirect.
- **Tab hygiene and session caps.** Tabs are owned or borrowed; a sweeper closes agent-owned tabs of idle, interrupted or aborted sessions past an idle threshold; a global run semaphore (200), a sub-agent cap (8) and a five-tab warning bound the agent. [SRC] Aside has no absolute run TTL and does not reap running runs. [SRC] [F-t2-006](#F-t2-006) adds a reaper and caps to Quarry, which has neither; [F-t2-007](#F-t2-007) takes the page hygiene.
- **Side-panel chat bound to the active tab.** `sidePanel.setOptions` is called per tab with a session id, the target session is resolved on tab activation, and a "sidecar to this page" framing is injected on the first user message. [SRC] Verevon's chat split is read-only and fed by screenshots; [F-t2-012](#F-t2-012) carries the binding.
- **Settle defaults and ref re-resolution.** After an action Aside waits for a 350 ms quiet DOM window, tracks same-site requests up to 1.2 s, dwells on SPA URL changes and caps at 8 s; stale refs are re-resolved by role, name and ordinal when unique. [SRC] [F-t2-034](#F-t2-034) carries the settle logic and notes re-resolution as an option.
- **Routines, site playbooks and code mode.** One `routine_update` tool manages cron, heartbeat and event-triggered runs; sixteen SKILL.md playbooks auto-inject by URL or keyword; one persistent QuickJS scope per session exposes a small page, tabs, snapshot and fetch surface. [SRC] These map to [F-t2-061](#F-t2-061), [F-t2-043](#F-t2-043) and [F-t2-063](#F-t2-063); the first and last are nice-to-have and need ADRs, because a script runtime fits only if every binding call stays one governed Quarry step.

### 7.3 Firecrawl, commit 11e9dc5e2 (2026-10-12)

Firecrawl is best at the acquisition contract: format breadth behind one strict options object, a mature async job lifecycle, crawl scoping with typed denials, and a governed-web-access policy model for regulated customers. [SRC] Its anti-bot, OCR, actions and browser sessions run in closed hosted services (fire-engine, Hangar), so claims about them rest on client contracts only. [SRC] Its webhook delivery, crawl idempotency, path-secret admin routes and lexical map ranking are weaker than Verevon's and should not be copied. [SRC]

- **One strict options schema with inline formats.** Every endpoint validates against a shared strict object; `formats[]` is a tagged union with per-format options; the document returns inline with effective options echoed; a per-team permit waits a bounded fraction of the timeout. [SRC] It silently defaults `skipTlsVerification` to true unless headers or actions are present, which Verevon must not copy. [SRC] [F-t2-005](#F-t2-005) carries this and makes inline return the Zero-Data-Retention (ZDR) path.
- **Crawl scoping with typed denials and discovery.** A native Rust `filter_links` returns typed denial codes for depth, scope, domain, patterns, file type and robots; TypeScript maps each code to a message naming the option to change; robots is on by default and overriding it is an enterprise entitlement; sitemaps are seeded in parallel and URL permutations are locked before enqueue with redirect-race handling. [SRC] Quarry's live crawl has no scoping and its `CrawlFrontier` has no caller; [F-t2-016](#F-t2-016) and [F-t2-041](#F-t2-041) wire the existing code.
- **Async job and long-request contracts.** `GET /crawl/:id` pages results by cursor with per-URL errors and a robots-blocked list; cancel is a signal; a synchronous request that outlives its timeout returns a `processing_continues` 408 with a job id and `Retry-After` so an identical retry re-attaches. [SRC] Firecrawl crawls have no pause or resume and its WebSocket has no resume cursor, so those parts of [F-t2-017](#F-t2-017) come from Quarry's own Temporal signals. [F-t2-040](#F-t2-040) takes the batch and wait-or-resume shape.
- **Safe Mode and tri-state team flags.** An org policy is merged in the API layer, which rejects forbidden options, and recomputed in the worker for every URL including crawl children as a backstop that downgrades instead of trusting the request; team flags hold disabled, allowed or forced per capability. [SRC] An admin can set `allowBypassSafeMode`, so it is not strictly tighten-only. [SRC] [F-t2-022](#F-t2-022) adopts the two-layer enforcement; signed claims are Verevon's own design.
- **ZDR discipline across telemetry and caches.** A sampler returns NOT_RECORD for ZDR spans, a bounded FIFO registry catches traces flagged ZDR late, a log filter drops ZDR metadata, an inline cache-admission check excludes custom headers, actions, profiles and low-fidelity engine output, and a per-feature matrix states what degrades or refuses under ZDR. [SRC] [F-t2-004](#F-t2-004), [F-t2-003](#F-t2-003) and [F-t2-048](#F-t2-048) carry these; Verevon's gateway search cache has no org or ZDR key today.
- **Engine matrix, hedged waterfall and file handoff.** Engines declare feature flags and a quality score; candidates race under per-engine timers and the first acceptable result wins; `NeedsFeature` and `DropFeature` errors re-plan under a retry budget; files are detected by a stored reference, then Content-Type, then magic bytes, and the downloaded bytes are handed to the parser without a refetch. [SRC] [F-t2-057](#F-t2-057), [F-t2-047](#F-t2-047) and [F-t2-009](#F-t2-009) carry these; the file router is a W1 quick win.
- **Monitors and structured extraction.** Change tracking normalises content before compare, emits unified and JSON field diffs and runs a goal-aware judge; the monitor scheduler adds deterministic jitter and records `skipped_overlap` and `skipped_no_credits`; json extraction normalises the schema, uses strict `json_schema` output, runs a repair pass and picks a larger model for schemas with `$ref` or `$defs`. [SRC] The scheduler drives monitors, not generic jobs. [SRC] [F-t2-030](#F-t2-030), [F-t2-018](#F-t2-018) and [F-t2-019](#F-t2-019) carry these.
- **Tenant fairness, metering and quality loops.** A per-tenant backlog with expiry and an in-flight priority penalty returns 429 only on overflow; one pure pricing function makes failures free; a URL reputation gate runs before the first engine and on every redirect; a hermetic test site, record-and-replay fixtures and a CI matrix gate releases; a finished agent run exports as a skill. [SRC] These map to [F-t2-025](#F-t2-025), [F-t2-046](#F-t2-046), [F-t2-049](#F-t2-049), [F-t2-044](#F-t2-044) and [F-t2-051](#F-t2-051). Cached generated extractors ([F-t2-065](#F-t2-065)) were demoted to nice-to-have because Verevon should generate declarative profiles, not code.

### 7.4 Apify platform, public docs, October 2026

Apify is best as a platform substrate: least-privilege by construction, schema-driven job units, per-run storages with export, and cooperative budgets between platform and workload. [DOC] All evidence is documentation, so these are shapes to adopt, not observed code. [DOC] Its marketplace, link-by-id default sharing, unsigned webhooks and retention-only data controls conflict with Verevon's rules and are not recommended. [DOC]

- **Least-privilege tokens with scope propagation.** Tools default to limited scope, broad scopes need explicit human approval, agents are excluded from high-privilege tools, and scope propagates from caller to run to webhook. [DOC] [F-t2-036](#F-t2-036) adopts this for durable, tenant-scoped grants.
- **Charge-within-cap budgets.** The caller sets a maximum total charge; before each billable event the executor asks how many units remain chargeable; at the cap the platform aborts the run. [DOC] Quarry enforces only `max_steps`; [F-t2-008](#F-t2-008) combines this with Firecrawl's settle-once-under-row-lock for browser time.
- **Browser pool lifecycle.** A new page goes to the first active browser below `maxOpenPagesPerBrowser`; a browser retires after N pages and closes after 300 s of inactivity. [DOC] Quarry relaunches its single Chromium on any viewport change; [F-t2-007](#F-t2-007) carries this (W1 quick win).
- **Learned per-site rendering mode.** The adaptive crawler runs HTTP first, samples a fraction of requests in both modes, compares results and feeds a per-site predictor. [DOC] [F-t2-057](#F-t2-057) adds the learned mode to Quarry's planner.
- **Schema-driven job units and per-run storages.** One manifest declares input and output schemas; the same schema renders the form, validates API input and becomes the MCP tool definition; tasks are saved inputs that can be run, scheduled and shared; each run gets a dataset, key-value store and request queue with server-side export. [DOC] [F-t2-053](#F-t2-053) exposes Quarry's inert presets this way and [F-t2-052](#F-t2-052) adds result sets.
- **Hosted MCP with OAuth.** A Streamable-HTTP MCP endpoint behind OAuth loads tool groups on demand and maps every call to the same governed path as in-product calls, beside a full OpenAPI. [DOC] Verevon's OpenAPI covers 46 paths and nothing serves MCP; [F-t2-064](#F-t2-064) carries this but needs an ADR because the repo documents a deferral.
- **Secret inputs encrypted per user and tool.** A random AES-256-GCM key encrypts the value and is wrapped with an RSA key unique to the user and Actor; only ciphertext reaches logs. [DOC] This covers input fields, not browser profiles, so [F-t2-020](#F-t2-020) borrows it as a security baseline rather than parity.
- **Operations and isolation.** Webhooks carry a rich event vocabulary, payload templates and ad hoc per-run hooks; alerts fire on run status and dataset field statistics; each run gets an isolated container (technology undisclosed). [DOC] These feed [F-t2-031](#F-t2-031), [F-t2-029](#F-t2-029) and [F-t2-060](#F-t2-060); the last is an XL bet gated on the substrate ADR.
