## Appendix D. What code verification changed

Code verification read the Verevon implementation for every recommendation. Outcome: 77 recommendations kept in the list, 6 moved down one tier, 0 dropped as already built; 61 were reworded because the code showed a more precise gap, a better place to build it, or reusable parts.

### Tier changes after code verification

- [F-t2-054](#F-t2-054) Run- and turn-scoped tabs: deterministic cleanup, persisted tab sets and cold restore under a live-page budget: Recommended to Nice to have. The premise (agent-opened tabs left behind, Quarry recording turn ids) does not match the code: agents cannot open tabs, the Model Plane already closes the run at loop end, and the useful remainder (tab persistence, cold restore) depends on unbuilt prerequisites, so it belongs after durable sessions and caps.
- [F-t2-057](#F-t2-057) Engine planner v2: declared capability matrix, typed re-plan signals with budgets, learned per-domain mode and a domain-intelligence registry: Recommended to Nice to have. Partial and mostly an internal efficiency and robustness refactor with little user-visible value: per-request escalation already exists, only three drivers are registered, the registry is already planned (Phase 4), and the guidance part is placed on a channel the Model Plane treats as untrusted. Demote and narrow to the per-domain render-mode memory.
- [F-t2-061](#F-t2-061) Agent routines: scheduled, heartbeat and event-triggered agent runs with per-fire browser grants: Recommended to Nice to have. The cron foundation exists, but the distinctive parts (heartbeat, event routines, per-fire browser grants) are blocked by the Wave-3 draft-only ruling and unbuilt prerequisites (grant issuance, scheduled tool loop, ZDR lane). Keep as a later-wave item with the narrowed first slice.
- [F-t2-063](#F-t2-063) Code-mode browser control: sandboxed script runtime over typed Quarry bindings, with approval-input hardening: Recommended to Nice to have. Code-mode is already planned generically, the browser variant has unbuilt preconditions (grants, planner loop, measurements) and unproven savings, and the proposed in-process isolate conflicts with the existing sandboxed-child pattern. Keep as a later slice of the generic code-mode work.
- [F-t2-064](#F-t2-064) External contract: full OpenAPI, then an audience-bound MCP server for Quarry and read-only connectors, SDK call-and-wait and a first no-code connector: Recommended to Nice to have. The OpenAPI completeness half already belongs to F-t2-005; the MCP/n8n/CLI half reverses a documented deferral, depends on customer authentication that does not exist and has no committed consumer, so it should be a conditional later item rather than a recommendation.
- [F-t2-065](#F-t2-065) Cached declarative extraction profiles generated by the Model, with bounded browser-agent escalation: Recommended to Nice to have. Absent is confirmed, but the item is not buildable as described: the profile executor is far too weak to be the generation target, the Quarry to Model Plane inference grant is refused, and Phase B has no cost enforcement on the production step route. Keep Phase A as a later, re-sourced item and mark Phase B blocked.
