- P1 deviation: the claim carries org_id and expires_at beyond the listed {space_ref, kind, subject_id, issued_at}. org_id binds it to the request's organization (step 4) and expires_at makes it short-lived.
- P1 deviation: the envelope version is `space-kind-v1`, not `v2`. It uses the same Control key set and Ed25519 envelope, and the verifier reuses only configured_control_space_decision_keys and lookup_key. It does not reuse the Decision verifiers, which need the full decision shape and a payload digest. A distinct tag stops a decision and a claim from verifying as each other.
- P1 gap: the SPA is not wired (out of lock). It must send the row's origin_space_ref as `space_ref` (REST body) or `spaceRef` (memory.restore action input), and the memory.restore contract in src/shared/actions must accept it. Until then the claim path is inert and unknown-kind notes stay withheld, which fails closed.
- P1 deviation: RestoreMemory reads threads FOR UPDATE instead of FOR SHARE. A verdict that stamps must hold the thread row until its commit. No other transaction takes a share lock on threads (memory_declassify's FOR SHARE is on agent_memory), so no new lock-order edge with a share holder.
- P1 risk: one claim names one Space. A row linked to a personal thread that needs stamping and to a room or unrecorded thread in another Space is still refused, because only threads in the attested Space are stamped.
- P2 decision: an invalid claim (malformed, bad signature, unknown key, wrong org or subject, not personal, expired, or no key configured) is treated as absent. Only a closed reason is logged. Fail closed either way.
- P2 decision: the gateway refuses ZDR before any Control call, on the claim path only, so a restore without a hint adds no org-core dependency. model-gateway's and session-core's ZDR refusals still come first on every path.
- P2 risk: a Control outage, an older Control that returns 404, or a refusal yields no claim, so the restore refuses thread_kind_unknown. The deploy order is safe either way; deploy Control first so claims flow.
- P2 risk: a claim is replayable for its two-minute life by the same subject, against threads of the same Space. There is no nonce or consumption record. The org, subject and Space binding limits it to the owner's own rows. The route is not in the decision-audit table, since it is not an authority decision.
