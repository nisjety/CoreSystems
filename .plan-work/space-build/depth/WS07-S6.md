- P2 risk: any body-read error on csp-report (too large or a broken stream) returns 413 `report_too_large`; the plan lists only 400 and 413 and `axum::body::to_bytes` does not distinguish them cheaply.
- P2 risk: a wrong Content-Type returns 400 `invalid_report` (not 415); browsers always send one of the three accepted types.
- P2 gap: report volume is bounded only by the gateway IP rate limiter; the counter label set is closed (<= 21 directives x 3 dispositions), so cardinality is safe, but a flood still costs CPU.
- P2 risk: UNVERIFIED that Firefox/Safari accept `frame-ancestors` and `report-uri` in the Report-Only header without console warnings (frame-ancestors is ignored in report-only mode by spec; harmless).
- P3 follow-up: `CSP_REPORT_LOG_HOSTS` logs origin via tracing::info; no dedupe, so a noisy page can fill dev logs.
- P3 test-gap: nginx -t and a curl of the Report-Only header on a built image are not run (Docker not used); the nginx-headers node test (S2) does not exist yet.
