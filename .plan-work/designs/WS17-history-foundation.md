## 8. Effort and risks

**Total** about 40-58 engineer-days serial (S1 4-6, S2 3-5, S3 5-7, S4 3-4, S5 3-5, S6 4-6, S7 3-4, S8 8-12, S9 6-9). **Critical path:** WS01 S0 -> S1 -> S3 -> S5 (value: find and recall, W2-early); then D1 (OD19) + WS04 -> S8 -> S9. S2/S4 (FE) overlap their backends; S6 and S7 run in parallel after S1/S3. Build order follows the audit: paging and index before fork, tree last.

**Top risks.**
1. **A history reader missed by the tree** (silent branch mixing into prompts, learning, Dreaming). Mitigation: flag-independent `on_active_path`, source-scan allowlist test, ships dark, randomized invariant test, capability-core test.
2. **Search cost across tenants** (GIN has no org key). Mitigation: owner filter in SQL, 2 s statement timeout, EXPLAIN gate on a 20-tenant corpus in S3, fall back to a cascading side table or `btree_gin` before enabling.
3. **Prompt injection through recall** and **waived-content laundering through recall/fork**. Mitigation: `PriorConversation` trust class with screening, owner-only, current thread excluded, waived/zdr threads excluded from recall and refused for fork (D4 ruling needed), conversation-only turns exclude the tool.
4. **Hot-spot collisions** (`sessions.proto`, `grpc.rs`, `use-chat-controller.ts`, `ChatMessages.tsx`) and migration numbering against the live 0044/0045 set. Mitigation: WS01 S0 first, additive hunks, new files for new logic, integrator numbering.
5. **Backfill and `CONCURRENTLY` at boot** (S1 `UPDATE`, S3 index build inside `sqlx::migrate!`). Mitigation: document batch variant, `-- no-transaction`, test migration on a populated disposable DB, revert files.
