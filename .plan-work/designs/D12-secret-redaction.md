## 3. Design decisions

### D12-1 Where the module lives, and why `redact_sensitive` is not the seed

- Options: (a) `quarry-runtime` (where `redact_sensitive` is). Rejected: the AX projection is built in `quarry-browser`, which `quarry-runtime` depends on, so the driver could not call it. (b) `quarry-browser`. Rejected: `quarry-core` needs it for `AgentAction::redacted_for_record` and `QuarryError` masking, and `quarry-transform` (F-t2-050 PII stage) must reuse the secret-shape rules. (c) a new `quarry-redact` crate. Workable, but adds a workspace member for about 700 lines. (d) a module in `quarry-core`: `quarry-browser`, `quarry-runtime`, `quarry-edge` and `quarry-transform` all already depend on it (verified in the four `Cargo.toml` files); `regex = "1"` is already in the workspace lock through `quarry-transform`, so adding it to `quarry-core` adds no new crate.
- **Recommendation: (d) `Qcore/redaction/` [NEW]** (`mod.rs`, `shapes.rs`, `field.rs`, `luhn.rs`, `url.rs`, `json.rs`, `stamp.rs`, `action.rs`). Pure functions, no I/O, no clock, no randomness, no model call.
- `redact_sensitive` / `AgentScratchpad` stay untouched and unwired (no `lib.rs` hunk); `docs/SECRET_REDACTION.md` [NEW] states that they are superseded. Rationale: its 24-character mixed-alphanumeric rule redacts content hashes and ids, and its email rule is PII scope (F-t2-050). This deviates from the card's "reuse `redact_sensitive` as a seed" on evidence.

### D12-2 Two profiles, and what each one covers (answers "snapshots always mask, durable captures redact by shape")

`Profile::Live` is applied to everything Quarry **returns** to any caller (Model Plane, gateway, SPA), including ZDR runs. `Profile::Durable` is applied to everything Quarry **keeps or emits beyond the caller**: receipts, checkpoints, events, JSON artifacts, logs, error text.

| Rule family | Live | Durable | Why |
|---|---|---|---|
| Field-semantic: value of an editable field classified `password`, `otp`, `card`, `phone`, `secret` (input type, autocomplete token, label/name/id/placeholder regex, Luhn on the value) | yes | yes | A field value the user or agent typed is never needed by the planner and is the precondition for F-t2-024. Over-redaction risk is small and confined to values of classified fields. |
| High-confidence shapes in any string: PEM private key block, JWT, `sk-`/`sk_live_`/`rk_live_` keys, `AKIA`/`ASIA` ids, `gh[pousr]_`, `glpat-`, `npm_`, `xox[baprs]-`, `AIza`, `whsec_`, `Bearer`/`Basic` credentials, URI userinfo passwords | yes | yes | Unmistakable structure, near-zero false positives (ported from `EC/scrub.rs:47-74,82-95`). |
| Contextual shapes: labelled secret assignment (`password=`, `api_key:` ...), numeric OTP next to an otp/code/pin label, PAN-shaped digit runs (13 to 19 digits, valid issuer prefix, Luhn) | no | yes | These can be the task's subject on a live page ("read me the API key shown here", a 16-digit order number that happens to pass Luhn). Persisting them is never required. Aside draws the same line (interactive snapshot redacts only password inputs; durable capture redacts by pattern). |
| URL query and fragment secrets (keys `token`, `access_token`, `id_token`, `refresh_token`, `code`, `key`, `api_key`, `sig`, `signature`, `password`, `secret`, `session`, `sid`, `otp`, `jwt`, `x-amz-*`; fragment `access_token=`) | no | yes | The Live `url` is the user's address bar and a navigation target; masking it would break reload and the UI. The Model Plane scrubs the URL in its own prompt and event (S4). |
| `extraction_result` values | high-confidence shapes only | all Durable rules | Caller-requested data; narrow rules keep extraction working (the card's main risk). |

Marker format: `[redacted:<kind>]`, `kind` in `password|otp|card|phone|secret|token|key|credential`. The kind lets the planner know a field is filled and sensitive without a value. Counts only, never lengths, go into the stamp. Idempotence is a tested property (`redact(redact(x)) == redact(x)`).

### D12-3 Deterministic, versioned, auditable

- `pub const RULE_VERSION: &str = "qr-redact/1"`. Any rule add, remove or regex change bumps it; the golden file carries the version and a test fails if the golden and the constant disagree.
- Every rule has a stable id (`field.password`, `field.otp`, `field.card`, `field.phone`, `field.label`, `field.luhn`, `shape.jwt`, `shape.pem`, `shape.aws`, `shape.github`, `shape.gitlab`, `shape.npm`, `shape.slack`, `shape.google`, `shape.openai`, `shape.stripe`, `shape.bearer`, `shape.basic`, `shape.userinfo`, `ctx.labelled_secret`, `ctx.otp_numeric`, `ctx.pan`, `url.query`, `url.fragment`).
- Output stamp (new type `RedactionStamp`, `Qcore/redaction/stamp.rs`): `{ rule_version, profile, mode, values_masked: u32, by_rule: BTreeMap<String,u32>, probe: "ok"|"partial"|"failed"|"skipped", probe_ms: u32, screenshot: "none"|"masked"|"withheld" }`. It carries no content. Where it appears: `BrowserObservation.redaction` (Live stamp), `ProofBundle.redaction_rule_version` (so the proof manifest says which rules covered its artifact ids), `StepReceipt.redaction_rule_version` (receipt column, S3), Model Plane `BrowserObservation.redaction_rule_version` (S4). Artifact bytes carry no stamp (the artifact store has no metadata channel, `ArtifactStore::put` takes only org, run, page hash, kind and body); the proof bundle is the link.
- Regex engine: the `regex` crate (linear-time, no backtracking, so no ReDoS). One `RegexSet` pre-pass per string; replacement only on hits; strings are already bounded (1 000 bytes AX, 500 console, 500 snippet), JSON artifacts are walked leaf by leaf with a 64 KiB per-leaf cap (longer leaves are truncated to the cap before matching). Budget asserted by a test: 1 MiB of mixed text under 150 ms in release (`redaction_perf_budget`, `#[ignore]` outside `--release` runs).
- Modes (`Mode::{Enforce, Shadow, Off}`): process-wide, set once at startup by the edge (`init_mode`), default `Enforce` when never set (so library and test callers are safe by default). Shadow computes and counts but returns the input unchanged; Off is a no-op. In `ENVIRONMENT=production` only `Enforce` is accepted (edge refuses to start otherwise, same pattern as `main.rs:132-176`). Rationale for a process-wide setting rather than a field: `ObservationRunner` is built by struct literal at 7 sites (`Qedge/agent_routes.rs:2324,3140`, `Qrt/agent_loop.rs:65`, four tests in `observation.rs` at 2884, 3017, 3044, 3131) that D2/D3/D6/D8 also edit; and the memory note "gateway: AppState not env" shows library-side env reads are hazardous, so the library never reads env: only `quarry-edge` main parses `QUARRY_EDGE__REDACTION_MODE` and calls `init_mode`.

### D12-4 Field-semantic masking needs input facts: how the snapshot builder gets them, and what it costs

An AX node carries role, name, value and (in the CDP `properties` array) states such as `focusable`, `editable`, `required`, `invalid`, `autocomplete` (the ARIA token only). It does **not** carry `input type`, the HTML `autocomplete` token, `name`/`id`, or form context. So the driver must probe the DOM.

- Probe set: AX nodes that are not ignored, have `backendDOMNodeId`, and role in `textbox`, `searchbox`, `combobox`, `spinbutton` (the same roles that can hold a typed value; `is_actionable_ax_role` 1200-1225 already lists them). Hard cap 64 nodes and a 400 ms total deadline.
- Options for fetching the facts:
  - **A** `DOM.describeNode{backendNodeId, depth:0}` per node: one small CDP call each, returns `nodeName` and the flat `attributes` array (type, autocomplete, name, id, aria-label, placeholder, inputmode, maxlength). Cheapest. Needs confirmation that `describeNode` by `backendNodeId` works without `DOM.enable` on the pinned Chromium `[UNVERIFIED]`.
  - **B** `DOM.resolveNode{backendNodeId}` then `Runtime.callFunctionOn(this => ({...}))` then `Runtime.releaseObject`: three calls per node, but this exact sequence is already proven in this codebase (`execute_native_target_action`, `Qbr/chromiumoxide.rs:1232-1374`, resolves by backend id without `DOM.enable`), returns the reflected IDL values (`this.type` normalises an invalid `type` attribute to `text`), the form context (`this.form?.querySelector('input[type=password]')`) and `getBoundingClientRect()` for S5 in the same call.
  - **C** `DOMSnapshot.captureSnapshot` once per page: one call, but serialises the whole DOM (an order of magnitude more bytes on large pages) and still needs the layout flag for rects. Rejected for the live path.
  - **D** an in-page script that tags elements with a marker attribute: mutates the page and is observable by it. Rejected.
- **Recommendation:** implement a `FieldProbe` seam inside the driver with A as primary and B as fallback, chosen by the result of the Q10 recipe (D12-6, which also answers whether A works). Cost model (assumption, to be measured by `probe_ms` in the stamp): a typical form page has 1 to 8 editable nodes; with A that is up to 8 pipelined round trips, a few milliseconds to about 15 ms; with B about 3x. Pages with no editable role pay nothing. The 64-node cap bounds the worst case at roughly 64 pipelined calls (`futures::future::join_all` on the same websocket).
- Failure semantics are fail-closed on **values only**: any probe error, timeout or cap overflow marks that node `FieldKind::Unknown`, whose value is masked (name kept), and the stamp reports `probe: "partial"` or `"failed"`. Rollback switch `QUARRY_BROWSER_FIELD_PROBE=off` forces every editable value to be masked (no probe at all).
- Classification (`Qcore/redaction/field.rs`, `classify_field(&FieldFacts, accessible_name) -> Option<FieldKind>`), first hit wins: (1) `type=password` -> `Password`; `type=tel` -> `Phone`; (2) `autocomplete` tokens after stripping a `section-*` prefix and `shipping|billing` words: `current-password`, `new-password` -> `Password`; `one-time-code` -> `Otp`; `cc-number`, `cc-csc`, `cc-exp`, `cc-exp-month`, `cc-exp-year` -> `Card`; `tel`, `tel-national`, `tel-local`, `tel-area-code`, `tel-extension` -> `Phone`; (3) label regex over accessible name, `aria-label`, `placeholder`, `name`, `id` (English plus Norwegian terms because Verevon's users are Norwegian): `cvv|cvc|csc|cid|otp|one[- ]?time|2fa|mfa|passcode|passphrase|pin(?: ?code)?|ssn|social security|secret|security code|verification code|api[_-]?key|private key|iban|account number|routing number|passw|passord|passwort|contrase|mot de passe|engangskode|bankid|kortnummer|fødselsnummer|personnummer|kontonummer` -> `Secret` (or `Otp`/`Card` when the matched word says so); (4) the field value passes the PAN test (13 to 19 digits, valid issuer prefix, Luhn) -> `Card`; (5) `in_form_with_password` plus a name/id of `user|login|email` stays **unclassified** (a username is not a secret). ### S5. Screenshot masking by element rectangle (follow-on slice; fail closed)

**Goal.** No screenshot Quarry stores, forwards to the vision sidecar, embeds in a proof bundle or returns to a VLM shows the value of a classified-sensitive field; where that cannot be guaranteed the screenshot is withheld, never published unmasked. Depends on S1 (field facts and classification) and S2 (stamp).

**Verified before designing.** `ScreenshotAction` bytes come from `Qrt/observation.rs:517` (`self.browser.screenshot(session, *full_page)`); the implicit viewport capture at 654; the driver implementation `Qbr/chromiumoxide.rs:2392-2406` returns PNG bytes (`CaptureScreenshotFormat::Png`, `capture_beyond_viewport`); the PDF path 2438-2446. Neither `png` nor `image` is in `Q/Cargo.lock` (grep, 0 matches), so Rust-side masking needs one new dependency (`png`, MIT or Apache-2.0; its helper crates `flate2`/`miniz_oxide`/`crc32fast` are mostly present, `Q/Cargo.lock:2001,3473`). Quarry has no `deny.toml`; the dependency is gated by the existing `cargo-audit` CI job. The vision sidecar and every artifact consume the Rust-produced bytes, so masking in the driver's `screenshot()` masks all of them with no change at the 20 artifact-write sites (D12-5).

**Design.**

1. `Qbr/sensitive_rects.rs` [NEW]: `scan_sensitive_rects(page: &Page, deadline) -> RectScan { rects: Vec<RectPx>, unresolved_visible: u32, oopif_frames: u32, scroll: (f64,f64), dpr: f64 }`. One read-only `Runtime.evaluate` with a const script (shared with the per-node function of S1 option B so the field facts and the rectangle come from the same source) that walks `document.querySelectorAll('input,textarea,select,[contenteditable]')`, recursing into open shadow roots and same-origin iframes (accumulating the iframe offset), classifies with the page-context facts (type, autocomplete, label text) mirroring `classify_field` (the Rust classifier is authoritative: the script returns facts, not verdicts), and returns for each element visible in the viewport or page: facts, `getBoundingClientRect()` plus frame offset, and `visibility`/`display`. Rust then runs `classify_field` on the facts, keeps sensitive ones (and every editable with a non-empty value whose kind is `Unknown`, fail closed) and returns padded rectangles (4 CSS px).
2. `Qbr/screenshot_mask.rs` [NEW]: `mask_png(png: &[u8], rects: &[RectPx], opts) -> Result<Bytes, MaskError>` decodes with the `png` crate, fills each rect with a solid colour (a visible `#1f2937` block, so the model and the user can see that something was masked), re-encodes. Caps: refuse above 40 megapixels (`MaskError::TooLarge` -> withhold). Budget 10 to 30 ms for 1280x720 `[UNVERIFIED]`, measured by `mask_ms` in the stamp.
3. Chromiumoxide `screenshot()` (2392): scan, capture, scan scroll again, compare `scroll` (a scroll between scan and capture invalidates the rectangles: re-scan once, else withhold), mask, return. A new field on the stamp `screenshot: "none"|"masked"|"withheld"` plus `mask_ms` travels through a new `BrowserDriver::screenshot_masked(&self, session, full_page) -> QuarryResult<MaskedScreenshot { bytes: Option<Bytes>, state: ScreenshotState, rects: u32 }>` (default impl calls `screenshot` and reports `none`, so the non-native drivers and the test doubles keep compiling). `observation.rs:517,654` call `screenshot_masked`; a `withheld` result omits `screenshot_artifact_id`, skips the vision sidecar and the artifact writes for the image family (686-834), and adds a typed `policy_denials`-style note `screenshot_withheld:sensitive_field_unresolved` to the observation (a non-error). The explicit `Screenshot` action returns `ErrorCode::SecurityBlocked` (403; `Qcore/error.rs:49`) with the same reason when withheld, so the model can react instead of silently receiving nothing.
4. Rules, by situation: sensitive field visible, rect resolved -> masked; sensitive field visible, rect unresolved (frame offset unknown, zero-size rect on a visible element, probe error) -> withheld; no sensitive field present -> unmasked; `type=password` hidden by `display:none` -> ignored; cross-origin iframe on the page (`oopif_frames > 0`): not scannable from the page session `[UNVERIFIED]`; default policy **allow with the count in the stamp**, strict policy `QUARRY_BROWSER_SCREENSHOT_OOPIF=mask` blanks every cross-origin iframe rectangle (safe, visually heavy). `AgentAction::Pdf` is withheld when any classified field has a non-empty value (`typed_field_kind` plus the same scan; printing renders input values).
5. The live frame stream (`/v1/agent/runs/:id/frames/*`) is the owner's own view and is not masked here (a JPEG screencast would need decode/encode per frame); it is the exposure to settle in the Space interface (section 7a): a Space member watching another member's browser must not see a typed password, which is a Space-product decision, not an in-slice fix.

- **No direct database crossing.** Confirmed: the only SQL is Quarry's own `quarry_step_receipts` column and an optional Quarry-owned log table.
- **Model proposes, Quarry executes or rejects.** Respected and strengthened: the model never receives a typed secret's value back, and the model's own typed value (its proposal) is masked in the durable record by Quarry, not by the model. S5's withheld screenshot and the F-t2-024 executor-side fill extend the same rule. The stop-criteria and `done` decisions in the Model Plane read the raw observation in memory only, never persisted unscrubbed (`grpc.rs:1015-1042`).
- **ZDR must propagate through every content-persisting boundary.** Masking is **independent of the ZDR flag** (D12-10): Live observations are masked on ZDR runs too (they are returned although nothing persists), Durable masking applies to events, logs and errors always and to receipts, artifacts and checkpoints whenever they are written (non-ZDR). Boundaries covered: receipts (S3), checkpoint URL (S3), events (S2), JSON artifacts (S2), image artifacts (S5), logs (S6), errors (S2), planner prompt and events (S4). Boundaries **not** covered here and owned elsewhere: Quarry telemetry spans (D10 S8), the gateway in-memory `last_observation` and session cache (D9/D4), the Model Plane checkpoint (already scrubbed at `grpc.rs:1042`), the live frame stream (open question 4), scrape artifacts (F-t2-050). **Rule at risk:** the live frame stream and an OOPIF credential field in screenshots are the two places this design cannot guarantee (both marked `[LIMIT]`).
- **Channel Plane** is not touched.

## 8. What can proceed WITHOUT an ADR/decision, and what is blocked

**Proceeds now (no ADR):** S0, S1 (after the Q10 recipe, which is a measurement, not a decision), S2 (staging in shadow first), S3 with the default receipt policy `sensitive` (reversible by flag), S4, S6. These are tightenings: they only mask, they add optional fields, and every rollback is "previous image".

**Needs a product decision, not an ADR:** the default receipt text policy `sensitive` versus `all` (question 2); URL masking in Live observations (question 1); legacy-row rewrite (question 3, S7); screenshot OOPIF policy and member-visible live frames (question 4). S5 can start with `allow` plus the stamp count, so it does not wait for question 4.

**Blocked by ADR:** F-t2-024 E3 and E5 (custody, audit 9.3 topic 2). E1 and E2 (fill_otp contract and approval card) are blocked by **other items** (F-t2-001, F-t2-013, F-t2-015), not by an ADR. No other part of this design is ADR-gated; D12-1 to D12-13 are engineering decisions with recommendations.

**Not gated but not started here:** F-t2-050 (PII), F-t2-020 (cookie/profile storage encryption).

## 9. Open questions for the user (only real blockers)

1. **Live URL masking.** The Live `BrowserObservation.url`, `ObservationReady.url` and `ProofBundle.source_url` stay raw in S2 except the event URL (masked), because masking the address-bar value would break reload and navigation; the Durable profile and the Model Plane prompt strip query tokens. Accept raw URLs in the returned observation, or require token stripping there too (which breaks magic-link and OAuth-callback flows in the UI)? Recommendation: accept raw in Live, strip everywhere durable.
2. **Receipt typed-text policy.** `sensitive` keeps benign typed text (search queries, form fields that are not classified) in receipts for audit and procedure compile; `all` masks every typed string and makes compiled procedures replay-useless (`RepairRequired` on every typed step). Recommendation: `sensitive` default, `all` per org later. Needs the product owner before S3 merges.
3. **Legacy data.** Mask on read only (default, S3), or also a destructive one-shot rewrite of old receipts (S7), which conflicts with append-only evidence? Recommendation: read-time masking only. Screenshots written before S5 cannot be re-masked: accept retention-based expiry?
4. **Who may see a live browser frame containing a typed secret?** The owner's frame stream is unmasked (a limit of S5). Should Space members get a masked stream (later slice), receipts only, or the same unmasked view as the owner with a visible "secret field" notice?
5. **Strict screenshot mode for cross-origin iframes** (`QUARRY_BROWSER_SCREENSHOT_OOPIF=mask`): default `allow` leaves payment/login fields inside out-of-process iframes visible in screenshots (counted in the stamp, not scannable). Is that acceptable for non-ZDR default deployments, or should the default be `mask`?
