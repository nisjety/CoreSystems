## 2. Verified current state

### 2.1 What the driver does today (all [C] unless noted; `Qbr/chromiumoxide.rs` is 3551 lines and has NO uncommitted edits)

**One browser, identity includes the viewport.** `ChromiumoxideDriver` holds `browser: Arc<Mutex<Option<Browser>>>` (117), `handler` (119), `active_viewport: Arc<Mutex<Option<BrowserViewport>>>` (120), a single-slot `live_frame_cache` (122, `CachedLiveFrame` at 80) and a global `page_epoch` (121). `ensure_browser(viewport)` (194-271) returns early only when a browser exists AND `*active_viewport == viewport` (197). Otherwise it closes the browser (200-204), aborts the handler task (205-207) and clears `pages`, `devtools_events`, `egress_receipts`, `egress_sequence`, `egress_policies`, `proxy_receipt_cursors`, `session_telemetry`, `dialogs`, `dialog_pages` and the live-frame cache (208-217). It launches a new Chromium with `builder.viewport(...)` only when `Some` (244-246). `None != Some(1280x800)` is a mismatch.

**Where it runs.** `acquire` (1914-1942, `ensure_browser` at 1925), `goto` (1988-2015, `ensure_browser` at 1991 on EVERY navigation) and `open_tab_page` (371-557, `ensure_browser` at 378). So two sessions with different viewport options ping-pong: B's `acquire` relaunches and kills A's tabs; A's next `goto` relaunches again and kills B. After a kill, A's next action fails `chromiumoxide: no current page; call goto() first` (358-365, a non-retryable `DriverFailed`).

**Who sends which viewport.** Model Plane `execution-core/src/quarry_agent.rs` [C] and `browser_agent.rs` [C] contain no `viewport` string, so a Model Plane run starts with `viewport: None` (checked by grep). The gateway `FE/apps/gateway/src/domains/browser.rs` [C] uses `body.viewport.unwrap_or(DEFAULT_VIEWPORT)` (463, `DEFAULT_VIEWPORT` = 1280x800 at 345-348) and always puts a viewport into the start body (489-492); the SPA literal is `FE/src/features/dashboard/home/KnowledgeComposer.tsx` [M] line 817 (hunks at 542, 1172, 1755-1757 do not touch it). `[DRIFT]` the card says the gateway "always sends 1280x800": it sends 1280x800 unless a client supplies another viewport. Quarry's `normalize_viewport` (`Qedge/agent_routes.rs` [C] 1897-1915) keeps `None` as `None` and accepts 320x240 to 3840x2160; a resumed run inherits `checkpoint.viewport` (1447-1452).

**[NEW FINDING] `None` is not "no emulation".** chromiumoxide 0.9.1's `BrowserConfigBuilder` defaults `viewport: Some(Viewport::default())`, which is 800x600 with touch emulation on (registry source `chromiumoxide-0.9.1/src/browser/config.rs:154` and `handler/viewport.rs`; `handler/emulation.rs` `init_commands` issues `Emulation.setDeviceMetricsOverride` + `setTouchEmulationEnabled(true)` to every new target). The driver passes a viewport only when the lease has one, so a Model Plane run today runs at 800x600, not at the browser default. Moving `None` to a fixed 1280x800 changes what every Model Plane run renders; see decision D3-2.

**No hygiene calls.** There is no `Emulation.setFocusEmulationEnabled`, `Page.setWebLifecycleState` or `Emulation.setDeviceMetricsOverride` anywhere in the quarry crates (only `wreq::Emulation` in quarry-tls, which is TLS fingerprinting). The cdp types exist in the pinned crate (`chromiumoxide_cdp-0.9.1` `cdp.rs`: `SetFocusEmulationEnabledParams` 53715 and `SetDeviceMetricsOverrideParams` 53984 in `emulation`, `SetWebLifecycleStateParams` 91883 in `page`, `ScrollIntoViewIfNeededParams` 43673, `GetContentQuadsParams` 44208, `DispatchKeyEventParams` 62456, `InsertTextParams` 62723).

**[NEW FINDINGS] resource and crash behaviour of the single browser.**
- The per-launch directories made by `chromium_launch_dirs` (888-905: `<QUARRY_BROWSER_PROFILE_ROOT>/profiles/edge-<pid>-<nanos>` and `crashpad/...`) are never removed (grep for `remove_dir` in the file finds nothing), and `ensure_browser` calls `browser.close()` but never `browser.wait()`. Each relaunch leaks a profile directory.
- There is no crash detection. The handler task (261-265) just drains events; when the Chromium process dies the task ends, `guard.is_some()` stays true, nothing relaunches, and every session on that driver fails until the edge restarts.
- `close_run` (`Qedge/agent_routes.rs` [C] 3562-3640) releases the driver session only when `Arc::try_unwrap(entry_arc)` succeeds; on `Err(_still_in_use)` (3629, 3646) it logs "session will drop on last ref" but `BrowserSession` has no `Drop` that releases driver state, so the pages and CDP context stay in the driver maps forever. A driver-level backstop is therefore not redundant with the edge reaper. (D2's `finish_run` removes this particular leak by releasing a clone of the session instead of relying on `try_unwrap`; the driver backstop remains for the other paths: a client that vanishes between `acquire` and the registry insert, a crashed handler, and any future caller that forgets to release.)
- `step` holds the per-run `TokioMutex` for the whole action (`agent_routes.rs` 2248 `entry_arc.lock()`), and `close_run` also takes that lock (3583, 3594), so one hung CDP call blocks both further steps and close until the 60 s router `TimeoutLayer` (`Qedge/routes.rs` [M] 81) drops the future.
- Two `ChromiumoxideDriver` instances exist in production: the scrape-render one inside `BrowserDriverAdapter` with `RuntimeLeasePool::new(2)` (`Qedge/main.rs` [M] 331-340, `new()` at 334) and the agent one (`main.rs` 1284-1288, constructed with the profile store) that serves every `/v1/agent/runs` route. The in-app UI session posts to `/v1/agent/runs` (`browser.rs` 503-506), so UI sessions and Model Plane runs share `agent_driver`; the collision is on that instance only. The scrape instance always acquires with `viewport: None` (`Qrt/browser_driver.rs` [C] 156) and never relaunches for viewport reasons.
- The `RuntimeLeasePool` sizes 2 and 4 (`main.rs` 323, 337) gate only scrape rendering (`browser_driver.rs` 137-142). `Qbr/pool.rs` `LeasePool<D>` (32-38) and `Qbr/persistent_session.rs` `PersistentSessionRegistry` (81) are UNWIRED (only their own tests use them), so the JSON reuse note "LeasePool for the scrape path" points at dead code.

**Health.** `Qedge/routes.rs` [M] 309-311: `health()` is a static `"ok"`; `ready()` (312-326) checks `state.readiness.durable` only and returns JSON (`{"status":"ready","durable":true}` / 503). `[DRIFT]` `Q/docs/openapi.yaml` [M] lines 32-43 document `/ready` as `text/plain` "ready". **Deadlines (F-t2-026).** Explicit timeouts exist only for downloads (`DOWNLOAD_BEGIN_TIMEOUT` 10 s and `DOWNLOAD_COMPLETE_TIMEOUT` 30 s, lines 76-77, used at 2286 and 2302), the live-frame screencast (caller `timeout_ms`, 1734) and the profile capture (`timeout(Duration::from_secs(5), capture_snapshot)` at 685). `BrowserConfig::builder()` (226-262) sets no `request_timeout` or `launch_timeout`, so every other command rides chromiumoxide's `REQUEST_TIMEOUT` 30 s (`handler/mod.rs` 34) and `LAUNCH_TIMEOUT` 20 s (`browser/config.rs` 15). ## 3. Design decisions

Tag legend: "ADR-GATED n" names the audit section 9.3 topic number that must be decided first. Everything not tagged can be built now.

### D3-1 Remove the viewport from browser identity; apply it per page (F-t2-007 A)
- Options: (a) per-page `Emulation.setDeviceMetricsOverride` at attach, launch Chromium once with no viewport; (b) one Chromium per distinct viewport (no kill, but capacity multiplies and ping-pong becomes a process-churn problem); (c) `Browser.setWindowBounds` per window (window size, not device metrics; does not fix `innerWidth`/DSF determinism).
- Recommendation: (a). Always launch with `.viewport(None)` so chromiumoxide's handler stops applying its 800x600 default to every target (see section 2.1), then in `open_tab_page` immediately after `browser.new_page` send `Emulation.setDeviceMetricsOverride { width, height, deviceScaleFactor, mobile, screenOrientation }` (plus `Emulation.setTouchEmulationEnabled` when `is_mobile`) built from the lease viewport. The override is per CDP session, survives navigation and renderer swaps, and is applied before the first `goto`, so no reload is needed.
- Rationale: it removes the kill with a handful of CDP calls and keeps `BrowserLease.viewport` semantics (the lease doc comment at `Qcore/lease.rs` 19-22 only needs to say "per page"). `ensure_browser` stops taking a viewport; `goto` stops calling it (line 1991).

### D3-2 What `None` means (behaviour change to be acknowledged)
- Options: keep the effective 800x600; fix to 1280x800 DSF 1 (matches the gateway `DEFAULT_VIEWPORT` and `default_stream_viewport` at `agent_routes.rs` 1917-1924); 1440x900 (Aside's AI-tab floor).
- Recommendation: 1280x800, DSF 1, desktop, resolved in one function `resolve_viewport(Option<BrowserViewport>) -> BrowserViewport` in `Qbr`, overridable with `QUARRY_BROWSER_DEFAULT_VIEWPORT=WxH` (set `800x600` to restore today's Model Plane rendering). Every lease then has a fixed viewport, which is the precondition for deterministic hit-testing in S10.
- Consequence: Model Plane runs will render at a larger viewport than today (more content per screenshot, different responsive breakpoints, larger PNGs). It is a deliberate product-visible change; section 9 asks the user to acknowledge it. Not an ADR.

### D3-3 Page hygiene set (F-t2-007 A)
- Per page at attach, in this order: device metrics (fatal on failure: coordinates must be deterministic), `Emulation.setFocusEmulationEnabled(true)`, `Page.setWebLifecycleState(active)` (both non-fatal, log at warn once per page). Placement is before the devtools collectors, dialog collector and Fetch guard so those start on a configured page; the Fetch guard stays before any navigation exactly as today (`install_network_guard` 498-506).
- Kill switch: `QUARRY_BROWSER_PAGE_HYGIENE=0` skips the two non-fatal calls only; the viewport application is not switchable (a revert is the rollback).
- Not added: `Target.setAutoAttach` flatten (chromiumoxide already manages sessions), `Page.enable`/`Network.enable` (the collectors already enable what they use).

### D3-4 Who owns capacity, reaping and health (coordination with D2: F-t2-006 and F-t2-025)
| Concern | Owner | Why |
|---|---|---|
| Run registry (`RunRegistry`, `RunSlot` reserved before `acquire`, D2 S4), per-org / per-actor / global concurrent-run caps at `start_run` with typed 429 and `retry_after`, run idle and absolute TTL sweeper calling the shared close helper (timeline event, checkpoint close, receipts, optional grant revoke), `RunEntry.last_activity`, fleet console, budgets, fair share | D2 | These are run-lifecycle and tenant policy; they need receipts, grants and checkpoints that live in the edge |
| Driver resource backstop: global `max_sessions` and per-slot `max_pages` enforced inside `acquire`; idle reaper for driver sessions nobody released; crash detection and slot relaunch; page-opening health probe; `/ready` browser section; process retirement and launch-dir cleanup | D3 (this document) | These protect the host process from leaks that the edge cannot see: `close_run`'s `Err(_still_in_use)` branch, a handler that exits, a client that vanished between `acquire` and run insertion |
| Interface | shared | The driver returns `QuarryError { code: RateLimited, details: { reason: "browser_session_cap" | "browser_page_cap", scope: "driver", limit, active, retry_after_seconds } }` (the same `details` shape D2 uses for its run caps, with `reason` values that cannot collide with D2's `org_run_cap | org_interactive_run_cap | global_run_cap`; `retry_after_seconds` is the field name `ApiError` already uses, `Qedge/api_error.rs` [C] 22); `start_run` already maps driver errors through `driver_err` (1515), so no D2 change is needed for correct propagation. D2's global run cap must be set at or below `QUARRY_BROWSER_MAX_SESSIONS`; the driver exposes its limits in `BrowserDriver::health()` so D2 can log a WARN at boot when the numbers conflict |
| Reaper ordering | rule | The driver reaper acts only on a session with no driver call for `QUARRY_BROWSER_SESSION_IDLE_S` (default 3600 s) or older than `QUARRY_BROWSER_SESSION_MAX_AGE_S` (default 21600 s). D2's design (`designs/D2-quarry-run-control.md` D7) sets agent idle 300 s, interactive idle 900 s, takeover idle 1800 s, agent ceiling 1800 s and interactive backstop 14400 s, and its sweeper always releases through `finish_run`; the driver defaults sit above every one of those (at least 2x the largest idle TTL and above the 14400 s backstop) so D2's authoritative close (receipts, checkpoint, `agent.expired` event) always runs first. The driver reaper is a leak backstop and writes no receipts. It deliberately does NOT use the lease `ttl_s` (the gateway sets 120 s on UI sessions, D2 section 2). `release` must be idempotent because D2's `finish_run` releases a `BrowserSession` clone and the reaper may have released it already |
Live-frame polling and any driver call count as a touch, so a session a person is watching is never reaped.

### D3-5 One process with caps, then an optional K-process pool (F-t2-007 B) - isolation claims ADR-GATED 10
- Options: (a) one Chromium, admission cap, idle reaper, crash relaunch, retirement; (b) K lazily launched Chromium processes ("slots"), a session pinned to one slot for its lifetime, retire-after-N pages; (c) a container or microVM per session or tenant (F-t2-060, XL).
- Recommendation: build the slot bookkeeping once as a pure, Chromium-free structure (`SlotBook`, section 4 S5) and ship (a) as `K = 1` first (S5); add (b) in S6 as `QUARRY_BROWSER_POOL_SIZE`, default 1, raised only after a measured memory budget. (c) stays F-t2-060.
- A pool is crash containment and capacity, not tenant isolation: all sessions of all orgs in a slot still share one renderer-process family, so no isolation claim may be made from S6. ADR-GATED 10 (execution substrate) governs isolation and remote or per-tenant slots.
- Slot struct (Rust, in `Qbr/slots.rs` [NEW] for bookkeeping and `chromiumoxide.rs` for the process handle):
  - `SlotId(u32)`; `SlotStatus { Starting, Ready, Retiring, Dead }`.
  - `SlotState { id, generation: u64, status, open_pages: u32, pages_served: u32, sessions: HashSet<String>, launched_at: Instant, last_used: Instant, last_probe: Option<ProbeResult> }` (pure data, std types only).
  - `SlotBook { cfg: SlotConfig, slots: Vec<SlotState>, session_slot: HashMap<String, SlotId>, last_touch: HashMap<String, Instant> }` with `admit(session_key, now) -> Admission { Admit { slot, launch_needed } | Busy { retry_after, scope } }`, `page_opened(slot)`, `page_closed(slot)`, `release(session_key)`, `touch(session_key, now)`, `reap_idle(now) -> Vec<Reaped>`, `retire_candidates() -> Vec<SlotId>`, `mark_dead(slot, generation) -> Vec<String>` (affected sessions). It sits behind a `std::sync::Mutex` that is never held across an await.
  - `BrowserSlot { id, browser: tokio::Mutex<Option<Browser>>, handler: tokio::Mutex<Option<JoinHandle<()>>>, launch_dirs: Mutex<Option<ChromiumLaunchDirs>>, transport: SlotTransport }` and `enum SlotTransport { LocalProcess }` (a `RemoteCdp { ws_url }` variant is deliberately not written; it is the F-t2-059/060 seam and needs ADR 10 first).
  - Driver fields that stay driver-global because they are already keyed by `session_key`: `pages`, `devtools_events`, `egress_receipts`, `egress_sequence`, `egress_policies`, `proxy_receipt_cursors`, `session_telemetry`, `dialogs`, `dialog_pages`. `[CLAIM partly false]` the card's risk "re-key driver-global maps per slot without breaking receipt ordering" is overstated: those maps are already per session; `ensure_browser` clears them only because it kills every page. Moving a session between processes is not supported (page handles are process-bound), so receipt ordering is untouched. The only truly global mutable state is `live_frame_cache`/`page_epoch` (see D3-17).
- Egress invariants carried over unchanged: every slot launch uses the same argument builder, so `--disable-quic` is present whenever `pinned_egress_proxy.is_some()` (today 237-243); every browser context still gets its proxy from `provider.endpoint_for_session(session_key)` with `proxy_bypass_list("<-loopback>")` (404-415); `PinnedEgressProxyEndpoint::parse` (`Qbr/lib.rs` 330-367) stays loopback-only and is NOT relaxed here (a sidecar proxy type or reviewed relaxation is ADR 10's decision, audit 9.3 item 10).
- Retirement hygiene: when a slot retires or dies, `wait()` the child, then `remove_dir_all` its `ChromiumLaunchDirs`; on edge start remove stale `edge-*` directories under `QUARRY_BROWSER_PROFILE_ROOT` whose pid is not the current process. This also bounds any Chromium disk state a ZDR session could have touched.

### D3-6 Health probe behind `/ready`, not `/health` (F-t2-007 B)
- Options: probe on request (rejected: `/ready` and `/health` are unauthenticated, so a request that creates browser pages is an amplification vector and ties up the request); a background prober with a cached snapshot (recommended).
- Design: each launched slot has a prober task every `QUARRY_BROWSER_PROBE_INTERVAL_S` (15). The probe opens `about:blank` in a throwaway browser context created through the SAME helper as session contexts, so it also gets the pinned proxy endpoint (`endpoint_for_session("probe:<slot>")`) and a deny-all egress policy, preserving the invariant "no browser context exists outside the pinned proxy" (the page never navigates), then closes the page and disposes the context, all under a 3 s deadline (`Op::HealthProbe`). Two consecutive failures mark the slot `unhealthy`; an unhealthy slot with no sessions is retired and relaunched on demand; one with sessions is left running (never kill live work on a probe).
- `BrowserDriver` gains `async fn health(&self) -> BrowserHealth` (default `NotApplicable`), reading the cached snapshot only. `/ready` (`Qedge/routes.rs` [M] 312-326) keeps its durable check and adds a `browser` object (state, slots launched, sessions open, max_sessions, per-slot `open_pages`, `retiring`, `last_probe_age_s`, no ids): 503 only when the `browser-agent` feature is compiled, at least one slot has launched, and every launched slot is unhealthy or dead. Never-launched is ready (a cold edge must not flap). `/health` stays the static liveness string and the Docker `HEALTHCHECK` stays on it, so a wedged Chromium degrades readiness without restarting the container.
- `[DRIFT]` `Q/docs/openapi.yaml` [M] documents `/ready` as `text/plain`; the code already returns JSON. S5 corrects the schema.
- Why not `AppState`: a new field needs edits at four construction sites including `test_support.rs` [M] and `tests/support/mod.rs` [M] (hotspots). The trait method on the existing `state.agent_driver` needs none.

### D3-7 Crash behaviour
- The handler task is changed from "drain events" to "drain events, then on stream end call `book.mark_dead(slot, generation)`". Affected sessions get a typed `DriverFailed` with `details { reason: "browser_process_lost" }`, `retryable: false`; their per-session maps stay until `release` so the edge can still close them. The next `acquire` launches a new generation. Sessions are never silently migrated (page state is lost; a run resumes through the existing checkpoint path, `start_run` 1425-1564).

### D3-8 CDP deadlines, bounded attach, retry-once (F-t2-026)
- Architecture, in order of value: (1) set chromiumoxide `request_timeout` (15 s) and `launch_timeout` (20 s) explicitly in the builder (today absent, 226-262) as the safety net for all 64 call sites; (2) `Qbr/deadlines.rs` [NEW]: `enum Op` (one variant per operation), `const fn deadline(op) -> Duration` (one table), `fn cdp_err(op: Op, e: CdpError) -> QuarryError` (maps `CdpError::Timeout` and everything else to typed errors in one place) and `async fn with_deadline<T>(op, fut)`; (3) a `read_with_retry(op, || fut)` helper used only for `content`, the AX snapshot (`native_page_projection`) and read-only `evaluate`.
- Error shape: `ErrorCode::Timeout` (HTTP 504, existing; no new wire code) with `details { "op": "<name>", "deadline_ms": n, "effect": "none" | "unknown" }`. `Timeout` is `retryable` by default (`Qcore/error.rs` 38-43); for effectful operations the wrapper sets `error.retryable = false` (the field is public, `error.rs` 70) so a hung click is never blindly replayed. Details carry no URL, selector or page text.
- Starting deadlines (calibrate before tightening; no latency histogram exists in the repo today, `BrowserTelemetry` carries only `startup_latency_ms` and `usable_observation_latency_ms`, so S3 adds a debug-level duration log per op as the calibration source): launch 20 s (outer 25 s); tab attach (context + page + hygiene + guards) 15 s; navigate (`Page.navigate` response) 30 s; content 15 s; AX snapshot 10 s; screenshot 10 s; pdf 30 s; evaluate 15 s; input dispatch 5 s; native target resolve + action 10 s; `wait_for` min(caller, 30 s) with each `find_element` poll bounded 2 s; page/context close 5 s each; probe 3 s; profile capture 5 s (existing); download begin 10 s and complete 30 s (existing, moved into the table). Codex's 20 s / 15 s / 5 s are a reference, not a calibration.
- Bounded attach must clean up: `open_tab_page` creates a context and a page before it finishes; on timeout the wrapper closes the page and, if this call created the context, disposes it, then returns the typed error. It also releases the `browser` mutex that today is held across the whole function (379), so one stuck attach no longer blocks every other session's attach.
- Retry rule: retry once after a short (100 ms) pause only when the error text is a destroyed-context signature (`Cannot find context with specified id`, `Execution context was destroyed`, `Inspected target navigated or closed`) and only for the three read helpers. Never retry navigate, click, type, select, press, upload, download, respond_dialog, or any ref/coordinate action: the Model Plane already refuses to retry `browser.act` (`MP/.../permission/mod.rs` 261-271) and a replay could double-submit.
- Step-level interplay (coordination, not D3-owned): the per-op deadlines can sum past the 60 s router `TimeoutLayer` (`Qedge/routes.rs` 81). Recommend D2/runtime add a step budget around `ObservationRunner::execute` (about 50 s) so the typed `Timeout` arrives before the untyped 504 and before the run lock is dropped mid-effect.

### D3-11 The closed block taxonomy (F-t2-027)
- Strong signals, `BlockReason` (closed, snake_case on the wire): `captcha_widget` (a rendered captcha or Turnstile/hCaptcha/reCAPTCHA widget or its iframe), `waf_interstitial` (a vendor challenge page identified by DOM, URL or title markers, such as Cloudflare "Just a moment" or `challenges.cloudflare.com`, Akamai, HUMAN/PerimeterX `px-captcha`, DataDome, Imperva/Incapsula, AWS WAF captcha; never by status alone), `challenge_loop` (the same strong fingerprint, reason + host + title hash, seen at least twice in one run after the single permitted recovery), `unexpected_bot_error` (served text states automated or unusual traffic was detected, requiring two independent markers).
- Non-signals, `ChallengeStrength::NonSignal`, never promoted: `bare_status` (403, 429 or 503 on an ordinary document with no strong marker), `rate_limited` (429, `Retry-After`, "too many requests": slow down, not a block), `auth_required` (sign-in, 401), `consent_required`, `paywall`, `geo_blocked` (451, region text), `server_error` (5xx), `timeout`.
- Wire (additive, `#[serde(default)]`): `ChallengeSignal` gains `strength: ChallengeStrength { strong, weak, non_signal }` and `block_reason: Option<BlockReason>`; `ChallengeKind` gains `Paywall` and `GeoBlocked` (the existing `Waf` finally gets produced); `requires_escalation` is true only for `strong`; the constant 0.98 confidence is replaced by marker-class confidence (structural DOM marker 0.95, vendor title or URL marker 0.85, text marker 0.6, non-signals at most 0.5). Existing consumers keep working: Model Plane does not parse the field today, the SPA type does not declare it, and `Q/docs/openapi.yaml` [M] types `challenge` as an open object (2606-2609), so S7 also gives it a real schema.
- Input: move `classify_challenge` out of `observation.rs` into `Qrt/challenge.rs` [NEW] (this also shrinks the overlap with F-t2-015/021/034, which edit `observation.rs`), and classify from URL + title + vendor markers found in the page HTML the runner already fetches (`content`, observation.rs 607) + the main-document HTTP status taken from the response events already collected (`normalize_response_event`, `chromiumoxide.rs` 1545-1589) + the existing text snippet. The 500-character snippet alone cannot see an iframe or a status. `[UNVERIFIED]` the 500-char byte-index panic in `text_snippet` (observation.rs 2140-2141, F-t2-034's finding) should be fixed by whoever lands first because the classifier input passes through it.
- Honest limit: marker lists age, and a table of constants cannot be proven complete; the test corpus (section 4 S7) is the quality bar, and unclassified blocks surface as `unknown` plus the real HTTP status, never as a guess.

### D3-12 One recovery: Quarry enforces, the Model proposes
- Options: (a) Quarry silently performs a wait and a reload when it sees a strong signal; (b) the Model may propose at most one low-risk recovery and Quarry counts and rejects the rest.
- Recommendation: (b). A Quarry-initiated reload is an action the Model did not propose (it breaks "Model proposes, Quarry executes or rejects") and `Page.reload` can re-submit a POST. State lives in `ObservationContext` (in memory, per run): per host `{ strong_seen: u8, recovery_used: bool, last_fingerprint }`. After a strong signal the observation reports `recovery: "available"`; after the one allowed recovery (a `Wait` up to 5 s followed by one same-URL `Navigate`) a second strong signal with the same fingerprint becomes `challenge_loop`; from then on `Navigate` and clicks that lead to the same host are rejected with `ErrorCode::ChallengeDetected` (existing code, 403) with `details { reason, host, recovery: "exhausted", next: "user_takeover_or_other_source" }`. Observation-only actions, screenshots and human takeover stay allowed.
- Hostname aggregate telemetry (audit): in-memory only, `(reason, host) -> count`, no URL, path or content; for ZDR runs count by reason only and never log the host. No persistence in W1 (no migration; if a durable domain registry is wanted later it is a separate item and the next free migration number would be 0010).

### D3-13 Narrowing the live evasion-adjacent paths ("honest" mode) - ADR-GATED 5
- What is shipped and decided by the ADR: bare 401/403/407/429/503 currently trigger (a) rotation to the next driver and thus the Chrome-TLS-fingerprint driver (`fallback_driver.rs` 95-108), (b) proxy rotation (`fetch.rs` 237-285, `egress_broker.rs` 149), (c) caller-forced tiers via `prior_block_signals` (`driver_plan.rs` 40, 45-46), (d) the "stealth" preset wording.
- Proposed rule (to be confirmed by ADR 5): a status is never an identity-change trigger. Keep: host slow-down (AIMD, autoscaler), `Retry-After` honouring, same-identity backoff retries for 429 and 503, and proxy health rotation on TRANSPORT failures only (`mark_transport_error`; that is reliability, not evasion). Remove: rotation on status, the TLS-fingerprint fallback as a block reaction, and request-controlled `prior_block_signals` forcing (keep the field accepted for SDK compatibility, ignore it, document it as deprecated). Whether the Chrome-TLS driver stays registered for non-block reasons is an ADR question.
- Mechanism now, behaviour after the ADR: S8 centralises the triggers in one function `escalation_allowed(trigger)` behind `QUARRY_BLOCK_ESCALATION=legacy|honest`, default `legacy`, so S4 and S7 do not wait for the ADR and the flip is a one-line default change after approval.
- Preset: rename "stealth" to a neutral id (for example `careful`) with `stealth` kept as a deprecated alias for one release (the id is a public API value: `GET /v1/presets/stealth`, `presets_test.go` 51-107, SDKs), and change its unused `Block` to `{ on: challenge, action: abort }`. Product decision, ADR-GATED 5.

### D3-14 Actionability pipeline and trusted input (F-t2-015, W2)
- Where: inside `ChromiumoxideDriver::act_on_verified_target` for native targets (`act_on_verified_target` 2026-2101 -> `execute_native_target_action` 1232-1374), implemented in `Qbr/actionability.rs` [NEW] with pure decision functions (unit-testable without Chromium). **Definition of done.** With the flag on, a click on a ref covered by an overlay fails `TARGET_REPAIR_REQUIRED` with `details.reason = "target_covered"` and a tag, the same click succeeds after the overlay is dismissed, `event.isTrusted` is true in the page, governed downloads and uploads behave exactly as before, and the actionability-failure rate per reason is logged.

Repeat with the flag off and show the old behaviour (silent no-op or an unverified postcondition). [UNVERIFIED] availability and stability of the public test page; if absent, state that only the live-lane fixtures back the claim.

**Effort.** M (8 engineer-days: pipeline 4, live tests 2, contract and docs 1, evidence and soak setup 1).

**Risks.** A click that opens a modal dialog can stall the input acknowledgement (handled above). Reasons change the failure text the Model reads: sibling session (b) owns the planner sentence that tells it to dismiss an overlay or scroll and re-observe rather than loop.

## 6. Plane ownership, ZDR propagation and Model-proposes/Quarry-executes check

- **Plane ownership.** Every D3 slice is inside the Ingestion Plane (quarry-browser, quarry-runtime, quarry-core, quarry-edge, Quarry compose, the Quarry control preset). The only cross-plane edits are S9's Model Plane, gateway and SPA changes, which consume Quarry's additive fields through their own contracts and are owned by the sibling sessions. There is no database in any D3 slice (no migration; the next free Quarry migration is `crates/quarry-runtime/migrations/0010_*.sql`, unused) and no cross-plane DB access. The admission cap is a host-resource guard, not a quota or entitlement: per-org capacity and plan quotas stay with Control Plane and F-t2-025 (D2). Policy of record (ADR 1) is untouched.
- **Model proposes, Quarry executes or rejects.** Respected, and in two places chosen for it: S7 enforces the single recovery by counting and rejecting, not by Quarry reloading on its own (a Quarry-initiated reload is an action the Model did not propose and can re-submit a POST); S10 makes Quarry reject covered, disabled or unstable targets with typed reasons instead of clicking blindly. S5's busy error, S3's timeouts and S7's `ChallengeDetected` are Quarry rejections. No new Quarry-initiated effectful action exists; the health prober never touches a session or navigates. Rule at risk: none, provided option (a) of D3-12 is not chosen later.
- **ZDR.** No new persistence. Block episodes and hostname counters are in memory and die with the run or process; ZDR runs count by reason only and never log the host. Health and slot data are content-free (counts, ages). New error details carry an operation name, a deadline, a reason and a tag name, never a URL, selector, text or page content (note: existing `DriverFailed` details already include `url`/`selector` for some call sites, for example the goto failure at `chromiumoxide.rs` 2001-2003; `cdp_err` must not copy those into `Timeout`). The idle reaper never persists a profile. Retirement and crash cleanup remove each launch's user-data directory, which also bounds residue. The per-session live-frame cache (D3-17) holds frames in memory with the existing 250 ms TTL and MUST be cleared on `release` and on reaping, or frames could outlive a ZDR session in process memory. Persistent-profile ZDR rules (`agent_routes.rs` 527-533, 1470-1476) are untouched. The probe context is created through the same pinned-proxy helper with a deny-all policy, so the egress boundary (`--disable-quic`, per-session proxy, CDP Fetch guard) is not bypassed by monitoring.
- **Egress invariants.** `--disable-quic` stays whenever the pinned proxy is configured, for every slot launch; the per-context proxy and `<-loopback>` bypass override stay as they are; `PinnedEgressProxyEndpoint::parse` stays loopback-only. Anything non-loopback (sidecar proxy, remote CDP slot) is ADR 10's decision.
