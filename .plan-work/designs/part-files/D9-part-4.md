#### Slice 4a. `useBrowserSessionController` without touching KnowledgeComposer

**Goal.** One module that owns the browser-session lifecycle for any host (chat dock now, Space later), reusing the proven reducers instead of copying them.

### Slice 6. Bind the panel to a live session (F-t2-012b)

**6a. Observed live view (read-only; no ADR).** Goal: the chat panel shows the agent's actual page (frames) and the evidence panels for a chat run, without any change to Quarry's ownership rule.

Contract this design needs from the Model Plane side (names are proposals; D8 and sibling (b) own the final shape):
- execution-core records `{ quarry_run_id, lease_id }` for the orchestration run when `client.start_run` succeeds (`browser_agent.rs:674`) and drops it when the loop ends (finding F6a: today nothing carries it). The SPA and gateway never learn the Quarry ids; everything is keyed by the orchestration `run_id`.
