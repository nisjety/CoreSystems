
## 4. Slices (PR-sized, in build order)

Order: S0 (pure module + goldens) -> S1 (driver probe and AX masking) -> S2 (observation, stamp, events, errors) -> S3 (receipts, typed text, procedures) -> S4 (Model Plane) -> S6 (logs lint) -> S5 (screenshots) -> S7 (optional legacy job). S4 can run in parallel with S1 to S3 once S0 has frozen the golden. Each slice leaves the tree green and is independently shippable; S2 is the first slice that changes what callers see.

Common test environment (from MEMORY and S9): the Quarry Rust workspace does not build on the Windows host (boring-sys2 needs cmake, clang, perl, go, protoc), so run Rust tests in a `rust:1` container with the `quarry-cargo`, `quarry-go` and `quarry-target` volumes and `bash -c` (not `-lc`); a full `cargo test --workspace` takes more than 10 minutes. `quarry-core` has a small dependency closure; `cargo test -p quarry-core redaction` may run on the host `[UNVERIFIED]`. Model Plane on Windows: `cargo test -p <crate> --lib` (two cargo targets fail pre-existing). Live-Chromium driver tests: `CHROMIUMOXIDE_TEST=1 cargo test -p quarry-browser --features chromiumoxide <name> -- --nocapture` (the guard pattern at `Qbr/chromiumoxide.rs:3253`), using `page.set_content(...)` so no network is needed.

**API / data model.** Additive `StepReceipt.redaction_rule_version` (JSON and SQL column `redaction_rule_version TEXT NULL`). Receipts remain append-only: no UPDATE. Stored typed text becomes `"[redacted:password]"` etc. Procedures compiled from receipts gain `redacted_input`.

**Flags / rollout / rollback.** `QUARRY_EDGE__RECEIPT_TEXT_MODE` (`sensitive` default, `all` masks every typed string; D8's human-browse metadata mode is stricter and wins for human steps). Mode `Enforce` governs everything else. Rollback: previous image; the column is nullable and ignored by old code. **Policy default to confirm with the product owner before merge** (section 9, question 2): `sensitive` keeps benign typed text (search queries) in receipts for audit and procedure compile; `all` is safer but makes procedures useless.

**Tests.** `cargo test -p quarry-core redaction::action`: `type_ref_into_password_is_masked`, `type_ref_into_search_box_keeps_text_under_sensitive_policy`, `all_typed_policy_masks_everything`, `selector_type_with_password_selector_is_masked`, `jwt_typed_into_unclassified_field_is_masked_by_shape`, `select_and_dialog_prompt_are_masked`, `navigate_url_query_token_is_masked`. `cargo test -p quarry-runtime receipts procedure`: `complete_masks_action_and_observation`, `fail_receipt_masks_typed_text_from_the_pre_action_snapshot`, `receipt_stamp_is_set`, `legacy_receipt_is_masked_on_read_and_idempotent`, `compile_procedure_flags_redacted_input`, `compare_replay_returns_repair_required_for_redacted_input`; Postgres tests (`#[ignore]`, `--features postgres-queue`, existing harness in `postgres_step_receipts.rs`): `append_persists_redaction_rule_version`, `legacy_null_version_decodes`. **Definition of done.** The three receipt paths (REST step, WS action, failure) are masked; a legacy row inserted with raw text is returned masked by `GET .../receipts`; the migration applies on a clean database and on one at 0011; procedures with typed secrets never report `Exact`.

**Deployment evidence.** Rebuilt `quarry-edge` and a Postgres-backed edge (`QUARRY_EDGE__DATABASE_URL`, durable stores; `ARTIFACT_BACKEND` not `memory` in production mode, per S9 H2). Flow: the S1 flow with `zdr:false`, then `psql -c "SELECT action::text, observation::text, redaction_rule_version FROM quarry_step_receipts WHERE run_id='<run>'"`. Assertions: the typed step's `action` text is `[redacted:password]`; `observation::text` contains no `S3cretP@ss` and no 16-digit card fixture value; the version column is `qr-redact/1`. Then insert a legacy-shaped row by hand (raw text, NULL version) and call `GET /v1/agent/runs/{id}/receipts` as the owner: masked output. Finally `POST /v1/agent/runs/{id}/procedure` and assert the typed step has `redacted_input:true`.

**Effort.** M, about 4 engineer-days (action masking and builder 1.5, store and migration 0.75, edge wiring and read-time masking 1, procedures 0.75). **Risks.** Interplay with D2's `step.rs` rewrite and D8's human-receipt mode (single function, section 5); receipts of the typed `Press` key stream cannot be classified (a password typed one `press` at a time is masked only if the key is not a printable single character `[LIMIT]`: acceptable because `Press` has no text field today and the model uses `type`); masking `target_resolution.fingerprint` changes `normalized_text` of masked fields to the marker, which is stable between observations (verified by the fingerprint tests).
