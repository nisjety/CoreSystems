### 2.4 Quarry evidence routes exist and are not proxied

`Q/crates/quarry-edge/src/agent_routes.rs` [C] router L3660-3715 registers `receipts` (handler `list_receipts` L2414), `egress-receipts` (`egress_receipts` L3515), `procedure` (`compile_run_procedure` L2466), `procedures/replay-check|quality-check|impact-check` (L2501, L2515, L2526), `devtools` (`devtools_events` L3454), `live-view`, `events/stream` (`agent_events_stream` L2658). `DevtoolsQuery` L1061-1066 has only `after_sequence` and `limit`. The gateway router `browser.rs` L369-449 proxies none of receipts, egress-receipts, procedure, live-view or events (grep over `GW` and `FE/src` finds the strings only in `FleetRunConsole.tsx:131` as display text). Shapes that matter for the proxies:

- `StepReceipt` (`quarry-runtime/src/step_receipts.rs` L183-206) carries the full post-action `observation`; the compile route requires every receipt `Completed` with a `Verified` outcome else it returns 409 (`browser_procedure.rs` L61-100). `ProcedureStep.action` is the raw action JSON, including typed `text` (audit risk 4: typed text is stored verbatim until F-t2-021).
- `BrowserEgressReceipt` (`quarry-core/src/contracts.rs:591`) serialises snake_case (`tab_id`, `timestamp_ms`) while `BrowserDevtoolsEvent` (`quarry-browser/src/lib.rs:225-243`) serialises camelCase. The egress route says it is "safe to read during a live ZDR session" and returns `zdr: bool`.
- Devtools console events carry `category: "console"`, `level` in {error, warning, debug, info} for console API calls (`chromiumoxide.rs` `console_method_level` L1638) and the CDP `Log` levels for log entries, a text truncated to 1000 bytes (L1648), and a full `payload` (the raw serialised CDP event, with remote object ids); the ring buffer holds 512 events (L74).
- The gateway devtools proxy `get_devtools_events` (`browser.rs` L1784-1850) forwards the caller's raw query string through `query_suffix` (L3058-3063). New filter parameters would flow through unvalidated; the new routes use an allowlist (decision D-14).

### 2.6 Control, tabs and the control epoch

`BrowserControlMode` is persisted on the run (`step_receipts.rs` L55-90). Quarry's `/step` ignores it (D2 slice S3 fixes that and adds `controlEpoch`, `initiatedBy`, `expected_epoch` on the control route, `USER_TOOK_OVER`). The projection the gateway exposes (`browser_response_from_owner_projection` L2589-2706) passes `tabs` through verbatim and hard-codes the capability list (L2578 and L2700). Quarry's `BrowserTab` has `{tabId, title, url, active}` only (`quarry-browser/src/lib.rs:215-221`); there is no `openedBy`. `new_tab` "makes it active" (trait doc `lib.rs:509-515`; `chromiumoxide.rs:2492-2510`), and steps act on the active tab only, so an agent working in a background tab needs a per-step tab id that does not exist (Slice 7).

### 2.9 Findings that change planning

- F1. The 12-step, first-host budget makes every omnibox feature, the dock's interactive mode and the evidence panels low value for human sessions until WS8 changes the gateway literals (`browser.rs:483-494`) and Quarry keys budgets on the initiator (D2 `StepInitiator`).
- F2. Browser UI strings are hard-coded Bokmål and e2e selectors depend on them (section 2.3).
- F3. Free-text search through `search_web` reads the gateway cache that has no org in its key (D4 slice S-1 fixes it); a new traffic source into it should not be enabled in production before that fix.
- F4. Suggestions from `search_suggestions` are org-scoped and not ZDR-gated server-side; ZDR must be enforced at the gateway (`zdr.rs` [C] `request_zdr` L44 and `org_zdr_enabled` L67), not only in the SPA.
- F5. `browser.observe` and `browser.act` are unclassified as untrusted content (section 2.5): a security fix that belongs next to the new console tool.
- F6. (F6a, F6b above) A chat run's Quarry session cannot be addressed by any client nor read by the user's token; the panel binding is a Model Plane and Quarry contract before it is a UI task.
- F7. `get_devtools_events` forwards the raw query string.
