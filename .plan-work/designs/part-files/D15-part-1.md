### 2.2 Model Plane

- `POST /v1/ai/chat` (`http_routes.rs` route 413, `AiChatRequest` 1813-1829 with `messages`, `model`, `provider`, `subscription_connection_id`, `structured_output_schema`, `zdr`; handler `ai_chat` 2328-2385): a **non-persisting unary machine route** reachable by user and service tokens. It makes no budget check, publishes no `USAGE_ENVELOPE`, and applies neither the org's PII-redaction nor `injection_defense` policy (those live only on `invoke`: `pii_redaction_required` 8946).
- A service principal needs **two bearers** for `ai_chat`: `Authorization` (`aud=model-gateway`, scope `models:invoke`) and `x-inference-authorization` (`aud=inference-core`, same `sub`, `service_id`, `org_id`, and scope `models:invoke`), enforced by `verify_delegated_service_inference_bearer` (`auth.rs` 1006-1029) and installed as `VerifiedInferenceBearer` (extractor 443-455, a missing extension is 401). inference-core itself demands the exact scope `inference:invoke` (`MP/inference-core/src/auth.rs` [M] `authorize_invoke` 233-239). No first-party service has ever called `/v1/ai/chat` end to end with a service identity [UNVERIFIED beyond the code and tests read; check the running stack's gateway log for `service principal route or scope denied`].
- Rate limit: one token bucket **per `org_id`** shared by every caller of the authed router (`MP/model-gateway/src/rate_limit.rs` [C] 1, 24, 78-118; layer at `http_routes.rs:258`).
