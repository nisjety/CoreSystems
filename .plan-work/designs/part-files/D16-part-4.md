### Slice E3: backfill, erasure hop, tombstone and cache purge, then plaintext removal (Track A; migration 0016)

**Goal.** No plaintext profile rows remain; org erasure reaches `quarry_profiles`, tombstones and Redis.

**File-level change list.**
- `QR/profile_backfill.rs` [NEW] and a small bin `QE/bin/profiles_backfill.rs` [NEW] (or an admin subcommand): batch (200 rows), resumable (`WHERE envelope IS NULL AND snapshot IS NOT NULL ORDER BY org_id, profile_id`), seals each row through `EnvelopeProfileStore::reseal` with the CAS on `rev`, rate-limited, reports counts only, then `UNLINK`s the old `quarry:profile:{org}:*` keys. Idempotent; safe to run while the fleet is live.
- `QR/migrations/0016_profile_plaintext_null.sql` [NEW] (provisional): after the backfill gate, `UPDATE quarry_profiles SET snapshot = NULL WHERE envelope IS NOT NULL; ALTER TABLE quarry_profiles ADD CONSTRAINT quarry_profiles_no_plaintext CHECK (snapshot IS NULL OR envelope IS NULL) NOT VALID;` then `VALIDATE CONSTRAINT` in a later migration. - `QE/internal_routes.rs` [NEW] (or in `QE/profile_routes.rs`): `DELETE /v1/internal/orgs/:org/profiles` mounted on the `internal` router (routes.rs 105-122, outside `require_auth`), authenticated by `QUARRY_EDGE_INTERNAL_TOKEN` with the `ct_eq` pattern of `change_routes.rs` 440-468; implements the `OrgErasable` list (profiles first): delete rows and tombstones for the org, `SCAN`+`UNLINK` `quarry:profile:v2:{org}:*`, evict the org from the DEK cache. - `docs/RUNBOOKS.md` [M]: the backfill and rescue procedures.

**API / data-model changes.** Internal route above; migration 0016; no public change.

**Flags / rollout / rollback.** Backfill is run by an operator (no flag); the erasure hop is active when quarry-control has `QUARRY_EDGE_URL` set (unset = today's behaviour). Plaintext nulling is irreversible by design; take a database backup first (runbook).

**Tests.** `backfill_seals_every_plaintext_row_and_is_idempotent`, `backfill_cas_loses_to_a_newer_save`, `backfill_unlinks_old_plaintext_cache_keys`, `purge_org_deletes_rows_tombstones_and_cache_keys` (Postgres and Redis lanes), `internal_route_requires_token`, `purge_is_idempotent`; Go: `HandleErasure_calls_edge_and_naks_on_edge_failure`, `edge_purger_is_skipped_for_user_subjects`. Commands: Postgres/Redis lanes; `cd "apps/Ingestion Plane/Quarry-v2/services/quarry-control" && go test ./...`.

**Definition of done.** Zero plaintext rows (`select count(*) from quarry_profiles where snapshot is not null` returns 0); a throwaway org's erasure removes its profile rows, tombstones, Redis keys and (E2) its KEK.

**Deployment EVIDENCE.** Rebuild edge and quarry-control images. (3) Redeliver the same event (replay from the JetStream consumer) and confirm idempotent zero counts.

**Effort.** M, 5 engineer-days.
