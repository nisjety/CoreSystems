### Slice S0: CDP capability spike (Track B, 1.5 engineer-days, no product code merged except tests)

**Goal.** Replace the three [UNVERIFIED] statements of D16-12 with recorded facts on the pinned Chromium (149.0.7827.102 per D3) before C1 commits to an architecture.

**Method.** A throwaway `#[ignore]` live test module `QB/tests/profile_cdp_spike.rs` [NEW] (kept as a regression test, run with `CHROMIUMOXIDE_TEST=1 -- --ignored`, public origin `https://example.com`, using D3 S1's `live_driver()` stub-egress helper). It answers: (1) does `Storage.getCookies { browserContextId }` return cookies of ALL origins visited in one session context, with `expires`, `session`, `sameSite`, partition key, and does `Storage.setCookies` on `about:blank` (before navigation) apply them, including a host-only `__Host-` cookie restored with `url` and rejected with `domain`; (2) does `DOMStorage.getDOMStorageItems`/`setDOMStorageItem` work for an origin with no live frame in that target (expected: no); (3) do `IndexedDB.requestDatabaseNames` and `requestData` work for an origin with no live frame (expected: yes), and what must be done to turn `RemoteObject` values into JSON; (4) does `Page.addScriptToEvaluateOnNewDocument` seeding run before page scripts and in iframes (origin check), and does a `pagehide` -> `Runtime.addBinding` flush arrive before the renderer is torn down on navigation and on `page.close()`; (5) latency of `Storage.getCookies` and of a 5 MB IndexedDB export.

**Output.** A short result table appended to this design's slice C1 before C1 starts (or the spike test's doc comment); C1 picks "frame-less CDP" or "journal/flush" accordingly. Effort and risk: the only risk is an unavailable Chromium in CI (D3 S1 provides the live lane first).

### Slice C1: complete snapshot capture in quarry-browser (Track B)

**Goal.** Capture the whole context jar with expiry and SameSite, web storage and IndexedDB for every visited origin, bounded and ordered, behind a flag.

**File-level change list.**
- `QB/session.rs` [C]: schema v2 per D16-11 (`SameSite`, `PartitionKey`, `OriginState`, `IdbDatabase/IdbStore/IdbRecord`, `snapshot_version`, `truncated`), `#[derive(Default)]` on `Cookie`, helper `SessionSnapshot::redacted_view()` used by P0's `redact`, helper `earliest_cookie_expiry()`. Delete the dead `BrowserSession::capture/hydrate` pair (625-676; no caller) so there is one capture path.
- `QB/profile_capture.rs` [NEW]: `async fn capture_context_cookies(browser: &Browser, ctx: &BrowserContextId) -> QuarryResult<Vec<Cookie>>` (`storage::GetCookiesParams`), mapping `expires` (>0 to `DateTime<Utc>`, else `session: true`), `same_site`, `priority`, `partition_key`, `source_scheme`; `async fn capture_origin_state(page: &Page) -> QuarryResult<OriginState>` running the in-page serializer (`const SERIALIZER_JS: &str`, tagged encoding of Date, ArrayBuffer and typed arrays as base64, Map, Set, BigInt, Blob via `FileReader` as base64, skipping non-cloneable values and counting them, per-store and per-origin byte caps); `struct OriginJournal { visited: BTreeSet<String>, flushed: HashMap<String, OriginState> }` fed by the `Runtime.addBinding` flush (or by the frame-less CDP domains if S0 says so); `fn merge_and_cap(..) -> (SessionSnapshot, CaptureReport)` applying D16-11 caps and the empty-capture guard; a `CaptureReport` of counts only.
- `QB/chromiumoxide.rs` [C]: `SessionPages` (97-110) gains `journal: OriginJournal` and `profile_restored: bool`; `capture_snapshot` (1771-1849) is rewritten to take `(browser, context_id, all live tabs, journal)` and call the functions above; `persist_current_page` (675-697) no longer requires an active tab (cookies come from the context), runs with the budget of D16-12 (cookies 2 s, storage 4 s, IndexedDB 4 s, total 10 s; `Op::ProfileCapture` in D3's deadlines table moves from 5 s to 10 s), applies the empty-capture guard, saves with P1's `SaveMeta`; the lifecycle listener (640-652) and `update_tab_metadata` (559-573) record visited origins (http/https only, cap 64); `install_profile_flush(page)` registers the `pagehide` script and the `EventBindingCalled` listener for each new page (inside the profile-enabled path only, never for non-persistent leases); a checkpoint hook `capture_profile_checkpoint(session)` is exposed for D8's attach/detach and for an optional timer (off by default; capture today happens only at release, so a crash loses everything; checkpointing is flagged, not default).
- `QB/kernel.rs` [C] 239-262 and 540-590: map the new cookie fields (`same_site` now available, `expires`), keep flat storage; handle `ProfileLoadError` per D16-14.
- `QE/profile_routes.rs` [C]: `redact`/`restore_probe` use `origins` when present (counts per origin, `earliest_expiry`).
- Tests touched for the added `Cookie` fields (`..Default::default()`): `session.rs` tests (330-615), `kernel.rs` tests (1066-1162), `chromiumoxide.rs` 3420, `QE/tests/profile_roundtrip.rs` [C] 53-70 and the Postgres tests (242-253).

**API / data-model changes.** Snapshot schema v2 (additive, JSON inside the envelope or JSONB; no SQL change). Probe and redacted view gain `origins_count`, `earliest_expiry`, `truncated`.

**Flags / rollout / rollback.** `QUARRY_BROWSER_PROFILE_CAPTURE_V2=0|1` (default 0 for one release; 0 keeps today's capture), `QUARRY_BROWSER_PROFILE_MAX_BYTES`, `QUARRY_BROWSER_PROFILE_IDB=0|1` (IndexedDB can be turned off independently). Rollback: flag off (v1 snapshots remain readable; v2 snapshots read by an old binary lose the new fields but keep the flat ones: C1 also writes the active origin's entries into the legacy flat fields while the flag is on, so an old binary still restores something).

**Tests.** Unit (CI, no Chromium): `cookie_mapping_expiry_session_samesite_partition`, `tagged_serializer_roundtrip` (JS run by a small Node-free harness: the serializer string is exercised in the live lane, its Rust decoder in unit tests with fixture JSON), `merge_and_cap_drops_largest_idb_first_and_sets_truncated`, `cookies_are_never_dropped_by_caps`, `empty_capture_does_not_replace_a_non_empty_profile`, `journal_caps_at_64_origins_and_ignores_non_http`, `legacy_flat_snapshot_deserializes_and_restores_into_initial_origin`, `schema_v2_roundtrip_through_serde`. Live (`CHROMIUMOXIDE_TEST=1`, `#[ignore = "needs a public origin"]`, example.com via `evaluate`, the style of the existing tests at 3405-3550): `capture_includes_cookies_of_a_previously_visited_origin` (visit two origins, close the first tab, release, assert both origins' cookies present: today only the active tab's URL cookies), `capture_records_expiry_and_samesite`, `capture_includes_localstorage_of_a_closed_tab_origin`, `capture_includes_indexeddb_records`, `capture_with_slow_indexeddb_still_saves_cookies`. Commands: `cargo test -p quarry-browser`, `cargo test -p quarry-browser --features chromiumoxide -- --test-threads=1 --ignored` with `CHROMIUMOXIDE_TEST=1`.

**Definition of done.** A release after browsing two origins stores every cookie of the context with expiry/SameSite and the storage and IndexedDB of both origins, within the caps, and a restore probe reports them.

**Deployment EVIDENCE.** Rebuild the edge image with the browser-agent feature and `QUARRY_BROWSER_PROFILE_CAPTURE_V2=1`. Flow: a persistent run that navigates `https://httpbin.org/response-headers?Set-Cookie=a%3D1%3B%20Max-Age%3D86400` then `https://example.com/` (a second origin), closes. Assertions: `POST /v1/profiles/<id>/restore_probe` returns `cookies_count >= 1`, `origins_count >= 2` and an `earliest_expiry` about 24 h ahead (before the slice: cookies of the last page only, no expiry); the redacted `GET` shows the cookie `a` with `expires` and `same_site` set and `value:null`; `psql` shows the row sealed (E1) or the live test output shows the IndexedDB database. The live-lane tests above run in the Docker test image with Chromium and are attached as the proof for storage and IndexedDB (the stack's agent has no un-gated script action to create them by hand, F-t2-002).

**Effort.** M-L, 7 engineer-days after S0 (capture module 3, journal and flush 2, schema and kernel/tests churn 1, live tests 1).

**Risks and mitigations.** IndexedDB export size and capture time (caps, 10 s budget, cookies first, IDB flag); `pagehide` flush unreliability (best-effort by design: live tabs are captured directly at release, the flush only covers origins left earlier; S0 measures it); chromiumoxide `Browser::execute` for `Storage.*` needs the browser lock (do not hold the `browser` mutex across awaits: D3 S3 fixes the long hold at `open_tab_page` 379; capture clones the context id and drops the guard); cookies for origins the egress policy would not allow (they were set by allowed origins' subrequests, so capturing them does not widen egress; restore never navigates to them); partition-key cookies need Chrome 114+ semantics (verified by S0 on the pin).

### Slice C2: restore (Track B; depends on D3 S2)

**Goal.** Restore the full snapshot before the first navigation, once per context, without a reload, report what was restored.

**File-level change list.**
- `QB/profile_restore.rs` [NEW]: `async fn restore_into_context(browser: &Browser, ctx: &BrowserContextId, page: &Page, snapshot: &SessionSnapshot, now: DateTime<Utc>, policy: &RestorePolicy) -> RestoreReport` implementing D16-13: build `CookieParam`s (skip expired; skip stale session cookies by `policy.session_cookie_max_age`; host-only via `url`), call `storage::SetCookiesParams { cookies, browser_context_id: Some(ctx) }` (chunks of 100; a rejected cookie is counted, never fatal), then register the seeding script with `page.evaluate_on_new_document` (chromiumoxide `Page::evaluate_on_new_document`, page.rs 1274) containing the origin-keyed map (`serde_json` embedded, `</script>`-safe escaping not needed for CDP but string-escaped), the sentinel `__quarry_profile_seeded_v1`, localStorage seeding, and IndexedDB recreation (open with the saved version, create stores with keyPath/autoIncrement/indexes, put records through the tagged decoder). Legacy flat entries map to the initial URL's origin. `async fn apply_profile_emulation(page: &Page, snapshot)`: `Emulation.setLocaleOverride`, `Emulation.setTimezoneOverride`; UA never overridden (`ua_changed` computed from `Browser.getVersion`/page UA at capture).
- `QB/chromiumoxide.rs` [C]: in `open_tab_page` (371-557) the restore block (507-545) becomes: for the first tab of the context (`!session_pages.profile_restored`), after `install_network_guard` (498-506) and BEFORE the initial `goto` (507-511), call `restore_into_context(..)` and set `profile_restored = true`; subsequent tabs skip it (fixes 2.3-1); delete `hydrate_cookies`/`hydrate_storage`/`cookie_param` (907-967) and the reload (528-538). `load_snapshot` (661-673) returns `Result<Option<SessionSnapshot>, ProfileLoadError>` per D16-14: `KeyUnavailable` aborts `acquire`/first tab with the typed 503; `Corrupt` starts fresh and sets `lease_restore_failed` so `persist_current_page` skips saving. D3 S2's `apply_page_hygiene` (right after `browser.new_page`, 484-487) calls `apply_profile_emulation` on the first tab. The restore report is stored in `session_telemetry` and appended through the timeline sink as a `profile_restore` event (counts only; `quarry_browser_timeline_events` migration 0009: no storage values).
- `QB/lib.rs` [C] 262-290: no capability change (`persistent_profile` already advertised); `BrowserTelemetry` in `quarry-core` `contracts.rs` [C] 100-124 gains an optional `profile_restore: Option<ProfileRestoreSummary>` (additive, `#[serde(default)]`, counts only; coordinate with D12/D3 who edit the same struct).
- `QE/agent_routes.rs` [C] 1533+: the run's first observation or session info surfaces the `profile_restore` summary so the UI can say "restored 14 cookies, 2 origins, 3 expired skipped" (UI work is D9's; Quarry only exposes the field).

**API / data-model changes.** `ProfileRestoreSummary { cookies_total, cookies_applied, skipped_expired, skipped_session_stale, origins_seeded, idb_databases, ua_changed, snapshot_age_s, truncated }` on the session/telemetry JSON and as a timeline event. No SQL.

**Flags / rollout / rollback.** Shares `QUARRY_BROWSER_PROFILE_CAPTURE_V2` for the new restore path (v1 snapshots restore through the new path too, flat entries into the initial origin; the old reload path is deleted, so the rollback is a revert). `QUARRY_BROWSER_PROFILE_SESSION_COOKIE_MAX_AGE_S` (default 604800).

**Tests.** Unit: `host_only_cookie_restores_with_url_not_domain`, `expired_cookie_is_skipped_and_counted`, `stale_session_cookie_is_skipped`, `seeding_script_embeds_only_matching_origin_map`, `sentinel_prevents_reseeding` (script logic exercised in the live lane), `restore_report_never_contains_values`, `legacy_flat_entries_target_initial_origin`, `key_unavailable_aborts_acquire_with_503`, `corrupt_profile_starts_fresh_and_does_not_overwrite`. Live (as C1): `restore_applies_cookies_before_the_first_request` (compare the first request's `Cookie` header via the egress receipts or a response that echoes it: no anonymous first hit), `second_tab_does_not_rehydrate_stale_profile_cookies` (profile with persistent lease, change a cookie in tab 1, open tab 2, assert tab 1's newer value survives), `localstorage_of_second_origin_is_seeded_on_first_visit_only`, `indexeddb_roundtrip_across_sessions`, `restore_works_for_a_profile_saved_by_v1` (fixture), the existing three live tests unchanged (3405, 3458, 3515). Commands: as C1.

**Definition of done.** A profile saved after logging in at origin A restores into a new session so that A's first request is authenticated, other origins' storage appears on first visit, a second tab never overwrites the live jar, and the session reports what it restored.

**Deployment EVIDENCE.** Rebuild the edge image (after D3 S2 is on the stack). Flow: run 1 (persistent) visits `https://httpbin.org/response-headers?Set-Cookie=quarry_e2e%3DCANARY-d16-c2%3B%20Max-Age%3D86400%3B%20Path%3D%2F` and closes. Run 2 on the same profile navigates directly to `https://httpbin.org/cookies`: the observation text contains `quarry_e2e` (before the slice this also works for the current-URL cookie, so the discriminating checks follow). Run 1b visits two origins first; run 2 shows cookies of both (before: only the last page's); the session response for run 2 carries `profile_restore.cookies_applied >= 2`, `skipped_expired` correct for a seeded expired cookie; `docker logs quarry-edge` for run 2 shows exactly one navigation request to httpbin (no reload) and the egress receipts list no anonymous first request (`GET /v1/agent/runs/{id}/browser/egress-receipts` shows a single request for the restore URL, where the old path showed two); open a second tab in run 2 after changing a cookie: the newer value persists on tab 2.

**Effort.** M, 5 engineer-days.

**Risks and mitigations.** The seeding script runs in every frame at document start (origin check first, then a sentinel read; negligible cost but measured); an app that enumerates localStorage can see the sentinel key (stripped at capture; named and versioned so it can be changed); IndexedDB recreation can fail on version mismatch (record the failure, never block navigation, count in the report); restoring stale session cookies can look like a hijack to the origin (7-day default max age, `snapshot_age_s` surfaced to the UI so the user can see a very old profile); D3 S2 must land first (both edit `open_tab_page` 507-545); the existing "second tab shares cookies" semantics are unchanged because the context is shared.
