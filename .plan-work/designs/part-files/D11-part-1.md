**Honest label.** The audit's "M" for F-t2-010 does not hold. Five findings the audit does not carry (section 2.2) are loop-correctness prerequisites: a single failed Quarry action ends the whole durable run, planner errors silently degrade to an observe loop, the planner is stateless, `done` drops the answer, and the risk gates would not see `press`/`select`. Without them a prompt and a flag flip would ship a planner that cannot recover from its first stale ref. Realistic total for F-t2-010 is **L, about 26 engineer-days**, one engineer, Model Plane Rust only; F-t2-045 skip-only is **S to M, about 3.5 days**.

**Default-on gate (from the audit and this design).** `default_on` ships only after F-t2-001 (grants), F-t2-008 (budgets, [D6] S1 `on` plus S4), F-t2-021 (capture-time redaction) and the S1/S3/S4 slices here. `org_opt_in` can run in dev and staging earlier, because it adds no new default exposure. ### 2.2 Findings the audit does not carry (all `[READ]`)

| # | Finding | Evidence | Why it matters |
|---|---|---|---|
| F1 | **One failed Quarry action ends the durable run.** A stale or ambiguous ref is HTTP 409 `TARGET_REPAIR_REQUIRED` (`Q/crates/quarry-core/src/error.rs:50` [C]); `QuarryAgentClient::step` returns `AgentClientError::Status` (`EC/quarry_agent.rs:688-701`); the loop sets `PlanStatus::Failed` and breaks (`EC/browser_agent.rs:749-752`). `observation_from_wire` can only produce `Success` or `Blocked` (`EC/quarry_agent.rs:412-416`), so the `ObservationStatus::Failed` branch in `plan_next_action` (530-533) is unreachable from Quarry | files cited | "observe, act, re-observe to confirm" and any escalation ladder cannot run: the first stale ref stops the task. This is the dominant success-rate lever, larger than the prompt |
| F2 | **Planner errors are swallowed.** `decide_next_action` logs a warning and falls back to a deterministic `Observe` when `next_action` errs (`EC/browser_agent.rs:840-844`) | cited | An expired bearer (inference bearers default to about 300 s), a refusal or a transport error silently turns the run into an observe loop that burns steps until `max_steps`; the user sees a "successful" browse of nothing |
| F3 | **The planner is stateless and its prompt is unbounded.** It receives the goal and only the latest observation; there is no action log; `extracted_text` is inserted whole (no cap) and 40 targets with unbounded `name`/`text` (`EC/llm_planner.rs:206-235`). The SPA suggest path caps at 16,000 characters (`MG/http_routes.rs:1988`). No scrub or screening is applied although `scrub::scrub_string` (`EC/scrub.rs:148`) and `provenance::assess` with the untrusted-content framing (`EC/provenance.rs:60-140`) exist in the same crate | cited | the audit's "raw observation text enters the prompt unscrubbed" is exactly right, and it is fixable inside execution-core before F-t2-021 lands (it reduces planner-prompt exposure only; receipts and screenshots stay F-t2-021's) |
| F4 | **`done` drops the answer.** `NextAction::into_browser_action` returns `None` for `done` and discards `reason` (`EC/llm_planner.rs:312`); the loop completes with the fixed string `agent reported task complete` (`EC/browser_agent.rs:836-839`) | cited | a browsing run never returns what it found |
| F5 | **The risk gates do not cover the new verbs.** `bound_target` resolves a snapshot target only for `Click` and `Type` (`EC/browser_agent/browser_risk.rs:354-366`); posting markers apply only to `Click` (293); `Evidence::of` reads only url, selector and the bound target (324-340). A `press Enter` after typing into a password field, or a `select` on a destructive control, would carry no evidence and pass unseen | cited | "keep per-step risk gates" is not automatic when the verb set widens; S4 extends the classifier |
| F6 | **The run's credentials are shorter than a planner run.** `RunDeadline::for_run` (`EC/run_budget.rs:97`) already computes "stop starting work before the earliest bearer `exp` less 60 s", but only the chat loop uses it (`EC/runtime_loop/agent.rs:1288`); the browser loop holds one fixed inference bearer (`EC/llm_planner.rs:126`) | cited | with [D6]'s 900 s agent default or a 240 s planner default, the bearer expires mid-run (and F2 hides it) |
| F7 | **ZDR and waiver are not propagated into the planner call.** `planner_infer_request` leaves `zdr` at the default `false`; `execute_browser_agent` receives `verified_zdr` but not `waived` (`EC/tool_bridge/mod.rs:165-173`; `execute_step_inner` has `waived` at `EC/runtime_loop/mod.rs:484`). The module doc claims the planner forwards `x-org-id` metadata so inference-core's budget guard caps its calls (`EC/llm_planner.rs:16-22`); the code sets only `authorization` (165-171) | cited | the gateway refuses ZDR runs, so this is defence in depth, but the documented guard does not exist |
| F8 | **inference-core's budget layer cannot cap a run.** Org and user come from the verified principal (`IC/grpc.rs:1118-1119`); the intent layer only **downgrades the model** to a cheap fallback when cost-core says over budget (`IC/provider/intent.rs:207`). I found no Rust caller of `POST /api/v1/cost/record` for inference spend under apps/Model Plane (the only writers found are the Data Plane forwarder and a fine-tune plan item) | grep over `MP/rust`, `MP/go`, `MP/docs` | [D6] section 7 assumes the combined run cap can read planner spend from `cost-core GET /api/v1/cost/run`. That is `[UNVERIFIED]` and probably empty for planner calls. The only guaranteed per-run planner cap is an in-process token meter (D1 below) |
| F9 | **Run ceilings are caller-controlled.** `max_steps: input.max_steps.unwrap_or(20)` and `max_runtime_s ... unwrap_or(120)` take any positive value (`EC/tool_bridge/mod.rs:880-881`) | cited | needs an execution-core ceiling independent of the gateway |
| F10 | **`PlanConfig` has many struct-literal sites** (`EC/browser_agent.rs` tests 1069-1086, `ECT/browser_agent_e2e.rs:57-75, 138-156`, `tool_bridge/mod.rs:874-892`) and no `Default` derive | cited | S1 derives `Default` and uses `..Default::default()` at the sites; `cargo check --workspace --all-targets` (CI line 112) is the net |
