
## 3. Design decisions

Each decision lists options, the recommendation and why. **ADR-GATED(n)** names the audit 9.3 topic number that needs an owner ruling; **DECISION** is a smaller choice the user should confirm but that does not block the build.

**D1. Where capture happens, and in what order.** Options: (a) inside `BrowserDriverAdapter::do_fetch` on the scrape session; (b) a second visit through `PageRenderer`-style `acquire -> goto -> screenshot` (what the visual-RAG path does, `page_renderer.rs` 140-160); (c) a new post-fetch pipeline step that re-acquires. Recommendation (a). (b) and (c) navigate a second time, so the pixels can differ from the DOM that was extracted, cookies and action effects are lost, and every capture doubles the egress and the per-host politeness cost. Order inside `do_fetch`: `acquire -> egress policy -> goto -> wait_for -> actions -> hydration settle -> content -> final-url probe -> captures -> release`. Captures come after `content` so the markdown and the screenshot describe the same DOM; actions come before settle so the settle loop sees the post-action DOM. A capture failure never loses the extracted page (D7).

**D2. How capture bytes reach the pipeline.** Options: (a) `FetchResponse.captures: Option<Box<PageCaptures>>` (the card's choice: "bytes returned through the fetch response"); (b) an out-parameter on `FetchHints` (`Arc<Mutex<Option<PageCaptures>>>`) with no literal churn; (c) have `do_fetch` store artifacts itself. Recommendation (a), landed as its own mechanical PR (slice 4a) with a `FetchResponse::new(...)` constructor so future fields stop touching 20 literals. (b) hides data flow and breaks silently when a `FallbackDriver` rotation serves the response from another driver; (c) cannot work because the artifact key needs `page_hash`, which is derived from the final body fingerprint computed only in the pipeline (`pipeline.rs` 524, 595), and because the ZDR decision and the org stamp live there. `PageCaptures` holds bytes (bounded by D5's byte caps below) plus content-free metadata and the ordered action outcomes; it is `#[derive(Debug, Clone)]` like `FetchResponse` and is `None` for every non-browser driver.

**D3. Driver API shape and capability flags.** Options: (a) change `BrowserDriver::screenshot(session, full_page)` and `pdf(session)` signatures (breaks six implementations: chromiumoxide, browserless, browserbase, kernel, `pool.rs` test double, `ActionRuntime` mocks, plus `observation.rs` and `page_renderer.rs` callers); (b) add `capture_screenshot(session, &ScreenshotOptions, &CaptureLimits) -> CapturedImage`, `capture_pdf(session, &PdfOptions) -> CapturedPdf` and `current_url(session) -> Option<String>` as **default methods** (defaults delegate to the legacy call when the options are the legacy ones, else `Unsupported`, and `current_url` defaults to `Ok(None)`), and add two booleans `scrape_actions` and `capture_options` to `BrowserDriverCapabilities` (struct at `quarry-browser/src/lib.rs` 269-286; only chromiumoxide sets fields explicitly, 1873-1889). Recommendation (b): additive, the agent path keeps using the legacy methods, and `do_fetch` checks the flags before running anything so a driver that cannot run actions fails the request up front (501) instead of silently dropping them.

**D4. The public action vocabulary is its own enum.** Options: (a) expose `quarry_browser::actions::Action` (15 variants including `Navigate`, `Evaluate`, `ClickPoint`, `MouseWheel`, `Back`, `Forward`); (b) a separate wire enum `ScrapeAction` in `quarry-core` mapped onto the internal enum. Recommendation (b). The internal enum is an executor vocabulary for trusted code; exposing it would make `Evaluate` (D2 forbids it) and `Navigate` (off-host navigation and a way to bypass `wait_for` semantics) part of a public contract that is hard to retract. Wire types (camelCase fields, `type` tag), each validated field by field:
`wait{milliseconds | selector, timeoutMs}`, `click{selector}`, `write{selector, text}` (Firecrawl's `write` has no selector and types into the focused element; the driver's `type_text` needs one, so it is required), `press{key}`, `scroll{to:"top"|"bottom" | selector | direction:"up"|"down", pixels}`, `select{selector, value}`, `screenshot{fullPage, clip, quality, viewport}`, `pdf{...}`. Reserved and not built: `scrape{}` (an intermediate HTML and markdown snapshot, Firecrawl's `scrape` action). **Denied with `action_denied`**: `executeJavascript`/`evaluate` (F-t2-002 and D2: no raw script; the read-only evaluator is a future new variant), `navigate`, `back`, `forward`, `clickPoint`, `mouseWheel` (internal only), upload, download, dialog responses. Unknown `type` is `unknown_action_type`. `scroll direction` maps onto the internal `MouseWheel` at the viewport centre for lazy-loaders that listen for wheel events; `to` and `selector` map onto the internal `Scroll`.

**D5. Caps (server-side, all enforced at validation and again at execution).** `actions` at most **50** (Firecrawl `MAX_ACTIONS`); total wait at most **60 000 ms**, where `wait.milliseconds` counts in full, `wait{selector}` and `wait_for` count their `timeoutMs` in full (the worst case, not the observed time) and one `wait` is at most 30 000 ms; `timeoutMs` default 5 000 (the existing `DEFAULT_WAIT_FOR_TIMEOUT_MS`, `browser_driver.rs` 28) and at most 30 000; selector at most 512 bytes and valid for CDP `querySelector` (no script injection surface: the driver passes it to `DOM.querySelector` or, for `select`, JSON-escaped); `write.text` at most 4 096 bytes each and 16 KiB in total; `press.key` from a named-key allowlist (`Enter`, `Tab`, `Escape`, `Backspace`, `Delete`, `Space`, `Arrow*`, `Page*`, `Home`, `End`) or one printable character; `scroll.pixels` at most 20 000; at most **8** captures in total across `formats` and `actions`; total capture bytes at most **32 MiB** per request; per-capture viewport at most 3840 x 2160 at device scale factor 1 to 2 (Firecrawl allows 7680 x 4320; a 3840 x 2160 DSF 2 frame is already 66 Mpx of raster); `quality` 1 to 100. All numbers can be lowered but not raised by environment (`QUARRY_EDGE__SCRAPE_ACTIONS_MAX`, `..._MAX_WAIT_MS`, `..._CAPTURE_MAX_BYTES`). Firecrawl's `executeJavascript` has no script cap in the scrape schema (verification corrections); not relevant because Evaluate is denied.

**D6. Run on the SAME page: extend `ActionRuntime` with an attach mode, and keep it inert.** Options: (a) let `ActionRuntime` acquire its own session as today and re-navigate (loses the host-pinned egress policy installed by `do_fetch` 181-196, the cookie context, and the isolated per-request context: a second `acquire` for the same key reuses the same CDP context in the best case and a brand-new one with deny-all policy in the worst); (b) `ActionRuntime::attached(driver, session)` that borrows the existing session (never acquires, never releases, `owns_session=false`) and a new `run_scrape(&self, plan, budget, cancel) -> ScrapeActionRun` that enforces the budget and returns ordered `ActionOutcome`s; (c) run actions inline in `do_fetch` with a hand-written loop. Recommendation (b): `ActionRuntime` is where the per-action driver mapping already lives (`execute_action`, 211-410) and it has tests; (c) duplicates it. In attach mode: no event sink (the existing sink would emit `PageFetched` with failure text under a non-ZDR-aware `emit`; D10 part 1 flagged it), no artifact store (it returns bytes; the pipeline persists them with the right org, ZDR check and `page_hash`), the Screenshot and Pdf arms call the new `capture_*` methods with the validated options, and Evaluate stays refused (A2). A missing driver or session is an error, never the dry-run `Ok` the current default path returns. The existing `run`/`acquire`/`release` and their tests stay unchanged (extra defensive change: a `zdr::guard` in the two `store.put` arms, so the unwired runtime cannot become a ZDR hole later).

**D7. Failure semantics and ordered results.** Options: Firecrawl fails the scrape on any action failure and groups outputs by type (`screenshots`, `scrapes`, `javascriptReturns`, `pdfs`; verification corrections); Verevon's `OnError` has `Abort | Continue | Retry`. Recommendation: wire `actionsOnError: "abort" | "continue"`, default `abort`, and **no `retry`** (D3 section D3-8: a replayed click or type can double-submit; the Model Plane already refuses to retry `browser.act`). Results are one ordered array `actions[]` (an improvement over Firecrawl's per-type arrays, marked `[INF]` in the verification) with `{index, type, status: "ok"|"failed"|"skipped", duration_ms, error?: {code, message}, output?: {kind, content_type, bytes, width?, height?, artifact_id? | data_base64?}}`. On `abort` the request fails with `ErrorCode::DriverFailed` (502, `retryable=false`), `details {reason:"action_failed", action_index, action_type, actions:[...ordered, later entries "skipped"]}`; a budget or deadline overrun is `ErrorCode::Timeout` with `details.reason = "actions_deadline"`. On `continue` the page is extracted from whatever state it reached, the response is 200, failed entries stay in `actions[]` and one warning `action_failed` per failure (at most 50) is added. Error messages never echo `write.text`; selectors may appear (they are the caller's own input). To classify without matching message text the driver gets a typed `details.reason` (`element_not_found`, `wait_timeout`, `driver_error`) in the three methods slice 5 touches (`wait_for` 2800-2827, `click`/`type_text` 2828-2918, `select` 3019-3040); D3's `cdp_err` is the eventual home.

**D8. Evaluate inside actions follows the F-t2-002 policy: not expressible.** There is no `evaluate` in the wire enum (D4), `ActionRuntime` refuses the internal variant (A2), and `scrape` field validation turns any `executeJavascript` into a 400 `action_denied` with a message pointing at the policy. A future read-only evaluator is a new action variant behind its own validation and the script-execution ADR (topic 6), never a relaxed `Evaluate` (D2 wire-contract rule). Internal driver scripts (`scroll`, `select`, `back`) keep running constant, Quarry-authored JavaScript; those are not caller scripts.

**D9. Who may send actions or captures: flags, scope, safe mode. ADR-GATED(6) for the Model-facing half.** The card title says "grant-gated". The BrowserBroker grant (F-t2-001) governs `/v1/agent/*` runs; `/v1/scrape` carries no grant and no run (D7 design, section 2: acquisition routes "carry no grant"), so a broker grant cannot gate it. The equivalent gate that exists today is the **service scope** model (`Q/quarry-edge/src/auth.rs` [C] 504-545). Recommendation: (1) `QUARRY_EDGE__SCRAPE_CAPTURE` `off|on` and `QUARRY_EDGE__SCRAPE_ACTIONS` `off|user|on`, both `off` in the committed compose; (2) user principals may send captures when capture is `on`, actions when actions is `user` or `on`; (3) a **service principal** needs the new scope `scrape:interact` in addition to `scrape:read|write` for `actions` (captures need only the existing scrape scopes: they are read-only), and no principal is granted it in `plane-service-principals.json` [C] until the owner decides, so the Model-facing path is closed by construction; (4) **interactive-scrape safe mode** for any request with `actions`: `PageRunner` runs with `ingest: None`, `local_index: None`, `page_renderer: None`, `source_registrar: None`, `title_enricher: None`, and a request that also sets `ingest:true` is a field error (`not_supported_with_actions`), because content captured after interaction is not the page's canonical content and the local-index write-back (`pipeline.rs` 846) and the Model title hop (`pipeline.rs` 780-799) would otherwise persist or ship it (Ingestion captures evidence; durable knowledge goes through Data Plane contracts only, and an action-mutated page is not evidence of the URL). Why scope rather than broker grant: stated divergence, section 6. Why this is safe enough for users: a scrape session is a fresh isolated context with no cookies or profile (the lease has `persist_profile: false`, `browser_driver.rs` 160), host-pinned egress denies off-host loads, and there is no credential entry (D17). It can still submit a public form from the org's egress address, which is the residual risk (section 6), accepted for a user who asked for it and not for an unattended Model.

**D10. Time budgets and the heavy lane.** Facts (finding I): 60 s router layer, 25 s gateway client, 30 s model-gateway client, D5's 55 s `timeout_ms` cap. Options: (a) shrink the action wait cap to fit (about 20 s); (b) keep the 60 s total-wait cap and give `/v1/scrape` a longer, explicit lane. Recommendation (b), because the card and Firecrawl specify 60 s: replace the router-wide `TimeoutLayer::new(60s)` (`routes.rs` 81, 303-305) by a path-aware deadline middleware (60 s for everything, 125 s for `/v1/scrape` only while actions are enabled; same 408 shape for the others); the handler enforces its own deadline (55 s as D5 for plain requests, 115 s with actions, `ErrorCode::Timeout` before the layer fires); the gateway forwards a body that contains `actions` or a capture format with a per-request 125 s timeout instead of the 25 s client default (`GW/config.rs` 289-293). model-gateway keeps its 30 s: Model-originated action lists stay closed (D9). **Heavy lane:** a request with actions can hold one of the two scrape browser permits (`RuntimeLeasePool::new(2)`, `main.rs` 337) for up to a minute and the pool's acquire timeout is 30 s (`browser_driver.rs` 26), so two action scrapes would starve every plain browser scrape. `BrowserDriverAdapter` gets a `heavy: Arc<Semaphore>` (default 1 permit, `QUARRY_SCRAPE_HEAVY_PERMITS`); a request with actions `try_acquire`s it and gets 429 `RATE_LIMITED` (`details.reason = "heavy_browser_busy"`, retry-after 5 s) immediately instead of queueing. Stitching uses the same permit with the opposite rule: if it is busy the capture falls back to crop-at-limit with a warning (D13). Per-org fairness is D6 design slice S6's job (F-t2-025); this lane only protects the shared pool.

**D11. Capture options and the single-capture limit.** `screenshot` accepts `fullPage` (default **false**, matching Firecrawl and keeping the common path to one viewport frame), `clip{x,y,width,height}` in CSS pixels in page coordinates (wins over `fullPage`; validated against `Page.getLayoutMetrics` `cssContentSize` and clamped, an empty result is `invalid_clip`), `quality` 1 to 100 (presence selects JPEG, absence PNG: Codex captures JPEG q80 for model use, PNG stays the lossless archive default), and `viewport{width,height,deviceScaleFactor}` applied with `Emulation.setDeviceMetricsOverride` for the duration of the capture only and restored afterwards, also on error (the page layout can reflow, so the capture is last). `pdf` accepts `format` (`Letter` default, `A3`, `A4`, `Legal`, `Tabloid`), `landscape`, `printBackground` (default **true**; `PrintToPdfParams::default()` omits backgrounds, which makes most PDFs look broken), `scale` 0.1 to 2, and `maxPages` (default 100, at most 200, sent as `pageRanges "1-N"`, the only bound on PDF size before bytes exist). The single-capture limit is a named constant `SINGLE_CAPTURE_MAX_DEVICE_PX = 16_000` (conservative against the common 16 384 px texture limit; **[UNVERIFIED]** for the pinned Chromium 149.0.7827.102: slice 3 includes a measured spike on a 20 000 and a 32 000 px page and records the result in `QR/docs/SCRAPE_CAPTURE.md` [NEW]). Past it, with stitching off or its permit busy, the capture is **cropped** to the limit, `truncated:true`, warning `screenshot_truncated`; with stitching on, D13 applies. CDP's `Page.printToPDF` can also return a stream (`transferMode: ReturnAsStream`); the plain base64 reply is used in v1 with the 32 MiB cap checked after, because `chromiumoxide` sets no websocket message limit (`chromiumoxide-0.9.1/src/conn.rs` 37-39: `max_message_size(None)`), so memory is bounded by `maxPages` and the post-check, not by the transport [INF].

**D12. Fidelity under the host-pinned egress boundary (finding E). ADR-GATED(1) if the product wants more.** Options: (a) keep host-only egress and report what was denied; (b) allow a bounded set of third-party **subresource** hosts (images, CSS, fonts) read-only for scrape renders; (c) disable the boundary for captures. (c) is rejected: it is the strength the audit says not to regress. Recommendation (a) for this workstream: after capture, count denied requests from `egress_receipts` (`Q/quarry-browser/src/lib.rs` trait method; `BrowserEgressReceipt.decision` in `quarry-core/src/contracts.rs` 591-602, which carries a `url` that is never copied out) and return `captures.blocked_requests` plus warning `third_party_resources_blocked`. (b) is a policy decision that belongs with the web-policy owner (ADR topic 1, D7's `domains.allow` extension and its "sub-resource denial needs a `BrowserEgressPolicy` extension (S6)"): a second allow-list that admits subresources but never navigation or XHR needs a new policy field in `BrowserEgressPolicy` and in the CDP Fetch guard. Left as an open question (section 9).

**D13. Tile-and-stitch: clip tiles first, scroll-stitch as the measured alternative.** Options: (A) per tile, `Page.captureScreenshot{clip{x:0,y,width,height}, captureBeyondViewport:true}` with no scrolling, stitched in Rust; (B) Aside's method: scroll to each tile, wait 150 ms plus two animation frames, capture the viewport with `captureBeyondViewport:false`, 200 CSS px overlap trimmed (card, `[SRC]` from the extracted daemon, which always stitches). Recommendation: build (A) as the default and decide (A) versus (B) from the slice 6 spike on three fixtures (a banded 25 000 px page, a sticky-header page, a lazy-image page); (A) has no scroll side effects and no overlap to trim, (B) triggers lazy loaders and repeats fixed headers in every tile. Neither is known to win without a run, so the default is **[UNVERIFIED]** until the spike. Stitching writes PNG row by row through the `png` crate's stream writer so memory is O(tile) not O(page); a JPEG result needs the full RGB buffer, so its pixel cap is lower. Caps: tile height at most 4 096 CSS px, at most 16 tiles, content height at most 60 000 CSS px, stitched pixels at most 40 Mpx (PNG) or 24 Mpx (JPEG), one stitch at a time per process (the heavy permit), whole stitch deadline `min(tiles x 10 s, 60 s)` (D3's `Op::Screenshot` is 10 s per call). Over a cap: crop and set `truncated`. New direct dependencies `png` and `jpeg-encoder` (versions pinned at implementation, **[UNVERIFIED]** against `cargo audit --deny warnings`, a hard CI gate with four existing ignores, `quarry-v2-ci.yml` 231-237), optional behind the `chromiumoxide` feature of `quarry-browser`; `miniz_oxide` is already in `Cargo.lock`. The vision sidecar's tiles are OCR preprocessing and are not reused (verification constraint).

**D14. Storage, content types, ZDR inline, and the key-aliasing fix. ADR-GATED(4, soft).** Non-ZDR: every capture is stored through the existing `artifacts.put(artifact_org, run_id, page_hash, kind, bytes)` with `artifact_org` = the verified claim org (`pipeline.rs` 596-600), so reads are tenant-bound (`resource_routes.rs` 157); `OutputFormats.screenshot/pdf` carry the `FormatRef` (`pipeline.rs` 702-703 replaced). Distinct keys: because the filesystem and S3 object key is deterministic (finding G), each capture passes a **distinct page-hash label**, `page_hash(final_url, "<fp>#cap:<label>")` with labels `final.screenshot`, `final.pdf`, `action.<index>.screenshot`, `action.<index>.pdf`; a test writes two screenshots for one run on the filesystem backend and reads both back as different bytes. JPEG gets `ArtifactKind::ScreenshotJpeg` (stem `screenshot_jpeg`, extension `jpg`) and `content_type_for_key` maps `jpg`/`jpeg` to `image/jpeg` (the `png` and `pdf` mappings exist). ZDR (`zdr.is_active()`, including the floor raised by the user token's org posture, `auth.rs` 136-142): **no artifact, no cache, no event content, no record**; bytes come back inline as `data_base64` in the response, capped by a **separate** capture inline cap (`QUARRY_EDGE__SCRAPE_CAPTURE_INLINE_MAX_BYTES`, default 6 MiB to match model-gateway's `BROWSER_SCREENSHOT_MAX_BYTES`, ceiling 16 MiB, shared across all captures of the request) because D5's text cap (1 MiB) would reject most screenshots. Binary cannot be truncated: over the cap the capture is **omitted**, listed in `omitted`, with warning `capture_exceeds_inline_cap`, and the page content is still returned. This is D4's matrix row 13 ("refused until F-t2-023 ships an inline path, then inline-only"); it is the recommended default of the ZDR ADR (topic 4), proceeding behind the flag without loosening any refusal.

**D15. Cache admission.** The Quarry page cache is keyed by `quarry:page:{fingerprint}` with no org and no options (`quarry-edge/src/cache.rs` [C] 31-33) and is read only when the caller supplies `prev_fingerprint` (`routes.rs` 432-438). Recommendation: any request with `actions`, a capture format, or a non-default viewport is **not cache-admissible**: `ResolvedScrapeOptions::cache_admissible()` returns false, both the read and the write are skipped (D5 D14's rule; `is_default()` is already false for these), and the cached `NormalizedOutput` can therefore never carry another org's capture reference. Defense in depth: capture refs only ever exist for non-default requests. The gateway side (F-t2-003): D4's `Admission` request-shape deny list gains `actions` (already listed), any `formats` element that is an object or the string `screenshot`/`pdf`, and `viewport`; slice 7 adds the cases and a body allowlist for `scrape_preview`. `scrape_stream` and `internal_run_page` (crawl/batch durable path) reject `actions` and capture formats with 400 `unsupported_in_stream` / not accepted (no durable job may carry actions, and inline bytes must never ride Temporal history, D5 D18).

**D16. Per-request session isolation first (finding A).** Options: (a) leave as is; (b) always mint a per-request lease with `session_affinity_key = "{host}~{lease_id}"`, `org_id = hints.org_id` (today empty, `browser_driver.rs` 163), never seed or return it to the pool (`LeaseGuard::take_lease`, `lease_pool.rs` 193-196), keep `host` only as the permit-pool key; (c) wait for D3's slot design. Recommendation (b) as slice 1, with a kill switch `QUARRY_SCRAPE_SESSION_ISOLATION=0`. It is small, independent of D3, and a precondition for letting actions mutate a page. Cost: the pinned egress provider creates a per-session listener keyed by the session key (`endpoint_for_session`, `chromiumoxide.rs` 413-416) and releases it in `release`; a unique key per request means one listener per request, as agent runs already do **[UNVERIFIED]: per-request proxy setup latency; measure in slice 1**.

**D17. Credential entry in `write` is refused heuristically. ADR-GATED(2, soft).** A model- or user-supplied `write` can type a password. Secret custody (who holds user secrets used in pages) is ADR topic 2 and F-t2-024; this workstream must not become a side door. Recommendation: validation rejects `write` whose selector matches a closed credential heuristic (`type=password`, `autocomplete` values containing `password` or `one-time-code`, `name`/`id`/`aria-label` fragments `pass`, `pwd`, `otp`, `secret`, `token`, `cvc`, `cvv`) with `credential_entry_denied`; `write.text` is never logged, echoed in `effective_options`, persisted in the scrape record (D5 D13) or included in an error; only action types, counts and the total wait are echoed. The heuristic is string-level and fail-closed, documented as **not a guarantee**: a page can name a password field anything. A structural check needs the element type, which needs a DOM probe that does not exist without `Evaluate` (it would be a `DOM.describeNode` call in the driver, a follow-on).

**D18. Gateway artifact access: org-bound route now, owner-bound optional later.** Facts (finding H): the existing gateway artifact route authorizes by browser session or orchestration run; a scrape artifact has neither. Options: (a) a new route `GET /api/v1/knowledge/scrape-artifacts/:artifact_id` that authenticates the user, validates the id, requires a Quarry token for the user's org and lets Quarry's org-bound `get_artifact` decide (`NotFound` normalised for foreign ids, as the browser route does); (b) additionally record `artifact_id -> user_id` at scrape-response time in gateway Redis and require the same user on read. Recommendation (a) for v1, because the artifact is org-owned in Quarry by design, the scrape response goes only to the caller, ids are ULIDs, and (b) depends on `GATEWAY_CACHE_REDIS_URL` which is a no-op when unset (D4 section 2). (b) is a flagged follow-on if product wants per-user privacy inside an org. ZDR: an org under ZDR gets the same terminal `withheld` answer as the browser route (no artifact can exist). Content types: allow `image/png`, `image/jpeg`, `image/webp`, `application/pdf`; anything else is refused (the browser route's `image/png` fallback is not copied); PDFs are served `Content-Disposition: attachment`, `X-Content-Type-Options: nosniff` and `Content-Security-Policy: sandbox` (untrusted page output must not execute in the app origin; an inline PDF preview in a sandboxed iframe is a later UI choice). The stale comment at `browser.rs` 1463-1465 is rewritten (slice 7).
