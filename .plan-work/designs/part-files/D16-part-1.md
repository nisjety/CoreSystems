## 2. Verified current state

### 2.1 What the code does today (path:line, all read in the live tree)

**Capture.** `capture_snapshot(page: &Page)` is `QB/chromiumoxide.rs` [C] 1771-1832. It calls `Page::get_cookies()` (1772). In chromiumoxide 0.9.1 that is `execute(GetCookiesParams::default())` on the Network domain, documented "all cookies that match the tab's current URL" (`chromiumoxide-0.9.1/src/page.rs` 900-907) [CONFIRMED]. It then maps each cookie to `Cookie { .. expires: None }` (1781-1789), reads `localStorage`/`sessionStorage` of the current document only through one `page.evaluate` (1792-1811), hard-codes `indexed_db: vec![]` (1817), leaves `viewport` to the caller (`persist_current_page` 693) and captures UA, locale, timezone from page JS (1797-1799). Capture runs only in `release` (1944-1949 via `persist_current_page` 675-697, 5 s timeout at 685) and only for the active tab. Nothing is saved while a run is live.

**Restore.** `open_tab_page` (371-557) calls `self.load_snapshot(&lease)` on EVERY tab creation (472; `load_snapshot` 661-673 swallows load errors and starts fresh). Cookies are hydrated after the initial `goto` through `hydrate_cookies` (925-942, `Page::set_cookies`, which needs a real http(s) page URL), storage through `hydrate_storage` (944-967, `window.localStorage.setItem` on the current page only), then the page is reloaded (528-538). UA, locale, timezone and the saved viewport are never re-applied.

**Schema.** `SessionSnapshot` (`QB/session.rs` [C] 15-35): `cookies: Vec<Cookie>`, `local_storage: Vec<(String,String)>` and `session_storage` with no origin, `indexed_db: Vec<IndexedDbEntry>` (declared with origin/database/store/key/value, 42-49, never populated), UA, viewport, locale, timezone. `Cookie` (307-317) has `expires` but no `same_site`, no `session`, no partition key, no priority. A second, unused capture/hydrate pair exists in `session.rs` 625-676 (`BrowserSession` behind feature `chromiumoxide`; no caller found by grep) that also writes `expires: None`.

**Store stack.** `main.rs` [M] 551-600 builds `PostgresProfileStore` when `profile_store_kind == "postgres"` and feature `postgres-queue` and a DSN exist, else `InMemoryProfileStore`; then `cached_profile_store::maybe_cache(inner, redis_url)` wraps it (598-600). `ProfileStore` (`QB/session.rs` 146-183) is snapshot-typed (`save(org, id, &SessionSnapshot)`), so the Redis layer serializes `SessionSnapshot` itself (`QR/cached_profile_store.rs` [C] 80-135: `serde_json::to_vec(snapshot)`, key `quarry:profile:{org}:{profile}`, TTL 3600 at 40). Redis therefore holds plaintext cookies. `PostgresProfileStore` (`QR/postgres_profile_store.rs` [C]) stores `snapshot JSONB` (`0002_profiles.sql`) with `INSERT .. ON CONFLICT (org_id, profile_id) DO UPDATE SET snapshot = EXCLUDED.snapshot, updated_at = NOW()` (81-93): no ordering, no tombstone. `delete` is a bare `DELETE` (123-131). `S3ProfileStore` (359 lines, plaintext JSON at `profiles/{org}/{id}.json`) is exported (`QR/lib.rs` [M] 166) and never constructed. Production boot requires durable profiles (`main.rs` 694-708).

**Routes.** `QE/routes.rs` [M] 135-157 mounts under `require_auth`: `POST /v1/profiles` (`save_profile`, stores a CLIENT-SUPPLIED `SessionSnapshot` verbatim, `QE/profile_routes.rs` [C] 102-126), `GET /v1/profiles`, `POST /create` (128-171), `GET/PATCH/DELETE /:id` (`load_profile` 268-299 returns the full snapshot including cookie values, `update_profile` 173-266, `delete_profile` 301-317), `POST /:id/restore_probe` (361-430, counts only, no navigation). Every handler scopes by `claims.org_id` only. None checks ZDR, principal type, owner or scope.

**Run start.** `QE/agent_routes.rs` [C] 1415-1432 takes `body.profile_id` as supplied, 1455-1476 refuses a persistent profile for a ZDR run (`zdr_forbids_persistent_profile` 527-533; message prefix `zdr_persistent_profile_forbidden:`), 1487-1508 builds the lease. There is no ownership or scope check at attach: any caller of the org can attach any profile id.

**Kernel driver.** `QB/kernel.rs` [C] 239-262 restores `cookies`/`local_storage` from the same store with `same_site: None // Cookie struct in session.rs predates same_site`, load errors swallowed (`.unwrap_or(None)`); release saves a snapshot fetched from the third-party Kernel API (540-590).

### 2.3 New findings (not in the audit)

1. **Second tab re-hydrates stale cookies over the live jar.** `load_snapshot` runs per tab (472) and hydration applies whenever the tab has an initial URL and the profile has cookies (512-526). Opening a second tab of a persistent session overwrites the session's fresher cookies with the saved ones. The existing test `second_tab_on_same_session_shares_that_sessions_cookies` (`chromiumoxide.rs` 3515) uses a lease with no profile, so it cannot catch this. Fixed in C2.
2. **Restore sends the first request unauthenticated.** Cookies are applied after the first `goto` and a reload repairs it (the origin sees one anonymous hit, which also trips login-redirect side effects). `Storage.setCookies` on the browser context needs no page URL, so restore can precede navigation. Fixed in C2.
3. **A failed restore can destroy the profile.** `load_snapshot` turns every load error into "start fresh" (669-671); the release then saves the fresh (possibly empty) snapshot over the real row. With encryption this becomes dangerous (key service down = every profile overwritten). `Kernel` has the same shape (`.unwrap_or(None)`). Fixed by D16-14.
4. **Two unrelated "profile" stores share the path name.** quarry-control mounts `mountSimple[store.BrowserProfile](r, "/v1/profiles", ..)` (`QC/internal/resources/resources.go` [C] 42; `BrowserProfile{ID, Name, SnapshotURI, CreatedAt}` in `QC/internal/store/store.go` [C] 326-331) with no org column (the purge doc calls it global). It is not the edge's profile data and is not changed here; flagged because an erasure or ACL review that greps `/v1/profiles` will find both.
5. **Gateway profile picker is silently empty.** `GW/domains/ingestions/profiles.rs` [C] 51-61 keeps only list entries that are JSON strings (`v.as_str()`), but Quarry's list returns objects `{profile_id, name, scope}` since the Phase 3 continuation (`profile_routes.rs` 36-57). `/api/ingestions/profiles` (used by `VerevonIngestionsPage.tsx` tests) returns `profiles: []` for a real stack. One-line gateway fix, owner: the browser-UI workstream (D9); listed in section 7.
6. **`persist_current_page` can save a worse snapshot than it loaded** (no active tab returns early, but a tab on `about:blank` or an error page saves an empty cookie list). No "never replace a non-empty profile with an empty capture" rule exists. Addressed in C1 (empty-capture guard).
7. **`restorable` in the probe ignores expiry** (410-411 counts items only). Once expiry is captured, an all-expired profile still reports `restorable: true` unless the probe is changed (P0/C1).
8. **Doc drift.** `docs/RUNBOOKS.md` [M] 117-128 tells operators to `curl /v1/profiles/<id>` and check `expires_at` (no such field exists). `docs/CONTRACTS.md` [C] 150-201 specifies an S3 artifact snapshot (`state.bin.enc`, `scheme`, `key_source: env:QUARRY_PROFILE_KEY | kms:<id>`), which differs from the Postgres reality and from this design's envelope. The OpenAPI file `docs/openapi.yaml` [M] documents no `/v1/profiles` path (only run-body fields at 2394-2436).
9. **Org-core migration runner has a ledger now.** `OC/internal/database/migrate.go` [C] 14-76 applies `*.up.sql` in lexicographic order with a `schema_migrations` ledger; the header of `008_rls_tenant_isolation.up.sql` ("no ledger, re-applies every boot") is stale. New org-core migrations should still be written idempotently (`IF NOT EXISTS`), as the existing ones are.
