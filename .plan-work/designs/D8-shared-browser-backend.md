What changed against the audit cards, in one paragraph: the audit says "Claims has no on-behalf-of field" so attach needs a new Auth Core claim. That is true only of Quarry's `Claims` struct; **Auth Core already mints `acting_user_id` and a `jti` (consumed once by integration-corev2) through an RFC 8693 token exchange** (section 2.1, `[CLAIM-PARTIAL]`). It is nevertheless the wrong primary mechanism for attach (D8-1): a bare delegation claim would authorise a service to drive every live session of the user, which is exactly the widening the brief forbids. The recommendation is a grant-bound attach (Model Plane owns browser grants) with the claim kept as an optional hardening phase.

## 2. Verified current state

### 2.1 What the code does today (path:line, all `[READ]` by D8 unless marked)

**Quarry authority and admission (Ingestion Plane).**
- `RunEntry` holds one `BrowserSession`, one `ObservationContext`, one `constraints`, one `control_mode`, one `actor_id` (`Q/edge/agent_routes.rs:79-102` [C]); the registry is `Arc<StdMutex<HashMap<String, Arc<TokioMutex<RunEntry>>>>>` (107). There is no tab ownership, no lane, no epoch, no delegate.
- Ownership: `caller_owns_browser_run` requires `run_org_id == claims.org_id` and `run_actor_id == claims.actor_id()` (474-482); `caller_owns_live_run` wraps it (484-486). Every handler (`step` 2249, `set_browser_session_control` 1752, tabs 3222/3260/3367/3420, `list_receipts`, projections) answers a non-owner 404 "agent run not found". `Claims::actor_id()` returns `user_id`, which for a service principal is normalised to `service:<id>` (`Q/edge/auth.rs:144-160, 168-174` [C]); `Claims` has no `acting_user_id` or `jti` field (62-91) and `validate_and_normalize_principal` rejects a service token that also carries a `user_id` (163-174). **A Model Plane service call on a user-owned run is therefore a 404 today** (confirmed).
- Governed start: broker domains replace client domains and are required in prod (`start_run` 1372-1413); per-step exact equality `broker_domains != run_domains` (`validate_run_grant` 314-338, called from `step` 2257-2267, `execute_ws_action` 3094-3101, `new_tab` 3279-3289). `canonical_broker_domains` rejects an empty or over-32 list and any non-canonical ordering (`Q/br/lib.rs:59-77` [C]); `is_canonical_broker_domain` rejects IP literals and single-label names (132-151). **No grant can express "any public host".**
- Budget and lease: `enforce_step_budget` counts every action, human or agent (446-451), called at `step` 2294 and `execute_ws_action` 3118; `ttl_s = max_runtime_s.unwrap_or(120)` is stored in the lease and read by nothing (1446, 1502, per D2 2.4). The gateway creates every UI session with `max_steps: 12`, `allowed_domains: [first host]`, `max_runtime_s: 120` (`GW/browser.rs:483-494` [C]).
- Control: `set_browser_session_control` writes `entry.control_mode = body.mode` and a `Control` timeline event with `initiated_by: Human` hard-coded (1733-1781). `step` and `execute_ws_action` never read `control_mode` (2228-2409, 3086-3193). `[D2]` S3 moves enforcement into Quarry (`admit_action`, `RunLive`, `StepInitiator`, `USER_TOOK_OVER`).
- Step handler holds the run `TokioMutex` for the whole action (`step` 2248-2408; `execute_ws_action` 3093-3191). Human WebSocket actions and agent REST steps on one run therefore serialise FIFO; a 10 s agent navigation blocks the user's click. The `ObservationContext` (step counter, `current_url`, `page_hash`, `previous_observation`, egress cursor, `active_snapshot`) is single and shared (`start_run` 1571-1599).
- Receipts store the post-action **observation and the action verbatim** for every non-ZDR step (`StepReceipt.action`, `.observation`, `Q/rt/step_receipts.rs:183-210`; `quarry_step_receipts.action JSONB NOT NULL, observation JSONB` in `0007_step_receipts.sql`; written at `step` 2352-2366 and `execute_ws_action` 3155-3165). The checkpoint stores `current_url` in a dedicated column and in state JSON after every step (2391-2398; `0006_agent_run_checkpoints.sql`). **With free human browsing this becomes a persistent record of every page the user visits and every string the user types** (new finding F1, section 3 D8-5). Timeline Action items expose only action name, outcome and error code (`browser_timeline_action` 764-779), so metadata-only receipts do not break the UI.
- Tabs: tab routes are session-level and owner-only (3202-3451). `new_tab` revalidates the grant, re-applies the **session-wide** egress policy and always makes the new tab active.
- Sensitive approvals read `entry.grant_id` and demand a matching parent run grant (`sensitive_approval_for_action` 144-282, 154-157); the used-approval set is process-local (98-101).
- Run routes are registered at 3659-3728; `/interact` aliases `step` (3666). `StepBody` has only `action`, `instruction`, `extraction_profile` (818-824): execution-core's `StepRequest` already sends a `grant_id` field (`EC/quarry_agent.rs:612-630` [C]) that Quarry **silently drops** (new finding F8). The same body is used by the MCP facade `browser.observe`/`browser.act`, which steps an existing Quarry run by `quarry_run_id` + `lease_id` + `grant_id` with the service token (`EC/tool_bridge/mod.rs:237-295, 307-322` [C]); on a user-owned run that is the same 404.

**Browser driver (quarry-browser).**
- One `SessionPages { active_tab_id, tabs, browser_context_id, download_dir }` per session key = `lease.session_affinity_key` = run id (`Q/br/chromiumoxide.rs:97-110`, `session_key` 273-275 [C]). **Every driver call resolves its page through `active_tab_page`** (346-356; about 30 call sites of `current_page`/`current_tab_page`/`active_tab_page`, grep count 30 including the definitions). Human and agent therefore share one "active" tab; there is no way to act on a non-active tab.
- `open_tab_page` ends with `session_pages.active_tab_id = Some(tab_id)` (555): **every new tab steals the active slot** (finding F2). Popups are rewritten into same-tab navigation by `install_popup_bridge` (969-1007), so tabs only exist through the API, which keeps the ledger simple.
- All tabs of a session share one CDP browser context (one cookie jar, 401-470, 473-487).
- Egress policy is **per session**: `egress_policies: HashMap<session_key, BrowserEgressPolicy>` (130), looked up by the CDP Fetch guard for every request (`install_network_guard` 706-757, which already receives `tab_id` 709), set by `configure_egress_policy` (1907), cleared at release (1976) and, today, wholesale by a new lease (212, removed by `[D3]` S2). `BrowserEgressPolicy::allows_url` is a pure allow-list check with `restricted: bool` (`Q/br/lib.rs:32-129`); the SSRF layer (`guard_page_request_target` after the policy check, 767-793; DNS-pinned per-session proxy, `--disable-quic`) is independent of the list. **An open-web mode is a few lines in `allows_url` and does not touch the SSRF layer** (finding F3). A single-host allow-list also blocks third-party subresources (scripts, fonts, images) because the Fetch guard checks every request `[INF]`; verify in S8.0.
- Per-session registries read by observation: `devtools_events` (2591-2612), `egress_receipts` (2614-), `dialogs`/`dialog_pages` (137-142). Both event types carry `tab_id` (`BrowserDevtoolsEvent.tab_id`, `BrowserEgressReceipt.tab_id`, 799-806) but the readers do not filter by it, and `ObservationRunner::execute` reads all of them per session (`Q/rt/observation.rs:576-600`). **If a human tab and an agent tab share a session, the agent's observation would carry the human tab's network URLs, console lines and dialogs** (finding F4: a privacy leak into model input; the pin must filter every collector).
- `BrowserSession` is `Clone` (`{ lease, inner: Arc<Mutex<SessionInner>> }`, `Q/br/lib.rs:666-677`) and is constructed by struct literal in 13 places (`browserbase.rs:246,361`, `browserless.rs:223`, `chromiumoxide.rs:1926`, `kernel.rs:500`, `pool.rs:163`, `Q/rt/lib.rs:226`, `browser_driver.rs:348`, `observation.rs:2841`, `agent_routes.rs:2068`). The driver trait has default-`Unsupported` tab methods (`lib.rs:504-525`); `BrowserDriverCapabilities` is `Copy + Default` (269-286).

**BrowserBroker (Model Plane, Go).** `defaultGrantTTL = 15 min` (`BB/internal/server/server.go:22` [C]); `AcquireGrant` rejects an empty domain list through `NormalizeAllowedDomains` (61-64); `AcquireGrantRequest.mode` already exists and means `local|cloud` (`MP/proto/model_plane/v1/browser.proto:30-33`, `scopeURLForMode` 170-179), so a grant kind needs a **new field**, not `mode`. `Grant` has `SessionKey`, `ParentGrantID`, `ExpiresAt` and no kind, owner on validation, renewal or absolute cap (`BB/internal/grant/grant.go:44-70`). `[D1]` adds kind, `owner_id`, `zdr`, `absolute_expires_at`, `Repository`, `Derive`, a reserved `Renew`, per-owner caps and a policy hook; D1 allocates proto field numbers 10 to 19 (WS1), 20 to 39 (F-t2-032), 40 to 49 (F-t2-008).

**Model-gateway and execution-core.** `POST /v1/browser/runs` requires a verified browser bearer, refuses ZDR browser runs outright (`MG/browser_run.rs:297-315` [M], `browser_run_zdr_blocked`) and resolves a grant by exact policy equality (138-202); `[D1]` 1b makes it derive a narrower run grant from a `session` parent. `execute_browser_agent` builds `PlanConfig` and calls `run_browser_agent_loop`, which **always leases its own Quarry run** (`EC/browser_agent.rs:658-695`) and always `close_run`s it (773-775); a Quarry step error fails the plan (749-753). `PlanConfig` (243-292) has no attach field.

**Verevon gateway and SPA.** `run_action` pre-flips the whole session into `human_takeover` on any human action (`GW/browser.rs:715-731` [C]) and blocks agent-labelled actions in takeover (705-714): **incompatible with concurrent co-browsing**, because a user clicking in their own tab would pause the agent in its tab (finding F5). `start_ai_run` starts a separate lease at the user's current URL (1311-1318) with the interim `session:{id}` grant string (1235) `[D1]` replaces that. `BrowserControlMode` is a session-level enum (261-285). The SPA has `browser_tab.create|select|close`, `browser_action.set_control_mode` action contracts (`FE/src/shared/actions/action-registry.ts:3025-3080` [C]) and `BrowserTab = {…, active}` (`FE/src/shared/api/browser-client.ts:204`).

**Auth Core (Control Plane).** `POST /api/:audience/token-exchange` verifies a user `aud=session-core` bearer, then mints a 90 s token for `audience` with `principal_type=service`, `acting_user_id=<subject user>`, `jti`, the **subject's** `zdr`, audited durably (`AC/plane-token.controller.ts:404-553` [C]; `AC/convex-token.service.ts:238-262, 666-704, 868-` [C]). ### D8-1. ADR-GATED (audit topic 3, shared human+agent sessions): three options, one recommendation

**What has to be true of any answer.** (R1) a user can browse past one host for longer than 120 s; (R2) a Model Plane run can drive a tab inside the user's visible session; (R3) neither ever widens the user's ACL or a Space's authority; (R4) Quarry still executes or rejects every action (model proposes); (R5) ZDR is never weakened.

| | Option 1: broker `human_browse` kind with renewal, plus a session-bound `attach` child grant | Option 2: delegation claim so a service principal attaches to a user-owned run | Option 3: end the session and resume with a new grant |
|---|---|---|---|
| What it is | The broker (already the browser authority, validated by Quarry on every action) mints a root `human_browse` grant (open public web minus deny-list, renewable) and, from the user's own bearer, an `attach` child bound to one Quarry run. Quarry validates both per step | Execution-core presents a token that says "service X acting for user U" (Auth Core RFC 8693 exchange, `acting_user_id`); Quarry lets it act on U's runs | Close the user's Quarry run, let the Model Plane run resume the checkpoint under a grant it owns, give it back afterwards |
| R1 free browsing | **Yes**: the only option that addresses navigation policy (`allows_url` open-web mode, F3) and lifetime (renewal) | No. Claims say nothing about hosts or TTL | No |
| R2 attach | Yes, through Quarry attach registry + tab pin | Yes, but see R3 | **No**: `resume_run_id` requires `caller_owns_browser_run(checkpoint.actor_id == claims.actor_id())` (`agent_routes.rs:1334-1342`), so a service resumer gets 404; fixing it means rewriting `actor_id`, which hides the run from the user. Resume restores the URL only (1536-1564): tabs, cookies (no persistent profile) and form state are lost. ZDR runs cannot resume at all (1350-1356) |
| R3 never widen | Yes, by construction (invariants I1 to I8 below): the child is derived only from the owner's bearer, bound to one run, narrower, short, revocable, with no `space_id` anywhere | **No on its own**: `acting_user_id == run.actor_id` authorises the service on **every live session of that user**. A Space-hosted run for user U could drive U's personal browser session. It needs an owner-set binding anyway, which is Option 1's attach record | Yes (nothing is shared) but only by not sharing |
| R4 | Yes: Quarry validates the attach grant per agent step (existing per-step broker call, `agent_routes.rs:2257-2267`) | Yes | Yes |
| R5 ZDR | attach refused for ZDR runs (`model-gateway` already refuses ZDR browser runs; Quarry refuses too); ZDR human sessions allowed with no persistence | Exchanged token carries the **subject's** zdr, but Quarry ignores service `zdr` claims by design (`auth.rs` `zdr_floor`) | impossible for ZDR |
| Control Plane / Auth Core change | **None** in phase A. Quarry already holds `browser:read` on `browser-broker` under D1; derive and renew use the user's own browser bearer, which D1 1b already forwards | Registry row `execution-core.tokenExchange.quarry`, Quarry claim parsing, Control Plane sign-off | none |
| Per-step cost | one broker `ValidateGrant` per action (already paid today); high-rate human input adds a few ms per action | an Auth Core exchange per token lifetime (90 s) on the browsing hot path; a cache gives up to 90 s revocation lag | none |
| Replay / revocation | attach grant id is a bearer capability, but only the registered `execution-core` service token can use it, Quarry pins the first attaching actor, and revocation takes effect on the next step | `jti` single use is enforced by the consumer (integration-corev2); Quarry has no guard; reuse across runs needs a run-bound claim | n/a |
| Effort | XL overall (this document) | M for the claim alone (S8.10), but it still needs Option 1's binding | S, but a product regression |
| Verdict | **Recommended** | **Phase B hardening only** (S8.10, optional): adds cryptographic delegator identity on top of Option 1 | **Rejected** as the shared-session mechanism; kept only as today's degraded fallback (a separate private lease) when attach is off |

**Option 2b (the OD13 proposal: forward the user's own `aud=quarry` bearer to the agent loop).** Rejected for attach. With a user token the caller passes `caller_owns_browser_run` natively, but then **the agent's origin is client-asserted** (D2 D2: a user-token caller is Human unless it volunteers `initiated_by: "agent"`), so a caller that omits the hint bypasses the takeover gate; and a 300 s bearer cannot cover a run whose grant lasts 15 minutes. The service principal is the only unforgeable "this is the agent" signal Quarry has.

**Recommended design (Option 1), in detail.**

1. *Grant kinds `[D1]` + D8.* Root kinds: `session` (D1, a host allow-list of at most 8) and `human_browse` (new: no host list; `policy_mode = "open_web"`, `denied_domains` from the broker's policy hook; renewable; absolute cap). Child kinds: `run` (D1, AI run with its own lease), `sensitive_approval` (existing), and `attach` (new: bound to one Quarry run through `resource_id`, an explicit allow-list of at most 8 hosts, at most 900 s, never renewed).
2. *Who mints.* Only the broker, only from a verified **user** bearer (`[D1]` D5: no service principal holds `browser:write` on `browser-broker`; a contract-spec assertion). Verevon gateway asks model-gateway; model-gateway `POST /v1/browser/runs` with `attach_session_id` derives the attach child with the caller's own bearer inside the request, before any thread/run write (the D1 D2 pattern).
3. *What Quarry stores.* `AttachState { attach_id, grant_id, delegate_actor, tab_id, nav_policy (allow-list), budget, phase }` in memory beside the run (process-local like sensitive approvals, `agent_routes.rs:98-101`), created by `POST /v1/agent/runs/{run_id}/attach` from the service principal presenting the attach grant. Quarry validates it at the broker: `active`, `kind == attach`, `owner_id == run.actor_id`, `resource_id == run_id`, `parent_grant_id == run.grant_id`, org equal, domains canonical.
4. *How a delegate step is authorised* (`resolve_caller`, new, runs right after the `closed` check of `[D2]` `admit_action`): owner token gives `Caller::Owner` (unchanged); a **service principal** with `QUARRY_EDGE__ATTACH=1` whose request carries `grant_id` equal to a live `AttachState.grant_id` of the same org and whose `claims.actor_id() == AttachState.delegate_actor` gives `Caller::Delegate`; everything else is the existing 404. Delegate steps are `Initiator::Agent` regardless of any body field, run on the **pinned agent tab** only, under the **attach** nav policy and **attach** budget, and revalidate the **attach** grant (which implies the parent, because revocation cascades `[D1]`).
5. *What a delegate may call.* `attach` (once), `step`/`interact` (own tab), `tabs/{tab_id}/mark` (own tab), `GET tabs` (own tab only, filtered), `DELETE attach/{id}` (own). It may not: start or close runs, change control, open/close/select other tabs, read frames, receipts, timeline, devtools, egress receipts or profiles.
6. *Never-widen invariants* (each has a named test in S8.2, S8.5 or S8.6):
   - **I1** Attach authority exists only if the owner's bearer derived it: `TestDeriveAttach_OtherOwnersParentIsNotFound`, `attach_grant_of_another_user_is_refused`.
   - **I2** Attach policy is a strict subset of the parent's and an explicit list of at most 8 hosts; a `human_browse` parent never lends open web (`TestDeriveAttach_RejectsInheritFromOpenWeb`). The agent tab additionally runs under a per-tab egress policy equal to the attach list (D8-6), so a click-through to a third host is blocked at the Fetch guard, not just by a post-check.
   - **I3** No `space_id`, `team_id` or "shared" flag exists in `AcquireGrantRequest`, `DeriveRunGrantRequest`, the attach body or `AttachState`. A Space member has no path: deriving needs the owner's bearer; Quarry compares `grant.owner_id` with the run owner. Space-hosted agent runs attach only to the acting user's own sessions.
   - **I4** Time: `expires_at = min(now + 900 s, parent.expires_at)`; revoking the parent revokes the child `[D1]`; no renew path exists for `attach`.
   - **I5** Scope: the delegate allow-list in item 5; verified by a table-driven test over every route in `agent_router()` (3659-3728).
   - **I6** Origin: initiator comes from the verified principal plus the live attach binding (D8-4).
   - **I7** Revocation: "Stop agent" revokes the attach grant through the user's bearer and releases the attach; the next agent step is `403 SECURITY_BLOCKED` (G6 fix of `[D1]`). Give back and Take over change holder, not authority.
   - **I8** ZDR: `entry.zdr.is_active()` refuses attach (`403`, reason `attach_zdr_refused`).
7. *Failure modes.* Broker down: agent steps fail closed as today (`driver_err`); Quarry restart: attach state is lost, the delegate gets 404 `run_not_live`, the run fails or pauses (documented limit, not a regression); broker restart (in-memory store): grants lost, sessions end; `[D1]` 1c Postgres removes that for non-ZDR.

**Phase B hardening (optional, ADR-GATED topic 3 follow-up, slice S8.10): the Auth Core claim.** What it adds: cryptographic proof that the service is acting for the run's owner and for this run. Exact deltas:
- Registry `apps/Control Plane/config/plane-service-principals.json` [C]: `execution-core.tokenExchange = { "quarry": ["session-core"] }` (the scope `browser:execute` is already in `scopesByAudience.quarry`). Control Plane owner sign-off; spec bundle P3 in `AC/plane-service-principals-policy.contract.spec.ts` [C] (principal `execution-core` holds exchange on `quarry` only; refused on every other audience; parity script `scripts/tests/principal-registry-parity.test.sh`).
- `AC/plane-token.controller.ts` [C] `PlaneTokenExchangeBody` (114-120): optional `resourceRunId`; `AC/convex-token.service.ts` [C] `PlaneJwtClaims` (225-262): `resourceRunId?: string` emitted as claim **`quarry_run_id`** only when audience is `quarry`, `actingUserId` is set and the value matches `^[A-Za-z0-9_-]{8,64}$`; the 90 s TTL and subject-derived `zdr` are unchanged. New cases in `AC/plane-token-exchange.composition.spec.ts` [C].
- Quarry `Q/edge/auth.rs` [C] `Claims` (62-91): `acting_user_id: Option<String>`, `jti: Option<String>`, `quarry_run_id: Option<String>` (`#[serde(default, skip_serializing_if = "Option::is_none")]`); `validate_and_normalize_principal` (152-175) accepts `acting_user_id` only for `principal_type=service`; accessor `Claims::acting_user()`. `resolve_caller` additionally requires, when `QUARRY_EDGE__ATTACH_REQUIRE_DELEGATION=1`, `acting_user_id == run.actor_id` and `quarry_run_id == run_id`. Quarry does **not** consume `jti` (a token is reused across the steps of one run within its 90 s life, and it is run-bound); replay across runs is closed by `quarry_run_id`. Execution-core calls the exchange with the run's `x-session-authorization` bearer exactly as `mint_delegated_ingestion_token` does (`integration_tools.rs:591-652`).

### D8-2. ADR-GATED (audit topic 3; policy owner topic 1): the human navigation policy is "open public web minus a broker deny-list"

- Options: (a) raise the allow-list cap (32 to N) and let the gateway enumerate hosts; (b) a `human_browse` grant with `policy_mode = "open_web"` and a broker-owned deny-list; (c) a per-navigation approval prompt for every new host.
- Recommendation **(b)**. (a) cannot work: a page references dozens of third-party hosts that the Fetch guard checks per request (F3, `[INF]`), and the broker rejects wildcards; (c) is the Codex-style consent model and belongs to F-t2-032, not to day-one browsing.
- Representation. `ValidateGrantResponse.policy_mode` (`""`/`"allowlist"`/`"open_web"`) and `denied_domains`. Quarry parses them with a fail-closed `BrokerNavPolicy::from_validation`: unknown mode is an error, so **an older Quarry facing a `human_browse` grant fails closed** (empty `allowed_domains` is rejected by `canonical_broker_domains`, `lib.rs:61-63`).
- Enforcement point unchanged: the per-session `BrowserEgressPolicy` in the Fetch guard, the pre-step `domain_allowed`, the post-step `obs.url` check. Open-web `allows_url` admits only `http`/`https` hosts not matching a denied suffix; `data:`/`blob:` keep their rule (`lib.rs:99-129`). **The SSRF layer is untouched**: `guard_navigation_target`, `guard_page_request_target`, the DNS-pinned proxy and `--disable-quic` still apply after the policy decision. A test proves private, loopback, link-local and metadata targets stay blocked under open web.
- Default deny-list (broker env `BROWSER_BROKER_DENY_SUFFIXES`): `.internal`, `.local`, `.localhost`, `.localdomain`, `.lan`, `.home.arpa`, `metadata.google.internal`, `metadata.goog`. The org-level override is the `PolicyResolver.ResolveHumanBrowse` hook `[D1]`; which plane owns org policy stays open (ADR topic 1) and is not decided here.
- Who may hold the kind: user principals only. Quarry refuses a service principal on a `human_browse` grant (`403`, reason `human_browse_service_refused`). The AI never inherits open web: `Derive` from a `human_browse` parent requires an explicit non-empty host list of at most `BROWSER_BROKER_MAX_RUN_DOMAINS` (8) (this tightens the `[D1]` D3 rule "wide-human-browse guard", which assumed inheritance).
- Agent-labelled actions under the **user's** token on a human session (the `KnowledgeComposer` "apply suggestion" path, `actor: 'agent'`) keep the session policy: they are user-confirmed in the UI. `[UNVERIFIED]` confirm in S8.0 that no automatic (unconfirmed) caller uses that path.

### D8-3. ADR-GATED (audit topic 3, open question 10.2.2): renewal and idle semantics

- Grant: `ttl` 900 s (`BROWSER_BROKER_GRANT_TTL_SECONDS` `[D1]`), `RenewGrant` extends to `min(now + ttl, absolute_expires_at)`; **absolute cap for `human_browse` = 14,400 s (4 h)** so it equals the interactive backstop `INTERACTIVE_RUN_MAX_TTL_S` of `[D2]` D7 (D1's `session` absolute default of 8 h is unchanged; the user ratifies one number). Renewal is refused for revoked or expired grants (no resurrection), for `run`, `attach` and `sensitive_approval` kinds, for non-owners, and beyond the cap.
- Who renews: **user presence**, not Quarry. The SPA keep-alive (`POST /api/v1/browser/sessions/{id}/keepalive`, every 300 s while the browser surface is mounted and `document.visibilityState === 'visible'`) calls model-gateway `POST /v1/browser/grants/{id}/renew` with the user's own bearer. Rationale: `[D1]` D5 gives Quarry `browser:read` only; giving it a renew scope would make a compromised Quarry able to extend every grant to the cap. A laptop asleep for more than 15 minutes loses the grant (documented, non-resurrectable); the Quarry run then idles out under `[D2]` (900 s) and is **resumable** for non-ZDR runs (`resume_run_id` with a new grant, a follow-up owned by F-t2-035).
- Quarry idle: unchanged from `[D2]` D7 for class `Interactive` (900 s idle, 1800 s idle in takeover with no viewer, 4 h backstop; viewers block idle only). D8 adds nothing there except ratifying the numbers and `touch()` on every human step and keep-alive (the keep-alive does **not** touch the run: presence is not activity).
- Agent attach: 900 s from derive, never renewed; `QUARRY_EDGE__ATTACH_IDLE_TTL_S` (default 180) auto-releases an attach with no agent step, so a crashed execution-core cannot pin a tab.
- Replaces: the 120 s run TTL (`agent_routes.rs:1446`; already dead per `[D2]`), the gateway's `max_runtime_s: 120` literal (S8.3 stops sending it for human sessions) and the 15-minute cap as the *session* limit (it stays as the *idle* limit).

### D8-4. Human-versus-agent origin comes from Quarry, never from a client flag

- Rules (extend `[D2]` D2): `Agent` if `claims.is_service()`; for a service caller the initiator is `Agent` **and** it must resolve to a live attach (otherwise 404); for a user token the initiator is `Human`, with the `[D2]` tighten-only hint (`initiated_by: "agent"` can only make a request stricter). A service principal can never claim Human; a user token can never claim a delegate's lane (the lane comes from the attach binding, not a field).
- Per-tab holder (D8-7) is Quarry state mutated only by `Human`-initiated calls.
- Hazard for sibling (b): if the delegated-bearer work gives execution-core a **user** token on agent steps, those steps are Human to Quarry. The attach contract therefore requires a service principal; (b) must not route attach through a user token (section 7).

### D8-5. New decision (closest audit topic 4): human browsing evidence is metadata-only, and checkpoint URLs are stripped

- Problem (F1, section 2.2). Free browsing would write every visited page's observation and every typed string (`AgentAction::Type { text }`) into `quarry_step_receipts`, plus the full current URL into `quarry_agent_run_checkpoints.current_url` after each step. For a password field that is a stored credential; for a bank page it is stored content. Audit risk 4 ("evidence captures secrets") and `F-t2-021` (capture-time redaction) are not yet built.
- Decision: for `Initiator::Human` steps on a non-ZDR run, persist a **metadata-only receipt**: `action` redacted through `redact_action_for_human_receipt` (`Type`/`TypeRef`/`FrameTypeRef`/`TypeSemantic` text becomes `"[redacted]"`; `Navigate`/`Back`/`Forward` keep the **origin and path only**, query and fragment dropped; `Select`/`Upload`/`Press` values redacted), `observation = NULL`, outcome and cost kept, `initiated_by = human`. Agent-initiated steps keep today's full receipts (they are the audit trail of what the model saw). `checkpoint_for_entry` strips query and fragment from `current_url` for a run whose nav policy is open web. Env `QUARRY_EDGE__HUMAN_RECEIPT_MODE` = `metadata` (default) | `full` | `none` (`none` writes no human receipt at all).
- This is a **hard prerequisite for enabling `human_browse` in production**, and it is ZDR-neutral (ZDR runs persist nothing). It is a safe tightening that can ship before any ADR (section 8). `F-t2-021` later generalises redaction to agent steps; the receipt-builder edit point is shared (section 5 hotspot).
- ADR-GATED as a product decision: do non-ZDR users expect a browsing history in Verevon at all? This design says no; the timeline keeps action names and outcomes only.

### D8-6. New decision: the agent tab is pinned, narrower, and isolated from the human's collectors

- *Pin.* `BrowserSession` gains `tab_pin: Option<Arc<str>>`; `session.pinned_to(tab_id)` returns a clone. `ChromiumoxideDriver::active_tab_page` (346-356) resolves the pin first, so **no per-method change** across the ~30 call sites. A pinned tab that closed yields a typed `NOT_FOUND` (`details.reason = "pinned_tab_closed"`), never a fallback to the active tab.
- *Focus.* `open_tab_page(session, url, activate)`; the attach path calls it with `activate = false`, leaving `active_tab_id` (the user's tab) alone. Driver capability `background_tabs`.
- *Per-tab egress policy.* Key the policy map by `(session_key, Option<tab_id>)`; the Fetch guard (747-756) looks up the tab entry first, then the session entry. The agent tab carries the attach allow-list; the user's tabs carry the session policy (open web). `close_tab` and `release` delete the entries. Driver capability `per_tab_egress`. A human who takes over the agent tab **keeps the agent tab's narrow policy** (taking over changes who types, not what the tab may reach); the UI offers "open in my tab" for a blocked host. This guarantees the user's click cannot widen the agent's authority and needs no policy switch race.
- *Collector isolation (F4).* With a pin set: `devtools_events` and `egress_receipts` return only events whose `tab_id == pin`; `dialogs` only for dialogs whose page is the pinned page; `live_frame` renders the pinned page; `list_tabs` for a delegate is filtered by Quarry to its own tab. Driver capability `tab_pinning`. Test: `pinned_observation_never_contains_other_tab_events` (live lane).
- *Cookie jar (decision for the user).* The agent tab shares the session's CDP browser context, i.e. the user's cookie jar: that is the point of co-browsing (the agent works in the user's logged-in session) and what Codex and Aside do. Alternative: an isolated context per attach. Default: **shared jar**, attach is an explicit user act, `PersistentCookieUse`-style consent is implicit in "Ask AI on this tab"; per-origin consent arrives with F-t2-032 (ADR topic 1). Flagged as open question 3 (section 9).

### D8-7. New decision: control is per tab (holder + epoch), the session flag stays as a global pause

- State: `TabMeta { opened_by: human|agent, holder: human|agent, mark: none|deliverable|handoff, attach_id, epoch }` in `TabLedger`, plus `[D2]`'s session `control` atomic (`epoch << 1 | mode`) kept as the **global agent pause** ("Pause all agents": `human_takeover` refuses every delegate step, `[D2]` semantics unchanged).
- Agent admission: allowed iff session mode is `agent_control` **and** target tab is the attach tab **and** `holder == agent`; otherwise `409 USER_TOOK_OVER` with `details = { scope: "session"|"tab", tab_id, tab_epoch, control_epoch }`.
- Human admission: always allowed (Codex precedent: the user can interact at any time). A **non-passive** human action (everything except `Screenshot`, `Pdf`, `GetContent`, `Wait*`, `Scroll`, `MouseWheel`) on a tab whose holder is `agent` performs an **implicit Take over** atomically in Quarry: `holder = human`, `epoch += 1`, a timeline `tab_control` event with `initiated_by: human`. The next agent step sees the new holder: no in-flight cancellation (`[D2]` non-goal); the in-flight step completes and its receipt records the admission epoch.
- Explicit routes: `POST /v1/agent/runs/{run_id}/tabs/{tab_id}/control { holder, expected_epoch? }`, user token only (an agent can neither take nor give: `403`, reason `control_transition_requires_human`); `holder: "agent"` ("Give back") requires a live attach. Reveal is the existing `select_tab` (changes the user's active tab, not the holder).
- Gateway change (F5): `run_action` skips its session-level pre-flip (`browser.rs:715-731`) when the session projection advertises `tabControl: true`; the 409 pre-check for agent-labelled actions stays as UX-level early rejection.

### D8-8. New decision: two execution lanes, one run-global step counter

- Lane = `{ ctx: ObservationContext, last_observation, tab_id, lock }`. The human lane is the run's existing `ctx`; each attach owns a second lane. `admit_action` (`[D2]`) runs under the entry lock, then the entry lock is **released** and the action executes under the lane lock; receipts, `last_observation` and the checkpoint are written after re-taking the entry lock briefly.
- The step counter becomes `RunLive.step_seq: AtomicU32` (run-global); before executing, `lane.ctx.step = step_seq.fetch_add(1)` so event keys `{run_id}:action:{step}:started` and `proof_{run_id}_{step}` (`observation.rs:392, 953, 1010`) stay unique (F7).
- Until S8.7 lands, attach ships with serialisation (human clicks wait behind an agent step): acceptable for internal testing, **not for GA** (flag `QUARRY_EDGE__ATTACH` stays off in prod until S8.7).

### D8-9. Attach lifetime, budgets and limits

- One live attach per run in v1 (`409 attach_exists`); one agent tab per attach in v1 (multi-tab attach is a later extension of S8.9). Agent budget (`max_steps`, `max_runtime_s`, `max_cost_usd`) arrives in the attach body from the plan constraints execution-core already builds; Quarry enforces `max_steps` per attach (not on the session counter) and `max_runtime_s` at admission (`RATE_LIMITED`, `details.reason = "attach_runtime"`); cost caps stay with F-t2-008 (not duplicated here). **Human steps are exempt from `max_steps`, `max_runtime_s` and `max_cost_usd`** (`budgets_apply(initiator) = initiator == Agent`), a Quarry rule independent of what the gateway sends.
- Session-level `constraints.max_steps` for `human_browse` runs is normalised to 0 server-side.
- ZDR: attach refused; ZDR human sessions allowed, no receipts, no checkpoint, no timeline, keep-alive allowed.

### D8-10. The session state machine (shared with F-t2-035 and F-t2-054)

Three layered machines. States are Quarry's; Model Plane and the SPA read them from the projection.

**Run (Quarry run = visible browser session)**
`starting` -> `live` -> (`idle` is not a state: it is `live` with no viewer and no activity until the sweeper verdict) -> `expired` (resources released, non-ZDR checkpoint stays `active` and **resumable**; ZDR: gone) -> `live` again through `start_run` with `resume_run_id` and a fresh grant; or `live` -> `closed` (owner DELETE; checkpoint `closed`). Extra transitions from `[D2]` S4: `expired(max_age)` at the backstop, `agent.expired` event. `grant_lapsed` is not a run state: it is the condition "every step returns 403"; the sweeper reaps it by idle.

**Attach (delegate binding, in memory)**
`requested` -> `attached` (agent tab opened, `holder = agent`) <-> `paused_by_user` (`holder = human`, tab epoch +1; Give back returns to `attached`, epoch +1) -> `released` (delegate DELETE or turn end), `aborted` (owner "Stop agent"), `revoked` (grant revoked, expired or parent gone, detected at the next step or sweep), `idle_released` (`ATTACH_IDLE_TTL_S`), `session_ended` (run closed or expired). Disposition of the agent tab on any terminal state: close it unless `mark != none` (D8-11).

**Tab**
`open` with immutable `opened_by`, mutable `holder`, `mark`; `closed`. Events: `tab opened|selected|closed` (existing), `tab_control` (new), `attach` (new).

What F-t2-035 (durable hosted sessions) and F-t2-054 (run- and turn-scoped tabs) take from this: 035 = the `expired` -> `resumable` -> `live` arc and the grant lifetime (renew, absolute cap); 054 = attach lifetime equals turn scope, tab `mark` and `release` are the turn-end primitives. They must not add a parallel state enum: extend `RunLive` and `TabLedger`.

### D8-11. Tab marks and turn end (phase 3)

- Marks are `none | deliverable | handoff`. The **model proposes** `mark_tab` through an execution-core tool (`browser.mark_tab`, same grammar discipline as `browser.act`); **Quarry executes** it (`POST .../tabs/{tab_id}/mark`, delegate on its own tab or owner on any tab) and records it. Codex precedent (`markTab` with turn-scoped release; Interrupt/Stop end the turn).
- Turn end: execution-core calls `DELETE .../attach/{attach_id}?disposition=release` in a `finally` path (success, failure, cancel). Quarry closes the agent tab if `mark == none`; a `deliverable` or `handoff` tab stays open, becomes `holder = human`, keeps `opened_by = agent` and its mark (the SPA shows the badge; the user closing it clears it). No marks survive a session end.
- Orphan sweep: the `[D2]` sweeper tick also releases attaches with an expired or revoked grant or `ATTACH_IDLE_TTL_S` of inactivity.

### D8-12. Open question 12: one long-lived Quarry run across chat turns, or one per Model Plane run?

**Recommendation: both, keyed by who owns the browser, not by the chat thread.**
- **User-visible session** (opened from the Verevon browser surface): one long-lived, user-owned Quarry run (class `Interactive`, `human_browse` grant, renewable) that spans any number of chat turns. A Model Plane run that wants to work in it **attaches for the length of that run** (`attach_session_id`). A chat thread does not own a Quarry run.
- **Agent-private browsing** (no visible session, the loop today): one service-owned Quarry run per Model Plane run (class `Agent`, run grant), closed at run end. Unchanged.
- Consequences: F-t2-054's "turn-scoped tabs" are exactly attach lifetime; F-t2-035's "durable hosted sessions" is the resumable user-owned run. The thread-to-session binding (which visible session a chat attaches to) is carried per run by `attach_session_id`; a persisted binding and its UX belong to F-t2-012. ADR-GATED: this answers open question 12 and needs the user's ratification (section 9, question 5); S8.1 to S8.5 do not depend on it.

### D8-13. Rollout, compatibility and rollback rules

- Everything is additive and flag-gated off by default in production: Quarry `QUARRY_EDGE__HUMAN_BROWSE`, `QUARRY_EDGE__ATTACH`; broker `BROWSER_BROKER_HUMAN_BROWSE_ENABLED`; gateway `BROWSER_HUMAN_BROWSE`, `BROWSER_ATTACH` (AppState, not read in handlers). Dev defaults on.
- Fail-closed skew: new broker fields unknown to an old Quarry produce a rejection (empty policy), never a widening; an old gateway never requests the new kinds.
- **Tolerant timeline decode ships first.** New `BrowserTimelineEventKind` variants (`TabControl`, `Attach`) would make an old Quarry binary fail to decode the owner timeline after a rollback. S8.1 therefore adds `#[serde(other)] Unknown` handling and a decoder that skips unknown kinds, one release before S8.5 writes any (`[D2]` S4's new `Expired` lifecycle variant has the same property; flagged to D2).
- No migration is destructive; rollback is a flag flip, then an image swap.

### D8-14. What is deliberately not designed here

The omnibox, suggestions and hard reload (F-t2-011 frontend slice); per-origin consent and action-class grants (F-t2-032); the agent cursor and annotation presence (F-t2-038); chat dock (F-t2-012); credential handoff (F-t2-024; it will reuse tab holder: the user fills a secret in the agent tab after Take over); multi-agent attach; sharing a session with Space members (blocked: `ViewerGuard` counts owners only, `[D2]` 7(a)).

| Model Plane owns browser grants (BrowserBroker), reasoning, sessions, cost | every authority (`human_browse`, `attach`, renew) is minted or renewed by the broker only, from a verified **user** bearer; no service principal holds `browser:write` (`[D1]` assertion, extended to `RenewGrant`); model-gateway and execution-core never mint | OK |

ZDR, per slice. S8.1: a ZDR run may hold a `human_browse` grant (broker keeps it memory-only, `z_` prefix `[D1]`) and persists nothing (existing guards at `agent_routes.rs:493-495, 1615, 2360, 2374, 2391`; the new metadata-only receipt, the URL-stripped checkpoint and `policy_mode` are all inside non-ZDR branches); no history or suggestions exist server-side for anyone. S8.2: renew works for ZDR grants for process lifetime only; no domain strings in broker, model-gateway or gateway logs; metrics carry `outcome`. S8.3: the keep-alive persists nothing. S8.5 to S8.9: **attach is refused for ZDR** at three layers (model-gateway `browser_run.rs:307-315`, broker `ErrAttachZdrRefused`, Quarry `attach_zdr_refused`); the attach state, ledger and epochs are memory-only; timeline, receipts and `agent.attached` payloads exclude URL and title and are skipped for ZDR runs; `agent.attached/detached` use `emit_for_zdr` (live subscribers only). Collectors are pin-filtered, so a human tab's network URLs and console lines never enter a model observation (F4).

**Rules at risk, stated plainly.**
1. *Free human browsing widens the human's authority by design.* The audit asks for it. Mitigations: SSRF layer untouched and re-tested under open web, broker deny-list, user-only kind, absolute cap, metadata-only evidence, per-owner grant cap `[D1]`. The AI never inherits it (explicit list of at most 8, enforced at derive, per tab at the guard).
2. *The shared cookie jar.* The agent tab can act on any site the user is logged into **inside its allow-list of at most 8 hosts**; the user opted in by attaching. Per-origin consent is F-t2-032; an isolated-context option is open question 3.
3. *The BFF can ask for `human_browse` grants for the users whose bearers it holds* (the same trust boundary as `[D1]` section 6 item i): bounded by the broker's policy, per-owner cap, absolute cap and deny-list; it cannot derive for another user, mint attach for a run it does not own (Quarry checks `owner_id`), or widen.
4. *A compromised execution-core* holds the attach grants of in-flight runs and a service token, so it can drive those attached tabs inside their allow-lists until expiry (at most 900 s). It cannot attach to any other session (no grant), cannot reach human tabs (pin), cannot read receipts, frames or timelines. Phase B narrows this further.
5. *Metadata-only receipts reduce evidence for human steps.* Intended; agent steps keep full receipts. Procedures compiled from human sessions lose observations unless `HUMAN_RECEIPT_MODE=full` (dev only).
