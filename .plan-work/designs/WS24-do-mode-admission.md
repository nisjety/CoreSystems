Paths are relative to the repo root unless absolute. `MP` = `apps/Model Plane`, `FP` = `apps/Frontend Plane/verevonv3`, `CP` = `apps/Control Plane`, `EC` = `MP/rust/services/execution-core/src`, `GW` = `MP/rust/services/model-gateway/src`. ## 1. Scope, items resolved, owner

**Items:** F-t3-025 (Recommended, M, W2) and F-t3-030 (Recommended, M, W2). **Owner plane:** Model Plane (capability-core Go = admission table; execution-core Rust = Do-loop tools and edit engine; model-gateway = Ask-loop read arms, verify only) with Frontend Plane (classification map + CI ratchet) and Control Plane user-core (signed run decision/view generalisation). No Data, Ingestion, Application or Quarry code changes in this stream.

**IN**
- A model-access class for every one of the 168 registry actions, an exempt reason for every `none`, a compile-time exhaustiveness ratchet, and one generated, hash-pinned admission contract that the frontend, capability-core, execution-core and model-gateway all test against.
- Generalising the hard-coded `tickets.create`-only admission (Control `runActionTarget`, capability-core model-action view, execution-core `ticket_tools`) into a per-action table, with `tickets.create` seeded byte-identical.
- Workspace file tools for Do runs on the hydrated Space workspace: `workspace_read`, `workspace_grep`, `workspace_glob`, `workspace_list`, `workspace_edit`, `workspace_put`, on one small Rust edit engine, with a version token in the CAS hash domain, a per-run lock, and honest durability reporting.
- First new read admission (S8): Data Plane document listing in the Do loop through the already-held delegated Data Plane bearer.

**OUT (explicit)**
- Per-admission owner-plane work for further actions (inbox, social, insights reads; ticket/other writes). Each needs its own owner verifier and is listed in S7/S8 as "next admissions", not built here.
- Calling `PromoteWorkspace` (merging a run's overlay into the Space) and any changed-files review UI: F-t3-076 (W5) and WS22/F-t3-009. This stream keeps `diff_and_upload` + overlay as the only durable path and does not add a promote caller.
- Class vocabulary and per-tool allow/ask/never policy: WS05 (consumed). Approval UX and scope grants: WS13. Org policy registry/hooks: WS25. Browser: WS21. Per-thread sandbox computer / `SandboxBackend` seam: WS22. Enabling Do on the product route: OD2.
- Ask-loop (model-gateway `dispatch_tool`) side effects. The two loops stay separate; no write tool is added to the gateway.

### S2 [BUILD] - Pure workspace edit engine (M, 5-7 d)
**Goal:** all file semantics in one dependency-light module, fully unit-tested without sandbox or network.
- `EC/workspace_edit.rs` - NEW (register `pub mod workspace_edit;` in `EC/lib.rs` next to `:56`). Types: `WorkspaceRoot` (canonical root), `Version(String)` (`sha256:<hex>` from `content_version`, so the token equals the CAS baseline hash for unmodified files: "both guards agree"), `EditError` (closed, serialisable codes: `outside_root`, `symlink_refused`, `not_utf8`, `too_large`, `stale_version`, `read_first`, `no_match`, `ambiguous_match{count,lines}`, `secret_pattern`, `glob_too_broad`, `exists`, `not_found`).
  - `read(path, offset_line, limit_lines) -> {lines: "L<n>|text", total_lines, version, truncated}`; caps: default 200 lines, max 800, 64 KiB, per-line 2000 chars.
  - `grep(pattern, path_prefix?, glob?, context<=3, max_matches<=100, case_insensitive)` using `regex` (already a dep): files <= 1 MiB, skip binary, symlinks never followed, `{matches:[{path,line,text,before,after}], files_scanned, truncated}`.
  - `glob(pattern, path_prefix?)`: refuses patterns with no literal prefix or extension when the walk exceeds 5,000 entries (`glob_too_broad`); sorted output; max 500.
  - `list(path, depth<=3)`: max 500 entries, dirs first, `size`, no versions (avoids hashing everything).
  - `edit(path, old_string, new_string, replace_all, expected_version)`: requires `expected_version` (else `read_first`); matching ladder exact -> EOL-normalised -> trailing-whitespace-tolerant, each rung must be unique unless `replace_all`, ambiguity reports count and first line numbers; preserves BOM/EOL/mode; `would_redact(new_content)` -> `secret_pattern` (a secret is never written into a workspace; this is also what keeps token == stored hash); size cap 1 MiB; atomic temp+rename in the same directory; result `{version_before, version_after, replacements, first_changed_line, diff_preview<=40 lines}`.
  - `put(path, content, expected_version?)`: absent version = create-only (`exists` otherwise); with version = overwrite guarded; same secret/size/atomic rules; refuses reserved names (`attachments`, per WS08) and any path component starting `.verevon`.
  - `WorkspaceLock` = `Arc<tokio::sync::RwLock<()>>` (reads shared, edit/put exclusive); `HydratedWorkspace` gains `lock` (`EC/state.rs:94-98`, `Arc` keeps `Clone`/`Debug`).
- `EC/Cargo.toml` - `globset = "0.4"` (D8) and `tempfile` dev-dep if absent (not verified).
**Proto/data/flag/ZDR:** none; pure functions; no network. **Tests:** in-file unit tests plus `EC/../tests/workspace_edit_contract.rs` NEW (property-style: edit then `content_version` equals reported `version_after`; stale version refused; traversal `../`, absolute, symlink, `\\`-separator refused; binary refused; CRLF file edit keeps CRLF; concurrent edits via `join_all` on one path serialise with exactly one winner).
