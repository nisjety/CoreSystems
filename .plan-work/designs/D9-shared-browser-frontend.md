### 2.9 Findings that change planning

- F1. The 12-step, first-host budget makes every omnibox feature, the dock's interactive mode and the evidence panels low value for human sessions until WS8 changes the gateway literals (`browser.rs:483-494`) and Quarry keys budgets on the initiator (D2 `StepInitiator`).
- F2. Browser UI strings are hard-coded Bokmål and e2e selectors depend on them (section 2.3).
- F3. Free-text search through `search_web` reads the gateway cache that has no org in its key (D4 slice S-1 fixes it); a new traffic source into it should not be enabled in production before that fix.
- F4. Suggestions from `search_suggestions` are org-scoped and not ZDR-gated server-side; ZDR must be enforced at the gateway (`zdr.rs` [C] `request_zdr` L44 and `org_zdr_enabled` L67), not only in the SPA.
- F5. `browser.observe` and `browser.act` are unclassified as untrusted content (section 2.5): a security fix that belongs next to the new console tool.
- F6. (F6a, F6b above) A chat run's Quarry session cannot be addressed by any client nor read by the user's token; the panel binding is a Model Plane and Quarry contract before it is a UI task.
- F7. `get_devtools_events` forwards the raw query string.

## 3. Design decisions

Format: decision; options; recommendation; rationale. "ADR-GATED" marks a decision that needs a user or ADR answer, with the audit 9.3 topic number.

**D-1. Where free omnibox text goes.** Options: (A) render Verevon search results inside the browser frame area and let the user click a result to navigate; (B) hand off to the Home "Nett" tab (`?tab=web`, no query parameter exists, `DashboardHome.tsx` L60-64); (C) send it to chat only. Recommendation: A as the default Enter behaviour, plus an explicit "Ask Verevon" row (C) and an explicit "Search the web" row in the dropdown; B is not built. Rationale: A keeps the user in the dock, reuses `runWebSearch` (`search-client.ts:85`) and the gateway search route, and never sends a person to a third-party engine (the demo guard already encodes that policy). A result click is a normal `navigate`, so it is governed by Quarry exactly like a typed URL; until WS8 lands a cross-host click returns 403 and the UI says so (D-6).

**D-2. A new feature slice `FE/src/features/browser/`, not more code in BrowserChrome.** Options: keep adding to the 2172-line `BrowserChrome.tsx` (seven items touch it per sweep S7 hotspot 1), or put new components, stores and the extracted controller in a new folder and keep BrowserChrome hunks to wiring lines. Recommendation: new folder `browser/{omnibox,evidence,dock,session}`; BrowserChrome gets one-line mounts and prop additions. Rationale: CLAUDE.md asks for feature-sliced folders and "prefer existing plane patterns"; it also minimises merge conflicts with F-t2-028, 033 and 038, which all edit BrowserChrome.

**D-3. ZDR rule for omnibox history and suggestions: none.** No local history read or write, no suggestion fetch (local or remote), no search-home card recording, whenever the org retention verdict is "deny" (`isLocalRetentionAllowed()`, `chat-retention.ts`), the active chat thread is temporary, or the browser session is ZDR (`session().zdr`). The gateway also refuses server-side: `search_suggestions` returns the empty list when `request_zdr(&headers, None)` or `org_zdr_enabled(&state, &user)` is true. Options considered: allow remote suggestions under ZDR but not local history (rejected: the typed prefix is user content that would reach autocomplete-core), refuse the whole omnibox search (rejected: search is not retention, and `search_routes.rs` already skips `SearchIssued` when `zdr`). Free-text search itself stays available under ZDR and carries no `includeAnswer` by default. ADR-GATED, audit topic 4 (ZDR per feature): the recommendation matches the D4 default ("do not loosen refusals").

**D-4. Org-scoped autocomplete in the omnibox.** Options: (A) include `scope=queries` from autocomplete-core like the dashboard dropdown; (B) local history plus related queries only; (C) hosts only. Recommendation: A behind the same behaviour as the dashboard dropdown, flagged as an open question. Rationale: surfacing a colleague's query terms in a private browser bar is a product-privacy choice, not a technical one; today's dashboard already does it, so B or C would be inconsistent unless the user decides the omnibox is stricter. Listed in section 9 (question 2).

**D-5. What the local history stores.** Entries `{ url, title, lastVisitedAt, visits }`, max 200, key `verevon.browser-omnibox.v1:{org}:{user}` produced next to `webHistoryStorageKey` in `home-local-content.ts`, purged by `clearHomeLocalContent()` (so a ZDR verdict flip and sign-out-style purges reach it). URL scrub before storing: http(s) only, userinfo removed (`cleanWebHistoryUrl`), fragment dropped, query kept only when at most 256 characters and no key matches `token|key|secret|password|auth|session|code|sig|jwt` (case-insensitive), otherwise the query is dropped. Never stored: page text, screenshots, form values. Rationale: copy the proven shape of `web-history.ts` (zod, tidy, per-identity key) instead of inventing one.

**D-6. Navigation outside the session's scope.** Until WS8, a cross-host navigation returns Quarry 403 "outside the run's allowed domains". **D-7. **D-12. **D-13. How the dock binds to the agent's browser. **D-14. Evidence proxies: a new gateway module with allowlisted queries and compact projections.** New `GW/domains/browser_evidence.rs`, merged in `main.rs` next to `browser::router`. Rationale: the fabrication guard in `verevonv3-ci.yml` forbids domain reads of org headers, and receipts are the one place typed secrets live until F-t2-021.

**D-15. Procedure panel is read-only and server-composed.** One gateway call compiles the procedure from the caller's receipts and, server-side, runs Quarry's quality check on the raw procedure, returning `{ procedure (redacted), quality }`. No replay and no impact-check surface in this slice (they are for the owning release workflow). Rationale: the compile route only succeeds when every step is completed and verified; showing the reason a session is not compilable is itself useful, and the raw action JSON never reaches the browser.

**D-16. `browser.console` is a read-only Model Plane tool with a fixed output shape, and the untrusted-content classification is fixed with it.** Input `{ grant_id, quarry_run_id, lease_id, levels?, filter?, limit<=100, since_sequence? }` with `deny_unknown_fields`, validated like `browser.observe` against the broker-validated grant; output `{ entries: [{ sequence, tab_id, level, text }], next_sequence, truncated }`, never `payload` (raw CDP objects with remote object ids), each text capped at 500 characters and the whole result at 16 KB, passed through the existing scrubber. **D-17. **D-18. **D-19.
