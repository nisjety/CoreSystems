### F-t2-019 · Structured extraction that works in production: json, summary, question and highlights formats over a real Model Plane structured-output grant
| Tier | Verevon today | Effort | Plane | Wave | Confidence |
|---|---|---|---|---|---|
| Priority | Partial | M | Ingestion Plane (formats) + Model Plane (invoke) + Control Plane (grant decision) | W2 | High |

**What to build.** Add `json` (schema plus prompt), `summary`, `question` and `highlights` as scrape and crawl formats, executed by sending the schema and the ZDR flag to the Model Plane's existing `/v1/invoke` over an org-bound, metered service token. Add schema normalisation and one repair pass. Resolve the Control Plane grant that currently denies every Quarry-to-Model-Plane call, and make the gateway forward the schema as well as the prompt.

**Why it matters.** Schema-to-JSON extraction is the most used model feature of scrape APIs and the basis for monitors, research jobs and extraction profiles. The Model Plane already centralises ZDR-aware routing and cost, so Quarry should call it rather than hold model keys. Today extraction works only under a dev bypass [SRC].

**What the references do.** A built-in `json` scrape format and `question`/`highlights` formats are in 1 of 4 references (Firecrawl); a per-page summary is in at least 2 of 4 (Firecrawl, and Apify's Website Content Crawler offers an optional per-page AI summary) [SRC; DOC]. Firecrawl's `json` path normalises the schema (recursing into `$defs` and `anyOf`, making every key required and setting `additionalProperties:false`; it does not resolve `$ref`), routes schemas with `$ref`/`$defs` to a larger model, trims the markdown to 80 percent of the model's input tokens, calls the provider with a schema-constrained response format, runs a text and LLM repair pass on parse failure, and falls back to a second model of the same provider only on quota or rate-limit errors [SRC]. `question` and `highlights` run on a Firecrawl-hosted fine-tuned model or Gemini with token-based page trimming and a "page too long" warning; the 10,000-character limit applies to the prompt text, not the page [SRC]. Each of `json`, `question` and `highlights` adds 4 credits per page, and `/extract` is deprecated in favour of the `json` scrape format [SRC]. Models are hard-coded to specific vendors, so Verevon must route through the Model Plane instead [SRC].

**Verevon today.** `AiFormatRunner` (apps/Ingestion Plane/Quarry-v2/crates/quarry-runtime/src/ai_formats.rs:60-300) implements summary, json and query as a library: json is reachable only through `POST /v1/extract` with a schema (quarry-edge/src/extract_routes.rs:195-300; sequential, markdown capped at 20k, prompt field marked `dead_code` at line 48), query only through `/v1/answer`, summary has no caller, and there is no highlights format. The schema is pasted into the prompt and checked after the call; `ModelPlaneInvokeRequest` (quarry-runtime/src/mp_client.rs:31-40) carries neither `structured_output_schema` nor `zdr`, and ai_formats.rs:302-310 discards the ZDR argument. The `model-invoke` and `model-stream` rows are `granted:false` (quarry-runtime/contracts/cross-plane-token-requests.json:41-65; quarry-edge/src/model_plane_gate.rs), and `StructuredExtractClient` targets a `/v1/structured/extract` route that exists nowhere in the Model Plane. What exists to reuse: model-gateway `/v1/invoke` already accepts `structured_output_schema` and `zdr` (apps/Model Plane/rust/services/model-gateway/src/http_routes.rs:6693, 8987) with an OpenAI `response_format` mapping in inference-core (provider/openai.rs:463-490); the `ExtractStructured` RPC (model-gateway/src/grpc.rs:2516-2655) already does Quarry scrape plus schema-bound inference with an 80k character cap, ZDR-aware; and the model-free structured harvest (JSON-LD, hydration data) is a first pass.

**How to build it in Verevon.** Do not design a new Model Plane endpoint. Extend `ModelPlaneInvokeRequest` to send `structured_output_schema` and `zdr` to `/v1/invoke`, add normalisation and one repair pass in Quarry or as an inference-core option, and run the structured harvest first so the model fills only missing fields. Treat the Control Plane registry grant (D16, QB-T17, DEF-QB-T17-PART2, owner and date unassigned) as the gating decision, not an engineering detail. As an interim path that needs no grant, extend `ExtractStructured` (multi-URL, repair, highlights, summary) as the Model-proposed route and keep Quarry formats for the user-facing API once the grant lands. Provider strictness differs: OpenAI gets non-strict `json_schema`, Anthropic gets the schema only through the prompt (provider/anthropic.rs:725-737), so validate after every call. Page text is untrusted input; require highlights to be verbatim substrings. Per-page model cost multiplies in crawls, so this depends on the budgets in [F-t2-008](#F-t2-008) and the formats contract in [F-t2-005](#F-t2-005); multi-URL fan-out is [F-t2-040](#F-t2-040).
