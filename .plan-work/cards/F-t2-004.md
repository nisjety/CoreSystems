### F-t2-004 · ZDR-safe telemetry: span sampler, late-ZDR registry, log filter and safe/sensitive log fields in Quarry and the gateway
| Tier | Verevon today | Effort | Plane | Wave | Confidence |
|---|---|---|---|---|---|
| Priority | Partial | M | Ingestion Plane (adopted by Model Plane and Frontend Plane gateway) | W1 | Medium |

**What to build.** Phase 1 (S): remove the URL field logged inside the ZDR-active branch of change_routes.rs, sweep the roughly 250 tracing call sites for url, query and error-text fields (reqwest errors embed URLs), carry effective ZDR in a task-local or span field so a filter on the JSON fmt layer can drop sensitive fields, and add a lint. Phase 2 (M), delivered together with span emission in [F-t2-029](#F-t2-029): an OpenTelemetry sampler that drops ZDR spans, a bounded late-ZDR trace registry with a span processor, a documented safe/sensitive log-field contract mirrored in Rust and the Go `quarryotel` package, and an explicit exporter-disable flag.

**Why it matters.** ZDR must propagate, and today it stops at the observability boundary. A leak into logs or an OTLP exporter is invisible to users, breaches ZDR contracts, and blocks safe SIEM export and support diagnostics. The live exposure is log fields, since almost no spans are produced at the default filter.

**What the references do.** ZDR-aware telemetry is 1 of 4 references (Firecrawl). Its TypeScript OpenTelemetry setup carries a ZDR flag in context; a sampler returns NOT_RECORD for flagged requests, a registry of trace ids flagged ZDR after the span started (a Set with oldest-first eviction, capped at 100,000) is checked by a span processor on end so descendants are dropped before export, and a winston filter drops ZDR-flagged log lines [SRC]. One helper service, the Go html-to-markdown service, honours an `X-Zero-Data-Retention` header by omitting the request id, and only that client sends it [SRC]. Privacy-classified log fields are 1 of 4 references (Codex): every log call app-wide takes `{safe, sensitive}` tags, but how sinks treat `sensitive` was not found, so "sinks drop or hash sensitive" is a Verevon proposal [SRC; sink behaviour INF]. Codex's `BROWSER_USE_DISABLE_AMBIENT_NETWORK` is a sandbox kill switch for gates, Sentry and analytics, not a ZDR mechanism [SRC]. The Rust sampler shape is a port, not observed. Caveat: Firecrawl tracing is off unless an OTLP endpoint is configured.

**Verevon today.** apps/Ingestion Plane/Quarry-v2/crates/quarry-edge/src/telemetry.rs:25-64 installs a JSON fmt layer and an optional OTLP layer under one EnvFilter with no ZDR awareness; pkg/quarryotel/quarryotel.go:39-93 uses ParentBased(AlwaysSample). change_routes.rs:632-637 logs source_url inside the ZDR-active branch at debug level. The edge creates only tower-http spans (routes.rs:303) and the Go services call quarryotel.Init but no tracer.Start [INF from grep]. Posture already propagates through the token floor plus body flag (auth.rs:121-139), emit_for_zdr (quarry-runtime/src/events.rs:137) and the NATS envelope zdr key (apps/Model Plane/go/pkg/natsx/publisher.go:57). Reuse `Claims::effective_zdr_mode` as the single posture source and page_renderer.rs's URL-free ZDR log as the field-discipline pattern.

**How to build it in Verevon.** Do not add a ZDR header or NATS header: Quarry derives posture from the token floor or body flag and ignores a service-principal zdr claim (auth.rs:104-120), so a third carrier would go unread. Each plane owns its telemetry init (quarry-edge, mp-telemetry, gateway zdr.rs), so the helper is a documented contract, not shared code. Keep content-free counters available to ZDR tenants, noting the edge metrics crates are inert today (telemetry.rs:6-18). Risks: partial adoption gives false confidence, so enforce with a lint; over-suppression hides incidents.

**Quick win.** Phase 1 is a field sweep plus one test and removes the one known debug-level leak.
