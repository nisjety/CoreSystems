### F-t2-022 · Org-pinned, tighten-only web policy: tri-state capability gates delivered as signed claims and enforced by Quarry
| Tier | Verevon today | Effort | Plane | Wave | Confidence |
|---|---|---|---|---|---|
| Priority | Partial | L | Control Plane (policy of record) + Model Plane (grants) + Ingestion Plane (enforcement) | W2 | High |

**What to build.** Make the Control Plane the policy of record for web and browser capabilities (robots mode, maximum proxy tier, credential and cookie stripping, login or form-write actions in autonomous runs, raw evaluate, uploads and downloads, recording, persistent profiles, paid providers, domain allow and deny lists, ZDR) as `disabled`, `allowed` or `forced`. Deliver it as a signed claim to user-token callers and as action-class fields in BrowserBroker grants for Model-Plane-driven runs. Quarry resolves one `ResolvedPolicy`, rejects at the edge with typed errors and re-resolves per URL in `PageRunner` and the step path as a backstop. Requests, Spaces and the Model can only tighten.

**Why it matters.** This implements three Verevon rules directly: Quarry executes or rejects, ZDR must propagate, and Space access never widens an owner-plane ACL. Today no org or request web policy is applied at all; only ZDR is org-pinned [SRC].

**What the references do.** A Safe Mode is in 1 of 4 references (Firecrawl); tri-state team flags plus default-off browser gates are in 2 of 4 (Firecrawl, Codex). Firecrawl computes `ResolvedPolicy = merge(orgPolicy, defaults)` in the API layer, rejects requests that ask for forbidden options with `403 SAFE_MODE_BLOCKED`, and recomputes it in the worker for every URL including crawl children, where it silently strips `Authorization`, `Cookie` and `Proxy-Authorization` headers, write and press actions, profiles and URL userinfo [SRC]. Team flags hold `disabled|allowed|forced` per capability (ZDR, ignoreRobots, threatProtection, ipWhitelist); effective option = forced ? on : (allowed ? request : typed rejection). API keys additionally carry allowed endpoints and formats, cached for about 60 s [SRC]. It is not strictly tighten-only: an admin can set `allowBypassSafeMode` so a request may send `safeMode:false`, and allow-listed domains switch off robots, stealth and authentication controls [SRC]. Audit coverage is partial: rejection events are emitted only from the scrape, crawl, batch, extract and agent controllers and only when the team's SIEM flag is on; worker downgrades, map and search emit nothing [SRC]. `maxBrowserSessions` is declared but no enforcement was found [SRC]. Codex's browser gates (browserUse, full CDP access, WebMCP, record-and-replay, auto-auth, multi-window) are vendor rollout flags with client defaults of false and a Dev-only env override, not org-admin policy; the exception is the enterprise requirement `browser_use_full_cdp_access` [SRC]. Signed claims are Verevon's own design; Firecrawl reads flags from a cached account record [SRC; INF].

**Verevon today.** org-core's `RetentionPosture` (apps/Control Plane/org-core/internal/org/types.go:255-315) feeds an auth-core claim that `Claims::zdr_floor` raises over request flags (apps/Ingestion Plane/Quarry-v2/crates/quarry-edge/src/auth.rs:56-140), but only for user tokens. The edge hard-wires `RunPolicy::default()` (quarry-edge/src/routes.rs:461; main.rs:1485-1493), two unrelated `RunPolicy` types exist (quarry-core/src/policy.rs:1-17; quarry-runtime/src/policy.rs:55-80), control's presets (`fast` = RobotsIgnore) are never consumed (quarry-control/internal/resources/presets.go:45-80), and `/v1/blocklists` entries have no org column and are not read by the edge. The Model Plane gate is one coarse capability, `cap.browser.open` (apps/Model Plane/rust/services/execution-core/src/capability_policy.rs:793-794), plus capability-core org-scope grants (apps/Model Plane/go/services/capability-core/internal/policy/engine.go:158-215) and a sensitive-action allowlist in the broker (browser-broker/internal/grant/grant.go:30-36). Reuse the retention-posture delivery pattern, `effective_zdr`/`zdr_floor` merge semantics, broker `allowed_domains` and `BrowserEgressPolicy` deny-all defaults.

**How to build it in Verevon.** Run the ADR first: org-core claims versus capability-core grants, because capability-core already holds tenant-bound org-scope grants and is a competing policy of record. The claim channel reaches only user-token callers: execution-core and model-gateway call Quarry with service tokens whose ZDR claim is ignored by design, so for Model-Plane-driven runs the resolved policy must ride in the BrowserBroker grant or the start-run body. Ship a Quarry-only thin slice before any org-core storage or admin UI: one `ResolvedPolicy` replacing the `RunPolicy::default()` sites, tighten-only merge with the existing ZDR floor, typed denials for evaluate, upload and download (ties to [F-t2-002](#F-t2-002)), and reconcile or delete the second `RunPolicy` type, the unused presets and `/v1/blocklists` instead of adding a third shape. The remaining work is org-core storage, auth-core claim minting and broker action classes. Depends on robots enforcement [F-t2-016](#F-t2-016), the proxy-tier cap [F-t2-058](#F-t2-058) and production grants [F-t2-001](#F-t2-001); per-origin consent builds on top in [F-t2-032](#F-t2-032). Risks: policy resolved in two places can drift, so test both paths; claim staleness mid-run, mitigated by the short grant TTL and per-action revalidation; strict defaults can break login-based research, so keep escalation through approvals and never block the human user's own manual browsing.
