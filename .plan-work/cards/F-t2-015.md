### F-t2-015 · Actionability checks and trusted input for every ref-targeted action, then rich input actions
| Tier | Verevon today | Effort | Plane | Wave | Confidence |
|---|---|---|---|---|---|
| Priority | Partial | M | Ingestion Plane | W2 | High |

**What to build.** Change Quarry's ref-targeted click, type and select path from in-page `element.click()` to a pipeline: hit-test the element centre, scroll into view only if it is not hittable, wait until attached, visible, enabled and stable, then dispatch trusted `Input.dispatchMouseEvent` and `Input.dispatchKeyEvent`. Return typed failures (covered by a named tag, not visible, disabled, unstable) and keep the synthetic path only as an explicit fallback. Split out as follow-ups: cross-process iframe hit-testing, and rich input (press with modifiers, drag, select_text, paste with a per-session virtual clipboard).

**Why it matters.** Every AI click passes through this executor. Untrusted synthetic clicks silently do nothing on sites that ignore them or sit behind overlays; an honest "covered by cookie banner" error lets the model recover instead of looping.

**What the references do.** Custom actionability pipelines are in 2 of 4 references (Codex, Aside); Playwright's auto-wait gives Firecrawl's playwright service and Apify's Crawlee similar behaviour by inheritance [INF]. Codex is the best implementation: it hit-tests with a shadow-root-aware in-page `elementFromPoint` probe injected per frame hop through `DOM.resolveNode` and `Runtime.callFunctionOn`, using `getContentQuads` and `getBoxModel` for coordinate transforms [SRC]. Order: hit-test first, `DOM.scrollIntoViewIfNeeded` only if not hittable, then a 25 ms poll with a 500 ms deadline and 0.5 px tolerance until two consecutive samples match [SRC]. Errors read "covered by <tag> or otherwise not hittable", "did not settle after scrolling" and "couldn't be clicked" for unpositioned nodes; input is then dispatched as trusted mouse and key events [SRC]. Aside's `waitForReady` checks attached, visible, enabled and stable with a 32 ms sample and a 5 s timeout, and falls back to DOM activation with checked-state verification when the target is obscured [SRC]. Rich input is not unique to Codex: Aside also has trusted CDP input with modifiers, insertText, file-chooser interception and download events; only the virtual clipboard and held clicks or drag are Codex-specific [SRC for Aside, from the daemon blob]; Codex's held-click, drag and paste action set is doc-backed [DOC], while its clipboard bridge is [SRC].

**Verevon today.** `execute_native_target_action` checks only `isConnected`, then calls `element.click()` or sets the value and dispatches synthetic events (apps/Ingestion Plane/Quarry-v2/crates/quarry-browser/src/chromiumoxide.rs:1232-1330); the non-native verified-target path does the same in a page script (chromiumoxide.rs:2026-2093). There is no scroll-into-view, visibility, enabled, stability or covered-element check and no hit-test on the ref path. Only `click_point` (chromiumoxide.rs:2841) dispatches trusted mouse events, Press carries only a key string (apps/Ingestion Plane/Quarry-v2/crates/quarry-core/src/contracts.rs:699), and the only typed target error is `TargetRepairRequired` (quarry-core/src/error.rs:30). Reuse the backend-node resolution and per-frame context lookup (chromiumoxide.rs:1232-1290), `click_point`'s moved, pressed, released sequence (2841-2896), the `BrowserDriverCapabilities` flag pattern (lib.rs:269-286) and `ActionOutcome::unknown(postcondition_required)` in observation.rs.

**How to build it in Verevon.** Ingestion Plane quarry-browser only. Express failures as `ErrorCode::TargetRepairRequired` (409) with `details.reason`, because `ErrorCode` is a wire contract shared with the Go, TypeScript and Model Plane clients. Gate the pipeline behind a new driver capability flag so the Browserbase, Browserless and Kernel adapters are unaffected, and leave the synthetic path for governed download clicks until trusted-click download behaviour is verified. Quarry keeps returning an unverified postcondition rather than claiming success, and upload and download gates must not weaken. The Model Plane `browser.act` schema is a closed list, so modifiers, drag and paste need a separate Model Plane contract change. Risks: cross-origin iframe transforms and regressions in existing flows, hence the flag.
