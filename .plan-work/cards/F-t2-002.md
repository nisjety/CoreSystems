### F-t2-002 · Gate Evaluate and raw script actions behind a grant capability and one-shot approval
| Tier | Verevon today | Effort | Plane | Wave | Confidence |
|---|---|---|---|---|---|
| Priority | Partial | S | Ingestion Plane (plus a BrowserBroker allowlist change) | W1 | High |

**What to build.** Make the Quarry `/step` path deny `AgentAction::Evaluate` by default on agent runs. Either add `evaluate` to the broker's allowed sensitive actions and to Quarry's sensitive-approval path, binding the script hash into the one-shot approval, or reject Evaluate outright until a consumer exists. Remove `evaluate` and `pdf` from the unwired ModelPlanePlanner prompt. Build the isolated-world read-only evaluator only with [F-t2-023](#F-t2-023), where a return value is consumed.

**Why it matters.** Quarry otherwise fails closed, but Evaluate has no approval branch, so any risky action (submit, delete, read a sensitive field) can be expressed as script and bypass the risk-classified approval model. The executor must be sound regardless of which caller reaches `/step`. Severity is defense-in-depth: the exposure is internal service callers, not an open user-facing hole.

**What the references do.** Codex does not gate `playwright.evaluate` behind a capability or approval; it makes evaluate structurally safe. Scripts run in a dedicated isolated world with universal access off, against read-only wrappers that block assignment, `defineProperty` and `delete`; credential fields are masked, `import()` is blocked, and argument and result sizes are capped [SRC, from the beautified shipped plugin bundle]. This read-only evaluate is 1 of 4 references (Codex). Codex's consent gates apply only to raw Chrome DevTools Protocol (CDP): a `full_cdp_access_enabled` preference (default false), an enterprise requirement and per-origin consent; "domain allowlist" means CDP protocol domains plus a per-method denylist, not website domains [SRC]. Firecrawl's Safe Mode strips `executeJavascript` and rejects interactive sessions [SRC]; Aside isolates its REPL guest from the raw CDP client, though its `page.evaluate` may mutate the page [SRC]. A grant capability and one-shot approval are Verevon proposals [INF]. Caveat: the source record says Codex docs mark raw CDP development-only [DOC, not re-opened].

**Verevon today.** `sensitive_approval_for_action` covers only respond_dialog, upload_ref and download_ref and falls through at apps/Ingestion Plane/Quarry-v2/crates/quarry-edge/src/agent_routes.rs:280; the broker allowlist has no evaluate (apps/Model Plane/go/services/browser-broker/internal/grant/grant.go:30-36); ChromiumoxideDriver::evaluate runs in the main world (quarry-browser/src/chromiumoxide.rs:3003-3017). The Model Plane half is done: execution-core's browser.act schema (runtime_loop/agent.rs:3479-3512) and ACTION_SCHEMA (llm_planner.rs:53-65) never offer evaluate, and the gateway's sanitize_action denies it (browser.rs:3751). `/step` discards the script's return value (quarry-runtime/src/observation.rs:542-543). Reuse the one-shot `used_sensitive_approval_grants` set, `authorizes_exact_sensitive_action` (grant_validator.rs:98-109) and the typed `browser_action_denied` shape.

**How to build it in Verevon.** The gate lives in quarry-edge and quarry-runtime, not only in the planner schema; denials are typed Quarry errors. A new sensitive action class needs the broker allowlist and proto alignment. Sensitive actions require a parent run grant, and UI runs carry `session:{id}` today, so the gate must fail closed until [F-t2-001](#F-t2-001) lands. Drop the "hide it from the planner" sub-task; it is already true. Risk: an extraction flow may rely on mutating evaluate, so audit callers first.

**Quick win.** A default-deny branch plus one allowlist entry in a path that already has the approval machinery.
