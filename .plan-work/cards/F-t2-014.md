### F-t2-014 · Surface one canonical agent run trace in the UI: typed events, receipts, live view, correlation envelope
| Tier | Verevon today | Effort | Plane | Wave | Confidence |
|---|---|---|---|---|---|
| Priority | Partial | L | Model Plane (trace contract); Ingestion Plane and Frontend Plane deliver their halves | W2 | Medium |

**What to build.** First slice (S to M): gateway proxies for Quarry's receipts, egress-receipts and procedure routes, level and substring filters on the devtools route, and a read-only `browser.console` model tool. Later slice (L): extend the existing Model Plane `Event` envelope with `producer_seq` and agent or origin fields, publish Quarry browser-session, step-receipt, egress-decision and artifact events in it on NATS (persisted unless ZDR), add `x-request-id` intake as a tower layer in quarry-edge, a run origin enum, and real `from_seq` replay for Quarry's agent-event SSE (server-sent events). The existing single-run surfaces gain egress-receipt and procedure panels.

**Why it matters.** This is what users watch while the agent browses. Without it, "the Model proposes, Quarry executes or rejects" is invisible, approvals lack context and support cannot follow one run across gateway, Model Plane, Quarry and audit.

**What the references do.** A full versioned run-trace envelope is in 1 of 4 references (Firecrawl, beta), with Codex contributing UI-side pieces. Firecrawl's contract carries schemaVersion, eventId, runId, occurredAt, producerSequence and agent; producerSequence is monotonic per emitting agent, so consumers group by agent id and then order [SRC]. Only the OpenAPI contract and a proxy controller are in the repo; the events come from an upstream beta service, so persistence and ordering are not inspectable [SRC]. Firecrawl has no edge middleware for `x-request-id`: provider-tool routes adopt or generate and echo it and use it for safe retries, proxies forward it, and billing is keyed by it; the tower-layer design is Verevon's own [SRC]. Correlation ids and run origin appear in 3 of 4 references; Apify runs carry a `meta.origin` enum (WEB, API, CLI, SCHEDULER, WEBHOOK, ACTOR, MCP and others) [DOC]. Agent-readable console logs are in 2 of 4: Codex's `tab_dev_logs` takes levels (debug, info, log, warn, error), a filter and a limit; every result carries surface and tab metadata, and async notifications are drained into the next result but suppressed after native credential use [SRC].

**Verevon today.** A canonical envelope exists (apps/Model Plane/proto/model_plane/v1/events.proto:8-60: event_id, schema_version, producer, correlation_id, causation_id, org_id, user_id, zdr, fields 14-20 reserved), with EventLog query and subscribe on an opaque cursor (eventlog.proto:26-37, 50-90) and an OrchestrationEvent run stream carrying browser action, observation and approval events (orchestration.proto:990-1040). The SPA renders these in ChatLiveRunPanel (ChatLiveRunPanel.tsx:360-380) and a per-session timeline in BrowserTimelineDetail. Missing: Quarry's receipts, egress-receipts, procedure and agent-events routes (apps/Ingestion Plane/Quarry-v2/crates/quarry-edge/src/agent_routes.rs:3660-3730) are not exposed by the gateway router (browser.rs:368-470); the agent SSE accepts `from_seq` but replay is a no-op (agent_routes.rs:2650-2706); `DevtoolsQuery` has only after_sequence and limit (agent_routes.rs:1055-1072); Quarry handlers mint their own request id with no `x-request-id` intake. FleetRunConsole is a multi-run console against an unrouted `/v1/fleets`, not the target. Reuse the Event and EventType, the EventLog cursor, the run event stream proxy, the UI surfaces, Quarry's owner timeline and StepReceipt store, and execution-core scrub.rs.

**How to build it in Verevon.** The Model Plane owns run and session events, so extend `model_plane.v1.Event` rather than define a second envelope; Quarry publishes in it and never writes Model Plane storage; the Application Plane projects for realtime; the gateway only proxies. ZDR runs stay live-only with no persisted trace, and the immutable egress receipt is not retained under ZDR ([F-t2-004](#F-t2-004)). Request ids are never an authorization or tenancy key; cap length and charset. All Quarry routes stay owner-scoped. AI-run start depends on [F-t2-001](#F-t2-001). Risks: event volume, cross-plane ordering, and prompt injection or secrets in console and page text, which need the same redaction and untrusted-content labelling as observations.
