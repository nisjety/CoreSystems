### F-t2-016 · Scoped, robots-compliant crawl: wire CrawlFrontier scoping, robots enforcement and typed denials into the live crawl path
| Tier | Verevon today | Effort | Plane | Wave | Confidence |
|---|---|---|---|---|---|
| Priority | Stub | L | Ingestion Plane (quarry-control workflow + quarry-runtime frontier); Control Plane (override entitlement, audit) | W2 | High |

**What to build.** In risk order: (1) S: a default same-host (optionally subdomain) scope in both enqueue loops of the Go crawl workflow, since a crawl today follows external links up to `max_pages`. (2) M: a robots.txt preflight at enqueue and for batch through the guarded fetch path, with typed per-URL denial events returned by status and errors routes. (3) The scoping vocabulary on a ScrapeOptions-backed CrawlRequest (include and exclude patterns with ReDoS caps, subdomain and external-link switches, discovery depth, sitemap mode), an audited ignore-robots entitlement in the Control Plane, and a ZDR decision for the durable orchestrator path. Correct the GAP.md rows that call robots enforcement closed.

**Why it matters.** Scoping and robots compliance are table-stakes in both crawl references. Repo docs claim robots handling is closed while the code does not enforce it. Unscoped crawls waste budget and expose every org to compliance risk.

**What the references do.** Present in 2 of 4 references (Firecrawl, Apify); Codex and Aside have no crawler. Firecrawl's native Rust `filter_links` returns allowed links plus a denial map of typed codes, checking in order parse, protocol, depth, file type, section scope, backward links, exclude, include, robots, social media and external links [SRC]. Remediation sentences are built in TypeScript from the denial enum, several still name v1 options, and none names allowSubdomains [SRC]. Pattern caps are 1000 patterns and 100k characters in total across include and exclude, 2000 characters each [SRC]. robots.txt is fetched at crawl start through a forced engine list with an 8 s timeout and about one day of cache; fetch failure fails open and Crawl-delay is ignored [SRC]. Enforcement is on by default for crawl only; scrape checks robots only under Safe Mode or a team flag, and overrides are enterprise entitlements blocked under Safe Mode [SRC]. Apify's `enqueueLinks` offers a strategy, globs and a transformRequest hook, and robots respect is opt-in in Crawlee [DOC].

**Verevon today.** The Go `CrawlJobWF` (apps/Ingestion Plane/Quarry-v2/services/quarry-orchestrator/internal/workflows/workflows.go:396-516) and its durable-frontier variant (518-610) enqueue every extracted href after only a depth check; `links::extract` keeps external links (quarry-transform/src/links.rs:1-23; quarry-edge/src/routes.rs:817-840). `CrawlRequest` has only url, max_pages, max_depth, ingest and zdr (routes.rs:533-552), and 0 means unlimited. `CrawlFrontier`, `CrawlDenialReason` and `RobotsCache` have no production caller; the only live scope and robots logic is `/v1/map` (quarry-edge/src/map_routes.rs:87-109, 160-260); batch accepts any URL list unchecked; crawl and batch are refused under ZDR (routes.rs:553-590). Reuse `merge_and_scope` and `host_in_scope`, `RobotsTxt` and `sitemap` from quarry-transform, the frontier and denial types, the RobotsCache TTL logic, the per-page `page_failed` and `page_blocked` events (workflows.go:174-202) and the `knowledge.crawl_site` action schema (apps/Frontend Plane/verevonv3/src/shared/actions/action-registry.ts:568-571).

**How to build it in Verevon.** The Ingestion Plane owns crawl; frontier logic stays in Rust per ROADMAP Phase 5, so the Go workflow calls an edge endpoint or activity helper. `ReqwestRobotsFetcher` (quarry-runtime/src/robots_cache.rs:165-205) is a plain reqwest client without the SSRF guard or DNS pinning, so robots must be fetched through the guarded driver chain that `/v1/map` uses (map_routes.rs:118-128). A robots override is an audited Control Plane entitlement shared with [F-t2-022](#F-t2-022); the Model can propose a crawl but never request a bypass. The vocabulary rides on [F-t2-005](#F-t2-005), denials surface through [F-t2-017](#F-t2-017), sitemap seeding follows in [F-t2-041](#F-t2-041), and the user-agent token is unified in [F-t2-067](#F-t2-067). ZDR: the durable path refuses ZDR because `run_page` carries no zdr field and Temporal history stores URLs; lifting it is a design decision. Risks: changed defaults alter existing crawl results, so make them explicit with a legacy opt-out and show denial summaries in the UI; cap and linear-time-compile patterns against regex DoS.
