### F-t2-006 · Reap abandoned agent runs (idle and absolute TTL), cap concurrent runs, and make the fleet console real
| Tier | Verevon today | Effort | Plane | Wave | Confidence |
|---|---|---|---|---|---|
| Priority | Partial | M | Ingestion Plane (small Frontend change) | W1 | High |

**What to build.** Add a sweeper in quarry-edge that closes agent runs past their lease `ttl_s` or an idle timeout, refreshes last-activity on steps, attached viewers and takeover, and calls the existing close_run routine so the lease is released and a run.expired event is emitted. Add org-scoped and global caps on concurrent runs at start_run with a typed 429 plus retry-after, counting UI-created sessions too. Checkpoint non-ZDR runs for resume with run-id affinity routing rather than a shared registry. As a separate S, proxy `/v1/fleets` through the gateway and add the missing cancel route, or hide the fleet route until then.

**Why it matters.** An abandoned user or AI session holds a Chromium page and a usable grant with no user present: a resource leak on a shared host that grows with every run, and there is no cap on agent runs at all. The SPA has no beforeunload or sendBeacon close, so a closed tab or crash leaves the session open.

**What the references do.** Idle plus absolute TTLs for a multi-tenant server are best shown by Firecrawl; TTL handling appears in 2 of 4 references (Aside, Firecrawl). Firecrawl's hosted sessions carry an absolute `ttl` (default 600 s, max 3600) and an `activityTtl` (default 300 s), passed to the closed Hangar service as max lifetime and idle timeout [SRC; enforcement INF]. Aside, a local single-user daemon, gates run start with a global semaphore of 200, limits active sub-agents to 8 per run, and appends a text warning to tool output at 5 open tabs [SRC, from the daemon blob]. Its `flushIdleTabs` sweeper closes agent-owned tabs only for sessions in idle, interrupted or aborted status whose `updatedAt` is older than `closeAfterIdleMinutes` (default 15); it does not reap running runs and no event emission was seen [SRC]. Terminal ephemeral sessions are purged after 15 minutes; Aside has no absolute run TTL [SRC]. No reference evidence supports a fleet console. Caveat: Firecrawl's `maxBrowserSessions` is declared in team flags but no enforcement was found.

**Verevon today.** start_run computes ttl_s (apps/Ingestion Plane/Quarry-v2/crates/quarry-edge/src/agent_routes.rs:1446, 1502) but nothing reads it; enforce_step_budget checks max_steps only (446-451); runs leave the registry only through close_run (3623-3626). The agent ChromiumoxideDriver is one shared browser whose acquire never blocks (quarry-browser/src/chromiumoxide.rs:1914-1942; main.rs:1284-1288); the RuntimeLeasePool of 2 and 4 (main.rs:323, 337) gates only scrape rendering. The 15-minute grant TTL (browser-broker/internal/server/server.go:22) bounds grant use, not leaked pages. FleetRunConsole.tsx fetches /v1/fleets directly, the gateway has no such route, and its Pause button PATCHes an unregistered route (fleet_routes.rs:216-222). Reuse close_run, AgentRunCheckpoint and resume_checkpoint, control_mode as the takeover signal, and the quarry-control janitor pattern.

**How to build it in Verevon.** Ingestion Plane owns the browser lifecycle; grant revocation is a BrowserBroker call and optional given the grant TTL. A RunEntry owns a process-local Chromium session, so durable state only enables resume and cross-instance steps need sticky routing. ZDR runs are never checkpointed and simply expire. Never reap a run a user is watching or has taken over. Shares admission code with [F-t2-025](#F-t2-025), gains visibility from [F-t2-029](#F-t2-029), and gives [F-t2-008](#F-t2-008) its runtime enforcement.

**Quick win.** The sweeper reuses the existing close routine and the ttl_s already stored on every lease.
