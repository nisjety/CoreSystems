### F-t2-010 · Turn on the LLM browser planner by default, with budgets, a browsing procedure prompt and connector-first routing
| Tier | Verevon today | Effort | Plane | Wave | Confidence |
|---|---|---|---|---|---|
| Priority | Partial | M | Model Plane | W2 | High |

**What to build.** Move the durable browser planner in execution-core from the `QUARRY_BROWSER_AGENT_LLM` environment gate to an org-policy flag, once per-run step, time and token budgets exist. Add a versioned browsing procedure to the planner prompt (observe, act, re-observe to confirm; escalation ladder; stop rules) and widen the planner's action set to the Quarry verbs it cannot reach today (press, select, back, wait_for). Put connector-first routing guidance in the parent chat runtime loop so the model prefers Integration Plane provider actions or Quarry search and scrape before opening a browser, unless the user asked for the browser.

**Why it matters.** The durable run and chat autopilot are the paths users rely on for long tasks, and today they fall back to a deterministic planner unless an operator sets an environment variable. A procedure prompt raises task success at near-zero cost, and connector-first routing is cheaper, more reliable and honours provider OAuth scopes.

**What the references do.** A multi-step model loop over browser tools is table-stakes: 3 of 4 references (Firecrawl, Aside, Codex; Apify has no agent loop) [SRC]. Firecrawl's interact loop is the shape to copy: a capped interactive snapshot (about 40k characters) plus URL goes to the model with a single tool, the model re-runs snapshot after each command (no diff), an action-log reminder is injected each step, and the run stops at 25 steps or a per-command timeout [SRC]. Its only guardrail is a regex denylist for opening tabs, with no allowlist and no token or cost budget, so cite it for loop shape, not guardrails [SRC]. A procedure prompt is present in 2 of 4 references. Aside's prompt gives the real ladder: interactive snapshot, full snapshot, wait and re-snapshot, then annotated or raw screenshot; an action is unconfirmed until a fresh snapshot, strategy switches after two or three failures, progress is posted about every 30 seconds [SRC]. The "AX ref, semantic locator, set-of-marks, coordinates" ladder is a Verevon synthesis [INF]. Connector-first routing is unique to Codex (1 of 4) and is skill text the model is told to follow, not a code-level router [DOC]. Caveat: Codex procedure and efficiency caps are enforced only by model compliance [DOC].

**Verevon today.** `LlmPlanner::from_env` returns `None` unless `QUARRY_BROWSER_AGENT_LLM` is set (apps/Model Plane/rust/services/execution-core/src/llm_planner.rs:128-148) and nothing under apps/Model Plane sets it, so the deterministic planner runs by default (tool_bridge/mod.rs:170-232). The in-app browser is not agent-less: the SPA's suggest-action loop works without the flag (apps/Model Plane/rust/services/model-gateway/src/http_routes.rs:2015-2100). The durable planner's `ActionType` is goto, click, type, extract, observe, scroll and wait (browser_agent.rs:91-99) with a one-paragraph prompt and a 512-token cap (llm_planner.rs:170-263); press, select and back exist on Quarry's wire (quarry_agent.rs:125-175) but are unreachable, and get_content is already reachable through extract and observe. No per-run token budget or routing policy exists. Reuse `planner_infer_request` and `ACTION_SCHEMA`, `check_limits`, `stop_criteria` and the browser_risk HITL gates (browser_agent.rs:225-345), and the suggest-action prompt as the richer base.

**How to build it in Verevon.** Model Plane execution-core, in order: budgets (a per-run token budget is new work, since `max_cost_usd` feeds Quarry's flat action-cost table and per-org spend lives in cost-core), then prompt and schema, then the org-policy flag. Every widened action must map onto Quarry's governed `AgentAction` set and keep per-step grant, domain and risk gates: the Model proposes, Quarry executes or rejects. Default-on depends on [F-t2-001](#F-t2-001) (the durable run needs a broker grant and bearers the gateway cannot supply in production) and on [F-t2-021](#F-t2-021) (raw observation text enters the prompt unscrubbed). ZDR: model-gateway refuses durable browser runs under ZDR (browser_run.rs:297-310), so the flag cannot apply there. Risks: runaway cost without budgets, over-long prompts, eager routing that ignores an explicit browser request.
