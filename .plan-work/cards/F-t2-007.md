### F-t2-007 · Stop viewport-triggered browser relaunches: per-page emulation, a small Chromium process pool and page hygiene
| Tier | Verevon today | Effort | Plane | Wave | Confidence |
|---|---|---|---|---|---|
| Priority | Partial | M | Ingestion Plane (quarry-browser, quarry-edge) | W1 | High |

**What to build.** Part A (S): remove the viewport from browser identity and apply `Emulation.setDeviceMetricsOverride` per page or context at attach, together with `Page.setWebLifecycleState(active)`, `Emulation.setFocusEmulationEnabled(true)` and a fixed per-lease viewport. Part B (M): add an admission cap, idle reaper and health probe for the agent driver path, then optionally a pool of K Chromium processes with max open pages and retire-after-N, moving only the browser handle, pages and the single-slot live_frame_cache into per-slot state. Put the page-opening probe behind `/ready`, not the unauthenticated `/health`.

**Why it matters.** ensure_browser closes the shared Chromium and clears every session's pages, receipts, dialogs and telemetry whenever a lease's viewport differs, so a Model Plane run (no viewport) and a UI session (always 1280x800) on one edge destroy each other's live sessions; ensure_browser also runs on every goto, so mismatched sessions ping-pong. The in-app browser and AI runs need predictable capacity and crash containment, and pages that check focus misbehave without focus emulation.

**What the references do.** A browser process pool is 1 of 4 references (Apify's Crawlee BrowserPool, public source and docs): a new page goes to the first active browser below `maxOpenPagesPerBrowser` (default 20), a browser retires after 100 pages and closes when empty or via a 300 s inactivity sweeper, with pre and post hooks for launch, page create and page close [DOC, plus public source]. Firecrawl's Playwright service launches one Chromium and bounds concurrent pages with a semaphore (default 10); its `/health` creates a fresh context and blank page and closes them, with no navigation and no deadline [SRC]. Page hygiene is 2 of 4 references (Aside, Codex). Aside on attach calls Page.enable, DOM, Network and Inspector enable, `Page.setWebLifecycleState` active, `Emulation.setFocusEmulationEnabled` and `Target.setAutoAttach` flatten, guarded by an internal flag, with a stable 1440-wide AI tab viewport [SRC, from the daemon blob]. Codex disables Electron background throttling only while a tab is visible, driven or captured, a desktop-shell mechanism [SRC]. The Rust slot-vector plus semaphore shape is a Verevon proposal [INF].

**Verevon today.** ChromiumoxideDriver keeps one Browser plus one active_viewport (apps/Ingestion Plane/Quarry-v2/crates/quarry-browser/src/chromiumoxide.rs:114-126); ensure_browser (194-270) runs from acquire (1914-1926), goto (1991) and open_tab_page (378) and relaunches on any mismatch because the viewport is applied only at launch (244-246); no Emulation, focus or lifecycle call exists in the crate. The agent path acquires with no pool, semaphore or reaper (quarry-edge/src/agent_routes.rs:1512-1513); `/health` is a static ok (routes.rs:309). The gateway always sends 1280x800 (gateway/src/domains/browser.rs:481-489). Production frequency is unverified. Reuse the per-session isolated CDP contexts and the session-keyed maps for receipts, policies, dialogs and telemetry; the lease contract (quarry-core/src/lease.rs:19-22) already allows per-page emulation.

**How to build it in Verevon.** Pure Ingestion Plane change; gateway and SPA need none. The per-session pinned egress proxy and CDP Fetch boundary must stay bound to each session if sessions move between processes, and `--disable-quic` must remain when the pinned proxy is on (chromiumoxide.rs:236-243). ZDR sessions stay non-persistent. Acceptance test: a 1280x800 lease and a None-viewport lease concurrent on one driver, neither losing its page. The substrate choice needs the ADR shared with [F-t2-059](#F-t2-059) and [F-t2-060](#F-t2-060). Risks: memory pressure from more processes and receipt ordering when state is re-keyed.

**Quick win.** Part A alone removes the cross-session kill with a handful of CDP calls.
