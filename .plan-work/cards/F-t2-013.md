### F-t2-013 · Co-browsing: the agent works in the user's visible session in agent-flagged tabs, with takeover enforced inside Quarry
| Tier | Verevon today | Effort | Plane | Wave | Confidence |
|---|---|---|---|---|---|
| Priority | Partial | L | Ingestion Plane (control lease, tabs) + Model Plane (attach mode) + Frontend Plane (tab UI) | W2 (phase 1 in W1) | High |

**What to build.** Phase 1 (S, ships alone in W1): Quarry's `/step` derives the initiator from the verified principal (service principal means agent, user token means human), rejects agent steps while `control_mode` is human takeover with a typed `USER_TOOK_OVER`, stamps a monotonic control epoch on control events and receipts, and records the initiator in step receipts and tab operations. Phase 2: an attach mode so a Model Plane run binds to the user's Quarry session through a session-bound child grant and works in an agent-flagged tab that opens without stealing focus, with Reveal, Take over and Give back. Phase 3: deliverable and handoff tab marks so finished pages stay open.

**Why it matters.** Co-browsing is the core of a browser that users and AI share. Today the AI run drives a separate hidden lease, and takeover is enforced only in the Frontend gateway, so a Model Plane run that calls Quarry directly keeps acting after the user takes over. This corrects an earlier strength claim that takeover is authoritative in Quarry.

**What the references do.** No reference implements server-side control-mode arbitration of agent steps; per-step takeover enforcement is a Verevon design [INF]. The confirmed pieces come from Codex: `markTab` with handoff or deliverable marks scoped to a turn id, where turn end releases marked tabs and keeps a handoff tab open; Interrupt, SubagentStop and Stop hooks that end the turn; and hidden agent tabs hosted in a webview that stays at about:blank until the snapshot URL is known and opens without focus [SRC]. Codex's `user_took_over` is only the decline reason of its secure sign-in elicitation; in its in-app browser the user can interact at any time with no input lock found [SRC]. Its fail-closed tab-mention rule (match provider tab id, title and URL, never guess) is prompt instruction, not runtime enforcement, and manual handoff works only on the cloud backend [DOC]. Aside shows a "controlling the tab / Take over" strip and keeps owned-versus-borrowed session tabs with idle sweep and orphan reconciliation, but no daemon-side takeover handling was found [SRC][INF]. Firecrawl exposes an interactive live-view URL on its hosted browser sessions, so a human can act in the agent's session [SRC].

**Verevon today.** `BrowserControlMode` is persisted on the run record (apps/Ingestion Plane/Quarry-v2/crates/quarry-runtime/src/step_receipts.rs:55-90) and set by `set_browser_session_control`, which hard-codes `initiated_by` Human (agent_routes.rs:1733-1785). Enforcement lives only in the gateway from a caller-supplied actor field (apps/Frontend Plane/verevonv3/apps/gateway/src/domains/browser.rs:696-723, 2065-2075); the Quarry step handler (agent_routes.rs:2227-2294) never reads `control_mode`, receipts carry only the run owner, tab events have no owner field and there is no control epoch. A Model Plane run never attaches: `start_run` leases its own session with profile_id, start_url and an interim grant string (apps/Model Plane/rust/services/execution-core/src/browser_agent.rs:674; browser.rs:1235). Reuse the persisted control mode, the Control and Tab timeline events, `Claims::is_service` and `actor_id` (quarry-edge/src/auth.rs:60-139), and the broker's `SessionKey`, `ParentGrantID` and scoped-approval helpers (apps/Model Plane/go/services/browser-broker/internal/grant/grant.go:44-130).

**How to build it in Verevon.** Enforcement moves into Quarry `/step`; the gateway check stays as UX-level early rejection. Phase 2 is blocked by ownership: `caller_owns_browser_run` (agent_routes.rs:474-482) requires the caller's actor id to equal the run actor, execution-core calls Quarry with an org-scoped service token, and Claims has no on-behalf-of field, so a Model Plane run gets 404 on a user-owned session. Attach needs an explicit delegation design (Auth Core claim or session-bound child grant) that never widens the user's ACL or Space authority, scheduled after [F-t2-001](#F-t2-001) and treated as L to XL. [F-t2-011](#F-t2-011) covers the human navigation policy, [F-t2-038](#F-t2-038) the agent-activity presentation. ZDR sessions stay non-persistent (control timeline writes are skipped, agent_routes.rs:493-495). Risks: races between an in-flight step and takeover (hence the epoch), tab leaks without an idle sweeper.

**Quick win.** Phase 1 only: small, Ingestion Plane only, and it closes a real safety gap.
