### F-t2-021 · Secret redaction at capture time: AX/DOM snapshots, screenshots, OCR, receipts and logs, before storage or model exposure
| Tier | Verevon today | Effort | Plane | Wave | Confidence |
|---|---|---|---|---|---|
| Priority | Partial | L | Ingestion Plane (quarry-browser, quarry-runtime) + Model Plane (execution-core planner and persistence) | W2 | Medium |

**What to build.** A deterministic, versioned redaction module inside Quarry's snapshot builder that masks secrets before artifact write, event emission and the response to the Model Plane. Snapshots always mask password, tel, one-time-code and card fields by input type, autocomplete token, label pattern and Luhn check; durable captures also redact by value shape (JWTs, API-key prefixes, private-key blocks, numeric OTPs). Redact typed text in step receipts and the planner prompt. Screenshot masking by element rectangle is a follow-on slice.

**Why it matters.** Verevon records more than any reference (receipts, timeline, proof bundles, live frames), so it captures more secrets. The AX (accessibility) projection copies node values verbatim and receipts store typed text, so a password typed by the agent lands in storage and in the model prompt [SRC]. Redaction is a precondition for the credential handoff in [F-t2-024](#F-t2-024).

**What the references do.** Capture-time page redaction is in 1 of 4 references (Aside); some redaction is in 3 of 4 (Aside capture and logs, Firecrawl PII on output, Apify secret env vars in logs). Aside's capture redaction replaces values with `[redacted:capture]` using layered rules: sensitive input types (`password`, `tel`), sensitive autocomplete tokens, a field-label regex (cvv, otp, pin, ssn, secret), value patterns (JWT, AWS access key, API key, Slack token, private-key block, labelled secret, numeric OTP) and a card-number candidate regex with a Luhn check, applied to text and ARIA snapshots for durable capture, plus redaction of tool arguments and error bodies in logs [SRC, from a scratch copy of the daemon blob, no runtime confirmation]. The interactive agent snapshot path redacts only non-empty password inputs, so other secrets on a page still reach the model [SRC]. No reference redacts screenshots, OCR (optical character recognition) output or receipts [SRC]. Aside's origin-checked password fill sets the value through the native `HTMLInputElement` setter with input and change events, and its only caller unlocks an external password-manager extension page, not a website login; website fills go through the Vault extension with session, policy and URL checks [SRC]. Firecrawl offers opt-in `redactPII` on markdown through an external privacy service that fails closed to an empty string [SRC]; Apify encrypts secret env vars at rest and redacts them from run logs [DOC].

**Verevon today.** `native_projection_from_cdp` copies AX name and value verbatim (apps/Ingestion Plane/Quarry-v2/crates/quarry-browser/src/chromiumoxide.rs:1096-1130); snapshot target text falls back to the AX value (quarry-runtime/src/observation.rs:1573-1640); `StepReceipt` stores the whole `AgentAction`, including `Type` text, plus the post-action observation (quarry-runtime/src/step_receipts.rs:190-206); OCR and screenshot artifacts are written unmasked behind only a ZDR gate (observation.rs:700-790). `redact_sensitive` (quarry-runtime/src/agent_memory.rs:52) has no callers at all because `AgentScratchpad` is itself unused. Only egress URLs are redacted (chromiumoxide.rs:1053-1066). The Model Plane scrubs token patterns from step output and checkpoints before persistence (apps/Model Plane/rust/services/execution-core/src/scrub.rs:1-60; grpc.rs:1015-1042), but the `LlmPlanner` prompt receives raw observation text (execution-core/src/llm_planner.rs:170-263). Reuse scrub.rs as the richer pattern set (Bearer, JWT, `sk-`, AWS, GitHub, PEM, DSN, key=value), `redact_sensitive` as a seed, and `put_artifact_if_allowed` plus `build_active_snapshot` as the choke points.

**How to build it in Verevon.** Port the scrub.rs pattern set into a Quarry module and apply it in `native_projection_from_cdp`, `build_active_snapshot`, receipt persistence (mask `AgentAction::Type` text and the stored observation) and before artifact writes; scrub `extracted_text` in the planner prompt before inference. Field-semantic masking needs input type and autocomplete, which an AX node does not carry, so the snapshot builder must fetch them per input target (DOM describe or page evaluate); whether Chromium already masks password values in its AX tree is not verified. Rules must be deterministic and local with no model call, and must run on the ZDR path too, because live observations are returned even when nothing is persisted. Quarry and the Model Plane are separate workspaces, so share patterns by duplication with a conformance test, or record a shared crate in an ADR. Main risks: over-redaction breaks extraction, so keep rules narrow and typed; regex cost on large snapshots; screenshot masking depends on accurate rectangles.
