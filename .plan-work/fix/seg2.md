## 3. Workstreams

How to read this section. Each workstream (WS) is one design (D1 to D17) cut into slices; a slice is one PR-sized change with its own tests and deployment evidence. Slice ids are `WS<n>.<letter>`: the letter is the architecture memo's slice id (arch-B 1), and the design's own slice name is given in brackets, for example `WS3.C [D3 S2]`. Where the reconciliation list in arch-A section 2 (R-n) or a decision record (X-n, ADR-n, OQ-n) overrides a design, the override is used and named in one clause. Wave 1 workstreams are WS1 to WS5; later workstreams are cut the same way by the other section 3 parts.

Path tags come from `tools/provenance.sh` run on 2026-10-15 against the live tree (afb83928 plus about 324 uncommitted entries): `[C]` committed and unchanged, `[M]` committed but modified in the live tree (in-flight hunks exist: rebase, never merge blind), `[U]` untracked (exists only as uncommitted work), `[NEW]` created by this plan. Paths in section 3 are written in full, relative to the repo root. Line numbers are live-tree numbers read by the design agents and re-checked where stated; they drift once earlier slices land, so re-read before editing. Test commands that build Quarry Rust run inside the `rust:1` container with the `quarry-cargo`, `quarry-go`, `quarry-target` volumes and `bash -c` (a full `-p quarry-core -p quarry-runtime -p quarry-edge` run exceeds 10 minutes), because the Windows host cannot build the crates natively. Every "Deployment evidence" item means rebuilt local images, a running stack and a verified flow with a stated observable assertion; the evidence stack recipes are in arch-B 7.3 (the edge listens on `127.0.0.1:8082` in the Ingestion compose and `127.0.0.1:38080` in the standalone compose, not the `:8080` the Quarry smoke scripts default to). Baseline for every slice: the PRE-1 commit of the in-flight work (arch-B 2.1) is done first, and the regression guards in arch-A section 7 stay green.
