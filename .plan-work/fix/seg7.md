## 4. Sequencing and parallelism

This section is the operating manual for running 15 lanes at once without colliding. It condenses the sequencing memo (arch-B) and applies the architecture memo's reconciliation list (arch-A section 2, cited as R-n); where R-n changes a design or arch-B, the row says so in one clause.

Paths are written in full. Tags `[C]`/`[M]`/`[U]`/`[NEW]` come from `tools/provenance.sh` run on the live tree on 2026-10-15. Line ranges are the designs' live-tree ranges and drift as earlier slices land: re-read before editing. Slice letters are the catalogue ids (`WS3.D` is design D3's S3).

**Position 0 (process, before any lane merges): PRE-1, decision X-3.** About 324 uncommitted entries sit under the files nearly every slice edits, including 28 untracked golden and fixture files and 6 untracked gate files that `scripts/tests/zdr-contract-sync.test.sh` [M] and CI need, and session-core migrations `0044` and `0045` [U]. Commit or branch them as a baseline first. Until then every lane's append to a shared file conflicts and the gates pass only on the owner's machine. Only slices that touch no uncommitted hunk (WS4.A, WS3.B, WS3.E, WS2.E, WS1.A1; WS2.A and WS4.K with one hand-staged hunk each) may merge before position 0 completes; every slice that edits an [M] file (WS3.A, WS5.A, WS5.B, WS6.A, WS1.A0, WS1.A2, PRE-2) waits for it (X-3).

### 4.5 Feature flags and rollout table

Every behaviour change ships behind a default-off or observe-mode flag, and production defaults flip only after a recorded L2 run (6.2). Prefixes: edge `QUARRY_EDGE__*` (separator `__`; compose anchors drop the prefix, for example `USAGE_BROWSER_METRICS`), driver `QUARRY_BROWSER_*`, Go services `QUARRY_*`, Model Plane `<SERVICE>_*`, gateway unprefixed, SPA `VITE_*`. New flags use only the `QUARRY_EDGE__` form (the raw single-underscore `QUARRY_EDGE_AUTH_DEV_BYPASS` and `QUARRY_EDGE_ARTIFACT_BACKEND` are read case-sensitively by the production refusals: PRE-2). An unparsable value aborts boot in every new reader; the old `EdgeConfig` loader silently falls back to defaults (S9 `config.rs:334-341`) and must not be copied. Vocabularies differ by design (`off|observe|enforce` in WS7, WS14, WS17; `off|shadow|on` in WS6; `off|shadow|skip|on` in WS5; `lenient|strict` in WS5 and WS14); semantics are common: `observe` equals `shadow`.

## 5. Cross-session interfaces

Two sibling planning sessions share pieces of this plan. Sibling (a) is Verevon Space (agent PC and browser inside Spaces, Space grants that must never widen an owner-plane ACL, ZDR-safe telemetry and projections). "Owner" is the proposed owner of the code; the contract owner is named in the contract column. Every row ends in a question only the user can settle, marked FOR USER TO RECONCILE.

**Rule that governs every row.** Space access can only narrow an owner-plane decision (`apps/master-ownership-matrix.md` rule 10, line 166: projections only narrow access): grants are minted from the owner's bearer, Quarry compares `grant.owner_id` with the run owner, policy meets only tighten, projections hold ids and counters. A Space feature that needs a member to act on or read a browser owned by another member is a new design (a shared-session ACL), out of scope here.

### 6.2 Deployment evidence standard
