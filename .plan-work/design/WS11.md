## Design

### D1 Architecture

```
PHASE 1 (polled, derived)
SPA store (one poller per browser via Web Locks) -> BFF GET /api/v1/spaces/attention
  -> control_space_index (existing) -> Control POST thread-read-decisions (NEW bulk, N existing model.thread.read decisions)
  -> Convex spaceAttention:attentionForGateway (markers, floor, level, open mention counts)
  -> model-gateway POST /v1/spaces/attention -> Session Core SpaceAttention.GetSpaceAttention (verifies each decision)
  -> compose per room + badge rule (Rust, one place) -> {rooms, totals, gaps}

PHASE 2 (event signals)
Session Core: message/run commit -> space_event_log (WS02 trigger) -> AFTER INSERT trigger -> session_audit_outbox
  -> drainer -> NATS mp.v1.space.<space_ref>.event (JetStream MODEL_PLANE_SPACE_EVENTS)
  -> convex-subscriber durable -> Convex ingestSpaceEvent (membership gate, follows, level, coalesce) -> spaceAttentionItems
  -> (optional) Convex deliverOutOfApp -> notification-core /api/v1/notification-requests (type space.*, refs only)
Inbox: BFF GET /api/v1/spaces/attention/items -> Convex list + Control bulk decisions + Session Core headlines (titles, render time only)
```

Placement and why. Session Core stays the only writer and the only reader of conversation state and publishes ids. Convex owns every per-person projection (it already owns read markers, presence and the audience snapshot, and it is the plane CLAUDE.md names for "realtime projections and notifications"). notification-core is used only as the out-of-app courier, because it is not a ZDR-safe store (V2). Control owns who may read which Space and issues the decisions; it gains one bulk route and no table. The BFF composes and holds no state. No plane reads another plane's database; every cross-plane hop is an API or an event.

### D2 Meaning of the numbers (badge semantics, resolves the audit's double-count risk)

| Quantity | Source | Nature |
|---|---|---|
| `unread_threads` | Session Core, from the viewer's effective marker | derived, never stored |
| `mentions` | Convex open items of kind `mention` and `reply` in the room | stored, read-driven: resolved when the marker advances past the item |
| `needs_you` | Session Core pending approvals addressed to the viewer (WS10 predicate; until then run owner) | derived, state-driven: cannot go stale, no resolution event needed |
| `working` | Session Core running root runs in the room (20 min staleness window) | derived |

Room badge (computed once, in the BFF, tested as a table): `n = needs_you + mentions`; if `n > 0` then Count(n) at every level; else level `all` and `unread_threads > 0` gives a muted Count(unread), level `mentions` gives a Dot, level `off` gives none. `totals.badge` sums `n` over rooms only; unread is reported separately as `unread_rooms` and is never added, so one thread cannot count twice. Open `agent_done`, `agent_failed`, `invite` and `reminder` items appear in the inbox and in `totals.other_open`, never in a room badge or `totals.badge`. The SPA renders `badge` and never recomputes it (a second implementation is how `space-unread.ts` drifted from Convex).

Unread rule is the WS01 rule: a thread is unread when its latest user or assistant message is newer than the effective marker and its author is not the viewer. The request carries `rule` (`LAST_AUTHOR` when `features.human_posts` is on, `LEGACY_OWNER` otherwise: skip threads the viewer owns) so the sidebar and the open room never disagree. No marker means nothing is unread (unchanged). Effective marker = manual floor if set, else `lastReadAt`.

```sql
-- unread (cost proportional to new activity, uses migration A)
SELECT DISTINCT m.thread_id FROM messages m
 WHERE m.space_id = $space AND m.created_at > to_timestamp($since/1000.0) AND m.role IN ('user','assistant')
   AND (m.recipient_audience_revision IS NULL OR m.recipient_audience_revision <= $ceiling) LIMIT 101;
```

Precedence, fixed (audit order), `deliveryDecision`:

| Step | Rule |
|---|---|
| 1 | recipient equals actor: drop |
| 2 | recipient must be an active, acknowledged recipient of the Space audience (V15) and in the event's org, else drop (a mention of a non-member does nothing and reveals nothing) |
| 3 | `mention` and `invite`: pass every level and mute |
