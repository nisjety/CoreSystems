## Design

### D1 Architecture and data flow

```
In-room search (Ctrl/Cmd+F)
 SPA  -> BFF POST /api/v1/spaces/{space_ref}/search
 BFF   : session -> authorized_org_id -> space_lifecycle_by_ref -> flag
         -> Control POST /api/v1/internal/spaces/thread-read-decision (fresh per query)
         -> model-gateway POST /v1/spaces/{space_id}/messages/search   (decision in body)
 mgw   : verified bearer -> typed body (deny_unknown_fields) -> Session Core SpaceHistoryService.SearchMessages
 SC    : identity -> authorize_operation(session:read) -> human caller -> org/user match
         -> verify_thread_read_space_decision (Some = shared read, None = owner-only)
         -> revocation check -> ONE SQL (candidates + audience + owner + retention predicates) -> hits
 BFF   : re-check every hit.space_id == space_ref (502 otherwise) -> {data} envelope, Cache-Control: no-store

Open in context: hit -> /spaces/{ref}?thread_id=T&m=M#chat  (WS01 pane resolves T by transcript route)
Bare permalink:  /spaces/{ref}/m/{message_id} -> SPA route -> GET /api/v1/spaces/{ref}/entries/{message_id}
                 -> same decision -> SpaceHistoryService.ResolveMessage -> {thread_id} -> navigate (replace)
```

Plane ownership: message text, audience stamps, index: Model (Session Core), because it owns `messages`. Authority: Control (decision reuse, no new action id, no new entitlement). The BFF holds no state and never calls Session Core (V11 of WS01 still applies: it goes through model-gateway). Application owns only pins (S8). Nothing is copied into Data v2 or Convex.

### D2 Index design (Session Core)

Migration `0048_space_message_search_index.sql` (reserved number; 0046 and 0047 are taken by sibling designs, the sequencing owner assigns finals). First line `-- no-transaction` so sqlx 0.8 runs it outside a transaction (no existing migration does; UNVERIFIED that the pinned sqlx handles it as documented, prove it in S1 with a scratch DB):

```sql
-- no-transaction
CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_messages_space_fts
    ON messages USING GIN (to_tsvector('simple', left(content, 100000)))
    WHERE space_id IS NOT NULL AND role IN ('user', 'assistant');
```

Why an expression index and not a stored column or a search table:
- No rewrite of `messages` (a generated STORED column rewrites the table under ACCESS EXCLUSIVE); `CONCURRENTLY` blocks no writes.
- No second copy of text and no new purge hook: thread delete, org erasure and Space deletion delete `messages` rows (V9) and the index follows.
- `left(content, 100000)` bounds the vector. A `tsvector` over a megabyte of distinct words raises an error at INSERT, which would abort a message append. Text past 100,000 characters is not searchable; the response carries no flag for it, the runbook states it.
- Partial predicate `space_id IS NOT NULL` keeps personal chat text out of this index. Rows stamped before 0025 have `space_id` NULL (the 0025 check constraint forbids stamping one audience column alone) and are not searchable; S1 rollout runs a count to size that gap (rooms predate 0025 only in dev data, UNVERIFIED in other environments).
- `'simple'` has no stemming and no stop words, so Norwegian queries match exact word forms only. Prefix matching on the trailing token covers type-ahead. Decision D-9.
- Sibling b's owner-scoped chat search (F-t3-012) indexes the disjoint population `space_id IS NULL` with the same expression in its own migration; the query helper (`build_tsquery`) is shared. Neither migration depends on the other.
- Write cost: every Space message insert maintains the GIN index (pending list, `fastupdate` default). Accepted; measure in S1.
- Failed `CONCURRENTLY` build leaves an INVALID index that `IF NOT EXISTS` skips: runbook line `DROP INDEX CONCURRENTLY IF EXISTS idx_messages_space_fts;` then re-run. Down file `migrations/revert/0048_space_message_search_index.down.sql` (manual, outside sqlx, same convention as 0044/0045) drops it.

### D3 Session Core RPCs (new proto `apps/Model Plane/proto/model_plane/v1/space_history.proto`, module `space_history_grpc.rs`)

A new file avoids `sessions.proto` and `grpc.rs`, which WS01, WS04, WS12 and WS15 all edit. `build.rs` gains one list entry; `serve()` gains one `add_service` line and `HEALTH_SERVICE_NAMES` grows to 9.

```proto
service SpaceHistoryService {
  rpc SearchMessages(SearchSpaceMessagesRequest) returns (SearchSpaceMessagesResponse);
  rpc ResolveMessage(ResolveSpaceMessageRequest) returns (ResolveSpaceMessageResponse);
}
message SearchSpaceMessagesRequest {
  string org_id = 1; string user_id = 2; string space_id = 3;
  string space_read_decision_ref = 4; string space_read_decision_token = 5;
  string query = 6; bool prefix = 7;
  string thread_id = 8;           // scope=thread
  string author_subject_id = 9;   // scope=person
  string role = 10;               // "", "user", "assistant"
  google.protobuf.Timestamp since = 11; google.protobuf.Timestamp until = 12;
  string sort = 13;               // "recent" (default) | "relevance"
  uint32 limit = 14;              // 0 -> 20, clamp 1..50
  string cursor = 15;             // opaque, from the previous response
}
message SnippetSegment { string text = 1; bool matched = 2; }
message SpaceMessageHit {
  string message_id = 1; string thread_id = 2; string space_id = 3;
  string role = 4; string author_subject_id = 5; string agent_name = 6;
  google.protobuf.Timestamp created_at = 7;
  repeated SnippetSegment snippet = 8; string thread_title = 9;
}
message SearchSpaceMessagesResponse {
  repeated SpaceMessageHit hits = 1; string next_cursor = 2; bool truncated = 3;
  string coverage = 4;            // "shared" | "own_threads_only"
  repeated string excluded = 5;   // reasons content was withheld, e.g. "zdr_waived_threads"
}
message ResolveSpaceMessageRequest {
  string org_id = 1; string user_id = 2; string space_id = 3;
  string space_read_decision_ref = 4; string space_read_decision_token = 5;
  string message_id = 6;
}
message ResolveSpaceMessageResponse { string message_id = 1; string thread_id = 2; string space_id = 3; }
```

`SearchMessages` steps, in order, each denial before any query text reaches SQL:
1. `identity(&request)`; `authorize_operation(&caller, "session:read")` (a ZDR caller passes: this is a read); refuse a service principal (`is_service()`) with PermissionDenied. Agent recall is a different RPC under a different decision (conflict C10, not built).
2. Flag `SPACE_MESSAGE_SEARCH_CORE` off: `Unavailable("search_disabled")`.
3. Validate: `org_id`, `user_id`, `space_id` present; `caller.authorize_org`, `caller.authorize_user`; query 2 to 200 characters after trim, no control characters; limit and cursor shape; `scope` consistency (`thread_id` only with a thread filter).
4. `verify_thread_read_space_decision(token, ref, org, user, space)`: `Some(read)` gives the shared path with `audience_ceiling = read.recipient_audience_revision`; `None` gives the owner-only path (`coverage = "own_threads_only"`). A half-supplied decision is an error, as today.
5. Revocation: `EXISTS space_membership_revocations (space_ref, subject_id = caller)` returns PermissionDenied. The decision just minted already proves current membership in Control; this row (migration 0032) is a belt for a restored-then-revoked race, and costs one indexed lookup.
6. Concurrency permit: a per-replica semaphore of 8 in-flight searches; no permit returns `ResourceExhausted` (BFF 429 `search_busy`). The statement runs in a transaction with `SET LOCAL statement_timeout = '2500ms'`; timeout maps to `DeadlineExceeded` (BFF 503 `search_timeout`).
7. Query construction (`build_tsquery`, shared helper): `websearch_to_tsquery('simple', $head)`; with `prefix = true` the trailing token, reduced to Unicode alphanumerics of at least 2 characters, becomes `to_tsquery('simple', quote_literal(token) || ':*')` and is AND-ed. A query with no lexemes returns zero hits and `excluded = ["no_searchable_terms"]`, not an error.
8. One SQL statement (shape; `$3` is the ceiling or NULL):

```sql
SELECT m.id, m.thread_id, m.role, m.author_subject_id, m.agent_name, m.created_at, m.content
FROM messages m
JOIN threads t ON t.id = m.thread_id
WHERE t.org_id = $1 AND t.space_id = $2 AND m.space_id = $2
  AND m.role IN ('user', 'assistant')
  AND to_tsvector('simple', left(m.content, 100000)) @@ <tsquery>
  AND t.archived_at IS NULL
  AND ($3::BIGINT IS NULL OR m.recipient_audience_revision IS NULL OR m.recipient_audience_revision <= $3)
  AND ($3::BIGINT IS NULL OR t.recipient_audience_revision IS NULL OR t.recipient_audience_revision <= $3)
  AND ($3::BIGINT IS NOT NULL OR t.user_id = $4)                        -- owner-only path
  AND NOT EXISTS (SELECT 1 FROM runs r WHERE r.thread_id = t.id AND r.retention_class = 'zdr_waived')
  AND ($5::TEXT IS NULL OR t.id = $5) AND ($6::TEXT IS NULL OR m.author_subject_id = $6)
  AND ($7::TEXT IS NULL OR m.role = $7)
  AND ($8::TIMESTAMPTZ IS NULL OR m.created_at >= $8) AND ($9::TIMESTAMPTZ IS NULL OR m.created_at < $9)
  AND <keyset: (m.created_at, m.id) < (cursor_ts, cursor_id)>           -- sort=recent
ORDER BY m.created_at DESC, m.id DESC
LIMIT $limit + 1
```
   The expression `to_tsvector('simple', left(m.content, 100000))` must match the index expression character for character or the planner scans. `sort = relevance` ranks the newest 500 matches with `ts_rank_cd` and pages by offset up to 100 hits total, then `truncated = true`. Cursors are opaque (`v1`, kind, `(created_at micros, message_id)` or offset); a forged cursor can only move the window inside the already-authorized predicate, so cursors are not signed and never carry `messages.sequence` (V6).
9. Per-hit work on the page only (at most 50): `ts_headline('simple', content, tsquery, 'MaxFragments=1,MaxWords=24,MinWords=8,StartSel=[[h:<nonce>]],StopSel=[[/h:<nonce>]]')` with a per-request random nonce generated in Session Core, then parsed into `SnippetSegment`s. Content never travels as HTML; the SPA renders segments as text nodes, so message text cannot inject markup. Thread title mirrors `list_threads`: `COALESCE(presentation_title, first user message)` compacted to 96 characters, only for authorized hits.
10. Metrics: `record_metrics("search_space_messages", started, ok)` plus counters for hit count buckets and query length buckets. Never log query text, snippets or ids of hits.

`ResolveMessage` runs steps 1 to 5, then selects `m.thread_id` for `m.id = $6` under the same predicates (Space equality, audience ceiling, archived allowed, waived exclusion not applied because resolving is addressing, not indexing). Not found, hidden by audience, other Space and other org are all `NotFound("entry not found")`, so the response cannot be used to probe existence.

`HEALTH_SERVICE_NAMES` (`grpc.rs:47-56`) becomes `[&str; 9]` with `"model_plane.v1.SpaceHistoryService"`. The service is registered with `SpaceHistoryServiceServer::with_interceptor(history, auth.clone())` next to `RunServiceServer` (`grpc.rs:7361`).

No separate `/membership` call (the decision is the membership proof, as on the transcript route). After the response the BFF asserts every hit carries `space_id == space_ref` (pattern `thread_items_match_space`, `spaces.rs:2734`) and rejects with 502 otherwise. ZDR in the BFF: no use of `cache`, Dragonfly or any key derived from the query (the web-search route stores results without a ZDR check, `search.rs:285`, finding F-t2-003: not reused). Response `Cache-Control: no-store`. Logs carry route, status, hit count and latency only. ## Open questions for the user
