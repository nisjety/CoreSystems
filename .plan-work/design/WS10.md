## Design

### 3.1 Invariants (every slice must keep them)

1. Approval adds consent, never authority. The approved action runs as the requester (the run owner). The approver is recorded in `decided_by`. Owner-plane authorization at effect time is never skipped, and a grant waives only a prompt. This is assumes ADR 5 option A: authority re-resolved per hop, initiating human recorded on every hop.
2. Control owns the scope vocabulary, ceilings, grants and Space policy. Model Plane only tightens: execution-core folds every source with `max_restrictive` over `allow < ask < block`, so no source can loosen another.
3. The never-auto set (`requires_durable_owner_approval`, `requires_consent_to_disclose`, `permission/mod.rs:77,160`) is never passed by a grant. A `block` beats any grant.
4. ZDR: no grants, no once-token, no action digest, no held content. Refusals reuse existing catalogue codes `zdr_durable_mutation_forbidden` and `zdr_feature_not_supported{approval_continuation}`; no new catalogue keys (so `zdr-refusals.json` and its pins do not change).
5. Every claim on the card is derived from server fields (`resume_class`, `continuation`), never from static copy.
6. Realtime and push carry ids and kinds only (assumes ADR 2 option B). WS10 adds fields to approval state events but never content.

### 3.2 End-to-end flow

1. A gated tool call reaches `execute_step_inner` (`runtime_loop/mod.rs:467`). A new `approval_gate` folds: capability-core decision, hook decision, posture (`evaluate_call`), and, for Space runs, the Control gate view. Result `allow`, `ask` or `block`.
2. `block` returns `permission_denied_with_reason(...)` with a typed cause and source layer. `allow` proceeds as today.
3. `ask`: if the tool is never-auto, pause. Else if `resume_class == none` and Session Core `ClaimOnceApproval` returns a granted unconsumed approval for the same thread, tool and `action_digest`, pass. Else if Control `approval-grants/use` returns a thread or always grant, create a granted approval row with the signed use token and pass. Else pause as today (`pause_for_approval`, `agent.rs:4476`) with the new context.
4. The card reads the approval with tool label, cause, resume class and continuation state. The addressee decides: `POST /api/v1/spaces/{space_ref}/approvals/{approval_id}/decide` with a scope.
5. Gateway forwards the decision (owner path, or a Control `model.approval.decide` decision for a non-owner approver) to model-gateway then Session Core. For thread or always, the gateway then asks Control to record the grant, which Control verifies against Session Core.
6. For resumable kinds (`action_continuation`) the existing worker runs the action as the requester after a new Control authority re-check. For other kinds the once-token or the grant lets the agent's retry pass the gate.

### 3.3 Scope semantics

| Scope | Chosen by | Waives | Bound to | Stored in | Lifetime | Revocation |
|---|---|---|---|---|---|---|
| once | the addressee | this exact action | thread, agent, tool, `action_digest` | Session Core `approvals` row (`grant_scope='once'`, `consumed_at`) | approval expiry (3600 s) | consumed on use; expiry |
| thread | the requester for their own thread, or manager+ | prompts for that requester's runs in that thread | Space, agent, thread, requester, `action_key`, schema hash | Control `space_approval_grants` | 24 h default, max 7 d | creator or manager; cascades |
| always | manager+ and only if the Space ceiling is `always` | prompts for every member's runs of this agent in this Space | Space, agent, `action_key`, schema hash | Control `space_approval_grants` | none; `review_by` 90 d | manager/owner; cascade on agent removal or schema hash change |

`action_key` is the tool name, or `execute_provider_action:<operation>` for provider actions; never arguments. `action_digest` is `sha256` of canonical JSON (sorted keys) of `{tool, input}`; it lives only in Session Core and only for non-ZDR runs. The scope enum, the ceiling rule and "block beats grant" are defined in Control and consumed by the others (resolves conflict C3 for Space; siblings map onto it, see 12).

### 3.8 Tool policy (S5)

Layers: `org_floor`, `space_ceiling`, `agent`. For a tool or action key, within a layer the specific key beats `*`; across layers the result is the most restrictive. Absent rows mean `allow`, which never loosens the default gates (risk, posture, never-auto); only a grant waives a prompt. Control computes the merged view and a digest; execution-core folds it with its other sources (3.6). Legacy `approvalMode` maps to presets written as agent-layer rows (`blocked` gives `*`=block); `require_confirmation` and `auto` stay as the existing gateway filter in WS10 (changing the `agentic` strip is open question 4). The editor shows the merged level and its source layer per tool. Sibling b's declared classes and registry (F-t3-003, F-t3-032) feed the same fold later; nothing here blocks them.

### 3.9 Quarantine (S8)

At the render seam (`runtime_loop/mod.rs:811-813`): when `provenance.posture == Flagged`, the trust class is external, the run is Space-scoped, not ZDR, and the Space `quarantine_mode` is `enforce`, the output is encrypted into `quarantined_outputs` (`DescriptorCipher`, `continuation_crypto.rs`), an approval of new kind `APPROVAL_KIND_UNTRUSTED_CONTENT=6` is created (addressee requester, cause `quarantine`, `resume_class=none`), and the model receives a placeholder with no content. The run is not paused. Release is a `once` decision: a repeated call with the same `action_digest` triggers `claim_release`, which hands the held content over once, framed as data (`provenance::render`). Deny deletes the ciphertext; expiry at most 24 h. The preview (at most 1 KiB, plain text, never HTML or markdown, never auto-linked) is returned only to the deciding addressee after Control confirms. In `shadow` mode only a counter and a log fire. Semantic screening stays shadow-only and is not an input.

### 3.10 turn_origin (S7)

Assumes ADR 1 option A: the enum `direct | ambient | automation` is defined by WS01/WS08 and carried by the Control thread decisions and `runs.turn_origin`. WS10 only consumes it: a non-`direct` approval defaults to addressee `any_manager`, `thread` scope is not offered, and the once-token is disabled (no human to retry). NULL is treated as `direct` (every run today is human-direct or scheduled). The unresolved vocabulary conflict is C4; WS10 does not define its own enum.

## Definition of done and evidence

The repo counts a slice only after rebuilt local images, a running stack and a verified end-to-end flow. Rebuild: `cd "apps/Model Plane" && ./scripts/compose.sh up -d --build session-core execution-core model-gateway`; `cd "apps/Control Plane" && scripts/run-control-plane.sh up -d --build user-core` (bare compose build does nothing); `docker restart convex-gateway` and wait for "Convex functions ready!"; `cd "apps/Frontend Plane/verevonv3" && docker compose up -d --build gateway frontend` (restart Vite, host edits are not hot-reloaded). Seed, because dev has no policy rows: org effect policy with thread, agent-action and `approval_grant_entitled`; Space approval policy with ceiling `thread`.

Flows to run and capture (HTTP transcripts, SQL rows, container logs, screenshots):

1. S1: member A mentions an agent to run a gated provider write. Capture approval JSON with `tool_key`, `resume_class=action_continuation`, `continuation.state`; decide once; capture queued, running, completed, verified by read-back and the integration receipt actor equal to A. Repeat with a `none` kind (shell): the card says retry once, no "run continues".
2. S3/S4: retry of the `none` action passes (SQL `consumed_at`), the second retry pauses. Decide "this conversation": Control row and `created` event; next gated call passes with no pause; Session Core row `granted`, `grant_ref` set; a new thread pauses; manager revokes, next call pauses.
3. Negative: member without the role is refused the always scope; viewer refused; forged token refused; `block` in the Space ceiling denies with a typed cause even with a grant present; org floor beats Space ceiling.
4. ZDR org: grant create refused `zdr_durable_mutation_forbidden`; no digest rows; no held content.
5. S6: A requests, B (editor) is the named approver and decides; row shows `user_id=A`, `decided_by=B`, execution actor A. Remove A from the Space before approval: continuation ends `authority_changed`, nothing runs.
6. S8: flagged fixture page in shadow gives counter and log only; in enforce the content is held, preview shown inertly to A only, release is single-use, a second read returns the placeholder.

Done means these flows pass on freshly built images, the test commands above are green, and an evidence note (container image ids, `docker compose ps`, transcripts) is committed next to the plan.

## Open questions for the user

1. Who may create an "always" grant: managers and owners only (assumed), or also the requester for their own agent?
2. Should a Space manager be able to decide an approval addressed to a specific requester without being named (override), or only when the addressee is `any_manager`?
3. Is "approving runs the action as the requester" (invariant 1) the right rule, or should an approver's own authority apply? It changes S6 materially.

5. ZDR orgs get no approvals, grants or held content and a refs-only card. Is that acceptable as the product statement (audit open question 5)?
6. What false-positive rate is acceptable before quarantine moves from shadow to enforce, and who reviews the shadow report?
7. Is action-only continuation plus a once-token retry good enough until sibling b delivers in-place resume, or should WS10 wait for it before changing the card copy?
8. Should an `always` grant survive its creator losing the manager role (assumed yes; it is a Space policy decision with the creator recorded)?
