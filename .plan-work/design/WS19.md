## Design

### 3.1 Principles

1. The canvas is Space-owned, Data-stored. Control decides who may touch it; Data enforces the decision itself; the gateway only relays; Application holds no canvas content.
2. A client or gateway never supplies authority. `space_ref`, role, audience and author kind come from a Control-signed decision that wiki-store verifies; the author kind is derived from the envelope type, never from the request body.
3. Write safety is head compare-and-swap in the same transaction as the insert; a rejected save stores nothing.
4. ZDR: no canvas. Control refuses to issue, wiki-store refuses the token, the gateway refuses early with the typed catalogue code, the UI says so. Reads are refused too (D-5).
5. Canvas text is untrusted data when an agent reads it, and is never injected into a turn implicitly.
6. No second copy: no event with content, no embedding, no search index, no Convex content, no browser-persisted drafts in phase 1.

### 3.2 Data flow

```
Human read/save:  SPA -> BFF /api/v1/spaces/{ref}/canvas...
   -> session, org, lifecycle, flag, ZDR pre-check
   -> Control POST /api/v1/internal/spaces/canvas-decision  (op, ids, content_digest)   [signed Decision, 2 min]
   -> wiki-store /v1/space-canvas/spaces/{ref}/...  (bearer aud=data-plane + header X-Space-Decision)
   -> verify bearer, scope, ZDR, decision (signature, org, space, subject, action, schema, expiry, digest) -> org-scoped tx
Agent read/write: model proposes tool call -> execution-core gate (capability-core, hooks, WS10 policy)
   -> Control run-action-decision (action space.canvas.read|write, WS18 registry)       [run-action-v1]
   -> wiki-store (same routes, header X-Space-Decision; the human invoker's bearer is forwarded as for knowledge_search)
Purge:            Convex space-deletion action -> wiki-store /v1/internal/space-canvas/purge ; org-core erasure -> HardPurgeByOrg
```

### 3.3 Data Plane: tables (migration `apps/Data Plane v2/infra/postgres/migrations/20261020100000_space_canvas.sql` plus `.down.sql`; sorts after 20261003150000; the sequencing owner assigns the final stamp)

```sql
CREATE TABLE IF NOT EXISTS space_canvases (
    canvas_id        TEXT PRIMARY KEY DEFAULT gen_random_uuid()::TEXT,
    org_id           TEXT NOT NULL,
    space_ref        TEXT NOT NULL,            -- opaque Application SpaceRef, written only from a verified decision
    state            TEXT NOT NULL DEFAULT 'active',
    head_version_id  TEXT,                     -- no FK: avoids a cycle; kept consistent inside the write transaction
    head_version_no  INTEGER NOT NULL DEFAULT 0,
    created_by       TEXT NOT NULL,
    created_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT space_canvases_state_chk CHECK (state IN ('active','archived')),
    CONSTRAINT space_canvases_ident_chk CHECK (char_length(btrim(space_ref)) > 0 AND char_length(btrim(org_id)) > 0)
);
-- one active canvas per Space in phase 1; dropping this index is the whole multi-canvas migration
CREATE UNIQUE INDEX IF NOT EXISTS uq_space_canvases_active ON space_canvases (org_id, space_ref) WHERE state = 'active';

CREATE TABLE IF NOT EXISTS space_canvas_versions (
    version_id               TEXT PRIMARY KEY DEFAULT gen_random_uuid()::TEXT,
    canvas_id                TEXT NOT NULL REFERENCES space_canvases(canvas_id) ON DELETE CASCADE,
    org_id                   TEXT NOT NULL,
    version_no               INTEGER NOT NULL,
    parent_version_id        TEXT,                -- the head this version was written over (NULL for version 1)
    content                  TEXT NOT NULL,
    content_sha256           TEXT NOT NULL,       -- 'sha256:' + 64 hex, computed by wiki-store
    content_bytes            INTEGER NOT NULL,
    author_kind              TEXT NOT NULL,       -- derived from the decision envelope type
    author_id                TEXT NOT NULL,       -- user: decision subject; agent: 'run:' || run_id
    on_behalf_of             TEXT,                -- the human subject when author_kind = 'agent'
    run_id                   TEXT,
    change_kind              TEXT NOT NULL,
    restored_from_version_id TEXT,
    summary                  TEXT,                -- at most 200 characters, display only
    decision_ref             TEXT NOT NULL,       -- provenance, not authority
    authority_revision       BIGINT NOT NULL,
    audience_revision        BIGINT NOT NULL,
    idempotency_hash         TEXT NOT NULL,       -- sha256 of org, canvas, author, key; never the raw key
    created_at               TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT scv_author_chk CHECK (author_kind IN ('user','agent')),
    CONSTRAINT scv_change_chk CHECK (change_kind IN ('create','edit','restore')),
    CONSTRAINT scv_size_chk   CHECK (content_bytes BETWEEN 0 AND 65536),
    CONSTRAINT scv_agent_chk  CHECK (author_kind = 'user' OR (run_id IS NOT NULL AND on_behalf_of IS NOT NULL)),
    UNIQUE (canvas_id, version_no),
    UNIQUE (canvas_id, idempotency_hash)
);
CREATE INDEX IF NOT EXISTS idx_scv_canvas_created ON space_canvas_versions (canvas_id, created_at DESC);
-- both tables: ENABLE ROW LEVEL SECURITY; policy USING/WITH CHECK org_id = current_setting('app.current_org', true)
-- grants: space_canvases SELECT, INSERT, UPDATE; space_canvas_versions SELECT, INSERT only (append-only by privilege)
```
Both tables carry `org_id` so the simple per-table policy applies and no child-policy migration is needed. The app role cannot update or delete a version; purge runs on the owner pool like `HardPurgeByOrg`. No outbox, no NATS subject, no event with content in phase 1 (V7). The `.down.sql` drops both tables.

Limits (constants in `internal/canvas/limits.go`, NEW): content 1 to 65,536 bytes of valid UTF-8 without NUL (about 16k tokens, so a whole read fits one tool result); request body 128 KiB via `http.MaxBytesReader`; summary 200 characters; list page max 50; writes 60 per hour per author per canvas (429 `canvas_rate_limited`, a count over the `(canvas_id, created_at)` index inside the transaction) and 20 per agent run (`run_id` count, 429 `canvas_run_write_limit`). No server-side coalescing (it would break append-only); retention of old versions is ADR 8 (D-6).

### 3.4 Data Plane: write algorithm (repo `internal/canvas/repo.go`, NEW, on `orgscope.WithOrgScope`)

`Save(ctx, in)`, one transaction:
1. Resolve `(org, space_ref)`: `SELECT canvas_id, head_version_id, head_version_no FROM space_canvases WHERE org_id=$1 AND space_ref=$2 AND state='active' FOR UPDATE`. The row lock is the per-room serialisation (Buzz uses an advisory lock; a row lock is the same guarantee here and also covers the head read).
2. No row: if `expected_version_id` is not null, return `head_moved` with `head: null`. Else `INSERT ... ON CONFLICT DO NOTHING RETURNING`; zero rows (a concurrent creator won) returns `head_moved`.
3. Idempotency: `SELECT version_id, version_no, content_sha256 FROM space_canvas_versions WHERE canvas_id=$1 AND idempotency_hash=$2`. Hit with equal digest: return it with `deduplicated=true`. Hit with a different digest: `idempotency_key_conflict`. Replays never reveal content.
4. CAS: `head_version_id IS DISTINCT FROM expected_version_id` rolls back and returns `head_moved` with head metadata only (version id and number, author kind, time). No version row is written for a rejected save.
5. Unchanged: the new `content_sha256` equals the head's: commit nothing, return `unchanged=true`.
6. Rate limits (above), then `INSERT` the version (`version_no = head_version_no + 1`, `parent_version_id = expected`), then `UPDATE space_canvases SET head_version_id, head_version_no, updated_at`.
`Restore(ctx, in)` is the same transaction with content copied from `restore_from_version_id` (which must belong to this canvas), `change_kind='restore'`, `restored_from_version_id` set. `Head`, `ListVersions(before_version_no, limit)` and `GetVersion` are single scoped reads filtered by `org_id`, `space_ref` and `canvas_id`, so a guessed id from another room returns not found. Purge: `PurgeSpace(org, space_ref)` and `PurgeOrg(org)` on the owner pool.

### 3.5 Data Plane: authority and routes (wiki-store HTTP; `internal/handler/canvas.go`, NEW)

Mounted by a second function `mountCanvasRoutes` beside `mountProtectedRoutes` (`handler/wiki.go:86`), so the existing `wikiRouteHandlers` struct and its test are untouched. All routes sit behind the existing `authctx.Middleware`. Reads require scope `wiki.read`, writes `wiki.write` (existing scopes; the decision is the real gate, see D-7). Responses use `{data}` and errors `{error:{code,message,details}}` (the existing `writeAuthError` shape).

Per-request checks, in order, with typed refusals:
1. Flag `WIKISTORE_SPACE_CANVAS` on, else 404 `space_canvas_disabled`.
2. Bearer verified (existing). Claim `zdr` true: 403 `zdr_persistence_forbidden` on every canvas route.
3. `X-Space-Decision` present (400 `space_decision_required`), at most 16 KiB; envelope `v2.<kid>.<payload>.<sig>` for human operations or `run-action-v1.<...>` for agent operations; Ed25519 verify with the key set (`CONTROL_SPACE_DECISION_PUBLIC_KEYS_JSON` or the id and key pair); unknown key, bad signature, expiry or issue-in-future: 403 `space_decision_invalid`.
4. Claims must satisfy: `org_id == claims.OrgID`; `space_ref ==` the path segment; `subject_id == claims.UserID` (the bearer is the human's token on both paths); `service_audience == "data-plane-canvas"` for human decisions; `action_id` and `action_schema_hash` equal the route's; permission `canvas:read` or `canvas:write`; `zero_data_retention` false; non-empty `recipient_audience_*`, privacy refs and positive revisions. Failure: 403 `space_decision_mismatch`.
5. Digest: recompute the payload digest from the request (op, canvas id, expected version, restore source, `content_digest = sha256(content)` computed here, idempotency key) and the claims; inequality is 403 `space_decision_digest_mismatch`. This binds the bytes Control signed to the bytes stored, so a gateway cannot alter content after issuance. Digest formula: `sha256("data.space_canvas\x00v1\x00")` followed by length-prefixed fields `org_id, user_id, space_id, space_decision_ref, recipient_audience_ref, recipient_audience_hash, privacy_policy_ref, resource_authorization_ref, action_schema_hash, idempotency_key, op, canvas_id, expected_version_id, restore_from_version_id, content_digest`, then `authority_revision` and `recipient_audience_revision` as 8-byte big-endian (the shape of `threadAppendPayloadDigest`, `personal_thread_decision.go:336-359`). The same function is written in Control and in wiki-store; both test files assert one shared golden hex.
6. Author stamping: a `v2.` decision yields `author_kind='user'`, `author_id=subject_id`; a `run-action-v1` decision yields `author_kind='agent'`, `author_id='run:'+run_id`, `on_behalf_of=subject_id`, `run_id`. A request body field can never set these.

## Open questions for the user
