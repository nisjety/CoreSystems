## Design

### D1 Shape and ownership

| Piece | Owner | Why |
|---|---|---|
| Entitlement rows, revisions, history, audit intent, role check, validators | Control, user-core | It already owns the row and the fence |
| BFF routes, shape validation, flag, denial normalisation | Frontend gateway | Holds no state; validates, delegates, proxies |
| Console and denial copy | Frontend SPA | Presentation only |
| Nothing | Application, Model, Data | No change in phase 1 |

Data flow, write: SPA `PUT /api/v1/orgs/{id}/space-policy/entitlements` -> gateway (`require_session`, `require_org_admin`, flag, shape check, v1 delegation signed with the `verevon-gateway` token) -> user-core (`requireSpaceOrgPolicyAdmin`: principal, scope, delegation, canonical role from auth-core, write switch) -> one Postgres transaction (lock row, validate, UPDATE the eight columns only, fence active Spaces, INSERT event, INSERT `user_audit_outbox`) -> existing outbox worker -> `verevon.audit.v2.control.user-core.space_effect_policy_updated` -> audit-core.
Data flow, denial: SPA action -> gateway decision proxy -> user-core issuer -> evidence fails -> `DiagnoseDenial` -> `{error, code, details}` -> gateway `map_control_denial` -> `{error:{code,message,details:{reason,...}}}` -> SPA `presentSpaceDenial`.

All under the existing `internal` group (`server.go:331-382`), after `requireServicePrincipal`. The org is the delegated org only; no org, actor or role field is accepted in any body (same rule as the Space decision routes).

### D4 Control: authority and the write transaction

`requireSpaceOrgPolicyAdmin(write bool)` (new, `internal/http/space_org_policy.go`): (1) `auth_method == service_principal`, `service_id == verevon-gateway`, `delegation_verified`, scope present; (2) `s.orgAdminRole(ctx, userID, orgID)`, defaulting to a wrapper over `resolveMembershipFromAuthCore` (`handlers.go:68`), must return owner or admin: `ErrMembershipNotFound` -> 403, any other error -> 503, never a fallback to the local projection; (3) for writes, `s.spacePolicyAdminWrites` (env `SPACE_POLICY_ADMIN_WRITES`, read once in `NewServer`, never in a handler). A denied write also enqueues an audit event `space_effect_policy_write_denied` (outcome `denied`, reason code, no body). Scopes: add `serviceScopeForRequest` cases for the `org-policy` prefix (GET -> `spaces:policy:admin:read`, else `spaces:policy:admin:write`) and extend `serviceScopeRequiresVerifiedDelegation` (`service_auth.go:179-181`) with `strings.HasPrefix(scope, "spaces:policy:admin:")`. Add both scopes to the `verevon-gateway` entry (`docker-compose.yml:426`). Removing the scopes there is the hard kill switch.

Handlers use a narrow interface `spaceOrgPolicyStore` (pattern of `mailTaskEffectPolicy`, `server.go:62-68`) set in `SetSpaceRepository`, so tests inject a fake.

`ApplyOrgEntitlements(ctx, req)` in one transaction:
1. `SELECT ... FROM space_effect_policies WHERE org_id=$1 FOR UPDATE`; no row -> `ErrNoOrgEffectPolicy`, nothing inserted.
2. Replay check on `(org_id, idempotency_key)`: same `request_digest` returns the recorded result with `replayed:true`; different digest -> `space_policy_idempotency_conflict`.
3. `expected_entitlement_revision` must equal the row's, else conflict.
4. Expand preset or take the map; run `ValidateEntitlementChange(current, target)`; ZDR rules from the catalogue.
5. No change: commit and return `changed:false` (no event, no fence).
6. `UPDATE space_effect_policies SET <8 catalogue columns>, entitlement_revision = entitlement_revision + 1, updated_at = NOW() WHERE org_id=$1`. Privacy columns and `policy_revision` are untouched.
7. Fence: the statement at `repository.go:1302-1312` with `privacyChanged=false, entitlementChanged=true`, factored into `fenceActiveSpaces(ctx, tx, orgID, privacy, entitlement)`; returns `spaces_fenced`.
8. `INSERT INTO space_effect_policy_events`.

### D5 Control: hardening the operator writer (S1)

`upsertSpaceEffectPolicy` (`spaces.go:1359-1378`) decodes into `effectPolicyUpsertRequest`: privacy fields as today and the eight entitlements as `*bool`. An omitted entitlement keeps its current value (a new row defaults false), so no re-run can clear a bit it never mentioned. `UpsertEffectPolicy` gains `actor EffectPolicyActor{Type, ID}` (callers: the handler, passing `service:control-space-policy`, and `thread_read_decision_live_test.go:121`), builds its column lists from the catalogue, and writes an event (`operator_created` or `operator_updated`) plus an outbox row in the same transaction, only on an effective change. The script (`set-space-effect-policy.sh`) gains `--sandbox-capability-entitled` and `--process-registry-entitled`, sends an entitlement key only when its flag is passed, and documents that attestation rows are an operator act. This slice is also WS10's "dev policy admin": seeding any bit, audited, with no raw SQL.

### D6 Control: typed denial vocabulary (S2)

New `internal/spaces/denial.go`: `type Denial struct{Code DenialCode; Entitlement string; RequiredRoles []string; State string; Effect string}` implementing `error` with the current message text unchanged. Every `Validate*` and `Issue*` refusal in `personal_thread_decision.go`, `shared_thread_read_decision.go`, `shared_retrieval_decision.go`, `personal_retrieval_decision.go`, `personal_import_decision.go`, `schedule_create_decision.go`, `watch_decision.go` and `owner_grant_decision.go` returns a `*Denial` wrapped with `%w`, so `errors.As` works and existing `err.Error()` assertions still pass.

**Diagnose on deny, anti-enumeration by construction.** On `ErrNoCurrentMembership` the handler calls `Repository.DiagnoseDenial(ctx, spaceRef, orgID, subjectID, expectKind)`: one read returning flags (`org_member`, `space_kind`, `registration_state`, `space_member`, `has_policy`, `in_audience`), then a pure `classifyDenial(flags)`:
1. not an active org member, or Space not found in this org, or not an active Space member -> `space_membership_required`. These three are indistinguishable on purpose: a non-member never learns whether the Space or the policy exists.
2. member, registration not active -> `space_not_active` (`state`).
3. member, Space kind not served by this decision -> `space_kind_unsupported` (`kind`). This names the personal-only schedule, watch and import gaps honestly.
4. member, no policy row -> `space_policy_not_provisioned`.
5. member, shared Space, not in the current audience -> `space_audience_not_current`.
6. else `space_authority_incomplete`.
Diagnosis only labels a denial the authoritative query already issued; it can never grant.

| `space_not_active` | 403 | `space_manager` | `state` |
| `space_kind_unsupported` | 403 | `none` | `kind` |
| `space_policy_not_provisioned` | 403 | `org_admin` | none |

### D9 Idempotency, ZDR, concurrency

- ZDR: console and routes work for ZDR orgs (configuration, not content); ZDR-inert and unproven bits are refused 422; audit rows carry no content; denial reasons carry no content.
