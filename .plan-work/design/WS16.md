### D2 F-t1-062 locale, copy and dates

**Copy module.** `FV/src/features/spaces/lib/space-copy.ts` (N) holds every status, verb, outcome and fallback as `{no, en}` pairs. Both `activity-grammar.ts` and `threadStatus` (`space-thread-presentation.ts:34-47`) read it, so a status has one wording per language; English follows the existing `threadStatus` words (`Needs approval`, `Working`, `Queued`, `Completed`, `Failed`, `Stopped`), lower-cased inside a sentence.

**Grammar API.** Each of the ten text-producing builders (`activityFromThread` :182, `buildSpaceActivity` :267, `activityFromRun` :319, `activityFromSchedule` :365, `activityFromProcess` :434, `buildSpaceWork` :483, `activityFromOperation` :542, `activityFromAuthority` :592, `activityFromApproval` :665, `buildSpaceRecord` :733) gains a trailing optional `tr: Tr = noTr` (`type Tr = (no: string, en: string) => string`, `noTr = (no) => no`). The default keeps today's output byte-identical, so existing tests pass and the English path is added beside them. Components pass `useI18n().tr` (`SpaceActivityFeed.tsx:59`, `SpaceActivityPanel.tsx:153`, `SpaceWorkPanel.tsx:114`). Raw server tokens stay verbatim (honesty rule); counted words pluralise through `tr`.

**Formatters.** `FV/src/shared/i18n/format.ts` (N), pure:

```ts
export type FormatPrefs = { timeZone?: string; dateFormat?: 'MM/DD/YYYY'|'DD/MM/YYYY'|'YYYY-MM-DD'; timeFormat?: '12h'|'24h' }
export function formatDay(value: string, locale: Locale, prefs?: FormatPrefs): string
export function formatMoment(value: string | undefined, locale: Locale, prefs?: FormatPrefs): string
export function isValidTimeZone(zone: string): boolean
```
The locale default comes from `localeIntl(locale)`. A pref applies only when the server marks it explicit (D3), so the unset `MM/DD/YYYY` default never overrides Norwegian users. An invalid or unset zone falls back to the browser zone; unparseable input returns the raw value (today's behaviour). `dateFormat` is built from `formatToParts` in pattern order; `timeFormat` maps to `hour12`. `formatWhen` and `formatWhenWithTime` take a `{locale, prefs}` formatter from `useFormat()` (D3); call sites `SpaceRoomTimeline.tsx:387`, `SpaceActivityFeed.tsx:99`, `SpaceKnowledgePanel.tsx:170,222`. `SpaceActivityFeed.tsx:66` moves to `tr`.

**Ratchet.** `space-i18n-literals.test.ts` (N) scans non-test sources under `src/features/spaces` for Norwegian characters in string literals that are not arguments of `tr(`, failing above a checked-in baseline (0 after S1). It is the single gate sibling F-t3-066 reuses in CI.

### D3 Server-held preferences: contract and bootstrap

**Control contract v2** (`UC/internal/http/handlers.go`, additive, no migration; storage stays `user_settings` categories `language` and `appearance`):

`GET /api/v1/preferences` response body (still the bare legacy object, gateway pass-through):
```json
{"preferences":{"theme":"auto","language":"nb-NO","timezone":"Europe/Oslo",
  "dateFormat":"DD/MM/YYYY","timeFormat":"24h","compactMode":false,
  "crawlIngestMode":"auto","notifications":{"email":true,"push":true},
  "explicit":{"language":true,"timezone":true,"dateFormat":false,"timeFormat":false,"compactMode":false}}}
```
- `language`: unchanged default `"en-US"` for compatibility (AccountSettingsPage falls back on it); `explicit.language` says whether a row value exists.
- `timezone`: from key `timezone`, else the legacy `region` value only when it is a valid IANA name; otherwise the field is omitted. The `"US"` default is no longer returned (fixes V7). Settings then falls back to `profile.timezone`.
- `dateFormat`, `timeFormat`: `MM/DD/YYYY|DD/MM/YYYY|YYYY-MM-DD` and `12h|24h`; the stored word `auto` means "follow the locale" and reports `explicit` false.
- `compactMode`: boolean.

`PATCH /api/v1/preferences` accepts, in addition, `dateFormat`, `timeFormat` (enum or `auto`), `compactMode` (bool pointer), and now validates `timezone` with `time.LoadLocation` (400 `{"error":"timezone must be an IANA zone name"}`) and `language` against `^[a-z]{2,3}(-[A-Z]{2})?$` (max 10). It writes timezone to key `timezone` and stops writing `region`. Existing users with `region = "Europe/Oslo"` keep working through the legacy read. No data migration, so no migration number is consumed (user-core stays at 029; WS09, WS10, WS03, WS04 and WS12 hold 030 to 038).

Implementation sits in a new pure file `UC/internal/users/preferences.go` (N): `ResolveTimezone(lang map[string]any) (string, bool)`, `NormalizeLanguage`, `ExplicitKeys(rawRow, keys)`, `BuildPreferenceView`. A new `Service.GetSettingsExplicit(ctx, userID, category, defaults)` returns the merged map plus the set of keys present in the stored row (the existing `GetSettings` hides that). `UC/cmd/server/main.go` gains `import _ "time/tzdata"` (U2). Error bodies stay legacy strings; the typed envelope for user-core is WS03's.

Action contract first (`FV/src/shared/actions/action-registry.ts:761-767`): `settingsUpdatePreferencesInput` gains `dateFormat`, `timeFormat`, `compactMode`; the description at :2389 lists them; the dispatcher (`dispatchers.rs:3480`) is unchanged because it forwards the input.

**SPA bootstrap.** New `FV/src/shared/preferences/` (N): `UserPreferencesProvider.tsx`, `preferences-store.ts`, `use-format.ts`, `locale-map.ts`. Mounted in `AppShell.tsx` inside `I18nProvider` and outside `CoreShell`. It runs when the session is authenticated, calls `getPreferences()` once (re-reads on `visibilitychange` after at least 60 s hidden), never blocks render, and is fail-open (an error keeps cache and defaults). `settings-client.ts normalizePreferences` (:177) parses the new fields.

Locale precedence, in order:
1. First paint uses `localStorage['verevon.locale']` as today.
2. After load, `serverLocale = localeFromLanguage(prefs.language)` where `nb*`, `nn*`, `no*` map to `no`, `en*` to `en`, anything else (`fr-FR`, `de-DE`) to undefined (kept untouched on the server).
3. Adopt-once: if `localStorage['verevon.locale.synced.v1']` is absent and a local locale exists, the local value wins: `PATCH {language: 'nb-NO'|'en-US'}`, then set the marker. This stops the first release from flipping people whose old Settings value disagrees with the toggle they use daily.
4. Otherwise, with `explicit.language` and a mapped `serverLocale` different from the current locale: `applyServerLocale(serverLocale)` (new i18n method: sets the signal and cache, no write-through).
5. User toggles (`toggleLocale`/`setLocale` from CoreNavbar and CoreNavbarMore) emit a `source: 'user'` change; the provider PATCHes `language` (debounced 500 ms). A failed PATCH sets `verevon.locale.dirty=1`; at the next boot a dirty local value wins and is retried.
6. `i18n/index.tsx` gains `subscribeLocaleChange(listener)` and `applyServerLocale`; unauthenticated pages (login, onboarding) keep the cache-only behaviour.

Other fields: `theme` stays on the navbar payload path (unchanged). `compactMode` sets `document.documentElement.dataset.density = 'compact' | 'comfortable'` (D5). `timezone`, `dateFormat`, `timeFormat` feed `useFormat()` through `FormatPrefs` when explicit and valid. Settings UI: `AccountSettingsPage.tsx` gets three selects (Density, Date format, Time format), the language select offers only `en-US` and `nb-NO` plus any other stored value as a disabled option, and the timezone select keeps its four zones plus the current value. `SettingsPages.test.tsx:121` (expects `nb-NO`) stays valid.

Source-of-truth rule written into `preferences-store.ts`: `preferences` (user_settings) governs UI formatting; `profile.timezone` (user_profiles, shown to colleagues) is a directory fact and is only a fallback.

### D4 Shared announcer and row narration

`FV/src/shared/a11y/announcer.tsx` (N): `announce(message, {politeness = 'polite', key?, coalesceMs?})`, `<AnnouncerRegions/>` (mounted once in `CoreShell.tsx` after `FeedbackWidget`), `resetAnnouncerForTests()`.
- Two visually hidden regions per politeness (`A`, `B`; `role="status"` polite, `role="alert"` assertive; `aria-atomic`), written alternately with the idle one cleared after 150 ms, so an identical consecutive string still announces (the counter-keyed pair of the Grok Bot reference).
- Polite messages queue (max 5, oldest dropped), at most one per 1.2 s; the same `key` inside `coalesceMs` (default 1500) collapses; three or more become "N new messages in {room}". Assertive bypasses the queue and is reserved for a run that needs approval or a hard failure.
- Text is plain (`stripMarkdownPreview` from `FV/src/shared/lib/markdown-plain-text`), at most 140 characters, no ids, never stored or logged; ZDR needs no special handling because the text is already on screen and lives only in the DOM.
- Per-viewer `verevon.a11y.announce-posts` = `all | mentions | off` (default `all`), via `writeClientValue` inside try/catch.

Narration (`FV/src/features/spaces/lib/space-narration.ts`, N, pure, `tr`-aware): `narrateNewPosts(prev, next, viewerSubjectId, tr)` for turns by other authors (WS01 supplies `authorSubjectId`; before it only agent replies exist), `narrateRunChange` (`awaiting_approval` assertive, `failed` and `completed` polite once), `narrateSidebarMove`. `SpaceRoomTimeline.tsx` calls them from the poll diff and `SpaceApprovalPanel.tsx` announces a newly required approval. Existing page-local regions stay (they announce the viewer's own turn). `ChatPage.tsx:462,765` is not touched (sibling b); its hard-coded `Verevon svarer …` (:533) is reported and its migration to `announce()` left to b.

### D6 Viewer locale on Space turns

**D8.8 Authority at each hop.**
1. Browser to gateway: session cookie, `require_session`; org from `authorized_org_id`, user from the session; forged org or authority headers and body keys are stripped or rejected.
