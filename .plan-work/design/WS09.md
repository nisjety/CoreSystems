### What the audit or the sweep got wrong, or missed (design is against the code)

1. **The audit's slice 1 cannot work as written.** A "Space-read branch in `stream_run_events`" would stream plan, todo, approval, subagent and browser events. A room turn (direct tool loop) emits none of them. Its text deltas and tool steps exist only in model-gateway's owner-keyed stream buffer. The member attach therefore reads that buffer (S3, S4). `stream_run_events` gets no change in WS09 (reserved for WS10 and WS20).
2. **Session Core never writes `runs.status = 'running'` or `'awaiting_approval'`.** Runs are inserted `queued` (`apps/Model Plane/rust/services/session-core/src/grpc.rs:3117`, `apps/Model Plane/rust/services/session-core/src/terminalization.rs:564`) and only updated to a terminal state (`grpc.rs:3465`, `run_service_grpc.rs:814`, `terminalization.rs:1073`). `latest_run_status` is that column (`grpc.rs:5555-5582`). So other members see "Queued" for a whole live turn, and the approval card mount and composer approval block (`apps/Frontend Plane/verevonv3/src/features/spaces/components/SpaceRoomTimeline.tsx:224-226`, `apps/Frontend Plane/verevonv3/src/features/spaces/components/SpacePage.tsx:525-533`) test a status that never occurs. Verified by code search; UNVERIFIED live. S1 adds a derived phase.
3. **Raw frames are owner-private.** The same buffer holds `memory_recall.memories` (`sse.rs:2226-2231`), `tool_call.args` and `tool_result.output` (`apps/Model Plane/rust/services/model-gateway/src/sse_events.rs:157-169`), `grounding`, `reasoning_delta` and `queued_input.messages` (`sse_events.rs:360`). A member stream must be an allowlist projection, never a relay.
4. **Steer is owner-only by construction** (`queued_input.rs:181-186`) and its durable append runs under the caller's bearer (`apps/Model Plane/rust/services/model-gateway/src/session_flow.rs:1607-1636`); Session Core `AppendMessage` is owner-only until WS01 (`authorize_thread_owner(..., Mutate)`, `grpc.rs:4504`). So S2 ships owner steer; member steer needs WS01 plus a policy (S9).
5. **After WS01 a second concurrent reply is lost.** With two user turns and two runs, the first assistant append is allowed (last role user) and the second is refused by the reply slot rule (`grpc.rs:2487-2491`). INF; S1 adds the characterization test. This makes the guard a precondition of enabling member posting, not a nicety.
6. **No new Control audience is needed for WS09.** The existing Space-scoped `model.thread.read` decision already admits runs through threads (`run_service_grpc.rs:711-738`, code comment: reused on purpose). The stream is bounded by the 2 minute decision lifetime and re-verified every 15 s, so the audit's "stream-read audience" is a WS02 push concern, not a run-attach one.
7. **Haiku drifts confirmed**: `step_update` SSE frames carry no `id:` (`sse.rs:7608-7613`); verdict `use-chat-controller.ts:2049` is the plan-approval guard; the Go orchestrator pass-through (`apps/Model Plane/go/services/orchestrator-core/internal/orchestration/handlers.go:162-182`) is unauthorized but irrelevant once the attach avoids it.
8. **Adjacent exposure, not WS09 scope**: assistant message `metadata` (grounding snippets, citations, compaction summaries) is returned verbatim to every room reader (`http_routes.rs:8513-8530`, `apps/Frontend Plane/verevonv3/apps/gateway/src/domains/spaces.rs:2708-2711`). Flag to WS07 and WS17.
9. The owner-stop copy says "Stopped by you" for any server `stopped` frame (`SpaceRoomComposer.tsx:453-457,572-576`), wrong once a manager can stop a run (fixed in S8).

## Design

Assumes ADR 1 option A (Session Core stays the transcript owner; non-owner append arrives with WS01), ADR 2 option B (ids and kinds on the push wire; authority at subscribe and every delivery; no ZDR content cache) and ADR 5 (record the initiating human; delegates re-resolve). The per-run attach below is a content stream, but a per-viewer, re-authorized, uncached request, not the shared push wire.

### Data flow

(US in the key notation below is the ASCII unit separator 0x1f, the separator `scoped_stream_key` already uses.)

```
Owner browser --POST /api/v1/chat/stream--> gateway --> model-gateway invoke_stream_sse
   producer writes raw frames -> StreamBufferStore  mp:gw:stream:{org}US{owner}US{request}   (owner-keyed, unchanged)
   S3: also index_run(org, run_id) -> that key + persona name   mp:gw:streamrun:{org}US{run_id}  (pointer only, same TTL)
Member browser --GET /api/v1/spaces/{ref}/runs/{run}/live--> gateway (membership, lifecycle, ZDR, Control read decision)
   --POST /v1/spaces/{space}/runs/{run}/live {decision}--> model-gateway
        --gRPC AuthorizeRoomRunAttach--> Session Core (decision, audience ceiling, revocation, posture, phase)
        resolve_run(org, run) -> raw buffer key -> RoomProjector (allowlist) -> SSE frames
        every 15 s: AuthorizeRoomRunAttach again with the same token; at decision expiry: reauth_required, close
Finalize: the producer rebuilds the same projection from its own buffer -> messages.metadata.work (content-free), saved with the answer
```

### Authority at each hop (attach)

Browser: cookie session only; no decision and no run owner id on the wire. Gateway: membership and lifecycle, mints the read decision per attach, never caches it. model-gateway: re-verifies bearers; holds the token in memory only for the stream. Session Core: the only verifier (decision, audience ceiling, revocation, posture, ZDR, phase) at subscribe and every 15 s. Revocation latency is the 15 s heartbeat against `space_membership_revocations`, and at most the 2 minute decision lifetime if the NATS event was lost. The raw buffer is never read by this path; only projector output leaves.

## Feature flags and rollout

Mechanism: Model Plane uses a pure-value policy struct read from env once (the `AgenticSubscriptionPolicy` pattern, `apps/Model Plane/rust/services/model-gateway/src/normalize.rs:138-179`), compose `${VAR:-false}` in the base file and `"true"` in the dev override (as `FINETUNE_ENABLED` does); the gateway uses AppState fields from env in `build_state` (never `std::env::var` inside a handler); Session Core uses an explicit atomic set from `main.rs`. Convex env and capability-core `rollout_state` are not extended. Flags are rollout controls, never authorization inputs; the only authorization additions are the Control entitlement and decisions.

|---|---|---|---|---|---|
