## Design

### D1 Model
- **Room file** = a Data `documents` row: `type='space_upload'`, `space_ref=S` (from the signed decision), `owner_id` = uploading user, `visibility='shared'`, `content` = extracted text (at most 5 MiB), `metadata` = imports-core's existing `filename, content_type, size_bytes, sha256, extension, parser` plus `text_chars`, `created_by_kind:'human'`, `upload_id`, `scan_state:'not_scanned_text_only'`. No new table, no original bytes.
- **Audience** = owner plus a Control `resource_grants` row `(document, id, subject_type='space', subject_id=S, role='view')`. It is honoured only inside a Space-scoped read that carries a verified Space retrieval decision, and only for a user who is a current member and current recipient of S. Outside a Space read, `shared` + no user grant means owner-only, so the org-wide library never shows room files to non-owners.
- **Intersection rule** (ADR 2026-08-13): current Space decision (signature, ZDR, entitlement, privacy, audience revision) AND current Control membership/audience join AND owner-plane state (the grant the owner's attach act created, and `documents.space_ref = S` for listing). A Space subject can only narrow or co-require. Service principals never receive Space grants (`resolve_explicit_grants` returns empty for them and `space-visible` requires a verified user bearer), so agents gain nothing through this path. Agent use in room retrieval inherits the asking member's grants and is F-t1-046.
- **Single durable upload path** (conflict O9/11.4): imports-core owns durable uploads; sibling b's durable attachment phase (F-t3-017) adds a `context=chat` variant of the same route family instead of a second path.

### D2 Data flow (durable attach)
```
SPA  POST /api/v1/spaces/{ref}/files (multipart, Idempotency-Key)
GW   session, org, lifecycle, flag, ZDR precheck, body cap
     -> Control POST /internal/spaces/import-decision {space_ref, source_type:"space_upload", idempotency_key}   [gateway delegation]
     -> imports-core POST /api/v1/import/jobs/space-upload  (ingestion bearer, X-Space-Import-Ingress-Decision, raw multipart)
IC   verify decision == caller, typed validation, parse, quota, create job (intent only, no token), 202
     worker per item: Control POST /internal/spaces/import-execution-decision {intent}   [imports-core credential]
     -> documents-api POST /v1/documents (X-Space-Import-Decision)
DA   verify decision; owner=subject; visibility=shared; space_ref; room quota; dedupe; insert
     -> Control POST /internal/spaces/file-grant {decision_token, document_id}   [documents-api credential]
CORE verify own signature + action + audience + expiry; re-resolve membership/entitlement; upsert space grant; publish grants.changed
DA   201 + X-Space-Import-Authority-Accepted: true  (set only after the grant succeeded)
Read SPA -> GW GET /files -> Control retrieval-decision -> RE /v1/knowledge/space-sources (X-Space-Decision)
     RE granted = user grants UNION Control authz/space-visible(S) -> existing SQL
```
Control never writes Data and Data never reads Control tables; Data asks over HTTP with the user's data-plane bearer (existing pattern).

### D5 Control: grants (F-t1-057)
- **Owner-asserted delegation mode** (the reviewed mode the verdict asks for). New middleware `requireOwnerAssertedGrant` in `UC/internal/http/authz_facade.go`, selected by `requireVerifiedAuthzDelegation` for POST/DELETE `/authz/grant` and GET `/authz/grants` only when: service principal verified; delegation v2, `zdr=true`, user proof verified (the user's data-plane bearer, already required for reads); `delegation_operation` in `authz:grant|authz:revoke|authz:grants` matching the method; `delegation_resource_type/id` equal to the body or query selectors; `service_id == authztaxonomy.OwnerService(resource_type)`. The registry is a Go map in the new `authztaxonomy/owner_service.go` (`document -> documents-api`), not a JSON change, so the Rust mirror and lint are untouched. `granted_by` is set from the delegated user, never the body. The owning service must itself prove the actor administers the resource before calling; Control cannot see Data rows. The gateway principal can never pass: it is not an owner service and holds no `authz:*` scope.
- **Role**: Control accepts `view|edit` as today; a per-type `EditEnforced(resource_type)` predicate (false for `document`) turns `edit` into `role_not_supported`. Space-subject rows are `view` only (CHECK).
- **Space subject** (migration `039_resource_grants_space_subject.up.sql`, reserved number; sequencing owner assigns the final):
```sql
ALTER TABLE resource_grants DROP CONSTRAINT IF EXISTS resource_grants_subject_type_chk;
ALTER TABLE resource_grants ADD CONSTRAINT resource_grants_subject_type_chk
  CHECK (subject_type IN ('user','team','space'));
ALTER TABLE resource_grants DROP CONSTRAINT IF EXISTS resource_grants_space_role_chk;
ALTER TABLE resource_grants ADD CONSTRAINT resource_grants_space_role_chk
  CHECK (subject_type <> 'space' OR role = 'view');
```
  `idx_resource_grants_visible` already leads with `subject_id`, so no new index. `AclRepository.Grant` accepts `space` only through `GrantSpaceSubject(ctx, orgID, resourceType, resourceID, spaceRef, grantedBy)`, which requires an active shared Space in that org and `authztaxonomy.SpaceGrantable(resourceType)` (documents only).
- **Read time**: `ListVisibleForSpace(org, type, spaceRef, userID)` = grants with `subject_type='space' AND subject_id=$space` joined to `registered_spaces` (active, kind <> personal, same org), `space_memberships` (active user) and `space_recipient_audience_members` at the current revision. Exposed as R10.
- **Write path for attach**: R9 `file-grant` (decision-proved, because the import flow has no user bearer). Idempotent upsert; publishes `aqencia.controlplane.acl.resource_grants.changed` (`subject_type:"space"`) and an activity row `grant_space_file_access` (pattern: `UC/internal/handlers/document_acl.go:61`).
- **Revocation**: owner delete -> documents-api calls the owner-asserted DELETE; Space deletion revokes `subject_type='space' AND subject_id=S` (hook after `AuthorizeDeletion`, `UC/internal/spaces/repository.go:171`, call site UNVERIFIED); user erasure now also reaches the user's documents because `owner_id` is the real user.
- **Service credentials** (`apps/Control Plane/docker-compose.yml:425`, preflight `scripts/coresystem-cross-plane-preflight.sh:244` pattern): `documents-api` gains `authz:write` and `spaces:file-grant:write`; `documents-api` and `retrieval-engine` need `authz:read` (present state UNVERIFIED, the registry line is long); path `/api/v1/internal/spaces/import-decision` joins the `spaces:issue` case at `service_auth.go:114` and `/file-grant` maps to the new scope.
- **Second writer (V15)**: slice S2 adds a test that no configured gRPC credential holds `GrantDocumentAccess` or `RevokeDocumentAccess` except an explicitly named one, and removes the methods from the allowlist if none needs them.

### D6 Control: shared import decision (F-t1-013, ADR note 8)
`ValidateForSharedImport` (non-personal; role editor/manager/owner; recipient audience present; `ImportWriteEntitled`; `Privacy.ZeroDataRetention` false), `ResolveSharedImportDecisionEvidence` (copy of the shared retrieval resolver at `repository.go:963` selecting `p.import_write_entitled`, resource ref `control:{space}:ingestion-import:{authority_revision}`), `IssueSharedImportDecision` and `IssueSharedImportExecutionDecision`. Same action id `ingestion.import.write`, same schema `sha256:ingestion-import-v1` and same digest function, so imports-core, documents-api and the Go/Python/Rust verifiers need no schema change. Shared Spaces accept only `source_type='space_upload'` (connector imports into rooms stay refused; that is F-t1-036/047 territory). New route `import-decision` dispatches personal versus shared like `issueRetrievalDecision` (`spaces.go:729`); `personal-import-decision` stays for the connector path.

### D7 Ingestion (imports-core)
- New route `POST /api/v1/import/jobs/space-upload` rather than overloading `/upload`: different allow-list, limits and typed errors, and the legacy knowledge upload and its tests stay unchanged. It requires the ingress header (absent -> 403), refuses `zdr` (409 `zdr_persistence_forbidden` kept), validates every file before any parse (typed catalogue), enforces extension allow-list `SPACE_UPLOAD_ALLOWED_TYPES=pdf,docx,xlsx,pptx,txt,md,csv,json`, `SPACE_UPLOAD_MAX_FILES=10`, `SPACE_UPLOAD_MAX_FILE_MB=25`, runs `parse_uploaded_file` (zip budget and parse deadline already in place), rejects empty extracts and over-5-MiB text, then `create_job(source_type="space_upload", space_import_intent=...)`.
- Scan seam: `scan_upload(filename, bytes) -> clean|infected|unscanned` hook, default `unscanned` and recorded as `scan_state` (text-only storage; the hook is where sibling a's F-t2-039 scanner attaches before originals are ever retained).
- Idempotency: migration `005_space_upload_idempotency.sql`:
```sql
CREATE UNIQUE INDEX IF NOT EXISTS uq_import_jobs_space_upload_idem
  ON import_jobs (org_id, user_id, (space_import_intent->>'space_ref'), (space_import_intent->>'idempotency_key'))

```

- Job reads for a Space job require `job.user_id == auth.user_id` (closes the org-wide job-id read, V7). `_store_document` returns the document id and writes it to the item metadata for R2.
- Logs carry job ids, counts and codes only, never file names or text.

### D8 Data
