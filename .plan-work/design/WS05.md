## Design

### D1 Audit read gating (S1, W1, no new plane)
Owner: Control, audit-core, because it owns the rows and already verifies the signed role. The gateway is a second layer, the SPA only presentation.

| Caller (signed role) | `GET /v1/audit` | `GET /v1/usage`, `/v1/usage/summary` |
|---|---|---|
| `owner`, `admin` | whole org, any `user_id` | allowed |
| `member`, `viewer`, any other value | rows with `user_id = claims.UserID` only. `user_id` set to someone else: 403 `audit_scope_denied`. `event=tool_action` with no `user_id`: the redacted org-wide projection below | 403 `audit_scope_denied` (no consumer exists, verified) |

- audit-core `listAudit`: `role := strings.ToLower(strings.TrimSpace(authorization.UserRole))`; `admin := role=="owner"||role=="admin"`. Unknown role is self scope (fail closed). Success meta gains `scope: "org"|"self"|"org_redacted"`.
- Redacted row: `{id, occurred_at, ingested_at, plane, event, outcome, details:{tool, data_category, zdr, phase}}`; `user_id`, `actor_role`, `subject`, `resource_id`, `event_id`, `request_id` are dropped and `details` is whitelisted. Applies only to `event=tool_action`; no other event type is ever exposed org-wide to a non-admin.
- Errors use the typed envelope for the new denial: `{"error":{"code":"audit_scope_denied","message":"...","details":{"scope":"self"}}}`; existing string errors are untouched. Usage routes require `org_id` as today.
- Gateway `domains/audit.rs`: compute `admin = has_authorized_org_role(&user,&["owner","admin"])`; for non-admin a `user_id` other than the caller's id returns 403 `audit_scope_denied` before any upstream call (envelope `error(code,msg)`; WS01 adds `error_with_details`); `limit` clamped 1..=200; `org_id` stays `authorized_org_id` (the `verevonv3-ci.yml:60-72` guard stays green). The actor still carries the canonical role, so audit-core's decision is independent.
- SPA: `RecentSecurityEvents` shows org events only when `hasWorkspaceAdminAccess(session)` (presentation; V2 is the authority) and otherwise the member's own events with the note "Showing your own events". Trust Center unchanged in behaviour.
- Kill switch: audit-core `AUDIT_READ_ROLE_ENFORCEMENT` = `enforce` (default) | `report` (log would-deny with ids, serve as today) | `off` (boot warning). Remove after two releases.
- ZDR: rows are metadata only; ZDR orgs keep audit (security evidence). Nothing here persists content.

### D4 Domain verification (S6, W2, Control: org-core)
org-core owns `organization_domains`, so it owns the proof. Migration `021_org_identity_domains.up.sql` (+ `.down.sql`):
```sql
ALTER TABLE organization_domains
  ADD COLUMN IF NOT EXISTS verification_token TEXT,            -- public DNS challenge value, not a secret
  ADD COLUMN IF NOT EXISTS verification_expires_at TIMESTAMPTZ,
  ADD COLUMN IF NOT EXISTS last_check_at TIMESTAMPTZ,
  ADD COLUMN IF NOT EXISTS last_check_reason TEXT,
  ADD COLUMN IF NOT EXISTS revoked_at TIMESTAMPTZ,
  ADD COLUMN IF NOT EXISTS revoked_by TEXT;
ALTER TABLE organization_domains DROP CONSTRAINT IF EXISTS organization_domain_method_check;
ALTER TABLE organization_domains ADD CONSTRAINT organization_domain_method_check
  CHECK (verification_method IS NULL OR verification_method IN ('dns_txt','operator'));
-- organization_identity_audit_outbox: same columns, retry state and indexes as organization_gdpr_audit_outbox (017),
-- subject CHECK (subject LIKE 'verevon.audit.v2.control.org-core.%'), INSERT granted to the app role.
CREATE TABLE IF NOT EXISTS organization_sso_policy (             -- section D5
  org_id TEXT PRIMARY KEY REFERENCES organizations(id) ON DELETE CASCADE,
  mode TEXT NOT NULL DEFAULT 'off' CHECK (mode IN ('off','report','enforce')),
  break_glass_user_ids TEXT[] NOT NULL DEFAULT '{}' CHECK (cardinality(break_glass_user_ids) <= 2),
  revision BIGINT NOT NULL DEFAULT 1, updated_by TEXT, updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW());
```
The existing partial unique index `organization_domains_one_verified_owner` is the claim arbiter. RLS and grants copy 011. The outbox insert is an app-role INSERT (unlike the erasure outbox) because it is written in the same transaction as the change.

Verification: DNS TXT at `_verevon-challenge.<domain>` equal to `verevon-site-verification=<token>` (token 24 random bytes base64url, expiry 7 days). org-core resolves with `net.Resolver{PreferGo:true}`, 4 s timeout, resolvers from `ORG_DOMAIN_DNS_RESOLVERS` (default system); constant-time compare; no HTTP fetch, so no SSRF surface. A Brreg match or website URL is never proof (the table comment already says so). The domain is validated: FQDN, at most 253 bytes, NFC lower-case punycode, no IP literal, not a public suffix (`golang.org/x/net/publicsuffix`; x/net is an indirect dependency today, `go.mod:56`), not in `blockedAutoInviteDomains`.

|---|---|---|---|
| `GET /orgs/{id}/domains` | owner/admin | `{data:{domains:[{domain,status,verification_method,verified_at,auto_invite_enabled,challenge?:{type:"dns_txt",name,value,expires_at}}]}}` | 403 `identity_admin_required`, 503 |

Authority chain: SPA -> gateway (`require_session`, `has_authorized_org_role(owner|admin)`, flag) -> org-core with the v3 delegation under a new scope `org:identity:admin:self` -> org-core re-checks the signed role (owner/admin) and `requireActiveMembership` (`membership_guard.go`), never the platform role (unlike `authorizeOrgErasure`, which admits platform admins; identity admin must not). Auto-invite and auto-join are NOT built; `auto_invite_enabled` stays false and read-only.

### D5 SSO policy, provider admin and enforcement (S7, W2, org-core + auth-core)
Data: `organization_sso_policy` above. Modes: `off`, `report` (would-block is audited, nothing blocked: the safe rehearsal, mirrors the shadow/enforce pattern the audit cites for Buzz), `enforce`.

| Route (gateway `/api/v1/orgs/{id}/sso/...`) | Behaviour | Errors |
|---|---|---|
| `GET policy` -> `{data:{mode,revision,domains,break_glass_user_ids,providers:[{provider_id,domain,issuer,type,domain_verified}],can_enforce:{ok,reasons[]}}}` | owner/admin | 403 |
| `PUT policy` `{mode, break_glass_user_ids, expected_revision}` | `enforce` requires: one verified domain, one provider on a verified domain, the caller completed an SSO sign-in through that provider in the last 24 h (proof recorded by auth-core, below), every break-glass id is an active `owner` with two-factor enabled | 409 `policy_revision_conflict`; 422 `no_verified_domain`, `no_provider`, `sso_not_proven`, `break_glass_invalid`, `break_glass_requires_2fa` |
| `POST providers` `{provider_id, domain, type:"oidc", issuer, client_id, client_secret}` | domain must be verified for this org; org-core calls auth-core `POST /api/v1/internal/sso/providers` (dedicated credential `ORG_CORE_IDENTITY_SERVICE_TOKEN`, pattern `org-group-grant.controller.ts`); secret is write-only | 422 `domain_not_verified`, 409 `provider_exists`, 400 `invalid_issuer` |
| `DELETE providers/{provider_id}` | refused for the last provider of an enforced domain | 409 `last_provider_enforced` |

auth-core (migration `029_sso_enforcement.sql` NEW): `sso_signin_evidence(user_id, organization_id, provider_id, signed_in_at)` written from `databaseHooks.session.create.after` on SSO paths; no profile attributes stored. Enforcement hook in `databaseHooks.session.create.before(session, context)` (signature verified, `init-options.d.mts:1186`; fires for every session path per `sole-org-auto-activation.ts` header): classify `context?.path`; SSO paths are `/sso/callback`, `/sso/callback/:id`, `/sso/saml2/callback/:id`, `/sso/saml2/sp/acs/:id` (verified endpoint list); everything else (email, social callback, passkey, admin impersonation) is non-SSO. Look up the user's email domain, ask org-core `GET /internal/orgs/by-domain/{domain}/sso-policy` (new scope `org:domain:read:any` for the existing `auth-core` principal; 60 s positive cache): if `enforce` and the path is non-SSO and the user is not break-glass, throw `APIError('FORBIDDEN',{code:'SSO_REQUIRED'})`; `report` emits `sso.enforcement.would_block` instead. A break-glass password sign-in emits `sso.break_glass_signin` (audit-core). org-core unreachable: SSO paths proceed, non-SSO paths fail closed with 503 `sso_policy_unavailable` (precedent: token mint already fails closed when org-core is down, `service_auth.go:199-203` comment). A global ceiling env `SSO_ENFORCEMENT` (`off|report|enforce`, default `report`) is the platform kill switch for lockout incidents. The gateway `sign_in` maps `SSO_REQUIRED` to 403 `sso_required` with `details:{domain}`; the SPA then offers the existing `/api/v1/auth/sso/initiate?email=`.

Hardening in the same slice: auth.ts sets `disabledPaths: ['/sso/register','/sso/update-provider','/sso/delete-provider','/sso/request-domain-verification','/sso/verify-domain']` (option exists, `init-options.d.mts:1396`, unused today) so providers are only registrable through the org-core path that proves the domain; the internal controller registers with the plugin's validators if `auth.api.registerSSOProvider` accepts a service context, else a direct insert using the same schema (UNVERIFIED). When enforcement flips to `enforce` an auth-core internal route revokes existing sessions of covered non-exempt users in resumable batches (`listSessions` then `deleteSessions`); without it a covered user keeps a non-SSO session up to `SESSION_EXPIRES_IN` (7 days).

### D6 SCIM Users in org-core (S8, W2)
Host: org-core (the audit's choice; it owns org config, domains, entitlements and audit outbox) with the actual membership mutation done by auth-core (V7). Public edge: a stateless gateway route group `domains/scim.rs` (NEW, no session, bearer forwarded opaquely, 64 KiB body cap, no client org header trusted) -> org-core `/internal/scim/v2/*` under a separate principal `verevon-scim-edge` with scope `org:scim:any` (the gateway principal may not hold `:any`, `service_auth.go:144`). The org comes from the token, never from a header.

Migration `022_org_scim.up.sql`:

Only identity keys are stored; `displayName` and other profile attributes are neither stored nor applied (profile data belongs to auth-core/user-core; this also keeps ZDR and minimisation simple). Token mgmt (gateway `/api/v1/orgs/{id}/scim/...`, owner/admin, `org:identity:admin:self`): `POST tokens {name, expires_in_days 1..365}` -> 201 `{data:{token:{id,name,prefix,expires_at},bearer_token:"scim_<43 chars>"}}` (shown once, max 3 active; needs one verified domain and plan entitlement `sso`, plan coverage UNVERIFIED); `GET tokens`; `DELETE tokens/{id}`; `GET scim/status`. Events `org.scim.token.created|revoked`.

Supported SCIM surface (`application/scim+json`, errors per RFC 7644 section 3.12): `GET /ServiceProviderConfig` (patch true, filter true max 100, bulk/sort/etag/changePassword false), `GET /ResourceTypes`, `GET /Schemas`, `GET /Users` (filters `userName eq` and `externalId eq` only, `count` at most 100), `GET|PUT|PATCH|DELETE /Users/{id}`, `POST /Users`. `/Groups` returns 501.

| `POST /Users {userName, externalId?, active?}` | 400 `invalidValue` unless `userName` is an email whose domain is **verified for this org**; 409 `uniqueness` if the pair exists; org-core calls auth-core `POST /api/v1/internal/scim/memberships/provision` `{operationId, organizationId, email, externalId}`: find or create the user (no password, SSO-only), add member with role **`member` always** (any `roles` or `groups` attribute is ignored; SCIM can never grant admin); `active:false` stores the record without a membership. 201 with `Location` |

Operation ids: org-core derives a UUID from `(org_id, scim_id, target_active, revision)` and passes it as auth-core's `operation_id` (PK on `organization_membership_mutation_operation`), so a retried PATCH cannot double-apply. ### D7 Deprovision propagation (S9)
After the auth-core commit the existing outbox emits `auth.organization.member_removed` and `aqencia.controlplane.org.member_removed` (`auth-event.publisher.ts:738,742`), consumed by user-core (`event_handler.go:712-728`, status `removed`), Convex (`nats.ts:631`) and Session Core (`space.membership_changed`). Immediate effects: gateway live membership fails closed (403 `organization_membership_required`); plane-token mint fails; Space decisions fail once user-core applies the event, because every evidence resolver joins `user_org_memberships.status='active'`. Residual windows, stated honestly: plain-NATS event lag until WS04-S10 makes membership events durable; Space decisions already issued live up to their 2-minute expiry; in-flight runs end when Session Core consumes the revocation. This slice adds a propagation probe (a test that removes a member and asserts every consumer within 30 s) and a per-issuer test that each effect-bound decision route refuses a user whose `user_org_memberships.status='removed'`. The agent cascade is NOT built: Control holds no agent-to-owner link (ADR 4), so personal and room agents owned by a deprovisioned person are only stopped indirectly by their owner's failed re-authorization.

### D8 Space decision events (S5, W2, user-core)
Reuse `user_audit_outbox` through the seam WS03-S1 creates. Subjects `verevon.audit.v2.control.user-core.space_decision_denied` and `...space_decision_issued`; payload is `events.AuditEvent` (`plane:"control"`, `producer:"user-core"`, `user_id` subject, `resource_id` space_ref, `outcome` `denied|ok`); `event_id = "space-decision:<decision_ref>"` for issued events and `"space-denial:<sha256(route|org|subject|space|minute)>"` for denials so retries collapse. `details` holds `{decision_kind, action_id, service_audience, authority_revision, expires_at, zero_data_retention, reason?}` and never the token, `payload_digest`, `nonce`, content or recipient lists. Volume rule (audit: persisting every decision is high volume): emit denials for all issuer routes, and issued events only for effect-bound kinds: import, schedule-create, schedule-fire, watch-create, owner-grant, sandbox-capability, run-action, scheduled-run and scheduled-step. Never for thread-read, retrieval or append (the transcript is the record). `reason` stays empty until WS03 typed denial codes exist. Agent invocations stay the sibling-b `tool_action` stream (content-free, `audit_publisher.rs:298-332`); WS05 adds nothing to Session Core.
