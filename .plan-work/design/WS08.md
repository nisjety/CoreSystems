## Design

### D1 Vocabulary
- **Mention record**: `(message_id, subject_id, kind user|agent, source typed|locked, ordinal)` stored by Session Core beside a `post_kind='post'` message. Mentions exist only on human posts. Agent output never carries them, so agents cannot wake agents (loop-proof by construction).
- **Wake**: starting one agent run from a stored post. One wake = one run = one `(post, agent)`. Wakes of one post run sequentially in `ordinal` order inside the thread (the run slot, V7, allows it). Cap: 3 agents and 20 people per post.
- **`turn_origin`**: `direct | ambient | automation`, Control-signed, stored on `runs`. Phase 1 issues only `direct`; `ambient` and `automation` are rejected by Control until their slices exist. NULL on legacy runs means `direct` (WS10 reads it that way).
- **Wake rights** (`respond_to`): who may wake this binding. `members` (default, equals today), `managers`, `allowlist`. Managers and owners can always wake. `blocked` stays the "nobody" switch.

### D2 Data flow
```
Post with mentions
 SPA POST /api/v1/spaces/{ref}/threads[/{tid}/messages]  (WS01 R1/R2 + body.mentions)
  -> BFF: roster + binding validation, policy evaluation, visible-text check -> Control thread decision (WS01)
  -> model-gateway POST /v1/threads[/{tid}/messages] (+ mentions)
  -> Session Core AppendMessage: message row + message_mentions rows in one tx
  <- 201 {message_id, mentions:{recorded[], rejected[]}}      (per agent: expected | refused+code)
  -> model-gateway after commit: content-free mention.received per person (S7)

Wake (once per expected agent, sequential, driven by the poster's SPA)
 SPA POST /api/v1/chat/stream  {space_ref, thread_id, content, mentioned_agent_ref, wake:{message_id, client_wake_id}}
  -> BFF injectors: persona + policy (+respond_to with invoker role) -> Control run-wake-decision (signed, origin direct)
  -> model-gateway /v1/invoke/stream: wake_context, digest check, NO append, start_managed_run{wake}
  -> Session Core: verify decision, owner gate, trigger is the caller's own post with the bound digest,
     run row {turn_origin, trigger_message_id, agent_subject_id}; reply slot honours the mention count
  -> run streams as today; assistant row stores agent_name
```
The legacy path (`mentioned_agent_ref` without `wake`) is unchanged and remains the route for "Ask Verevon", skills, ZDR callers and flag-off.

### D5 Session Core (`apps/Model Plane/rust/services/session-core`)
**Migration** (provisional number 0048; the sequencing owner assigns, three designs claim 0046) with revert file:
```sql
CREATE TABLE IF NOT EXISTS message_mentions (
  org_id TEXT NOT NULL, message_id TEXT NOT NULL REFERENCES messages(id) ON DELETE CASCADE,
  thread_id TEXT NOT NULL, space_id TEXT NOT NULL, subject_id TEXT NOT NULL,
```
