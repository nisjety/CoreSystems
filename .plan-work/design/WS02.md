## Design

### 3.1 Architecture and data flow

```
Session Core Postgres: messages / runs / threads writers (any code path, same tx)
   | deferred constraint triggers (fire at COMMIT, head lock taken last)
   v
space_event_heads (per-Space counter) + space_event_log (ids and kinds only) -- pg_notify('space_events') at commit
   v                                                    (listener task per replica -> tokio watch per Space)
SpaceEvents.StreamSpaceEvents (gRPC, Session Core)  <- verifies Control decision (aud model-plane-space-stream), per-delivery gate
   v
model-gateway  GET /v1/spaces/:space_id/events (SSE)  <- user bearer, decision in headers
   v
BFF gateway    GET /api/v1/spaces/{space_ref}/events  <- session, org membership, mints decision, caps, frame validator
   v
SPA space-stream.ts -> debounced refetch of the existing projections (no bodies on the wire)
```

Why this shape: Session Core is the only plane that sees a post or run change and already owns the verifier, the erasure paths and the revocation table. A durable log plus a wake makes lag and lost NOTIFYs harmless: the stream always reads rows by cursor, the wake only removes latency. Authority is enforced at the data owner, so the BFF stays a validating relay with no durable Space state and no bodies (ADR 2). Heavier alternatives (NATS fan-out plus a Convex projection) add two brokers, a new gateway principal and a second durable copy; they stay available as reserved slice S7.

### 3.2 Event model (assumes ADR 2 option B)

SSE events on the wire (browser side; model-gateway emits the same):

| SSE event | data JSON (v1) | id line |
|---|---|---|
| `connected` | `{"v":1,"space_id","generation","head","resumed","lease_seconds","heartbeat_seconds","mode":"live\|poll_only"}` | `<generation>.<cursor>` (the position the stream starts from) |
| `space_event` | `{"v":1,"source":"session","space_id","generation","seq","kind","at","actor":{"type":"user\|agent\|system","id"?},"refs":{...}}` | `<generation>.<seq>` |
| `heartbeat` | `{"head","generation"}` every 10 s | `<generation>.<cursor>`: the highest seq the stream has fully processed, which is not `head` when rows are still queued |
| `cursor_too_old` | `{"reason":"retention\|generation_changed\|ahead_of_head","head","generation"}` | none |
| `closing` | `{"code","reconnect","retry_after_ms"}` | `<generation>.<cursor>` |
| `error` | `{"error":{"code","message","details"}}` (only after the head is committed) | none |

Cursor is the opaque string `<generation>.<seq>`; the `source` field and a future grammar `s:<gen>.<seq>;a:<gen>.<seq>` leave room for an Application-owned second source (reactions, roster, presence) merged at the BFF. Every frame that moves the position carries it in the SSE `id` line, so an idle room still gives the client a safe resume point and a lease renewal is a true resume, not a new first connect. Seq is strictly contiguous per generation: rows that cannot be shown to a subscriber are sent as `{"kind":"hidden"}` stubs and erased rows as `{"kind":"redacted"}`, so the client can enforce `seq == last + 1` (last is the highest of the last event seq and the last cursor id) and treat any hole as a resnapshot trigger.

Kind registry v1 (closed; unknown kinds are forwarded only as stubs; registry is the golden `apps/Model Plane/api/contracts/space-events.json`):

| kind | captured from | refs (ids and closed words only) | emitted |
|---|---|---|---|
| `thread.created` | `threads` AFTER INSERT, `space_id` set | `thread_id`, `origin` | S1 |
| `message.appended` | `messages` AFTER INSERT, `space_id` set, role user/assistant/system | `thread_id`, `message_id`, `message_sequence`, `role`; actor = author_subject_id or agent or system | S1 |
| `thread.updated` | `threads` AFTER UPDATE OF presentation_title, presentation_preview, pinned_at, persona_enabled | `thread_id`, `fields` (words `title`, `preview`, `pinned`, `persona`) | S1 |
| `thread.archived` | `threads.archived_at` NULL to NOT NULL | `thread_id` | S1 |
| `thread.deleted` | `threads` AFTER DELETE | `thread_id`; earlier rows of that thread are rewritten to `redacted` | S1 |
| `run.state_changed` | `runs` AFTER INSERT and AFTER UPDATE OF status, `space_id` set, `retention_class` <> zdr | `run_id`, `thread_id`, `agent_id`, `parent_run_id`, `state` (queued, running, awaiting_approval, completed, failed, cancelled, other), `prev` | S1 |
| `hidden`, `redacted` | rewritten or gated rows | none | S1 |
| reserved, not emitted here | approval requested or decided, run step (WS09), roster changed (WS04), binding changed (WS08, WS17), reaction changed and message revised (WS12), typing and presence (ephemeral, WS11) | | later WS |

`state` is the only vocabulary decision: it maps `runs.status` through one function (`space_events::run_state`); when sibling b settles the run-state enum (audit conflict C17) only that function changes. Run step deltas stay on the per-run stream (WS09); the Space stream never carries tokens.

Closing codes: `lease_expired`, `reauthorize`, `slow_consumer`, `server_draining` (S6), `upstream_unavailable` (gateway-emitted when the upstream breaks mid-stream) all with reconnect true; `membership_revoked`, `zdr_poll_only` with reconnect false; `invalid_frame` (gateway-emitted) resnapshots once then backs off. A Space that is deleted or archived simply fails the next decision mint (HTTP 403 `space_stream_forbidden`), so no separate code exists for it.

### 3.3 Session Core data model and capture (S1, reserve migration number 0046; assumes ADR 1 option A)

Migration `0046_space_event_log.sql` (plus `revert/0046_space_event_log.down.sql`), sketch:

```sql
CREATE TABLE space_event_settings (singleton BOOLEAN PRIMARY KEY DEFAULT TRUE CHECK (singleton),
  enabled BOOLEAN NOT NULL DEFAULT FALSE, updated_at TIMESTAMPTZ NOT NULL DEFAULT now());
INSERT INTO space_event_settings DEFAULT VALUES;
CREATE TABLE space_event_heads (org_id TEXT NOT NULL, space_ref TEXT NOT NULL,
  generation BIGINT NOT NULL DEFAULT 1, head_seq BIGINT NOT NULL DEFAULT 0, min_seq BIGINT NOT NULL DEFAULT 1,
  last_event_at TIMESTAMPTZ NOT NULL DEFAULT now(), PRIMARY KEY (org_id, space_ref));
CREATE TABLE space_event_log (org_id TEXT NOT NULL, space_ref TEXT NOT NULL, seq BIGINT NOT NULL,
  generation BIGINT NOT NULL, kind TEXT NOT NULL CHECK (kind ~ '^[a-z_]+(\.[a-z_]+)?$'),
  scope TEXT NOT NULL DEFAULT 'space' CHECK (scope IN ('space')),      -- widened by WS12/WS17 migrations
  actor_type TEXT NOT NULL CHECK (actor_type IN ('user','agent','system')), actor_subject_id TEXT,
  thread_id TEXT, run_id TEXT, message_id TEXT, audience_revision BIGINT,
  retention_class TEXT NOT NULL DEFAULT 'persistent' CHECK (retention_class IN ('persistent','zdr_waived')),
  refs JSONB NOT NULL DEFAULT '{}' CHECK (pg_column_size(refs) <= 512),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(), PRIMARY KEY (org_id, space_ref, seq));
CREATE INDEX space_event_log_thread_idx ON space_event_log (thread_id) WHERE thread_id IS NOT NULL;
CREATE INDEX space_event_log_age_idx ON space_event_log (created_at);
CREATE TABLE space_event_errors (at TIMESTAMPTZ NOT NULL DEFAULT now(), source TEXT NOT NULL, sqlstate TEXT NOT NULL); -- no ids
```

`space_event_emit(org, space, kind, actor_type, actor, thread, run, message, audience_revision, retention_class, refs)` is the single write chokepoint: returns early when `space_event.suppress` is `on` (transaction-local GUC) or `space_event_settings.enabled` is false; rejects refs keys outside the allowlist (`role`, `message_sequence`, `origin`, `fields`, `state`, `prev`, `agent_id`, `parent_run_id`); upserts the head (`INSERT ... ON CONFLICT DO UPDATE SET head_seq = head_seq + 1 RETURNING head_seq, generation`), inserts the row, and calls `pg_notify('space_events', {o,s,q,g})`. Per-table trigger functions (`space_event_from_messages`, `_threads_insert`, `_threads_update`, `_threads_delete`, `_runs_insert`, `_runs_update`) are `CREATE CONSTRAINT TRIGGER ... AFTER ... DEFERRABLE INITIALLY DEFERRED FOR EACH ROW WHEN (space_id IS NOT NULL ...)`; the runs triggers also require `retention_class <> 'zdr'` (needs 0044) and read the run's own stamped `recipient_audience_revision` (`grpc.rs:3114-3126`, `terminalization.rs:561-570`). Each body runs inside `BEGIN ... EXCEPTION WHEN OTHERS THEN INSERT INTO space_event_errors; END` (fail-open: a realtime defect never blocks a post; PL/pgSQL does not catch query cancellation, which is the one case that still aborts the commit). A failure rolls back that row's head increment with it, so the sequence stays contiguous.

Why deferred triggers and not Rust calls at the write sites: (1) they cover all writers present and future without editing the files WS01, WS09, WS12 and WS13 will also edit. Today the production write sites are few: messages only in `append_message_in_tx` (`grpc.rs:2432`, also used by `CompleteDirectRunWithMessage`); Space threads only at `grpc.rs:2207` (reached by `CreateThread` and `PrepareScheduledRunThread`, `4686`; `PrepareUserOwnedThread`, `4804`, never sets a Space); runs at `grpc.rs:3114` and `terminalization.rs:561`; run status at `grpc.rs:3465`, `terminalization.rs:1073`, `run_service_grpc.rs:814`. Every new member-append, revision or run-control path WS01, WS09 and WS12 add would otherwise need its own call; (2) they fire at COMMIT, so the head-row lock is the last lock a transaction takes. Rule to keep: no code path may take the head lock earlier; with this the lock order thread, run, head cannot deadlock against `threads ... FOR UPDATE` (`grpc.rs:2447`, `5957`, `6023`, `6087`); (3) seq order equals commit order per Space, so "rows with seq > cursor" can never skip a row that commits later. Each later WS that adds a kind adds its own trigger function that calls `space_event_emit`; no shared function is ever replaced. If sibling b changes how `messages` rows are inserted (versions or branches), only the messages trigger's WHEN clause changes.

Settings and generation: Session Core calls `space_events::sync_flag(pool, SPACE_REALTIME_EMIT)` right after `store::run_migrations` (`main.rs:70`). Going from disabled to enabled runs `UPDATE space_event_heads SET generation = generation + 1`, so clients that saw an interrupted log resnapshot via `cursor_too_old{generation_changed}`.

Retention and erasure (S1, not deferred): sweeper task every 15 min deletes rows older than `SPACE_EVENT_LOG_RETENTION_DAYS` (default 14) in batches of 5000 and moves `min_seq`. `thread.deleted` trigger rewrites that thread's earlier rows to `redacted` (nulling thread, run, message and actor ids) and inserts the tombstone. `purge_organization_data` (`gdpr.rs:226-440`) first runs `SELECT set_config('space_event.suppress','on',true)` (otherwise the deferred delete triggers would re-create rows after the purge) then deletes `space_event_log` and `space_event_heads` beside the `events` delete (`gdpr.rs:350`). `delete_space_threads` (`grpc.rs:6058`) does the same for its Space inside its transaction. `space_event_forget_subject(org, subject)` is shipped for the future user-erasure path. Assumes ADR 8 option A: the owner plane's own sweeper, no central one; legal hold is not modelled (rows are metadata) and F-t1-051 adds the hold check to this sweeper when it defines one.

### 3.4 Authority (assumes ADR 1 A, ADR 2 B, ADR 5 re-resolve per hop)

Control (S2): add `ThreadReadAudienceSpaceStream = "model-plane-space-stream"` to `threadReadAudiences` (`shared_thread_read_decision.go:41-52`). Same route `POST /api/v1/internal/spaces/thread-read-decision` (`server.go:359`, handler `spaces.go:640-680`), same action `model.thread.read`, schema, permission `thread:read` and digest; only the signed `service_audience` differs. Result: a stream token is refused by `ListThreads` and a read token is refused by the stream (both pinned). For shared rooms `thread_read_entitled` still gates issuance (deny by default, `repository.go:1010-1046`, `personal_thread_decision.go:198-215`; no new bit). Personal Spaces go through the existing own-scheduled fallback (owner only, `spaces.go:652-662`; whether that path checks the entitlement was not read, UNVERIFIED). No Control schema or flag change.

Session Core verifier (S3): `verify_space_stream_decision` generalises `verify_thread_read_space_decision_with_key` (`grpc.rs:1855-1960`) into a function that returns the claims and takes the expected audience; the two existing wrappers stay 3-line callers. It checks signature and key id, `service_audience == "model-plane-space-stream"`, action and schema hash, payload digest, `subject_id == caller.user_id()`, org, space, `thread:read` present and no write permission, privacy completeness, `issued_at` and `expires_at`. It returns `{recipient_audience_revision, issued_at, expires_at, zero_data_retention}`.

Per-delivery gate `gate(row, ctx) -> Deliver | Stub | Close(code)` (pure, unit-tested), applied to every row and at every heartbeat:

| Check | Result |
|---|---|
| `now >= lease_until` (lease = min(decision expiry minus 10 s, 85 to 100 s jittered)) | Close `lease_expired` |
| revocation row for (space, subject) with `revoked_at >= decision.issued_at - 5 s` (`space_membership_revocations`, 2 s shared cache) | Close `membership_revoked` |
| `row.audience_revision > decision ceiling` | Close `reauthorize`; cursor not advanced; gateway mints a new decision (Control returns 403 if the member was removed) |
| `row.scope` not in the known set | Stub `hidden` (fail closed) |
| caller ZDR, or decision `zero_data_retention`, or `retention_class` not allowed | no rows; mode `poll_only` |
| org mismatch | Close `membership_revoked` (cannot occur: every query is org and Space scoped) |

Row visibility inside a shared room equals today's listing rule (`list_threads` ceiling `t.recipient_audience_revision <= decision revision`, `grpc.rs:5583-5590`), so a late joiner sees history exactly as the listing shows it. Worst-case revocation latency: NATS delay plus 10 s with the plain-NATS event, otherwise the 2 min decision lifetime. A strict mode (Control re-check per lease) is S6 and only if the owner sets a tighter SLO.

Each hop re-verifies its own input: browser to BFF (session cookie, live org membership via `authorized_membership`, flag, rate limit, per-user slot cap, org ZDR); BFF to Control (fresh mint per lease; Control resolves active registered Space, active member, current recipient audience, entitlement); model-gateway to Session Core (JWT identity, user principal only, service tokens denied by `authorize_principal_route`, `auth.rs:1367-1401`); Session Core to Postgres (org and Space scoped; stream reads use a small dedicated pool, `SPACE_STREAM_DB_POOL` default 8, so streams cannot starve the 20-connection main pool, `store.rs:20`).

### 3.5 gRPC service in Session Core (S3)

New file `apps/Model Plane/proto/model_plane/v1/space_events.proto`, a separate service hosted on the existing endpoint, as `SessionRetentionService` and `ManagedRunLifecycle` are (`grpc.rs:7343-7362`). This keeps `SessionCore` and its three mocks (`execution-core/.../runtime_loop/agent.rs:5969`, `model-gateway/src/grpc.rs:3517`, `model-gateway/tests/e2e_invoke_chain_test.rs:1169`) untouched.

```proto
service SpaceEvents { rpc StreamSpaceEvents(StreamSpaceEventsRequest) returns (stream SpaceEventFrame); }
message StreamSpaceEventsRequest { string org_id=1; string user_id=2; string space_id=3; string decision_ref=4;
  string decision_token=5; bool resume=6; int64 generation=7; int64 after_seq=8; }
message SpaceEventFrame { oneof frame { SpaceStreamConnected connected=1; SpaceEventRecord event=2;
  SpaceStreamHeartbeat heartbeat=3; SpaceStreamCursorTooOld cursor_too_old=4; SpaceStreamClosing closing=5; } }
// connected, heartbeat and closing also carry int64 cursor (highest fully processed seq); heartbeat carries head.
message SpaceEventRecord { int64 seq=1; int64 generation=2; string kind=3; string at=4; string actor_type=5;
  string actor_id=6; string thread_id=7; string run_id=8; string message_id=9; int64 message_sequence=10;
  string role=11; string agent_id=12; string state=13; string prev_state=14; string origin=15;
  repeated string fields=16; string parent_run_id=17; }
```

Handler algorithm: `identity` and `authorize_operation(session:read)` (ZDR callers pass, it is a read); require a user principal equal to `user_id`; verify the decision; refuse with `RESOURCE_EXHAUSTED` above `SPACE_STREAM_MAX_STREAMS` (default 5000 per replica); read head; subscribe to the per-Space `watch` first, then read the head, then resolve the cursor (`resume=false` means live tail from head; `resume=true` validates generation, `after_seq <= head`, `after_seq + 1 >= min_seq`, else `cursor_too_old`); spawn the stream task. The task sends `connected`, drains once immediately (so a commit between the head read and the first wake is not missed), then loops on {wake from the `watch`, 10 s heartbeat, 30 s floor poll, lease timer}: read up to 200 rows with `seq > after` ordered by seq, run the gate, send, advance. A listener task (`PgListener::connect` on its own connection, not the pool) feeds the `watch` map and wakes every stream after a reconnect. Backpressure: `send` has a 15 s timeout then `closing{slow_consumer}`. Load model: one indexed range read per stream per wake and no database read per heartbeat (the head comes from the `watch`; revocation lookups go through the 2 s shared cache, so idle cost is bounded by distinct Space and member pairs, not by streams). Module files: `src/space_events.rs` (flag sync, listener, sweeper, gate, run_state) and `src/space_stream_grpc.rs` (service, verifier). Registered in `grpc::serve` (`7343`), name added to `HEALTH_SERVICE_NAMES` (`grpc.rs:48`, array becomes 9), proto added to `mp_protos` in `crates/mp-contracts/build.rs:37-57` (the edit is also the Docker fingerprint bust that file documents at `76-94`).

gRPC error mapping used by model-gateway: `UNAUTHENTICATED` to 401 `unauthorized`; `PERMISSION_DENIED` (bad, expired or wrong-audience decision, wrong subject) to 403 `space_stream_forbidden`; `INVALID_ARGUMENT` to 400 `invalid_request`; `RESOURCE_EXHAUSTED` to 503 `space_stream_capacity` with Retry-After; everything else to 503 `space_stream_unavailable`. These are not ZDR refusals, so the typed catalogue is not involved.

### 3.7 BFF route (S4)

New `apps/Frontend Plane/verevonv3/apps/gateway/src/domains/space_stream.rs` (`router(state)` merged at `main.rs:135`, `pub mod space_stream;` in `domains/mod.rs`). Its `SpaceStreamConfig` (flag, subscribe rpm, slot cap) is read once in `router()` and mounted as an `Extension`; tests mount `router_with_config`, so no test touches process env (a handler that read env raced under parallel tests before). The `env_bool` and `dev_flags_allowed` helpers in `config.rs` are private, so the module carries a six-line reader rather than widening them. `GET /api/v1/spaces/{space_ref}/events`, behind `require_session`:

1. Flag `SPACE_REALTIME_STREAM` off: 404 `space_stream_disabled`.
2. `authorized_org_id` empty: 403 `active_membership_required`. Bad `space_ref` or cursor: 400 `invalid_space` or `invalid_cursor`.
3. Subscribe limiter `RateLimiter::from_cache_with_rpm(&state.cache, 30.0)` keyed by org and user (pattern `config.rs:256-259`): 429 `rate_limited` with Retry-After. Per-user concurrent streams capped at 12 per replica: 429 `space_stream_capacity`.
4. `zdr::org_zdr_enabled` (fails closed, `zdr.rs:67`): answer 200 with `connected{mode:"poll_only"}` then `closing{zdr_poll_only, reconnect:false}`.
5. Mint the decision with `service_audience: "model-plane-space-stream"` through `proxy_json` to `{user_core_url}/api/v1/internal/spaces/thread-read-decision` (copy of `spaces.rs:1285-1348` returning `expires_at` too; `spaces.rs` is not edited). Control 403 or 404: 403 `space_stream_forbidden`. Idempotency key `space-stream-<nanos>` (a read, nothing to dedupe).
6. Tokens as `list_space_threads` (`spaces.rs:1152-1180`): `model_token`, `required_session_token`; failure is `delegated_auth_unavailable`.
7. Open upstream through `state.streaming_client`; relay with an incremental SSE parser. Every `space_event` frame is deserialised into a strict struct (unknown fields rejected), `space_id` must equal the path, kind must be in the golden registry, strings capped at 128, `audience_revision` stripped, then re-serialised. A violation drops the frame and sends `closing{invalid_frame}`. Unknown kinds pass only as stubs. The decision and token never reach the browser. No buffer or cache of frames exists in the gateway (no Dragonfly content copy, per ADR 2).
8. Lifecycle check (`space_lifecycle_by_ref`, which lists all org Spaces) is not called: Control's resolver already requires an active registered Space.

Errors use `{"error":{"code","message","details"}}` built locally in this module (the shared helper has no `details`). 502 `invalid_space_decision` and `invalid_model_gateway_response` on contract drift. nginx already suits SSE (`nginx.conf:74-90`: buffering off, 3600 s read timeout, 10 s heartbeats well under any idle timer).

### 3.8 SPA (S5)

New `apps/Frontend Plane/verevonv3/src/features/spaces/lib/space-stream.ts` using `readSseStream` (`sse.ts:29`, `lastEventId` supported): states `idle, connecting, live, degraded, unavailable`; first connect without a cursor, then one listing refetch after `connected{resumed:false}`; the controller keeps the latest `id` of any frame and every later connect sends it as `Last-Event-ID`, so lease renewals resume without a refetch; open timeout 8 s; 30 s silence watchdog on heartbeats; `closing{reconnect:true}` reconnects with 0 to 1 s jitter, errors back off 1 s to 30 s with full jitter, three failures within 10 s go to `degraded`; `404 space_stream_disabled` and `zdr_poll_only` go to `unavailable` for the page session; `403` and `membership_revoked` go to `unavailable` until the next successful 30 s authority recheck, which re-arms one attempt (a failed recheck keeps the page fail-closed as today); visibility, focus and online events resume at least 5 s apart; a hidden tab closes the stream after 30 s. Capture `docker compose ps`, image ids and build times, session-core log lines "migrations applied" and the listener subscribed line.
2. DB: `\d space_event_log`; `SELECT enabled FROM space_event_settings` is true.
3. A and B open the room. Capture HAR: one `GET /api/v1/spaces/{ref}/events` per tab, `text/event-stream`, first frame `connected`, no 6 s `/threads` timer.
4. A sends a Space turn. B's timeline updates within 1.5 s from a frame-triggered refetch. Record the interval between `space_event_log.created_at` and B's refetch. The run chip on B moves through states from `run.state_changed`.
5. Content-free proof: raw SSE capture contains none of A's message text; `SELECT * FROM space_event_log ORDER BY seq DESC LIMIT 20` shows ids and kinds only.
6. Lease renewal: three consecutive leases (about 5 min) with no gap, duplicate or visible flicker; count decision mints (about one per tab per 90 s).
7. Degrade and recover: stop `session-core`; B shows the degraded indicator within 35 s and polls every 6 s; start it; stream resumes by `Last-Event-ID`; a post made during the outage appears.
8. Revocation: remove B from the room through the existing member control. B's stream closes `membership_revoked` within 10 s of the NATS delivery (2 min worst case) and the room fails closed; a new `/events` returns 403.
9. Cross-use: a read token presented to the stream RPC and a stream token presented to `ListThreads` are both denied (grpc-level test run against the live service).
10. ZDR: set the org ZDR posture (org-core `metadata.interactiveRetention.zdr`, see the `zdr.rs` module doc); `connected` shows `poll_only`, SPA polls at 6 s, no rows exist for that org's runs.
11. Erasure: owner deletes a thread; the other tab receives `thread.deleted`; earlier rows of that thread read `redacted`.
12. Kill switch drill: `SPACE_REALTIME_STREAM=false` on the gateway then restart (SPA falls back); `SPACE_REALTIME_EMIT=false` then true (generation bumps, clients resnapshot).
13. Metrics scrape: `mp_session_space_stream_active`, opened and closed totals by reason, frames by kind, emit errors (labels bounded; no space, org, user or thread ids, per the ZDR-safe telemetry rule of sibling a).

Artifacts: screen recording, HAR, SQL output, container logs, command transcript, image ids.

| Other WS change how `messages` or `runs` are written | trigger `WHEN` clauses are the one place to adapt; kind registry golden catches wire changes |
