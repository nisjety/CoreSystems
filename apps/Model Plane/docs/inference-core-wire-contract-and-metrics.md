# inference-core: typed refusals on the wire, and the request counters

Two things a caller or an operator of inference-core can rely on, and how each
is held in place.

## 1. Typed refusals: read the kind, never the sentence

A call that asks for a guarantee no configured provider can honor is refused
before any provider is called. The refusal is a gRPC `FAILED_PRECONDITION`
with a content-free message and a trailer naming the kind:

| `x-mp-provider-error` | Meaning | Raised by |
|---|---|---|
| `zdr_unavailable` | The call requires zero data retention (the token's `zdr` claim, or the request's own `zdr` flag) and no matching deployment has an independently verified ZDR attestation. | `Infer`, `InferStream`, `CreateEmbedding`, and every non-chat modality (`reject_unattested_zdr_modality`) |
| `residency_unavailable` | No matching deployment meets the requested `min_residency` floor, or the embedding region is outside the EU boundary. | `Infer`, `InferStream`, `CreateEmbedding` |
| `tier_unavailable` | No configured provider satisfies the requested `min_privacy_tier`. | `Infer`, `InferStream`, `CreateEmbedding` |

The three kind strings are **frozen**. Callers (the Data Plane client, the
gateway's refusal catalogue) key on the exact strings; a rename is a breaking
change. A new refusal gets a new kind, it never reuses one.

The gRPC code and the message of each refusal are what they were before the
trailer existed, so a caller that has not adopted it behaves as it did. The one
code that changed is `CreateEmbedding`: a ZDR or tier refusal used to fall to
`INTERNAL`, which the embedding clients retry, and is now `FAILED_PRECONDITION`
like every other path (only the residency refusal was typed before). A decoder
must still accept an older server that sends the status without the trailer:
read the kind when it is there, fall back to the code when it is not, and never
match the message text.

Every other failure keeps its own typed kind where it has one (`too_long`,
`rate_limited`, `subscription_*`) and its plain code where it does not.

### The golden

`apps/Model Plane/api/contracts/infer-statuses.json` lists every way a call can
fail on the wire: the source (each `ProviderError` variant, the modality
refusal, the embedding path), the gRPC code, the kind, and any retry timing
trailer. It is **generated by the code under test**, not written by hand.

* Check: `cargo test -p inference-core --lib status_contract` (in
  `apps/Model Plane/rust`). The test fails when the file differs from what the
  code produces, and it fails (never skips) when the file is missing. The
  mapping over `ProviderError` is exhaustive, so a new variant does not compile
  until it is named in the contract.
* Regenerate after an intended change:
  `MP_UPDATE_GOLDEN=1 cargo test -p inference-core --lib status_contract`.
* Then update its pinned sha256 in `scripts/tests/zdr-contract-sync.test.sh`.
  Changing a contract is deliberately two steps; CI
  (`.github/workflows/model-plane-rust-ci.yml`) runs the script, and its
  `--self-test` proves it fails on a tampered golden.
* A consumer vendors a byte-identical copy inside its own build context and
  adds one row to `VENDORED` in the same script, so the copy cannot drift.

## 2. Request counters on `:8082/metrics`

`GET :8082/metrics` is the Prometheus text exposition of the process-global
recorder (`metrics::install_recorder`, installed first thing in `main`; a failed
install aborts the boot instead of leaving the scrape empty). There is no
feature switch: the counters are always on.

| Metric | Labels |
|---|---|
| `inference_requests_total` | `rpc`, `service`, `model`, `provider`, `outcome` |
| `inference_tokens_total` | `service`, `model`, `provider`, `direction` (`input` or `output`) |
| `inference_core_build_info` (gauge, 1) | `version` |

* **`outcome`** is `ok`, the typed kind above (or `too_long`, `rate_limited`,
  `subscription_*`), or the lower-case gRPC code (`invalid_argument`,
  `permission_denied`, `unavailable`, ...). A request refused before any
  provider was called moves its own series (`zdr_unavailable`) and the `ok`
  series does not move. A streamed answer is counted once, when it ends:
  `ok` on its final chunk, `stream_incomplete` when the provider flagged the
  turn so or the stream ended with no final chunk, `cancelled` when the consumer
  dropped it first. A unary call whose caller gives up while the provider is
  still working is `cancelled` as well (the provider may already be spending on
  it); a call is never counted twice.
* **`service`** is the verified service id of a service principal
  (`service:<id>`), the constant `user` for an end-user token, and
  `unauthenticated` when no credential verified. A service refused on scope or
  tenant after its credential verified is still counted under its own id.
* **`model` and `provider`** are what the response names (`model_used`,
  `provider_used`), never the caller-controlled request field. `unknown` when
  the call failed before a provider answered, `none` for a call that serves no
  model (a catalogue read).
* **Tokens** are the provider's reported counts. `input` already includes the
  prompt-cache read and write tokens, so the cache fields are not added again. A
  route that reports no usage (the subscription broker) creates no token series.
  A response the chain answered from its completed-response cache (the response
  carries `provider_timing.response_cache_hit`) reached no provider: it is
  counted as a call (`outcome="ok"`) and adds no tokens, because the tokens it
  still carries were counted when the call that filled the cache was served.
* **No org and no user is ever a label.** Every label derived from data a caller
  can influence goes through a bounded set (64 services, 128 models, 32
  providers, 64 outcomes): a value that is not a plain identifier becomes
  `invalid`, and a new value past the cap becomes `other`.
* `rpc` is the snake-case RPC name (`infer`, `infer_stream`, `create_embedding`,
  `list_models`, `transcribe_speech`, ...). Every RPC is counted by the
  `MeteredCore` decorator around the service (`src/metered.rs`); adding an RPC
  to the proto stops that file compiling until the RPC is delegated there, so
  nothing ships unmetered.

### Reading it

```
# Refusals by kind, per calling service
sum by (service, outcome) (rate(inference_requests_total{outcome=~"zdr_unavailable|residency_unavailable|tier_unavailable"}[5m]))
# Answered calls vs everything else
sum by (service) (rate(inference_requests_total{outcome="ok"}[5m]))
# Tokens per service and model
sum by (service, model, direction) (increase(inference_tokens_total[1h]))
```

### Live proof (free, no provider call)

`node "apps/Model Plane/scripts/smoke-inference-core-metrics.js"` runs all three
steps below and prints OK or FAIL for each (environment:
`INFERENCE_CORE_BEARER`, `INFERENCE_CORE_ORG_ID`, optional
`INFERENCE_CORE_GRPC` / `INFERENCE_CORE_HTTP`; the bearer is never printed).
Exit 0 means every check passed.

1. `GET http://127.0.0.1:18082/metrics` returns the exposition (at least
   `inference_core_build_info`), no longer the 37-byte stub.
2. One `ListModels` with a service bearer: `inference_requests_total` gains
   `rpc="list_models"`, the caller's `service`, `model="none"`, `outcome="ok"`.
3. One `Infer` with `request.zdr=true` and a valid service bearer (the token
   need not carry a ZDR claim: the effective flag is the token's OR the
   request's): the call returns `FAILED_PRECONDITION` with trailer
   `x-mp-provider-error: zdr_unavailable`, and `inference_requests_total` gains
   `outcome="zdr_unavailable"` while the `ok` series does not move. No
   provider is attested, so the refusal is expected until an operator attests
   one (`AZURE_OPENAI_ZDR_*`).

## Where the tests are

* `src/grpc.rs` (`mod tests`): the kind of every refusal, the embedding path,
  and the golden.
* `src/grpc/real_rules_tests.rs`: the metered path under the real rules. A real
  `JwtVerifier` verifies real RS256 tokens, the real `InferenceService` routes
  them through `FallbackChain::from_config` with a real Azure provider (attested
  through the real `ZdrAttestation::validate`, or not attested), and the
  assertions read the rendered Prometheus text and the Azure server's own
  request log (empty when a refusal happens before any provider call).
* `src/metrics.rs`, `src/metered.rs`, `src/http_health.rs`: label bounds, the
  stream tap, and the scrape over a real HTTP round trip.
