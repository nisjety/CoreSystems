# orchestrator-core

Temporal workflow and activity service for the **Model Plane** subsystem of CoreSystem.

---

## Overview

`orchestrator-core` drives multi-step AI run orchestration using [Temporal](https://temporal.io/). It exposes Temporal workflows and activities that coordinate session management, step execution, sandboxing, capabilities, and browser control across the Model Plane microservices.

---

## Architecture

### Proto-based gRPC clients (current)

All inter-service communication uses **buf-generated, typed gRPC proto clients**. The old JSON shim (`internal/rpc/`) has been deleted.

```
go/gen/model_plane/v1/          ← generated by `buf generate`
    sessions.pb.go
    sessions_grpc.pb.go
    execution.pb.go
    execution_grpc.pb.go
    ...

go/services/orchestrator-core/
    cmd/
        activities/
            activities.go       ← typed proto clients; NO JSON shim
        worker/
            main.go
    internal/
        config/
            config.go
        grpcclient/
            clients.go          ← grpcclient.Clients struct wires all proto clients
```

Import alias used throughout activities:

```go
mpv1 "github.com/triodelab/model-plane/gen/go/model_plane/v1"
```

### Deleted shim

`internal/rpc/` (the old `rpc.Invoke`-based JSON-over-HTTP shim) has been **permanently removed**. Do not re-add it.

## Activities

All activities are **fully implemented** with typed gRPC proto clients. There are no phantom stubs.

### Run lifecycle

| Activity | Downstream client | Description |
|---|---|---|
| `StartRunActivity` | `mpv1.NewSessionCoreClient` | Creates a new run session; falls back to local `RunMetadata` on `codes.Unavailable` |
| `ExecuteStepLoopActivity` | `mpv1.NewExecutionCoreClient` | Loops up to `MaxTurns` calling `ExecuteStep`; breaks on `completed` / `awaiting_approval` |
| `CompleteRunActivity` | `natsx.Publisher` | Emits `RUN_COMPLETED` envelope (idempotency key `<runID>:completed`) |
| `FailRunActivity` | `natsx.Publisher` | Emits `RUN_FAILED` envelope (idempotency key `<runID>:failed`) |

### Memory consolidation

| Activity | Downstream client | Description |
|---|---|---|
| `QueryMemoryEntriesActivity` | `mpv1.NewMemoryServiceClient` (letta-bridge) | `SearchMemory` with optional `Since` filter |
| `SummarizeMemoryActivity` | local helper `summarizeMemoryEntries` | Groups by `ThreadID`; truncates each summary to 512 chars |
| `WriteConsolidatedMemoryActivity` | `mpv1.NewMemoryServiceClient` (letta-bridge) | Calls `IndexMemory` per consolidated entry |

### Skill promotion

| Activity | Downstream client | Description |
|---|---|---|
| `ValidateSkillBundleActivity` | `mpv1.NewCapabilityCoreClient` | `ValidateSkillBundle` on signed bundle |
| `RunPromotionGateActivity` | `mpv1.NewCapabilityCoreClient` | `CheckSkillPromotion` gate |
| `UpdateRegistryActivity` | `mpv1.NewCapabilityCoreClient` | `PromoteSkill` to the registry |

### Helpers

- `publishRunEvent(ctx, runID, eventType, payload, suffix)` — builds an `envelope.Envelope` with a UUID `EventID`, schema version `1`, producer `"orchestrator-core"`, idempotency key `<runID>:<suffix>`, validates + encodes, then publishes to `natsx.RunEventSubject(runID)`.
- `summarizeMemoryEntries(entries)` — deterministic local consolidation used by `SummarizeMemoryActivity`.

### Deferred scope (not implemented)

The following activity surfaces are not present in `activities.go` and are deferred to later slices:

- Sandbox allocate/release (sandbox-manager)
- Browser launch/close (browser-broker)
- Direct Letta bridging outside the memory consolidation flow
- Run-metric recording (observability pipeline)

## Proto generation

Generated files live in the `gen` module:

```
go/gen/model_plane/v1/
```

To regenerate after `.proto` changes, run from the repo root (where `buf.gen.yaml` lives):

```bash
buf generate
```

The generated Go module path is:

```
github.com/triodelab/model-plane/gen/go
```

This is declared as a `replace` directive in `orchestrator-core/go.mod` pointing to `../../gen`.

## Building

> **Important**: `go/` is a Go workspace root (contains `go.work`), **not** a Go module. You cannot run `go build` directly from `go/`. Always `cd` into a module directory first.

### Build this service only

```bash
cd "apps/Model Plane/go/services/orchestrator-core"
go build ./...
```

### Build all 9 workspace modules

```bash
BASE="apps/Model Plane/go"
for dir in \
  gen \
  pkg/envelope \
  pkg/idempotency \
  pkg/natsx \
  services/browser-broker \
  services/capability-core \
  services/letta-bridge \
  services/orchestrator-core \
  services/sandbox-manager; do
  echo "=== $dir ===" && (cd "$BASE/$dir" && go build ./...) || { echo "FAILED: $dir"; break; }
done && echo "ALL OK"
```
