# SuperOffice System User Authentication (Server-to-Server)

## ✅ Implementation Complete

Full server-to-server authentication has been implemented using SuperOffice's **System User flow** for non-interactive, back-channel API access.

## 📚 Documentation

- **Official Docs**: https://docs.superoffice.com/en/api/netserver/authentication/online/auth-application/
- **Flow Type**: System User (back-channel)
- **Authentication**: SOTicket (not Bearer token)
- **Ticket Validity**: 6 hours with sliding expiration

## 🎯 What is System User Authentication?

System User authentication enables **true server-to-server communication** without requiring user interaction. It's designed for:

- ✅ Background processes and scheduled jobs
- ✅ Automated data synchronization
- ✅ System integrations without user presence
- ✅ Unlimited API access (not bound by user permissions)
- ✅ Long-running workflows

### Key Differences from OAuth

| Feature | OAuth (Interactive) | System User (Server-to-Server) |
|---------|-------------------|-------------------------------|
| **User Interaction** | Required | Never required |
| **Token Type** | Bearer access_token | SOTicket credential |
| **Validity** | 1 hour (with refresh) | 6 hours (sliding) |
| **Permissions** | User-specific | Unlimited |
| **Use Case** | Interactive apps | Background services |

## 🏗️ Architecture

### Flow Overview

```
1. Initial Setup (One-time)
   ↓
   Admin authorizes app via OAuth
   ↓
   Receive id_token with System User Token claim
   ↓
   Store System User Token securely

2. Server-to-Server Operations (Repeated)
   ↓
   Sign System User Token with private key + timestamp
   ↓
   Exchange signed token for System User Ticket (6hr validity)
   ↓
   Cache ticket (sliding expiration)
   ↓
   Make API calls with SOTicket authorization
   ↓
   Ticket refreshes automatically when expired
```

### Components Implemented

1. **`auth/system_user_handler.py`**
   - Signs System User tokens with RSA private key
   - Exchanges signed tokens for tickets
   - Caches tickets (6-hour validity)
   - Validates JWT responses
   - Manages ticket lifecycle

2. **`clients/socrm_system_user_client.py`**
   - API client using SOTicket authentication
   - Automatic 401 handling
   - All CRUD operations for major entities
   - Health check and diagnostics

3. **`config/settings.py`** (Updated)
   - System User configuration settings
   - Private key and certificate paths
   - Environment variable support

4. **`SYSTEM_USER_EXAMPLES.py`**
   - 5 complete working examples
   - Setup guide
   - Best practices

## 🚀 Quick Start

### 1. Prerequisites

You need:
- ✅ Application registered in [SuperOffice Developer Portal](https://dev.superoffice.com/)
- ✅ Application configured as "Server to Server"
- ✅ System User Token (from id_token during first admin authorization)
- ✅ Partner's private RSA key (`.pem` format)
- ✅ SuperOffice public certificate (for JWT validation)

### 2. Environment Configuration

Add to your `.env` file:

```bash
# SuperOffice System User Authentication
SOCRM_SYSTEM_USER_TOKEN="YourApp-abc123xyz456..."  # From id_token claim
SOCRM_CONTEXT_IDENTIFIER="Cust12345"                # Tenant ID
SOCRM_PRIVATE_KEY_PATH="/path/to/privatekey.pem"   # Your private RSA key
SOCRM_PRIVATE_KEY_PASSWORD="password"               # If key is encrypted (optional)
SOCRM_PUBLIC_CERT_PATH="/path/to/SuperOfficeFederatedLogin.pem"  # SuperOffice public cert

# Existing OAuth settings (still needed for initial authorization)
SOCRM_CLIENT_ID="your_client_id"
SOCRM_CLIENT_SECRET="your_client_secret"
SOCRM_TENANT="sod"  # or "stage" or "online"
```

### 3. Basic Usage

```python
from config.settings import Settings
from auth.system_user_handler import SystemUserHandler
from clients.socrm_system_user_client import SuperOfficeSystemUserClient

# Initialize
settings = Settings()
handler = SystemUserHandler(settings)

# Get ticket (cached automatically for 6 hours)
ticket = handler.get_system_user_ticket(
    system_user_token=settings.system_user_token,
    context_identifier="Cust12345"
)

# Create client with SOTicket authentication
client = SuperOfficeSystemUserClient(ticket, settings)

# Make API calls - unlimited access!
companies = client.get_companies(page=0, page_size=100)
sales = client.get_sales()
persons = client.get_persons()

# Check authentication status
if client.health_check():
    principal = client.get_current_principal()
    print(f"Authenticated as: {principal['FullName']}")
```

## 🔐 Security Requirements

### 1. Obtain Keys and Certificates

#### Your Private Key
- Generated by you during app registration
- Format: PEM-encoded RSA key
- Keep secret and secure
- Used to sign System User tokens

```bash
# Generate private key (if needed)
openssl genrsa -out privatekey.pem 2048

# Or generate with password protection
openssl genrsa -aes256 -out privatekey.pem 2048
```

#### SuperOffice Public Certificate
- Download from SuperOffice:
  - **SOD (Development)**: https://sod.superoffice.com/login/common/sod2stage-superoffice-com.crt
  - **Stage**: https://stage.superoffice.com/login/common/stage-superoffice-com.crt
  - **Production**: https://online.superoffice.com/login/common/online-superoffice-com.crt

- Convert to PEM format:
```bash
openssl x509 -in downloaded.crt -out SuperOfficeFederatedLogin.pem -outform PEM
```

### 2. Extract System User Token (First-Time Setup)

The System User Token is a claim in the `id_token` received during initial OAuth authorization:

```python
import jwt

# After OAuth callback, decode the id_token
decoded = jwt.decode(id_token, options={"verify_signature": False})

# Extract System User Token
system_user_token = decoded.get(
    "http://schemes.superoffice.net/identity/system_user_token"
)
# Example: "YourApp-abc123xyz456..."

# Also extract context identifier (tenant ID)
context_identifier = decoded.get(
    "http://schemes.superoffice.net/identity/ctx"
)
# Example: "Cust12345"

# SAVE THESE! You'll need them for all future System User authentication
```

**Important**: 
- System User Token is constant for each tenant/app combination
- Only obtain during initial setup or when tenant re-authorizes
- Store securely (encrypted database or secure secrets manager)

## 📊 API Usage

### Authentication Headers

System User authentication uses different headers than OAuth:

```
Authorization: SOTicket 7T:abc123xyz456...
SO-AppToken: your_client_secret
Accept: application/json
Content-Type: application/json
```

**Note**: `SO-AppToken` header must contain your OAuth `client_secret`.

### Available Operations

All standard SuperOffice API operations are supported:


## 🔄 Ticket Lifecycle Management

### Automatic Caching

Tickets are automatically cached with 6-hour validity:

```python
handler = SystemUserHandler(settings)

# First call - fetches new ticket
ticket1 = handler.get_system_user_ticket(token, context)

# Subsequent calls - uses cached ticket (no API call)
ticket2 = handler.get_system_user_ticket(token, context)
# ticket1 == ticket2

# After 6 hours - automatically fetches new ticket
ticket3 = handler.get_system_user_ticket(token, context)
# ticket3 will be different
```

### Sliding Expiration

Each time you use the ticket, the 6-hour window resets:

```
T+0:  Get ticket (valid until T+6h)
T+3:  Use ticket in API call (now valid until T+9h)
T+7:  Use ticket again (now valid until T+13h)
```

**Best Practice**: Keep using the same ticket, don't fetch new ones unnecessarily.

### Force Refresh

```python
# Force get a new ticket even if cached one is valid
ticket = handler.get_system_user_ticket(
    token,
    context,
    force_refresh=True
)
```

### Check Ticket Status

```python
status = handler.get_ticket_status(context, token)
print(f"Created: {status['created_at']}")
print(f"Expires: {status['expires_at']}")
print(f"Time remaining: {status['time_remaining_minutes']} minutes")
print(f"Valid: {status['is_valid']}")
```

### Invalidate Cache

```python
# Invalidate specific tenant's tickets
handler.invalidate_ticket("Cust12345")

# Invalidate all tickets
handler.invalidate_ticket()
```

## ⚠️ Error Handling

### 401 Unauthorized (Expired Ticket)

When a ticket expires, the API returns `401 Unauthorized`. Handle this by refreshing the ticket:

```python
from auth.system_user_handler import SystemUserError

def make_api_call_with_retry():
    max_retries = 2
    
    for attempt in range(max_retries):
        try:
            # Get ticket (uses cache if valid)
            ticket = handler.get_system_user_ticket(token, context)
            client = SuperOfficeSystemUserClient(ticket, settings)
            
            # Make API call
            return client.get_companies()
        
        except SystemUserError as e:
            if "expired" in str(e).lower() and attempt < max_retries - 1:
                # Invalidate cache and retry
                handler.invalidate_ticket(context)
                continue
            raise

# Usage
try:
    companies = make_api_call_with_retry()
except SystemUserError as e:
    print(f"Authentication failed: {e}")
```

### Common Errors

| Error | Cause | Solution |
|-------|-------|----------|
| `Private key not loaded` | Missing/invalid private key path | Check `SOCRM_PRIVATE_KEY_PATH` |
| `Token signing failed` | Invalid private key format | Ensure PEM format RSA key |
| `Ticket exchange failed` | Invalid System User Token | Verify token from id_token claim |
| `JWT validation failed` | Missing/invalid public cert | Download correct cert for environment |
| `401 Unauthorized` | Ticket expired | Invalidate cache and retry |

## 🔧 Advanced Configuration

### Custom Ticket Validation

```python
from cryptography.hazmat.primitives import serialization
from cryptography.hazmat.backends import default_backend

# Load custom certificate
with open("custom_cert.pem", "rb") as f:
    public_key = serialization.load_pem_public_key(
        f.read(),
        backend=default_backend()
    )

handler = SystemUserHandler(settings)
handler.public_key = public_key
```

### Multiple Tenants

```python
# Manage tickets for multiple tenants
tenants = {
    "Cust12345": "YourApp-token123...",
    "Cust67890": "YourApp-token456..."

handler = SystemUserHandler(settings)
```

```python
Scheduled sync job using System User authentication.
Run via cron or task scheduler.
"""

from config.settings import Settings
from auth.system_user_handler import SystemUserHandler, SystemUserError
from clients.socrm_system_user_client import SuperOfficeSystemUserClient

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

def sync_superoffice_data():
    """Sync data from SuperOffice to local database."""

    try:

        settings = Settings()
        handler = SystemUserHandler(settings)

            system_user_token=settings.system_user_token,
            context_identifier=settings.context_identifier
        )
        
        # Create client
        client = SuperOfficeSystemUserClient(ticket, settings)
        
        # Verify connection
        if not client.health_check():
            logger.error("Health check failed")
            return False
        
        # Sync companies
        logger.info("Syncing companies...")
        page = 0
        total_companies = 0
        
        while True:

            if not companies:

            save_companies_to_db(companies)

        sales = client.get_sales(page=0, page_size=100)
        save_sales_to_db(sales)
        
        logger.info(f"Sync completed: {total_companies} companies, {len(sales)} sales")
        return True
    
    except SystemUserError as e:
        logger.error(f"Authentication error: {e}")
        return False
    except Exception as e:
        logger.error(f"Sync failed: {e}", exc_info=True)
        return False

    success = sync_superoffice_data()
```
