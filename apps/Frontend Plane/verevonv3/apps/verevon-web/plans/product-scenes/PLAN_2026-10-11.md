# Product scenes 02 and 03: build plan, 2026-10-11

Owner decisions taken on 2026-10-11: route C (real SPA components, fixture-driven, frame-stepped capture), keep the pinned 5-stage loop, Norwegian only, fictional organisation, mocked backend wherever the real one is missing, scenes 02 and 03 only for now. Stage 01 stays a dashboard mock-up, stage 04 becomes a live interactive dashboard (later, on the same runtime), stage 05 stays the composer.

Audit this plan follows: [PRODUCT_CARD_FILMS_AUDIT_2026-10-11.md](../system-audits/PRODUCT_CARD_FILMS_AUDIT_2026-10-11.md).

## 1. Target

Two silent 8.0 s seamless loops, 1280×800 master at 60 fps (captured at 2× and downscaled), h264 + vp9 + poster, each showing the real Verevon chat shell solving one task end to end. Each scene sells a different capability, the way aside.com gives each tile its own feature. Static camera, no device mock-up, 250–450 ms ease-out motion, 8–16 px slides, one cursor move per decision, loop closes on a frame visually equal to the opening frame.

## 3. Architecture

### 3.1 Scene runtime inside the SPA (`src/demo/`)

A development-only runtime that lets the real chat page run with no gateway, no sign-in and a scripted clock. It is compiled in only when `VITE_SCENE_MODE=1`; a production build tree-shakes the whole folder (`import.meta.env` guard at the single entry point in `src/main.tsx`, plus a route guard so `/scene/*` returns the normal 404 in production).

Files:

| File | Purpose |
|---|---|
| `src/demo/scene-runtime.ts` | Installs a `fetch` interceptor for `/api/*`. Answers session, org, thread context, composer settings, knowledge and integrations from fixtures. Streams `/api/v1/chat/invoke` as a server-sent-event body built from the scene's timeline. Everything else returns an empty-but-valid shape so no component shows an error state. |
| `src/demo/scene-timeline.ts` | `type SceneEvent = { at: number; kind: 'sse' \| 'cursor' \| 'hover' \| 'ui'; ... }`. A scheduler built on `setTimeout` only, so it advances under CDP virtual time. Exposes `window.__verevonScene = { id, durationMs, ready: Promise, play() }`. |
| `src/demo/scenes/02-plan.ts` | The scene 02 timeline: composer prefill, send at 1 200 ms, grounding event at 1 450 ms, step events, artifact events, UI events for the right panel, cursor path, hover target selector. |
| `src/demo/scenes/03-undersok.ts` | Scene 03 timeline: wide-research items, run events with one browser observation (a fixture screenshot of a plain log view), artifact diff, approval chip. |
| `src/demo/fixtures/fjordform.ts` | Session user, org, composer settings, knowledge sources, the three grounding documents, the Visma order, the e-mail, the export log text. |
| `src/demo/SceneCursor.tsx` | An in-page cursor overlay (SVG arrow, 20 px, soft shadow) positioned by the timeline with a 350 ms ease-out transition. Screenshots never contain the OS cursor, so the visible cursor is this element. Real hover comes from CDP, not from this overlay. |
| `src/demo/ScenePage.tsx` | Route `/scene/:id`. Mounts the real `ChatPage` inside the real shell with the sidebar collapsed to the icon rail, hides the browser-only chrome that would not be in a product recording (appearance preview, feedback button), waits for `document.fonts.ready` and the first paint, then resolves `ready`. |

The SSE vocabulary is the real one from `src/shared/api/chat-client.ts`: `connected`, `message`, `grounding`, `citation`, `step`, `artifact`, `tool_call`, `tool_result`, `plan_proposed`, `done`. The wide-research and live-run panels consume `run-console-client` events (`subagent_attached`, `subagent_stopped`, `browser_observation_received`, `run_paused_for_approval`); the runtime replays those through the same stream the components already subscribe to. No component is modified to accept fixtures; the fixtures arrive through the transports the components already use.

What is missing in the backend today and is therefore mocked: nothing is required from the backend at all in scene mode. The Visma.net order source, the e-mail source and the browser observation exist as capabilities in the product and are represented by fixture payloads of the real event shapes.

### 3.2 Capture harness (`apps/verevon-web/scripts/capture-scene.mjs`)

1. Starts the SPA on the host with `VITE_SCENE_MODE=1` on a free port (no Docker, no gateway).
2. Launches Playwright Chromium headless, viewport 1280×800, `deviceScaleFactor: 2`, `prefers-reduced-motion: no-preference`, locale `nb-NO`, timezone `Europe/Oslo`, fixed date through `Emulation.setTimezoneOverride` and a fixed `Date` in the runtime so timestamps read «i dag».
3. Opens `/scene/<id>`, awaits `window.__verevonScene.ready`.
4. CDP: `Emulation.setVirtualTimePolicy({ policy: 'pause' })`, then for each of 510 frames (8.5 s at 60 fps, the extra 0.5 s feeds the loop crossfade): `Emulation.setVirtualTimePolicy({ policy: 'advance', budget: 16.6667 })`, await `virtualTimeBudgetExpired`, `Page.captureScreenshot({ format: 'png' })`. Cursor and hover events from the timeline are executed by the harness through `Input.dispatchMouseEvent` at the same virtual timestamps, so `:hover` is genuine.
5. Writes frames to the scratch directory, never into the repository.
6. ffmpeg (already on PATH): downscale to 1280×800 (lanczos), seamless loop by crossfading the last 30 frames over the first 30 (`xfade`), then encode h264 `crf 18, yuv420p, faststart`, vp9 `crf 30`, and the poster from frame 0 as webp.
7. Writes `public/product-scenes/<id>.mp4`, `<id>.webm`, `<id>-poster.webp`, and appends a provenance line (scene id, SPA commit, fixture hash, date) to `public/product-scenes/SOURCES.md`, the same convention `feature-films` use.

Risk and its check: compositor-driven CSS transitions must advance under virtual time. Headless Chromium does this; the first run captures a known 300 ms transition and verifies it spans 18 frames. If it does not, the fallback is a `requestAnimationFrame`/`performance.now` shim in the runtime (the timecut approach), already prepared as a flag.

## 5. Loop closure

The scene ends on the hovered approval button; the opening frame is the resting composer. Closing the loop in-page would need a fake "new chat" transition. Instead the harness renders 8.5 s and the encode crossfades the final 0.5 s into the first 0.5 s. At playback the result panel dissolves into the resting state over 500 ms, inside the brief's 6.5–8.0 s settle window, and frame 480 equals frame 0.

Not in this phase: stage 04 interactive dashboard (reuses `scene-runtime` in interactive mode without a timeline), stage 01 mock-up refresh, production deployment of the SPA route (it never ships).

## 7. Acceptance

- Each film: 8.000 s, 1280×800, 60 fps, silent, h264 and vp9, poster webp, seamless on loop (frame 479 → 0 shows no cut).
- Every visible string Norwegian, every data value from `fjordform.ts`, no real customer, order or person.
- No modification to any chat component; fixtures enter only through `fetch` and the run-event stream.
- `pnpm build` of the SPA contains no `src/demo` code (grep the bundle for `__verevonScene`).
- `prefers-reduced-motion: reduce` shows the poster and never plays.
- Loop frame on the site shows the film at every stage width in the three markers without letterboxing.
