# Interactive demo, stage 04 of the product loop: build plan (2026-10-11)

Owner request: stage 04 of the verevon.com loop becomes an interactive dashboard
that looks like the real product (localhost:5173) and lets a visitor solve a
case live. Stages 02 and 03 are the films (done). This plan merges the five
design reports in `scratchpad/reports/` (engine-0, ux-1, home-data-2,
build-hosting-3, site-4). Where this plan and a report disagree, THIS PLAN WINS.
The reports remain the detailed source for file contents, strings and edge cases.

SPA root: `C:/dev/CoresSystem/apps/Frontend Plane/verevonv3` ("SPA").
Site root: `SPA/apps/verevon-web` ("WEB"). Branch work later lands on
`feat/product-scene-films-02-03` through an isolated worktree. Nothing is pushed.

## What the visitor gets

The real Solid SPA, built as a separate trimmed static bundle (`/product-demo/`),
embedded in the pinned loop at stage 04 inside an iframe. It opens on the real
`/dashboard` home of the fictional Fjordform AS (greeting, weather, news, traffic,
"Fortsett der du slapp", prompt suggestions, docked composer) and the real
`/chat`. The suggestions are fictional case prompts (Bring delay, invoice 20471,
return 4821). Sending one runs the real chat UI against a scripted scenario
engine: streaming answer, sources, steps, an approval gate, Godkjenn that
completes. Free text gets an honest, clearly labelled fallback («Dette er en demo
med forhåndsdefinerte svar»). Never present a canned answer as a live AI.

## Hard rules (every builder)

* Norwegian bokmål in every visitor-visible string. Code, comments and tests in English.
* Fictional world only: Fjordform AS, Ida Berg, Nordlys Handel AS, ordre 4821,
  faktura 20471, Bring delay. E-mails only `@fjordform.example`. No Ima, Aquatiq,
  Velion, no real names, no real domains, no real tracking numbers.
* Nothing the visitor types may leave the page. The bundle makes zero requests to
  any origin other than its own static assets; every `/api/*` is answered in
  memory. No third-party fonts, favicons, images, maps or analytics.
* Storage in the iframe is in-memory only (opaque origin has none anyway).
* Do NOT reset, stash, checkout or overwrite other sessions' uncommitted files.
  Protected (read-only) list: `src/features/chat/components/{ChatMessages,ChatPage,
  chat-normalizers,chat-types,use-chat-controller,ScheduleDialog}.tsx|ts`,
  `src/features/chat/lib/prompt-suggestions*`, `src/features/agents/**`,
  `src/features/spaces/**`, `src/features/core/components/CoreSidebar.tsx`,
  `src/features/core/components/sidebar/ChatSidebarOrganizer.tsx|chat-sidebar-organizer.css`,
  `src/features/dashboard/home/DashboardComposer.tsx`, `src/shared/api/{chat-client,
  http,sse,notifications-client}.ts`, `src/shared/i18n/errors.ts`, `src/styles/global.css`,
  `src/index.tsx`, `src/app/App.tsx`, `src/vite-env.d.ts`, `.github/**`, `.gitleaks.toml`
  (only the hosting builder may append to `.gitleaks.toml` and the CI workflow it
  owns, by Edit, never by rewriting).
* Never touch scene mode: films must stay frame-identical. `src/demo/install.ts`
  gets only the additive responder hook described below; `pnpm test` for the
  existing demo tests must keep passing.
* The production SPA build must stay free of demo code (no `src/demo` strings in
  `dist` of the normal build).
* Use Write/Edit for any file with backslashes or backticks. Never `git add`,
  commit, reset, stash. Tests: `pnpm exec vitest run <files>`; type-check with
  `pnpm exec tsc -b` only at the end of a unit (other sessions have in-flight
  edits, so unrelated type errors in protected files are not yours; say so).

## Resolved decisions (conflicts between the reports)

1. **Clock**: fixed fictional clock Fri 2026-10-09 12:00 Europe/Oslo that then
   advances with `performance.now()`. Shared module `src/demo/clock.ts` (done:
   `installFixedClock(iso)`), constant `DEMO_NOW_ISO` in `src/demo/live/shared-types.ts`.
2. **Router/entry**: a dedicated demo entry. `src/demo/product-demo/main.tsx` installs
   guard → clock → fetch interceptor → live engine, then renders `DemoApp.tsx`
   (its own `createRouter` with `memoryHistory`, `base` unset, allowlisted routes only:
   `/dashboard`, `/chat`, `/chat/:threadId`, plus a calm «Ikke tilgjengelig i demoen»
   page for everything else). `src/index.tsx` and `src/app/App.tsx` stay untouched.
   The demo wraps the real page components and the real shell (`CoreLayout`/sidebar/
   navbar) exactly as the real routes do; the builder reads `src/app/App.tsx` and
   mirrors only the dashboard + chat routes.
3. **Iframe sandbox**: `sandbox="allow-scripts"` (opaque origin, no same-origin, no
   forms, no popups, no top navigation, no downloads). Host verifies
   `event.source === iframe.contentWindow` and the `{source:'verevon-demo',v:1}`
   envelope (types in `shared-types.ts`). Demo assets are served with
   `Access-Control-Allow-Origin: *` (module scripts and fonts from an opaque
   origin are CORS fetches). In-iframe `localStorage`/`sessionStorage`/IndexedDB/
   `document.cookie`/`navigator.geolocation`/`navigator.clipboard`/`window.open`
   are replaced by safe in-memory stubs by `guard.ts` before any app code runs.
   `scrollIntoView` and `focus()` are patched not to scroll the parent (iframe has
   its own scroll root, so this is a safety net only).
4. **Home liveness**: fixtures-driven (`fjordform-home.ts`): weather Oslo, four
   fictional news items, synthetic traffic labelled `Demodata`, navbar
   notifications/messages/calendar, Ctrl+K knowledge results, runs/schedules,
   org «Fjordform AS». Honest labels: a persistent «Demo · fiktive data» ribbon
   (outside the real UI, in `DemoApp`), no pretence of live data.
5. **Product fixes** (minimal, real bugs, safe because those files carry no other
   session's edits): E1 the third news tab/label hard-coded «Aquatiq» becomes the
   workspace name (`DashboardUpdatesCard.tsx`, `shared/actions/home-updates.ts`,
   enum `aquatiq`→`workspace`); E2 Norwegian-aware weather glyph/label table in
   `information-client.ts` (so «Lettskyet» gets the right icon); E3 neutral URL
   placeholders in `KnowledgeComposer.tsx` (4 strings); E5 string-path asset fixes
   (`CoreNavbar.tsx:182`, `dashboard-cards.ts:60,73,86` use `?url` imports;
   `dashboard-search-utils.ts:23` no Google favicon in demo, gate on `VITE_DEMO`).
   Everything else is hidden in the demo by `home.css` (feedback widget, Språk, Logg
   ut, Utseende, session-loading label) or by the allowlist.
6. **Fonts**: self-host Geist (variable) in the demo bundle under
   `src/demo/product-demo/fonts/` with `OFL.txt`. If the Geist Mono file cannot be
   obtained offline, the builder uses the system mono stack for the demo and lists
   it as an owner action (do NOT download from the internet; look in
   `node_modules`, e.g. the `geist` or `@fontsource*` packages, first).
7. **Timeline**: the +0.5 hold in the pinned loop is accepted ONLY if
   `ProductLoopSection.test.tsx` and the existing progress tests stay green with
   constants exported from `product-loop-progress.ts`; otherwise stage 04 keeps its
   present dwell and the shield-button covers activation.
8. **Mobile**: on touch/narrow screens stage 04 shows a static poster card with an
   «Åpne demoen» button that opens the same demo in a full-viewport dialog (focus
   trapped, ESC closes). Desktop gets a «Fullskjerm»-less inline frame only.
9. **Deployment**: committed static artifact in `WEB/public/product-demo/` produced
   by `pnpm demo:build` (`scripts/build-product-demo.mjs`), with
   `WEB/plans/product-demo/manifest.json` (source hash, file list, size, build
   date, dirty flag). A vitest/node check fails when the manifest is stale.
   `WEB/next.config.ts` adds headers for `/product-demo/:path*` (CSP described in
   build-hosting-3, ACAO `*`, `X-Content-Type-Options`, no cache for `index.html`,
   immutable for hashed assets) and a rewrite from `/product-demo` to
   `/product-demo/index.html`. `robots.ts` disallows `/product-demo/`.

## Interfaces (contracts; do not change without telling the orchestrator)

`src/demo/live/shared-types.ts` (written) defines `DemoRoute`, `DemoRouteContext`,
`ThreadRow`, `HomeWorld`, `DemoLiveOptions`, `DemoLiveHandle`, the iframe message
types and `DEMO_NOW_ISO`.

* Engine exports `installDemoLive(options: DemoLiveOptions): DemoLiveHandle` from
  `src/demo/live/index.ts`. It must be called AFTER `installFixedClock`, installs
  the existing fetch interceptor (`installSceneFetch` or the equivalent in
  `src/demo/install.ts`, builder inspects) with a responder hook so the live
  responder is consulted first for `/api/v1/chat/*` and the extra routes next,
  then the shared fixtures. The engine owns ALL `/api/v1/chat/threads*` and
  `/api/v1/chat/stream` routes, approvals, resume and thread messages.
* Home world exports `buildHomeWorld(now: number): HomeWorld` from
  `src/demo/fixtures/fjordform-home.ts` and `demoAllows(href: string): boolean`
  from `src/demo/allowlist.ts`.
* Hosting/entry builder calls both and wires them; it may add a thin DemoApp-level
  link interceptor that calls `demoAllows`.
* Site builder reads only the finished static contract: iframe `src`
  `/product-demo/index.html`, the message envelope, and poster files under
  `WEB/public/product-demo/`.
