1. FACT, blocker: the vector-leg corpus scope cannot work (D7 is not fixed).
   - Quarry's filter `filters.sources=["quarry"]` maps to a Qdrant payload key `source` (filters.rs:34). It is applied only in the dense arm (orchestrator.rs:1157-1170).
   - A live scroll of `dataplane_knowledge_embedv4` (100 of 207 points, keys only) shows payload keys {knowledge_id, document_id, org_id, chunk_index, text, document_date}. There is no `source` or `visibility`.
   - The writer confirms it: embedding-engine `qdrant_writer/mod.rs:90-125` and `batch/mod.rs:104-111`.
   - Sparse and keyword arms never read `filters.sources`; I grepped sparse, keyword and postprocess.
   - Net effect: the dense arm returns zero candidates for every Quarry search. The sparse arm stays unscoped and can return other org-visible documents. Live there are 1 sharepoint, 1 chat-upload and 2 quarry org-visible docs.
   - Every non-ZDR search still pays a Cohere Embed query call.
   - The comment at orchestrator.rs:1140 describes this exact failure class for Space filters.
   - Fix:
     - Make the scope server-enforced per service principal in the T03 route table (forced source=quarry), not a client filter.
     - Implement it as a SQL predicate on `documents.source` in the post-fusion gate (visibility gate at postprocess.rs:~499), covering every arm. Alternatively write `source` into the payload with a backfill and sparse support, which means a reindex.
     - Test it against real Postgres and Qdrant seeded with a mixed corpus.
