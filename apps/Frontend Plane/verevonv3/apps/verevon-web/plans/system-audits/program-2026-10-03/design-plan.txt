1. CORRECTED DESIGNS

Contextual retrieval (CR)
- CR stays ON with no off-switch. The env flag becomes an incident-only kill switch. The default flips to ON in code, compose and `.env.example`, with a default model and a boot-time check.
- Each knowledge unit gets a `context_status` state machine plus provenance. Legacy rows backfill with a NULL hash and status `legacy`, not an asserted-coherent hash. `embedding_model` is backfilled too.
- Inline generation is time-boxed. A DB-truth reconciler does backfill, repair and prompt-version refresh. Unchanged inputs make zero provider calls.
- Accepted `stop_reason` values are `{stop, end_turn}`. `{length, max_tokens}` counts as truncated. Test with a captured real Azure response.
- Lexical sync uses a DB-truth marker or a JetStream subject, because the core-NATS `units.contextualized` event is non-durable. Repair the Quickwit gap (52 of 207) via `documents.indexed` or rebuild with `--no-clear`.
- Metering goes through Data Plane usage v2 on a durable stream, then a data-orchestrator forwarder to cost-core `/api/v1/cost/record`, with a `feature` dimension. Pricing rows are needed for embed-v-4-0 and Cohere-rerank-v4.0-pro, or they price at the 3.00/15.00 default.
- Graph extraction: delete the `azure_openai` extractor and the Azure key in graph-index. Add the same state machine, DLQ and retry cap.
- No special case for single-chunk documents. The reconciler fills the one raw unit.
- Reranker sees context: once QB-A lands, add a flagged change so rerank text includes `chunk_context`, gated by the eval. This is why CR currently adds only +0.005 nDCG with rerank on.
- ZDR posture: a `tenant` retention posture. Auth Core resolves org-ZDR at mint. On resolution failure it returns 503 `retention_posture_unavailable` and issues no token, and the Data Plane maps that to `pending`. Tenant-principal token TTL is capped at 60s. The staleness window is disclosed.

Quarry option B (QB)
- `POST /v1/rerank` is a service-only sub-router in retrieval-engine-rs. It uses the existing paid Azure Cohere client, with no Model Plane and no subscription route.
- Auth is principal-aware, with a default-deny route table. Allowed: `/v1/retrieve*` and `/v1/knowledge/search` with `data:read`, and `/v1/rerank` with new scope `data:rerank`. Quarry's `zdr` and `sovereign_required` must be passed explicitly (wire values mapped from Quarry's `ZdrMode`, never "off").
- Vector-leg corpus scope is server-enforced as a SQL predicate on `documents.source='quarry'` in the post-fusion gate, covering all arms. The client filter cannot work because Qdrant has no `source`. That also makes rerank input public web text.
- ZDR on rerank:
  - `zdr_mode` is required on `/v1/rerank` (400 if absent).
  - It is the run-level flag after any BYO downgrade.
  - ZDR, sovereign and unapproved-processor cases return HTTP 200 with `status=skipped`, input order and a reason.
  - Quarry `/v1/search` requires `zdr` from service callers.
- Also fix:
  - `rrf_fuse` must keep `engines` and `fusion_score`.
  - Quarry must emit score and `score_kind` only after model-gateway calibration (T12) ships.
  - Vector leg gets an HTTP timeout, a kill switch, a budget, and viewer-grant skipping for service principals.
  - Redact the `retrieval.start` query when the mode is restrictive.
  - Highlights are deferred, because SERP snippets are 70-274 chars. They apply only to vector chunks or fetched text.
  - Idempotency key is `rerank:{org}:{request_id}:{contenthash}`. The "startup refuses" guard is a route-only 503.
- Delete Quarry's LLM reranker and `SEMANTIC_RERANK_MODEL`.

ZDR (ZR)
- Auth Core stays the only posture authority. A per-connection capability record (`supported/not_supported/cannot_verify`) lives in a side table in integration-corev2. An append-only ack ledger has no cascade FK, and the digest is computed only by integration-corev2.
- Ack and posture routes are bearer-only with `UserID == connection.UserID` and no internal-key bypass. This fits the earlier ruling that personal connections are owner-only.
- At turn start the BFF asks Auth Core for a signed decision. Auth Core mints `zdr=false` plus a connection-bound, versioned `zdr_waiver` claim. Model-gateway and inference-core honour it only for that exact connection and refuse any other route.
- Enforcers ship before minters. A kill switch sits on the decision route. The token set must be homogeneous, and every mint site carries the decision.
- Session-core records a `zdr_waived` receipt. Waived retrieval defaults to a filtering mode so restricted documents never go to the personal account. The ack text says retrieved org knowledge goes to OpenAI.
- The org flag is never written.
- Do mode on Terra still needs `AGENTIC_SUBSCRIPTION_ENABLED` and is not claimed closed.
- Space ZDR is not applied in v1.
