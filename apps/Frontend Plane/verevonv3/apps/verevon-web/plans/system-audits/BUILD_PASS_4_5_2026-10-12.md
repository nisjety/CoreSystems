## Open items from the reviewers (not fixed by the passes)

QB-T08 and the rerank cost path (shared with QB-M and QB-T05a R1 to R3):

- A. Cost never reaches cost-core. A web rerank call is recorded only in the Data Plane `cost_events` table as a schema v1 event; the forwarder selects `schema_version >= 2`, so cost-core never sees it. The live `cost_events` table has no `schema_version` or `forwarded_at` column and already holds 265 v1 tenant rerank rows, so tenant rerank has the same gap today. A v2 usage envelope from the producer and an owner decision are needed before `WEB_RERANK_ENABLED=1`.
- QB-M A: a publish that fails after the provider was paid is retried three times in about 1.2 s, then only counted and logged; the answer is served and cached and never re-recorded, and no alert references the metric. Owner decision: a durable outbox, or a fail-closed metering breaker plus an alert.
- QB-M B: a 2xx the provider billed but the route classed as degraded (no usable scores, or an unparseable body) is not metered; timeouts and transport errors after the send are billing-uncertain and also unmetered. Owner ruling needed.
- QB-M C: a replay after the 120 s cache TTL, or on another replica, makes a second paid call under the same ledger key, and the consumer's `ON CONFLICT DO NOTHING` drops the second row, so spend is under-counted. Needs a shared replay store or a per-call key.
- QB-M D: `USAGE_EMIT_ENABLED` is not wired to retrieval-engine in compose (the route then stays `metering_unavailable`, which is safe); QB-T08 owns that compose block.
- QB-M E: the usage-ledger golden's web-rerank case has count 1 where the table documents candidates (CR-T10 golden and its copies). QB-M F (pre-existing): tenant rerank hard-codes `zdr: false` and names the user in the event, so a ZDR org's spend is booked to a person.
- QB-T08 other: no price entry for Cohere rerank v4.0 pro in cost-core; counsel's Article 28 confirmation is needed before `WEB_RERANK_PROCESSOR_APPROVED=true`; region verification (strict calls are skipped until then); the service bearer in the matrix is fixture-signed, so no real Auth Core mint for quarry-edge has been exercised; `make smoke` and the auth matrix now need `DPV2_SERVICE_BEARER`.

QB-T05b: tenant and web permits are held across retry backoff, so under provider 429s a small pool degrades other tenants and the in-flight gauge overcounts (decide before setting `RERANK_PROVIDER_MAX_INFLIGHT`); a provider reply that maps to no valid index is billed but recorded as no cost (in QB-T05a's code; fix before enabling); the tenant client follows redirects and would re-send the api-key and tenant chunks (pre-existing; the route client refuses redirects); limits are per replica; one malformed `RERANK_PROVIDER_*` value resets all limits to defaults with an error log, which makes the tenant pool unbounded.
