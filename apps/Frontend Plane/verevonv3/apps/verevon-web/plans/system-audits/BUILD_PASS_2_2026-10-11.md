## Open items from the reviewers (not fixed by the pass)

Blocking Z-15 (A and B were found by its reviewer; A exists at HEAD, outside Z-15's files; the reviewer's item C was refuted, see below):

- A. Content routes outside the retention resolver. In `http_routes.rs`, `ai_translate` (and batch), `ai_translate_detect`, `ai_documents_*`, `ai_language*`, `ai_realtime` (and its session) and `ai_video_generate` send user content to inference with a caller-chosen provider and make no posture decision. Their request messages have no `zdr` field, and `INFERENCE_CALLS` in `zdr_posture.rs` lists none of them, so the inventory test passes. Fixing it needs new catalogue feature keys (regenerate `zdr-refusals.json` and its pin, plus the SPA copy) or an owner decision.
- B. The counting-double test for waived `reject` mode was not written (only request-body tests exist).
- C. Refuted by the orchestrator on 2026-10-11. The reviewer reported that a request carrying `x-zdr: true` only as a header runs as persistent because `ag_ui.rs` forwards the body unchanged. It does not: `stream_agent_ui` calls `normalized_model_body` (`ag_ui.rs:87`), which ORs the header into the body's `zdr` field, exactly as the chat stream (`chat/streams.rs:50`) and the JSON handlers (`chat/json_handlers.rs:92`) do, and `apply_org_zdr_posture` then raises it for ZDR orgs. The forwarded `x-zdr` header is redundant. No defect on those routes. Not checked: the fixed-body `/v1/invoke` calls in `knowledge/products.rs`. (The SPA never sends the header; only API callers would.)
