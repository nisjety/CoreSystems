## Open items from the reviewers (not fixed by the pass)

QB-T09 (the reason it is not shippable):

- A. Cost regression in the default configuration (owner decision). With the compose defaults (`SEMANTIC_RERANK=1`, `DATA_PLANE_URL` set), every non-ZDR search is either skipped (the Data Plane's `WEB_RERANK_ENABLED` defaults off) or degraded (`token_unavailable` until the Control Plane grant). Neither may be cached under the manifest's rule, so every non-ZDR search misses the cache and pays the SERP providers again. This is the open owner call from pass 1 ("deterministic skips should be cached too"). Options: open the Data Plane gate and the grant first; set `QUARRY_EDGE_SEMANTIC_RERANK=0` until then; or change the cache rule for deterministic skips.
- B. Deploy coupling: model-gateway's relevance gate (`relevance.rs`) uses Quarry's score as `provider_score`, and its Quarry request has no `score_kinds`, so it would lose the score with no error and chat source filtering would change. Its opt-in (QB-T12) must ship before or with this.
- C. Processor scope (owner decision): rerank sends the query and each candidate's title and snippet to the paid processor for every non-ZDR org; the only gate is the global `WEB_RERANK_PROCESSOR_APPROVED`; the per-request `allow_third_party_processing` flag is not carried.
- D. Token refusals (Auth Core 401 or 403) log at ERROR on every call, unthrottled; the owner's rule is once per minute.
- E. Wire changes against HEAD: highlights are gone (QB-T06 deferral); scores appear only for callers that send `score_kinds`; a whitespace-padded org id gets a Data Plane 403 (fail closed, low).
- F. A dropped call can release another call's half-open probe (at most one extra probe).
- H. Found by the orchestrator, missed by the reviewer: four `quarry-runtime` rerank tests fail in a full workspace run (three in `rerank::tests` and `dp_rerank_contract::the_request_carries_the_rerank_v1_fields_and_the_web_rerank_token`): the tests expect `input_too_small`, `Shadow`, the reranker's order and a v1 field, and the code gives `input_not_tenant`, `Skipped`, the input order and null. Details are in the verification section. Fix them in the rebuild.
- G. The manifest row `web-rerank` says granted, but the `data:rerank` grant for quarry-edge is not in the checked-in Auth Core policy. Flip the row to false until the grant lands, or make it a hard gate.
